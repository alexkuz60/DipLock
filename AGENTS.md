# AGENTS.md — инструкции для ИИ-агентов (DipLock)

> Файл читается автоматически ИИ-агентами (Copilot, Cursor, Codex, Claude Code и др.).
> Обзор полной архитектуры: `audit.md`, `README.md`. Держите этот файл компактным.

## Обзор

FastAPI-бекенд + React/TS-фронтенд для анализа ЭЭГ: EDF → артефакты → эпохи → фильтры → диполи → 3D-локализация.
Стек: **Python 3.12, FastAPI, MNE-Python, SQLAlchemy (SQLite/dev, PostgreSQL/prod), Docker**;
UI — **Vite 6 + React 19 + TypeScript (strict) + Tailwind CSS v4 + TanStack Query + zustand**.
Научные данные FSAverage (FreeSurfer) лежат локально в `~/mne_data/`.

## Команды

```bash
# --- backend ---
cd backend && python -m venv venv
venv/bin/pip install -r requirements.txt              # + requirements-dev.txt для тестов
venv/bin/uvicorn app.main:app --reload --port 8000    # рабочая директория — backend/
venv/bin/python -m pytest                             # тесты backend

# проверка API
curl http://localhost:8000/health        # {"status":"ok",...}
curl http://localhost:8000/init-status   # готовность MNE/БД/fsaverage + versions/paths/ui
curl http://localhost:8000/api/v1/meta   # версии, параметры расчёта, surface_version
# Swagger: http://localhost:8000/docs

# --- frontend ---
cd frontend && npm install
npm run dev        # http://localhost:5173/ui/ (proxy /api → :8000, CORS не нужен)
npm run test       # Vitest (jsdom)
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint 9
npm run build      # → ../backend/app/static/ui (раздаётся FastAPI по /ui/)
```

Спецификация UI и дорожная карта фаз — `docs/ui.md`; детали фронтенда — `frontend/README.md`.

## Конвенции

- **DRY**: частотные диапазоны (`freq_bands`) и длины эпох берите из `core/config.py`,
  не дублируйте в сервисах.
- **Не хардкодить пути** `/home/...` — только из `settings`/окружения.
- Типизация: все подписи функций — с аннотациями типов; докстринги на русском.
- **Async**: НЕ выполняйте тяжёлые MNE/CPU-операции напрямую в `async def` — используйте
  `asyncio.to_thread` / `run_in_executor` или job-очередь (`app/services/job_manager.py`).
- **Контракт API** описывается Pydantic-моделями в `app/schemas/` (+`response_model`): из OpenAPI
  генерируются TS-типы UI; «сырые» dict в ответах не добавляем.
- **Тяжёлые статические ассеты** (меш fsaverage, BA-индексы) — только отдельными кэшируемыми
  эндпоинтами (`app/services/surface_cache.py`), никогда внутри `/analyze`.
- Один шаг пайплайна = один модуль в `services/`, без смешивания ответственности.
- Кэшируйте ресурсоёмкие объекты (поверхности FSAverage, transform, labels).
- **Frontend**: новый раздел UI = запись в `frontend/src/app/sections/registry.ts` + компонент в
  `routes.tsx`; UI-тексты и подсказки — на русском, конвенции — `frontend/README.md`.
- **UI не запускает обработку сам** (важно): параметры раздела живут в zustand-срезе
  (`shared/state/`), правка параметра только помечает результат устаревшим и **не делает запросов**;
  расчёт стартует исключительно по кнопке (`POST /api/v1/jobs`) — сначала контролы и визуализация
  (можно на фикстурах), затем подключение расчёта. Новые контролы берите из `shared/ui/`
  (`FieldRow`, `SegmentedControl`, `SelectField`, `NumberField`, `CheckboxRow`, `StatusPill`).

## НЕ коммитить

- `venv/`, `__pycache__/`, `.env`, `data/results/`, `*.db` — см. `.gitignore`.
- `.env` содержит локальные пути/настройки — вместо него есть `.env.example`.

раздела.
**Правило:** новый сервис/багфикс → тест (backend → pytest, frontend → Vitest).

## Живой вьюер: интерактив (срез 2.9), разметка (2.10) и оверлеи (2.11)

- Команды из шапки (листание окна `<<` `<` `>` `>>`) идут во вьюер **только через состояние** —
  `navRequest` `{command, seq}` в `shared/state/edfRecording.ts`; `seq` монотонно растёт, поэтому
  повторный рендер и повторное монтирование вьюера не проигрывают старую команду
  (`handledNavSeqRef` инициализируется текущим `seq`). Императивных «ручек»/событий у вьюера нет.
- Параметры отрисовки, которые не должны переживать выход из раздела или обесценивать стадии, живут
  **в локальном состоянии** `TrackStack`: центр окна, курсор и разворот трека. В zustand — только то,
  что переживает перезаход (уровень зума, каналы, шкала амплитуды, видимость слоёв).
- **Каркас держит высоту окна**: `AppShell` — grid со строкой `grid-rows-[minmax(0,1fr)]`, колонка
  рабочей области — `min-h-0`. Без явной строки неявная растягивалась под содержимое: треки уходили
  за экран, резались `overflow-hidden` и внутренние скроллы (треки/панель) не появлялись вовсе.
  Правите каркас — проверяйте скролл в браузере, а не только тестами jsdom (там нет раскладки).
- Курсор ставится **кликом** и живёт до следующего клика (мышь его не таскает): `handleTrackClick`
  игнорирует клики после drag (`draggedRef`, порог dx > 3 px) и клики по кнопкам
  (`closest('button')` — подписи каналов и зоны артефактов).
- **Оверлеи вьюера — внутри прокручиваемого контента** (`data-testid="viewer-content"`), а не
  детьми скролл-контейнера (срез 2.11): абсолютный потомок скролл-контейнера скроллится вместе с
  содержимым, поэтому линия курсора `inset-y-0` имела высоту видимой области и при прокрутке вниз
  обрывалась на середине стека. Линия курсора тянется на весь стек, а подпись времени и карточка
  выделенной зоны «липнут» к верху области через `position: sticky` в контейнере `absolute inset-0`
  (его высота = высота всего контента — sticky работает до конца прокрутки). Новые оверлеи делайте
  так же; проверяйте прокруткой в браузере, jsdom раскладку не считает.
- **Ширина полосы прокрутки** (срез 2.11): `.scroll-y-always` задаёт её только через
  `::-webkit-scrollbar` (20 px вместо «тонких» 10 px — узкую полосу трудно хватать мышью). Стандартные
  `scrollbar-width`/`scrollbar-color` (Chrome 121+) отключают legacy-псевдоэлементы, поэтому для
  Firefox они вынесены в `@supports (-moz-appearance: none)`. Не возвращайте `scrollbar-width: thin`.
- Клик по названию канала разворачивает трек на высоту видимой области (`ResizeObserver`,
  фолбэк `TRACK_HEIGHT` при `viewportHeight === 0` в jsdom); соседи уезжают в скролл, стадии не
  сбрасываются. Скрытие канала в панели сбрасывает разворот. **mute/solo выпилены** — видимость
  каналов задаётся только чекбоксами панели.
- Неотключаемый вертикальный скроллбар — утилита `.scroll-y-always` в `styles/index.css`
  (`overflow-y: scroll` + `scrollbar-gutter: stable`), применена в треках и
  панели опций: полоса не «дёргается» между разделами. Не заменяйте её на `overflow-y-auto`.
- **Разметка эпох привязана к своей нарезке** (срез 2.10): у слоя-результата сетка строится по
  `epoch_length_ms` этого результата (`gridEpochLength`), у фикстуры/до расчёта — по параметру панели.
  Раскладывать `rejected_epochs` по текущему параметру нельзя: индекс живёт только внутри своей
  нарезки, и после смены длины эпохи штриховка уезжала на другой участок записи. Расхождение длин
  показывается пилюлей «разметка эпох: N мс» (стадия при этом помечена stale).
- **Ручные пометки эпох** (Ctrl+двойной клик по треку, `handleTrackDoubleClick`) хранятся
  **интервалами на таймлайне** (`EpochMark` в `shared/lib/viewerLayers.ts`), а не индексами, и живут
  в сторе записи (`edfRecording.epochMarks` — не в localStorage: правка относится к конкретной
  сессии). `toggleEpochMark` инвертирует итоговый вердикт эпохи и хранит правку только когда она
  расходится с решением алгоритма; правка видна и при выключенной штриховке, а снять её можно
  кнопкой «Снять» в панели «Эпохи». Счётчик «ручных пометок: N» считает **пометки**
  (`epochMarks.length`), а не ячейки сетки: после смены длины эпохи одна правка накрывает несколько
  эпох новой нарезки, а их штриховки сливаются в одну видимую полосу — счёт по ячейкам показывал бы
  «6» там, где пользователь поставил три (панель «Эпохи» считает так же). В расчёт диполей пометки
  пока не уходят (см. docs/ui.md §12).

## Проекции мозга: раздел «Диполи» (срез 3.1)

- Проекции рисуются **SVG, а не canvas**: цвета берутся токенами темы прямо в атрибутах
  (`stroke="var(--color-mri-dipole)"`, токены `--color-mri-*`). Canvas — только под пиксельную
  заливку реального тома МРТ (`docs/ui.md` §3.3), когда она появится.
- Геометрия — одна на все проекции (`shared/lib/mriProjections.ts`): **единый масштаб мм/пиксель**
  (`PROJECTION_SCALE = 1.5` px/мм, срез 3.3), поэтому фигуры **прямоугольные** — `projectionBox` даёт
  axial 240×294, sagittal 294×258, coronal 240×258 px, и анатомия не растягивается. `x = 0` —
  срединная сагитталь, `y = 0`/`z = 0` — через AC–PC. Клик по фигуре даёт точку
  **в плоскости своего среза** (`pointFromProjectionClick`), клик наводит все три среза
  (`applyPointToSlices` + `snapSlice`). Не дублируйте математику в компонентах и не заводите второй
  «невидимый» слой для мыши: попадание в поле Бродмана считается по тем же эллипсам, что нарисованы
  (`brodmannAreaAt`).
- **Колонки раздела «Диполи» пропорциональны ширине фигур** (`style={{ flex: '<box.width> 1 0%' }}` в
  `DipolesSection`): при равных колонках SVG растянулся бы по-разному, и общая шкала мм/пиксель
  пропала бы. Новые размеры/фигуры берите из `projectionBox`, а не задавайте «на глаз»: единый
  масштаб и целые пиксели фиксируют `mriProjections.test.ts::держит единый масштаб` (Vitest) и
  `DipolesSection.test.tsx` (пропорции колонок).
- Ряд фигур рассчитан на **десктопную ширину**: оболочка задаёт `min-width: 1366px`
  (`styles/index.css`), и на ней ряд ужимается пропорционально без переполнения (проверено в Chrome:
  ряд 886 px, изотропия 0.000%, расхождение шкалы между проекциями 0.13%). Уже — обрезка по решению
  продукта («мобильного адаптива нет»), а не баг раскладки: не «лечите» это сжатием одной проекции,
  иначе общая шкала сломается.
- Слои `head`/`mni`/`brodmann`/`dipoles` включаются чекбоксами панели; выключенный слой **не
  рисуется**, а не прячется прозрачностью. Порядок и подписи — в `shared/state/dipoleParams.ts`,
  отрисовка — `sections/dipoles/MriProjection.tsx`, сборка трёх фигур — `DipolesSection.tsx`.
- Срез наводится кликом (на глаз, с прилипанием к именованным) и `SliceScrubber` в панели (точно, с
  маркерами `x = 0`). «Точка под курсором» — локальное состояние проекции (только текст координат в
  строке под фигурой: маркера, бегающего за мышью, нет — его путали с кольцами диполей), в стор уходят
  слои, срезы, референс-точка и выделенное поле.
- Слой диполей — **пустой по замыслу**: раздел не имитирует расчёт, панель пишет «расчёт не
  подключён». Тип `DipolePoint` (MNI, момент, амплитуда, GOF, BA), векторы и хит-тесты уже есть —
  подключение расчёта станет сменой источника данных. Фикстура `demoDipoleLayer` — только для тестов
  и отладки отрисовки.
- Фикстуры слоёв (`demoHeadContours`, `demoSliceStructures`, `demoBrodmannAreas`) детерминированы
  (без ГПСЧ): картинка одинакова между рендерами, тестами и повторным монтированием. Это запасной
  вид: реальные структуры и поля приходят контурами атласа (раздел «Анатомия и поля Бродмана на
  срезах»), а контур головы из `mri/seghead.mgz` — следующий шаг.

## Реальный срез МРТ (срез 3.2)

- Том и срез живут **только на бэкенде**: `app/services/mri_slices.py` читает `mri/T1.mgz` +
  `mri/brainmask.mgz`, приводит их к MNI-сетке 1 мм (`fsaverage` совмещён с MNI305: `talairach.xfm`
  — единичная матрица), кэширует том на диске (`cache_dir/mri/volume-{version}.npz` + паспорт
  сборки) и отдаёт срез PNG (серый + альфа, вне маски прозрачно) через
  `GET /surface/mri/slice/{plane}/{mm}.png` с ETag/304 и заголовком `X-Mri-Slice-Mm` (фактический
  срез после квантования). UI не считает пиксели: он ставит `<image href>` в SVG.
- `MRI_BOUNDS` (Python) и `MNI_BRAIN_BOUNDS` (TS) — **одни и те же числа** (границы маски мозга,
  с мозжечком и стволом), плюс синхронны знаки `PLANE_*_SIGN`; расхождение ловит
  `tests/test_mri_slices.py::test_geometry_matches_frontend` чтением TS-таблиц. Меняете границы —
  меняйте обе стороны и проверяйте тестом, иначе срез «уедет» относительно сетки.
- **Укладка тома ≠ укладка сетки**: `T1.mgz` fsaverage лежит коронарно (`L, I, A`), поэтому строка
  обратной матрицы (она даёт индекс вокселя) и номер оси MNI **не совпадают** — оси y и z меняются
  местами. Узел сетки берётся своей осью вокселей (`voxel_indices`, `_voxel_axis_of`); «строка по
  номеру оси MNI» даёт вместо среза чужую анатомию, которую не исправляет ни один переворот
  картинки. Ловят это `test_voxel_indices_take_own_row_per_axis` (том-«линейка», быстро) и
  `test_real_volume_matches_independent_resample` (`nibabel.resample_from_to` — совпадение обязано
  быть пиксельным, `integration`). Меняете сборку тома — поднимайте `MRI_GRID_VERSION`, иначе на
  диске подхватится старый кэш.
- Полушария подписаны по RAS: **x > 0 — правое** (`AXIS_DIRECTION_LABELS.x`), а горизонталь
  аксиальной и коронарной проекций развёрнута знаками `PLANE_*_SIGN` — слева на экране правое
  полушарие (R), справа левое (L), т.е. радиологическая раскладка (вид снизу/спереди). Знаки
  зафиксированы тестом `mriProjections.test.ts::держит знаки осей MNI`.
- Срез в UI квантуется к сетке тома (`snapSliceToGrid`, «половина вверх» как в бэкенде): значение
  среза в UI дробное (0.1 мм), а картинка существует только на узлах 1 мм. URL картинки несёт
  версию ассета (`?v=`) — браузер кэширует срезы по URL, и после пересборки тома старые не «залипнут».
- Пока слой `mri` включён и загрузился, условная схема среза (`demoSliceStructures`) не рисуется:
  иначе поверх настоящей анатомии рисовалась бы «вторая». Недоступная картинка показывается текстом
  под фигурой, а состояние хранит **URL** неудачной картинки (не флаг): смена среза — новый URL, и
  попытка повторяется. Запрос к серверу в разделе ровно один — `/meta` за ссылкой на срезы; раздел
  по-прежнему **не запускает обработку**.
- PNG собирает свой энкодер (`app/utils/png.py`, без новых зависимостей): каналы чередуются
  **по пикселю**, иначе декодер прочитает пару «серый-серый» как один пиксель и картинка
  «раздвоится». Тест `tests/test_png.py` разбирает файл обратно (чанки, CRC, zlib), а не сравнивает
  байты с эталоном.

## Анатомия и поля Бродмана на срезах (срез 3.9)

- Контуры (структуры и поля) — **вектор, а не картинка**: `services/atlas_contours.py` строит объёмы
  меток на MNI-сетке 1 мм и отдаёт полигоны **в миллиметрах MNI по осям плоскости** через
  `GET /surface/contours/{plane}/{mm}` (JSON, ETag/304, `X-Contour-Mm`, `?v={version}`); UI рисует
  `<path>` и считает по ним попадание клика. Отдавать PNG было бы проще, но клик по структуре и
  подсветка поля тогда требуют второго, «невидимого» слоя геометрии — а он разъезжается с картинкой.
- Изолинии считает **свой** marching squares (`app/utils/marching_squares.py`): дырки (желудочек
  внутри структуры) возвращаются отдельными полигонами, заливка на клиенте — `evenodd`; ломаная
  упрощается Дугласом—Пекером (0.6 мм). matplotlib в рантайм не тянем — как и у топокарт.
- Структуры — метки `mri/aparc+aseg.mgz` (Desikan-Killiany + подкорка + желудочки), имена — из
  `FreeSurferColorLUT.txt` (файл поставляется с MNE) с русскими подписями и **fallback на имя
  атласа**; метки с `unknown` (неразмеченный обрезок коры) в атлас не входят.
- **Поля Бродмана размечены производно**: `lh/rh.ribbon.mgz` (лента коры) получает метку
  **ближайшей вершины** `PALS_B12_Brodmann.annot` (`cKDTree`). Метки PALS живут на поверхности, а не
  заполняют объём, поэтому «пятно на срезе» — это перенос поверхностной метки в объём; метод едет в
  ответе и в `/meta` (`method: nearest_cortex_vertex`), и UI **обязан** это подписывать (правило то
  же, что у «Быстрого режима» расчёта диполей). Не выдавайте разметку за измеренный атлас среза.
- **id меток в annot обоих полушарий совпадают** (2…67): правому полушарию даётся смещение
  (`_AREA_ID_OFFSET`), иначе rh перезаписывает lh и «BA17-rh» становится суммой двух полушарий.
  Признак ошибки — центроид поля у нуля и «двойное» число узлов.
- Выборка узлов — `_resample_nearest`: индексы применяются **к своим осям вокселей** и результат
  транспонируется в порядок MNI, потому что укладка `aparc+aseg` коронарная (`L, I, A`) и оси y/z
  меняются местами. Осевая укладка проверяется строго (0.99, а не 0.5 — поворот на 45° даёт ровно
  половину). Ловит это `test_resample_nearest_keeps_mni_axes` (том-«линейка» с коронарной укладкой)
  и `test_real_structure_centroids_match_affine` — центроиды таламуса/желудочка/ствола/гиппокампа
  обязаны совпасть с raw-томом через `affine` до миллиметра. Меняете сборку — поднимайте
  `CONTOUR_VERSION`, иначе на диске подхватится старый кэш.
- Измерено на живой машине (`aparc+aseg` + ribbon → объёмы): сборка **1.0 с**, кэш **0.4 МБ**
  (`cache_dir/contours/labels-{version}.npz`), срез — **~30 КБ JSON и ~100 мс**, 46 структур и
  19 полей на аксиальном срезе через AC–PC. Поэтому объёмы кэшируются, а контур считается по
  запросу; прогревать кэш заранее умеет `backend/scripts/build_atlas_contours.py`.
- В UI это два слоя: `anatomy` («Анатомические структуры») и `brodmann`. `null` контуров означает
  «ассета нет» → рисуется условная фикстура (эллипсы `DEMO_BA_LAYOUT`), а **пустой список меток** —
  это «на срезе их нет», и подменять одно другим нельзя (иначе на срезе без поля появилось бы
  нарисованное поле). Хит-тест идёт по тем же полигонам (`shapeAtPoint`) **от мелких к крупным**:
  клик по таламусу не должен называть накрывающее его белое вещество. Сервер отдаёт метки по
  убыванию площади — на это опирается и порядок перебора.
- Слой `anatomy` включается отдельно от `mri` и `brodmann`; выключенный слой не рисуется вовсе, а
  запросы контуров вообще не уходят (`enabled` в TanStack Query). Запросы раздела остаются
  **статическими ассетами** (`/meta`, `/surface/...`): раздел по-прежнему не запускает обработку.
- Границы (Python) и знаки осей (TS) общие с срезами МРТ: контур строится в тех же осях и
  раскладку (радиологические знаки) применяет UI — иначе контур «уедет» относительно картинки.

## Спектр, быстрый расчёт диполей и выдвижная панель (срез 3.4)

- **Быстрый режим ≠ точный фитинг** и это не «оптимизация»: `services/dipole_scanner.py` даёт
  **одну точку на эпоху** в пике GFP и ищет её **перебором узлов** объёмной сетки (~7 мм) на
  сферической модели головы (Φ = (m·r)/(4πσr³), σ = 0.3 См/м), без BEM и `mne.fit_dipole`.
  Ошибка позиции — порядка шага сетки, результат помечен `method='fast_grid'`, и UI **обязан**
  показывать метку («Быстрый режим, сетка N мм»). Меняете метод — меняйте метку, а не молчите.
  Свинцовое поле центрируется по каналам (average reference уже применён к сигналу), узлы ближе
  5 мм к электроду отбрасываются (`min_dist` у `fit_dipole`), момент — А·м → нА·м (×1e9).
  Перебор векторизован (`GᵀG`, `Gᵀd`, `np.linalg.solve` с регуляризацией и **явной осью** у правой
  части: numpy 2 не принимает вектор (n_grid, 3) как «пачку»), а сетка кэшируется `lru_cache`.
- **Скорость быстрого режима — измеренная, а не обещанная**: на живой записи (`data/edf/test.edf`:
  130.7 с, 500 Гц, 18 каналов, нарезка 500 мс → **261 эпоха**, все точки с MNI) расчёт занял
  **7 мм — 2.2 с, 4 мм — 11.8 с, 2 мм — 99.8 с**. Число узлов сетки растёт как шаг⁻³, поэтому шаг
  (диапазон 2–20 мм: `GRID_MM_RANGE` в UI, `ge/le` в форме роута, по умолчанию 7) — главный рычаг
  скорости, а не «оптимизация» кода. Сравнивать режимы нужно на одном числе эпох, иначе цифры
  несопоставимы.
- **Одна точка на эпоху — не траектория**: playback (срез 3.7) показывает кадр по сетке эпох и
  интерполирует его **для отображения**, но это по-прежнему одна измеренная точка на эпоху; GOF-график
  — следующий срез. Не выдавайте единственный кадр за траекторию в UI.
- **MNI — только через transform**: `mne.read_trans` + `mne.head_to_mni` (правило безопасности);
  при недоступном fsaverage точка отдаётся с `mni_coords: null` + предупреждение, а в слой проекций
  **не попадает** (`dipoleLayerFromScan`): рисовать её «где-то» нельзя.
- **Спектр и топокарты** (`services/spectral.py`): Welch PSD по эпохам (reject-порог), x1e12 в
  мкВ²/Гц (не через `units` — параметр дрейфует между версиями MNE), диапазоны — только из
  `settings.freq_bands`. Топокарта — **готовая PNG** (ортогональная проекция монтажа, IDW,
  серая шкала + альфа вне круга скальпа): пиксели UI не считает, лишний matplotlib в бэкенд не
  тянется. Кэш — дисковый, ключ и ETag — `spectrum_signature` (полоса, notch, эпоха, reject, n_fft,
  каналы), поэтому URL картинки **обязан** нести параметры расчёта + `v={topomap_version}`.
- **`None`, а не `NaN`**: диапазон вне частотной оси отдаётся как `null` («не измерено») — `NaN`
  невалиден в JSON и ломает разбор на клиенте; UI показывает «—», а не «0.00».
- **`reject_threshold_uv` эхом в результате**: URL/ETag топокарты считается по нему, поэтому
  клиент берёт параметры из **результата** (`spectrumQueryOf`), а не из текущих настроек панели.
- **Выдвижная панель** — новый проп `drawer` у `AppShell` (полоса **между** шапкой и `main`):
  содержимое не уезжает при прокрутке рабочей области, а `main` сохраняет свою прокрутку
  (`min-h-0`). Открыта одна панель за раз (`dipoleCalc.view`), кнопки — в тулс-хедере раздела
  (`routes.tsx`: `Drawer` в `SECTION_MODULES`).
- **Порог «КД ≥ X нАм» — параметр отображения**, а не расчёта: `thresholdDipoleLayer` фильтрует
  слой перед отрисовкой, точки в результате задачи остаются, а счётчик скрытых
  (`hiddenByThreshold`) считается по слою. Правка порога ничего не запускает и не делает запросов.
- **Задачи записи** (`kind=spectrum` / `kind=dipoles`) — через общий `job_manager`, результат рядом
  с записью (`/recordings/{id}/{kind}/{job_id}`), `_job_status` собирает `result_url` по `kind`.
  Новые поля прогресса `epochs_done`/`epochs_total` в `Job`/`JobStatus` заполняются колбэком
  `set_progress(..., epochs_done=…)`: «эпох 12 из 30» информативнее дробного прогресса. Задача
  стартует **только** `POST …/spectrum` / `POST …/dipoles`; сброс результатов — при загрузке новой
  записи и при «Закрыть запись» (`useDipoleCalc.reset()` из `edfRecording`). Ошибки задач хранятся
  **раздельно** (`error` / `spectrumError`): общий текст показывал бы сбой локализации как «спектр
  не рассчитан», а ошибка пересчёта не должна прятаться за прежним результатом.
- Полоса фильтра расчёта задаётся **формой в панели раздела** (срез 3.6, см. ниже): пресеты δ…γ
  приходят из `/meta`, есть «свой диапазон», «одиночная частота» (`f ± bw/2`) и «без фильтра».
  Живёт форма в `dipoleCalc`, а не в `edfParams`, чтобы расчёт не менялся «незаметно» от правок
  предподготовки записи.

## Воспроизведение траектории (срез 3.7)

- **Кадр идёт по сетке нарезки результата**: время сессии `t` растёт непрерывно, эпоха —
  `floor(t / epoch_length_ms)`, длительность воспроизведения — `n_epochs_total × epoch_length_ms`
  (×1 — реальное время записи: на `test.edf` 261 × 500 мс ≈ 130 с). Скорости — **только 1/2/4**
  (`PLAYBACK_SPEEDS`; чужое значение `normalizePlaybackSpeed` приводит к ×1).
- **Интерполяция — отображение, а не измерение** (`shared/lib/playback.ts`): между соседними эпохами
  позиция интерполируется по прямой, направление момента — **по дуге** (slerp с явными фолбэками у
  почти совпадающих и противонаправленных векторов), амплитуда — линейно (длина и плотность луча
  меняются плавно). Измеренные величины (эпоха, время пика, GOF, поле Бродмана, id) остаются у своей
  эпохи и не «размываются». В UI это подписано, в UI-текстах слово «измерение» к кадру не применяется.
- **Разрывы не «дотягиваются»**: интерполяция идёт только между соседними эпохами, у которых есть
  точки. У отброшенной эпохи кадр **пуст** — протягивать диполь через дыру в данных нельзя.
- **На паузе и при шаге кадр равен измеренной точке своей эпохи** (доля внутри эпохи — ноль): «остановился
  на интересном кадре» — это остановился на измерении, а не на выдуманном полутоне.
- **Время кадра — локальное состояние часов**, а не стор (`app/sections/dipoles/playbackClock.ts`):
  ~60 обновлений в секунду в zustand перерисовывали бы облако из сотен точек. В стор уходит только
  смена эпохи; раздел подписан на **признак** кадра (`playback.active`), не на номер и не на время.
- **Команды — через состояние** (`seekSeq`, как `navRequest.seq` в EDF): «покадрово» на границе записи
  не меняет номер эпохи, но обязано быть видно часам — поэтому счётчик пользовательских переходов
  растёт монотонно, а сдвиг часов (`setPlaybackEpoch`) его не трогает и при том же номере стор не
  трогает вовсе. Императивных «ручек» у проекций нет.
- **Кадр идёт контекстом, а не пропсом** (`playbackClock.ts` + `PlaybackFrame.tsx`): провайдер оборачивает
  ряд проекций, проекции приходят ему как `children` (те же элементы), поэтому React пропускает их
  перерисовку, а обновляется только `FrameMarker` в SVG. Провайдер перерисовывается сам — это нормально,
  и тест `PlaybackFrame.test.tsx` фиксирует, что статичный сосед рисуется один раз за сотни кадров.
- **Маркер кадра отличается гало**: кольцо позиции остаётся Ø 6 px (правило «все позиции — одинаковые
  кольца»), кадр отмечает второе кольцо (`DIPOLE_FRAME_HALO_RADIUS_PX`) акцентным цветом. Облако
  приглушается (`FRAME_DIM_OPACITY`), выделенный кликом диполь — нет: это осознанный выбор пользователя.
- **Шлейф траектории — история измерений, а не ещё один слой диполей** (`trailSegments`): отрезки между
  точками **соседних** эпох за последние `TRAIL_WINDOW_MS` (10 с сессии — окно во времени, а не в числе
  эпох, поэтому смысл не меняется при смене длины нарезки), гаснущие с возрастом от
  `TRAIL_ALPHA_HEAD` у кадра до нуля; число отрезков ограничено (`TRAIL_MAX_SEGMENTS`), иначе на коротких
  эпохах шлейф стал бы вторым рисунком облака. Через разрыв шлейф **не тянется** (два отрезка вместо
  сквозного), рисуется в слое позиций (путь — это «где был», а не «куда направлен») **под** маркером и
  живёт вместе с ним: нет кадра — нет и шлейфа. Толщина — как у луча (`TRAIL_STROKE_PX`), цвет — токен
  `--color-mri-dipole`: шлейф принадлежит тому же диполю, а не новой сущности.
- **Порог «КД» действует и на кадр, и на шлейф**: слабый диполь кадром не рисуется, а отрезок не
  рисуется, если слабее порога любой из его концов (иначе шлейф вёл бы к точке, которой на проекциях
  нет); воспроизведение при этом продолжается — эпоха видна в шапке.
- **Конец записи — стоп на последней эпохе**; play с последней эпохи начинает запись сначала. Уход из
  раздела останавливает часы (они живут только в нём), кадр при этом остаётся: вернувшись, видно, где
  остановились. Сброс кадра — кнопка «Снять кадр», новый результат расчёта и закрытие записи.
- **`Space` — воспроизведение** (`AppShell`, `docs/ui.md` §9): только в разделе «Диполи», в других
  разделах Space не перехватывается (обычная прокрутка), в полях ввода хоткей игнорируется.

## Поправки ручной проверки (срез 3.9): справка, слой анимации, структура в таблице

- **Анимация — свой слой** (`playback` в `dipoleParams.ts`, чекбокс «Кадр воспроизведения»): кадр, его
  луч и шлейф рисуются группой `layer-playback-{plane}` и **не зависят** от слоёв `dipoles`/`vectors`.
  Раньше при выключенных позициях гало кадра исчезало вместе с облаком, хотя кадр — не облако; теперь
  выключение облака убирает только облако, а выключение слоя анимации — анимацию целиком. Приглушение
  облака включается **вместе со слоем** (`DipolesSection`: `playback.active && visibility.playback`):
  нет кадра — нет и причины приглушать. Само приглушение `FRAME_DIM_OPACITY` = **0.3** (0.2 × 1.5):
  облако под анимацией должно читаться, но оставаться фоном (`< MARKER_OPACITY_MIN`).
- **Кольца позиций — Ø 6 px** (`DIPOLE_DOT_RADIUS_PX = 3`, штрих 2 px), гало кадра —
  `DIPOLE_FRAME_HALO_RADIUS_PX = 7`. Размеры остаются **экранными**: компонент делит пиксели на масштаб
  фигуры, поэтому правило «все позиции — одинаковые кольца» держится при любой ширине колонки.
- **Пояснений в рабочей области нет**: абзац о том, как читать фигуры, уехал в диалог «Справка»
  (`sections/dipoles/DipolesHelpDialog.tsx`) — кнопка `CircleHelp` в тулс-хедере **справа** (после
  распорки `flex-1`, как «Паспорт» в EDF). Рабочая область показывает данные и полосу состояния с
  числами, объяснения читаются по запросу. Правило общее: пояснительный текст не занимает место фигур.
- **Структура точки приходит с сервера**: `DipoleScanPointOut.anatomical_structure` — метка
  `aparc+aseg` в MNI-узле точки (`services/atlas_contours.structure_at`, тот же атлас и то же
  округление «половина вверх», что у контуров срезов). В таблице локализации это **отдельная
  колонка** `structure` («Структура»), а не подпись поля Бродмана: структура — измеренная метка
  объёма, поле — производная разметка коры. `None` (нет координат или узел без метки) → «—»: в
  объёме ~78% узлов не размечены (вне мозга и вне структур), и прочерк здесь честный, а не сбой.
  Считать структуру на клиенте по контурам срезов нельзя — получилась бы вторая анатомия, не
  совпадающая с расчётом.

## Позиции/векторы, выделение диполя, маркер позиции и окно частот FFT (срез 3.5)

- **Позиции и векторы — разные слои** (`dipoles` / `vectors` в `dipoleParams.ts`): «где» и «куда»
  отвечают на разные вопросы, а при плотном облаке точек лучи мешают читать позиции. Выключение
  позиций **не** выключает лучи: луч начинается от координаты диполя, и карта направлений без точек —
  осмысленный вид. Выключенный слой не рисуется вовсе (как и раньше), а не прячется прозрачностью.
- **Выделение диполя — состояние просмотра, и оно наводит срезы** (срез 3.5, поправка ручной
  проверки): `selectedPointId` живёт в `dipoleCalc` (не персистится, сбрасывается вместе с результатом
  задачи в `reset()`), клик по точке подсвечивает её **во всех трёх проекциях** **и наводит срезы на
  её позицию** (`onPick` с точными MNI точки): срезы обязаны меняться при любом клике по фигуре.
  Клик идёт по невидимой хит-зоне радиусом `DOT_HIT_RADIUS_PX`; `stopPropagation` остаётся, чтобы
  клик не обработался дважды — фигура навела бы срезы на «сырую» точку клика у края хит-зоны.
  Повторный клик по выделенной точке снимает выделение (`toggleSelectedPoint`), подпись выбора —
  пилюля в разделе.
- **Маркер позиции — белое кольцо фиксированного экранного размера** (поправка ручной проверки):
  Ø 6 px, штрих 2 px (`DIPOLE_DOT_RADIUS_PX`/`DIPOLE_DOT_STROKE_PX` в `shared/lib/dipolePoints.ts`)
  при любом размере окна — фигура растягивается по ширине колонки (`w-full`), поэтому `MriProjection`
  делит пиксели кольца на масштаб `renderedWidth / viewBox.width` (ResizeObserver; в jsdom масштаб 1).
  Обычное кольцо — белое (`--color-mri-dipole-point`), выделенный диполь залит оранжево-жёлтым
  (`--color-mri-dipole`). Толщина луча тоже фиксирована (`DIPOLE_RAY_STROKE_PX` = 2 px по экрану), а
  сила момента видна по **плотности и длине** луча: `dipoleRayVisual(amplitudeNaM)` даёт прозрачность
  0.35→1 с насыщением на `FORCE_FULL_NAM` (100 нАм) — одиночный выброс иначе растянул бы шкалу, и все
  прочие лучи выглядели бы одинаково слабыми. Не подмешивайте сюда порог
  «КД»: он по-прежнему **скрывает** слабые диполи и не меняет их вид.
- **Наконечник вектора — полигон, а не тег `<marker>`**: `dipoleArrowHead` считает длину наконечника от
  длины луча (4…9 px) и возвращает укороченный штрих `shaftEnd`, поэтому у короткого луча стрелка не
  накрывает весь луч, а у длинного не выглядит точкой. Один `<marker>` на проекцию этого не умеет
  (размер общий) — не возвращайте его «для простоты».
- **Геометрия эллипсов полей Бродмана — одна функция** (`ellipsePx` в `shared/lib/mriProjections.ts`):
  компонент берёт её и для отрисовки, и для хит-зоны. Радиусы в фикстурах заданы в долях полуразмаха
  своей оси, поэтому «пересчитать эллипс на месте в компоненте» нельзя: разъехавшиеся формулы сделают
  подсветку поля ложной (клик рядом подсветит поле, а клик по полю — нет), и глазами это не поймать.
  Согласие «нарисованный эллипс ↔ `brodmannAreaAt`» фиксирует
  `mriProjections.test.ts::держит эллипсы полей Бродмана ровно там, где их ловит хит-тест`.
- **Окно частот FFT — параметр просмотра** (`fftRangeHz` в `dipoleCalc`, персистится; `null` — весь
  диапазон): кнопки ритмов, поля «от/до» и «Весь диапазон» лишь срезают уже полученные числа PSD
  (`spectrumWithinWindow`) и **не делают ни одного запроса**. Логарифмический масштаб берётся по всему
  спектру (`psdScale`), иначе при сужении окна пики «подтягивались» бы к максимуму внутри окна и
  меняли высоту на глазах — сравнение с полным спектром стало бы ложным. Нормировка полос гистограммы
  тоже считается по всем диапазонам, поэтому полосы вне окна только приглушаются
  (`data-in-range="false"`), но остаются на месте. Окно **всегда** зажимается в частоты текущего
  расчёта (`clampFreqWindow`) — оно переживает смену записи, и чужое окно показало бы пустой график.
  Пустое окно (в нём нет измеренных частот) сообщается текстом, а не подменой на весь спектр.

## Форма фильтров расчёта диполей и спектра (срез 3.6)

- **Полоса — то, что уходит в задачу; пресет — выбор пользователя** (`shared/lib/calcFilter.ts`).
  Формы `POST …/dipoles` и `POST …/spectrum` принимают только `band_min`/`band_max`/`notch_hz`,
  поэтому в расчёт идёт **полоса** (`params.filterBandHz`), а δ…γ, «одиночная частота», «свой
  диапазон» и «без фильтра» лишь её задают (`filterPreset` + `filterBandHz` хранятся синхронно, как
  `FILTER_PRESETS` в `edfParams`). Не превращайте выбор в «вывод из чисел»: полоса 1–40 Гц совпадает
  с «широким» пресетом, и вывод сразу «отскакивал» бы обратно, пряча поля «своего диапазона» — свою
  полосу было бы невозможно ввести (тест «держит «свой диапазон» открытым»).
- **Диапазоны ритмов не дублируются в UI**: их отдаёт `/meta` (`freq_bands`, единственный источник —
  `core/config.py`) вместе с длинами эпох. Пока метаданные не загружены, ритмов в списке нет вовсе;
  «широкий 1–40», «свой диапазон», «одиночная частота» и «без фильтра» работают и без них.
  Сохранённый пресет-ритм, которого нет в текущих метаданных, заменяется пресетом по полосе
  (`filterPresetOf`) — значение списка не «повисает» вне пунктов.
- **Итоговая подпись печатает полосу, а не обещание названия**: `filterSummary` берёт числа из
  состояния. Если `freq_bands` сервера изменились после сохранения выбора, пользователь увидит
  фактические границы расчёта, а не «α 8–13» при полосе 8–12.
- **Одиночная частота = узкая полоса `f ± bw/2`**: ровно так её считает бэкенд для `single_freq`
  (`bandpass_filter.py`), а отдельного поля у этих задач нет — поэтому форма отправляет честную пару
  границ и показывает её в подписи. Меняете правило — меняйте и подпись, и тест, иначе UI будет
  обещать одно, а считать другое.
- **Сетевой фильтр — только 50/60 Гц** (`normalizeNotchHz`): значение из localStorage приводится к
  ближайшему, чтобы список и состояние не разъезжались («в списке 50, в задаче 55»).
- **Правка формы ничего не запускает** (правило раздела): сеттеры только меняют параметры и зажимают
  их в границы контролов (`normalizeCalcParams` — общая нормализация, ей же поднимаются сохранённые
  параметры прежней версии UI). Расчёт устаревает — панель показывает «параметры расчёта изменены —
  результат не пересчитан» (`resultMatchesParams`), как таблица локализации.
- Формат полосы в подписях — одна функция `filterBandText` (её же использует таблица локализации):
  свой формат в разделе заведёт второй «диалект» записи чисел.

- Раздел `/table` — **представление результата**, а не второй расчёт: он читает
  `useDipoleCalc().result` и состояния задачи/ошибки, и не делает **ни одного** запроса (это
  фиксирует тест: `fetch` не вызывался). Данные для него уже в браузере, поэтому сортировка и
  видимость колонок — чистая перерисовка, а не новый расчёт.
- Чистая логика — `shared/lib/tableRows.ts` (колонки, строки, сортировка, формат ячеек): в
  компонентах нет ни форматирования чисел, ни сравнений эпох. Настройки просмотра —
  `shared/state/tableParams.ts` (сортировка и состав колонок), в них ничего, кроме показа.
- **Показываются все точки результата**, включая точки без MNI: «все результаты расчёта» это все,
  а не «те, что удалось навести на проекции». Координаты у таких строк — «—» (не ноль!), а причина
  приходит `warnings` задачи. Так же ведут себя `NaN`-значения: «—», а не «0.00» (как `None` вместо
  `NaN` в `spectral.py`).
- **Полушарие — производная величина** (из знака MNI x, x > 0 — правое, RAS-раскладка проекций), и
  это написано в подсказке колонки: измеренное и выведенное не должны выглядеть одинаково.
  Колонки ROI нет, пока ROI не считается — пустая колонка читалась бы как «не определено».
- **Порог «КД ≥ X нАм» таблицу не фильтрует**: он параметр отображения проекций (срез 3.4), и в
  таблице честно показываются все точки, а расхождение с числом точек на проекциях объяснено
  подписью. «Тихая» фильтрация сделала бы два раздела противоречащими друг другу.
- **Результат принадлежит записи**: при загрузке новой записи и при «Закрыть запись» `dipoleCalc`
  сбрасывается вместе с таблицей (она просто становится пустой с объяснением, а не «последним
  результатом»). Если параметры расчёта в разделе «Диполи» изменили после расчёта, раздел
  предупреждает об этом (отпечаток `calcSignature`/`resultSignature` в `dipoleCalc`), но **не
  подменяет** числа и не запускает пересчёт.
- Сортировка среза — **только по номеру эпохи** (требование задачи): новые ключи (MNI, амплитуда,
  GOF) добавляйте вместе с фильтрами, чтобы сортировка и фильтрация опирались на один и тот же
  список полей. Нумерация эпох в таблице — с 1, как в подсказках проекций (`dipolePointTitle`).
- Виртуализация (TanStack Table + Virtual) пока не нужна: быстрый режим даёт одну точку на эпоху
  (десятки строк). Не тащите её в срез раньше, чем появится источник с тысячами строк.

## Правила безопасности

- Не передавать в `head_to_mni` путь-строку вместо `mne.Transform` (использовать `mne.read_trans`).
- CORS: не комбинировать `allow_origins=["*"]` с `allow_credentials=True`.
- Валидировать размер загружаемых EDF-файлов.
- MNE API дрейфует между версиями: `psd_welch`→`compute_psd`, `standard_1020`→`colin27_1020`,
  `read_labels_from_parc`→`read_labels_from_annot`, `baseline` по умолчанию `(None, 0)`.
  Проверяйте актуальный API через тесты.
- Фильтровать band-specific фильтром continuous **raw** до нарезки, а не короткие эпохи.
- Единицы EDF: часть файлов без physical dimension MNE читает как «вольты» (в 1e6 раз больше) —
  есть авто-детект масштаба (`_ensure_physical_units`) и переменная `EDF_UNITS`.
- Brodmann-атлас — `PALS_B12_Brodmann` (метки `Brodmann.N`), а не `aparc.a2009s`; нужен `nibabel`.
- BEM fsaverage: `fsaverage/bem/fsaverage-5120-5120-5120-bem-sol.fif`; average reference должна быть
  применена (`projection=False`), иначе `mne.fit_dipole` падает.
- `mne.fit_dipole` требует `Evoked` (не массив) и дорог — используйте `dipole_fit_decim`.
- Сигналы вьюера (2.5) отдаются **бинарным контейнером** `DPS1` (magic + uint32 LE + JSON-заголовок +
  float32 LE, канало-мажорно), а не JSON: 64k точек × 18 каналов в JSON не влезают. Чтение EDF —
  `preload=False` блоками; единицы контейнера всегда мкВ (опора на `units_autoscaled`, не на повторный
  авто-детект), min/max считаются по корзинам одним `get_data`-блоком с
  `np.minimum/maximum.reduceat`, уровни вне `signal_levels` → 400. Формат меняется только синхронно в
  `backend/app/services/recording_signals.py`, `backend/app/schemas/analysis.py`
  (`RecordingSignalsHeader`) и `frontend/src/shared/lib/signalFrame.ts`.
- **Записи просмотра не дублируются** (дедуп загрузок): `POST /recordings` считает sha256 содержимого
  в том же проходе по чанкам (`_save_upload(..., with_digest=True)`), реестр ищет запись по отпечатку и
  при совпадении **возвращает существующую** с `deduplicated=true` (200), а только что записанный каталог
  удаляет — копий на диске не появляется. Отпечаток + паспорт лежат в сайдкаре `recording.json` каталога
  записи (`write_sidecar`/`read_sidecar`), поэтому дедуп переживает рестарт: при первом обращении реестр
  лениво поднимает записи с диска (`_ensure_index`, `owned=False` — такие каталоги `clear()`/`_drop` НЕ
  удаляют, их сносит `prune_orphans` по TTL). Легаси-каталоги без сайдкара реестр не видит — их и дубли
  чистит разовый скрипт `backend/scripts/dedupe_recordings.py` (dry-run по умолчанию, `--apply` удаляет,
  попутно пишет сайдкары). Не заменяйте sha256 на «имя+размер»: копия с другим именем не поймается, а
  разные записи одного размера склеятся; корневые файлы каталога загрузок (`data/edf/test.edf`) не
  трогаются никогда — обход только по каталогам. Тесты: `backend/tests/test_recordings.py`
  (дедуп, сайдкар, восстановление, prune), `backend/tests/test_recording_cleanup.py`.
- Слои визуализации (огибающая треков) считаются min/max по корзине, а не «каждый N-й отсчёт»: иначе
  прореживание срезает пики артефактов — то, ради чего раздел существует. Пирамида сигналов строится
  лениво при первом запросе уровня и кэшируется на диске; уровни задаются `SIGNAL_LEVELS`, бюджет точек
  на ×1 — `SIGNAL_BASE_POINTS`.
- Слои результата вьюера (срез 2.6) — DOM поверх canvas-треков, а не часть uPlot: зоны артефактов,
  границы эпох, штриховка отброшенных. Контракт типов и цветов живёт в `frontend/src/shared/lib/artifacts.ts`
  (реэкспорт из `shared/state/edfParams.ts`), геометрия/фикстура — в `shared/lib/viewerLayers.ts`,
  отрисовка — в `app/sections/viewer/TrackLayers.tsx`. Цвета — токены темы (`--color-artifact-*`),
  заливка через `color-mix`, hex в JS не дублируется. До запуска стадии слои берутся из
  детерминированной фикстуры `demoLayers` с `source: 'demo'` (UI не имитирует обработку), после —
  из результата задачи (`source: 'result'`, срез 2.7), причём слоты стадий не перетирают друг друга.
  Слои и курсор делят одну систему координат с canvas-треками через `timeToX`/`xToTime`
  в `shared/lib/viewerMath.ts`.
- Предподготовка записи (2.7): стадия = задача (`kind=preprocess`) через общий `job_manager`, файл
  записи не удаляется. Контракт `PreprocessResult` (`backend/app/schemas/analysis.py`) отдаётся
  `app/services/preprocess.py`; `filter`/`artifacts`/`epochs` считаются на **свежем** сигнале (параметры
  фильтра уходят в запрос любой стадии), снимок параметров фиксируется в момент запуска кнопки
  (`stageSignature` + `markStageApplied(stage, signature)`), ошибка стадии показывается текстом.
  Детектор артефактов возвращает `zones` с каналами — аннотации MNE их не хранят. Пирамида сигналов
  пока «сырая»: перевод её на отфильтрованный сигнал — отдельный срез, а не тихая подмена данных.
- Экспорт окна (2.8) — **клиентский, без запросов**: данные уже в браузере, сервер не пересчитывает
  экран. Чистые модули `shared/lib/exportWindow.ts` (CSV, имя файла, деления шкалы, раскладка и сборка
  снапшота) и `shared/lib/download.ts` (Blob → ссылка → скачивание); кнопки — `viewer/ExportActions.tsx`
  в полосе вьюера, т.к. им нужны окно/каналы/canvas'ы треков (регистрируются в `TrackStack` через
  `canvasesRef`/`registerCanvas` — ref, а не состояние). CSV — длинный формат
  `time_sec,channel,min_uv,max_uv` (строка на пару «корзина × канал»): кадр уровня ×k прорежен
  сервером, выдавать его за полноразрешённый сигнал нельзя. PNG склеивается из canvas'ов uPlot плюс
  свои подписи/шкала/зоны/эпохи; canvas не читает CSS-токены — цвета через `getComputedStyle` с
  hex-fallback; отсутствие `toBlob` → текст ошибки, а не пустой файл.
- Ассет среза МРТ (3.2) — **только статический PNG с бэкенда**, UI пиксели не считает: `<image href>`
  в SVG, координаты — из общей геометрии проекций. Границы тома (`MRI_BOUNDS`-Python ↔
  `MNI_BRAIN_BOUNDS`-TS) и знаки плоскостей обязаны совпадать — обе стороны сверяет
  `tests/test_mri_slices.py::test_geometry_matches_frontend`; разошлись — срез уедет относительно
  сетки. Том (`T1`/`brainmask`) читается через `nibabel`, приводится к MNI-сетке 1 мм (без
  `head_to_mni` для пути-строки) и кэшируется на диске с версией; срез отдаётся с ETag/304 и
  заголовком фактического миллиметра, поэтому запросы кэшируемы и не попадают в `/analyze`.
