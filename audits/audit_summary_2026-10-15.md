# Summary: четыре аудита 15.10.2026 — итог для планирования

> **Дата:** 15.10.2026. **Вход:** `audits/audit_qwen.md`, `audits/audit_kimi.md`,
> `audits/audit_glm.md`, `audits/audit_deepseek.md` (все — на HEAD `26140ca`, срез 0015,
> одна формулировка задания, без погружения в код). Нумерация: S1–S9 (summary),
> расхождения — RS1–RS4.
> **Назначение:** свести выводы четырёх аудитов в один план дальнейшей работы.

## S0. Общая картина

Все четыре аудита независимо сошлись: **«большого переписывания» проект не требует**.
Инженерное качество высокое и самоподдерживающееся — инварианты закреплены
тестами-стражами, поэтому проект пережил рост до ~38.8k строк бэкенда, ~47k строк
рукописного клиентского кода, 118 путей API и 2284 тестов за ~5 недель без расползания.
Три реальных разрыва (вердикт Qwen, поддержан остальными):

1. **Методическое ядро не реализовано при готовой обвязке**: С0 (критерий годности
   диполя), С1 (поддиапазоны), С2 (кластеры), С5 (связность), С8 (пакетная обработка
   архива) — «нет» по `concept.md` §6. Таблица, групповой анализ и отчёты оперируют
   **несравнимыми между полосами** числами.
2. **Данные живут в двух поколениях схем** (legacy `sessions/epochs/dipoles` ↔ write-API
   4.4), read-API 4.7 не закрыт, квота кэша выключена, `data/cache` = 5.8 ГБ (99.7 % —
   рендеры «Нейромузыки», до 1.9 ГБ на запись).
3. **Документация нарушает собственные лимиты**: `AGENTS.md` 25 947 байт при договоре
   ≤15 КБ, `todo.md` 370 строк (33 «ЗАКРЫТ» против 9 открытых), битые ссылки на аудиты.

## S1. Консенсус четырёх аудитов

**Замечательно (единогласно):**
- сервисная архитектура «один шаг пайплайна = один модуль», слоистость «роут = форма и
  контракт, работа — в сервисах» (главный актив);
- контракт Pydantic → OpenAPI → TS-типы с двумя стражами свежести (pytest + CI);
- кэширующий слой (RAM → диск-персист → `cache_store` → ETag/304, отпечатки ассетов,
  сироты, LRU-механизм);
- async-дисциплина (29 `to_thread`, правило `ASYNC` в ruff), каркас UI (реестр разделов,
  «правка параметра не запускает расчёт»), тесты/CI (1055 pytest / 1229 Vitest);
- методическая честность: `fast_grid` ≠ `fit_dipole`, «GOF не сравним между полосами»,
  autoreject отклонён по замерам, ICLabel — advisory.

**Требует доработки (единогласно):**
1. `api/routes.py` — 2755 строк / 79 роутов / шесть доменов в одном файле (OM6).
2. Два поколения схем результатов; read-API 4.7 не закрыт; групповой анализ зависит от
   legacy-таблиц, которые новая ветка не наполняет.
3. Консилиум ~60 % — крупнейший открытый фронт (Т2 аудио/ASR, Т4 микрофон, Т6), качество
   сделанного высокое, но раздел не принят владельцем.
4. ЕмоЛаб / Нейроаудио — заглушки, Нейромузыка — эксперимент (статус заявлен честно).
5. Методическое ядро: С0 = 0 %, С2 = 5 %, С5 = 0 %, С8 = 0 % (только у Qwen — с замерами).
6. Гигиена документации и мёртвый код (docker-compose/`init_db.sql`/`/legacy`).

**Сомнительно — есть лучший вариант (3 из 4):**
- `docker-compose.yml` + `init_db.sql` + `backend/Dockerfile`: redis не используется,
  `init_db.sql` создаёт legacy-таблицы в обход alembic, том `./backend/data` не совпадает
  с фактическими данными, `--reload` ломает кнопку перезапуска → удалить/изолировать;
- legacy-ветка `/analyze` как источник кандидатов группового анализа → перевести на
  `recordings/analyses/dipole_points` после read-API 4.7;
- `init_db()` на каждой операции БД вместо `alembic upgrade head` в `lifespan` (Deepseek, P0).

### Шаг 1 — «Гигиена и честность» (1–2 дня, [правка]) — ВЫПОЛНЕН 15.10.2026 (см. S9)
1. Квота кэша: `CACHE_QUOTA_MB=4096` в `backend/.env`; `RECORDINGS_TTL_HOURS` — **оставлен 0**
   (решение 4.4, RS4); `.env.example` приведён к решению 4.4, состав квоты дополнен `audio`.
2. Убран глобальный `ignore::DeprecationWarning` из `pytest.ini` (маскировал дрейф MNE API —
   главный заявленный риск проекта).
3. `audits/` **версируется в git** (убран из `.gitignore`, ссылки в `AGENTS.md`/`docs` исправлены
   на `audits/…`); `data/protocols/` — явно игнорируется (решение владельца: черновики до
   вердикта).
4. Удалены `docker-compose.yml`, `init_db.sql`, `backend/Dockerfile`, `/legacy` +
   `static/index.html` (мёртвый код, единственный нарушитель alembic-правила).
5. Дефолты `config.py` → `_REPO_DIR`/`Path.home()`/SQLite (убрал хардкод `/home/...` —
   нарушение собственной конвенции `AGENTS.md`).
6. `init_db()` → мемоизация по URL + вызов в `lifespan` (P0 из Deepseek).
7. `todo.md` очищен от 33 закрытых записей (перенесены дословно в `docs/history.md`),
   `AGENTS.md` сокращён до ≤15 КБ; стражи-тесты (`test_docs_guards.py`).
8. `git gc --prune=now`.


### Шаг 2 — «Данные: read-API 4.7» (3–7 дней, [новое])
Read-API (`recordings`/`analyses`/`dipole_points`) + перевод кандидатов группового анализа
с legacy `/sessions`, legacy — deprecated. №2 у Qwen/GLM/Deepseek: дешевле любой новой
способности, раскрывает накопленные данные. Сюда же — `pytest-cov` + vitest-coverage
(мультипликатор перед Шагом 3, который тронет `dipole_scanner`/`spectral`/`roi`).

### Шаг 3 — «Методическое ядро» (1–2 недели, [новое] — главный прирост ценности)
**С0 (КД и базис нормировки) → С1 (поддиапазоны, с переиспользованием forward/inverse —
заодно оптимизация) → С2 (кластеры диполей)**. С0 открывает С1/С2 и паспорт критерия в
отпечатке прогона; без него всё построенное сравнивает несравнимое. Следом — **С8**
(пакетная обработка архива): инфраструктура готова (очередь, job_store, реестр), не
хватает планировщика серии и отчёта «обработано/ошибки/дубли».

### Шаг 4 — параллельный трек Консилиума ([новое])
ASR-пробы `transcribe` (Т2) → Т2 → Т4 (+ заявленная доработка общей очереди LLM/ASR перед
Т2), и **политика внешнего ИИ** (что уходит наружу, обезличивание, лимит бюджета,
предупреждение в UI). *Комментарий: GLM ставит Консилиум первым; я — вторым треком:
8 из 13 миграций и ~50 из 136 операций API уже ушли в раздел, который ещё не принят,
а С0 — единственное «крупное» с нулём. Если владелец приоритизирует Консилиум (миссия
10.10 — психоэмоциональный фон) — треки меняются местами, это осознанный выбор.*

### Шаг 5 — «Рефакторинг и оптимизация» ([реф/опт]) — только по мере касания и по замерам
- `n_jobs` для `compute_psd`/`eloreta`/`compare` (RS2) — с замером до/после через
  `journal`/`analytics.db`; можно вплетать в Шаги 2–3.
- Разрезка `routes.py` на роутеры по образцу `consilium.py`, ответственности в
  `report.py`/`compare.py`, `models/db.py` → `results.py`/`consilium.py`, `edfRecording.ts`
  на слайсы, `TypedDict`-контракты сервисов — при касании файлов, не кампанией.
- Клиент: код-сплиттинг бандла (~2.4 МБ), память аудио, float32 в `prepared_signal` —
  после замеров.
- **Не трогать**: слой кэшей/ETag, job-очередь, сервисную декомпозицию, инварианты
  `BAD_`/`DPS1`/`DPS2`/«история не UPSERT».

Отложенное **не поднимать**: sLORETA-Lite для δ, пакетная визуализация, Этап 5 клиента
(P7–P9) — вердикты остаются в силе.
