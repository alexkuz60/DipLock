# Эмо-звезда: расчёт кадров, лучей, темпа и вращения

> Спецификация **фактического** алгоритма «Эмо-звезды»: FFT-кадры, октавные
> блоки, децибельная шкала, глобальная нормировка, вращение по аккордам и
> темп-коррекция. Документ описывает текущий код, а не желаемое поведение:
> при расхождении источником истины остаются код и тесты, перечисленные в
> конце документа.
>
> Потребители: «Нейромузыка» (радар «Эмо») и «ЕмоЛаб» (звезда и
> «Эмограмма»). Контракт — `AudioEmoOut`, `schema_version = 6`
> (`backend/app/schemas/audio.py`).

## 1. Термины и поток данных

| Термин | Значение |
|---|---|
| Кадр (`frame`) | Одно окно FFT; в контракте — `{t_sec, rays[7]}` |
| Луч (`ray`) | Длина вершины полигона, `0…100` % радиуса; порядок `BAND_ORDER` |
| Счётчик | Сумма амплитуд двух октавных блоков; 7 счётчиков → 7 лучей |
| `global_max` | Максимум сырых счётчиков по **всем** кадрам и лучам; референс 0 дБ |
| `key_track` | Сегменты аккордов Chordino: `{t_sec, key_code, label}` |
| `tempo_track` | Оценки темпа VAMP: `{t_sec, bpm}` |
| `segment_track` | Сегменты QM Segmenter; в расчётах не участвуют |
| Доминанта | Вектор суммы компонент 7 вершин; зажимается к радиусу |
| Облако доминант | Доминанта каждого кадра после вращения и темп-коррекции |
| Суммарная доминанта | Центроид облака (среднее, не сырая сумма) |

### 1.1. «Нейромузыка»

1. EDF → полосовые стемы → микс → мастер **после контроля пика** (до
   эффектов 3D-цепочки).
2. VAMP по `master.wav`: Chordino → `key_track`, Tempo and Beat Tracker →
   `tempo_track`.
3. `emo_radar.frames_from_master(master, fs=48000, key_track, tempo_track)`:
   стерео-мастер → моно `(L+R)/2` → FFT-кадры.
4. `emo.json` пишется рядом с `master.wav` и входит в манифест рендера.
   Рендеры до среза «Эмо» добиваются лениво из `master.wav`
   (`GET /audio/render/{id}/emo`).
5. UI: кадры → динамический диапазон → вращение по аккордам →
   темп-коррекция → вершины → доминанта.

### 1.2. «ЕмоЛаб»

1. Файл wav/mp3 → `probe` (заголовок) → `decode_track`: моно `(L+R)/2`,
   ресемпл в **32 000 Гц**, максимум 1800 с.
2. `wav_bytes`: PCM_16 моно 32 000 Гц — временный WAV для Sonic Annotator.
3. Chordino (`chordino-simplechord-32k.n3`) → `key_track`.
4. Tempotracker (`qm-tempotracker-tempo.n3`, фиксированные 44 100 Гц) →
   `tempo_track`.
5. Segmenter (`qm-segmenter-segmentation-32k.n3`) → `segment_track` для
   визуального контроля; **на лучи, вращение и темп не влияет**.
6. `emo_frames(audio.data, fs=32000, ...)` → `emo.json` в
   `emolab/{track_id}/`.
7. UI использует те же модули, что «Нейромузыка».

Порядок шагов фонового анализа («ЕмоЛаб») и проценты статуса:

| Шаг | Функция | `pct` |
|---|---|---:|
| Декодирование | `track_input.decode_track` | 0.05 |
| Карта аккордов | `vamp_analysis.key_track_from_wav(..., CHORD_TRANSFORM_NAME_32K)` | 0.25 |
| Карта темпа | `vamp_analysis.tempo_track_from_wav` | 0.45 |
| Сегментер | `vamp_analysis.segment_track_from_wav` | 0.55 |
| ФФТ-кадры «Эмо» | `emo_radar.emo_frames` | 0.65 |
| Сохранение | `store.write_track_files` + манифест | 0.9 |

**Важно:** ключи и темп считаются **до** FFT-кадров, но не участвуют в их
расчёте. Бэкенд отдаёт dB-лучи и карты; вращение и темп-коррекцию применяет
UI. Поэтому «порядок данных» и «порядок геометрии» — разные вещи (§8).

## 2. Подготовка сигнала

### 2.1. Моно и частота анализа

- Стерео → моно: `x[n] = (L[n] + R[n]) / 2`; для моно-исходника — та же
  дорожка.
- Каналов больше двух — берутся первые два, затем среднее.
- «ЕмоЛаб»: `resample_poly(mono, 32000 / g, fs / g)`, где
  `g = gcd(fs, 32000)`.
  - 44 100 Гц → `320 / 441`;
  - 48 000 Гц → `2 / 3`.
- `float64`, проверка `np.isfinite`; NaN/inf — ошибка входного файла.
- `ANALYSIS_FS = 32000`, `MAX_DURATION_SEC = 1800`.
- «Нейромузыка»: `FS_AUDIO = 48000`; мастер уже в памяти, моно — `mean(axis=1)`.

| Поток | `fs_audio` | `hop_samples` | Длительность кадра |
|---|---:|---:|---:|
| «Нейромузыка» | 48 000 | 32 000 | `32000/48000 = 2/3` с |
| «ЕмоЛаб» | 32 000 | 32 000 | `32000/32000 = 1` с |

Один и тот же `hop_samples` при разной `fs_audio` даёт разные сетки времени;
шаг кадра всегда `hop_samples / fs_audio`.

### 2.2. Вход для VAMP

Sonic Annotator читает только файлы, поэтому WAV кодируется в памяти
(`track_input.wav_bytes`) и пишется во временный файл внутри
`vamp_analysis._run_transform`; файл удаляется всегда.

- WAV: PCM_16, моно, 32 000 Гц.
- Таймаут прогона: `VAMP_TIMEOUT_S = 300` с.
- Инструмент/трансформ не найден, процесс упал, таймаут или `rc != 0` →
  `None`; расчёт кадров не падает, соответствующая карта остаётся пустой.
- `VAMP_PATH` выставляется явно из `settings.vamp_path` (по умолчанию
  `~/vamp`).

## 3. FFT-кадры

### 3.1. Константы и окно

| Константа | Значение |
|---|---:|
| `EMO_FFT_SIZE` | `32768 = 2^15` |
| `EMO_HOP_SAMPLES` | `32000` |
| `EMO_OVERLAP_SAMPLES` | `32768 − 32000 = 768` |
| Окно | прямоугольное, без аподизации |

Для окна `x[0…32767]`:

```text
X_k = Σ_{n=0}^{32767} x[n] · e^(−2πikn/32768),  k = 0…32767
A_k = |X_k|
```

Используется **полный комплексный** `np.fft.fft`, а не `rfft`. Нормировки на
`N` нет; общий масштаб сокращается в дБ-отношении. Амплитуда бина — модуль
комплексного числа, а не мощность и не энергия.

### 3.2. Сетка стартов и число кадров

```text
starts = 0, 32000, 64000, …
```

```text
N ≤ 0            → 0 кадров
0 < N ≤ 32768    → 1 кадр (окно с zero-pad)
N > 32768        → ⌈(N − 32768) / 32000⌉ + 1
```

Эквивалент кода:

```text
last = (N − 32768 + 32000 − 1) // 32000
frames = last + 1
```

Последнее окно всегда покрывает хвост; если хвост короче 32 768, он
дополняется нулями. Окон «только из нулей» не появляется: хвост меньше
32 000 сэмплов уже покрыт последним окном.

| `N`, сэмплов | Кадров |
|---:|---:|
| 0 | 0 |
| 1…32768 | 1 |
| 32769 | 2 |
| 64768 (`32768 + 32000`) | 2 |
| 64769 | 3 |
| 96000 | 3 |

В контракт кадр пишется как:

```text
t_sec = start / fs_audio     (округление до 6 знаков)
rays  = [round(pct_i, 3) for i = 0…6]
```

## 4. Октавные блоки и 7 счётчиков

### 4.1. Блоки

```text
octave_blocks() = [(2^b − 1, 2^b) for b = 1…14]
```

Пара — `(первый_бин, ширина)`, полуинтервал `[start, start + width)`. Блок
`b` покрывает бины:

```text
2^b − 1 … 2^(b+1) − 2
```

14 блоков покрывают бины **1…32766 ровно по одному разу**. Бин `0` (DC) и
бин `32767` не участвуют.

| `b` | Бины | 32 кГц, Гц | 48 кГц, Гц | Луч |
|---:|---|---:|---:|---:|
| 1 | 1–2 | 0.98–1.95 | 1.46–2.93 | 0 |
| 2 | 3–6 | 2.93–5.86 | 4.39–8.79 | 1 |
| 3 | 7–14 | 6.84–13.67 | 10.25–20.51 | 2 |
| 4 | 15–30 | 14.65–29.30 | 21.97–43.95 | 3 |
| 5 | 31–62 | 30.27–60.55 | 45.41–90.82 | 4 |
| 6 | 63–126 | 61.52–123.05 | 92.29–184.57 | 5 |
| 7 | 127–254 | 124.02–248.05 | 186.04–372.07 | 6 |
| 8 | 255–510 | 249.02–498.05 | 373.54–747.07 | 0 |
| 9 | 511–1022 | 499.02–998.05 | 748.54–1497.07 | 1 |
| 10 | 1023–2046 | 999.02–1998.05 | 1498.54–2997.07 | 2 |
| 11 | 2047–4094 | 1999.02–3998.05 | 2998.54–5997.07 | 3 |
| 12 | 4095–8190 | 3999.02–7998.05 | 5998.54–11997.07 | 4 |
| 13 | 8191–16382 | 7999.02–15998.05 | 11998.54–23997.07 | 5 |
| 14 | 16383–32766 | 15999.02–31998.05 | 23998.54–47997.07 | 6 |

Частота бина: `f_k = k · fs / N`. Границы таблицы — частоты первого и
последнего бина блока; для блока 14 верхняя граница выше Найквиста и
означает зеркальный бин (см. §5.1).

### 4.2. Счётчики

```text
S_k = Σ A_i по block(k+1) + Σ A_i по block(k+8),  k = 0…6
```

Счётчик `k` (`k = 0…6`) суммирует блоки `k+1` и `k+8`; всего
`2^(k+1) + 2^(k+8)` амплитуд.

| Счётчик / луч | Блоки | Бинов | 32 кГц, Гц | 48 кГц, Гц |
|---:|---|---:|---|---|
| 0 / δ | 1 + 8 | 258 | 0.98–1.95 + 249.02–498.05 | 1.46–2.93 + 373.54–747.07 |
| 1 / δ/θ | 2 + 9 | 516 | 2.93–5.86 + 499.02–998.05 | 4.39–8.79 + 748.54–1497.07 |
| 2 / θ | 3 + 10 | 1032 | 6.84–13.67 + 999.02–1998.05 | 10.25–20.51 + 1498.54–2997.07 |
| 3 / α | 4 + 11 | 2064 | 14.65–29.30 + 1999.02–3998.05 | 21.97–43.95 + 2998.54–5997.07 |
| 4 / β | 5 + 12 | 4128 | 30.27–60.55 + 3999.02–7998.05 | 45.41–90.82 + 5998.54–11997.07 |
| 5 / γ | 6 + 13 | 8256 | 61.52–123.05 + 7999.02–15998.05 | 92.29–184.57 + 11998.54–23997.07 |
| 6 / γ-high | 7 + 14 | 16512 | 124.02–248.05 + 15999.02–31998.05 | 186.04–372.07 + 23998.54–47997.07 |

Счётчик 6 содержит **16 512** бинов против **258** у счётчика 0 — в 64 раза
больше. Это само по себе даёт ему большой вклад на широкополосном
материале, независимо от «высокочастотности» звука.

Порядок лучей — `BAND_ORDER` из `frontend/src/app/sections/neuromusic/
bandLabels.ts`:

```text
delta, delta_theta, theta, alpha, beta, gamma, high_gamma
```

Это **имена и цвета UI**, а не фактические границы полос ЭЭГ
`freq_bands` (`0.5–2 … 64–128 Гц`). Частотный состав луча — октавные блоки,
поэтому луч «δ» вовсе не обязан содержать только 0.5–2 Гц.

## 5. Полный FFT: зеркало и блок 14

### 5.1. Что попадает в блок 14

`np.fft.fft` возвращает полный спектр длины 32768. Для вещественного сигнала:

```text
|X_k| = |X_(32768 − k)|
```

Блок 14 — это бины `16383…32766`. В нём лежат:

- бин 16383 — последний бин ниже Найквиста;
- бин 16384 — Найквист (`fs/2`);
- зеркала бинов `2…16385` (бины `32766…16383`).

Бин 32767 (зеркало бина 1) в блок не входит, поэтому вклад бина 1
учитывается только один раз — в блоке 1.

Следствие для счётчика 6 (`γ-high`):

```text
S_6 = сумма блока 7 (бины 127…254)
    + сумма блока 14 (бины 16383…32766,
      то есть Найквист + зеркало почти всего спектра)
```

Это не «симметричная половина спектра», а **полный FFT без отбрасывания
отрицательных частот**. Поэтому:

- любой тон даёт вклад и в свой прямой бин, и в зеркальный;
- счётчик 6 структурно завышен относительно остальных;
- `global_max` может оказаться в счётчике 6;
- луч 6 (`γ-high`) может выглядеть «самым громким» не из-за высоких
  частот, а из-за зеркала и большего числа бинов.

Поведение зафиксировано тестом
`backend/tests/test_audio_emo.py::test_sine_peaks_in_counter_of_its_bin_and_mirror`:
синус на бине 400 (блок 8 → счётчик 0) даёт равные суммы в счётчиках 0 и 6
(зеркало — бин 32368, блок 14 → счётчик 6). Это **текущий контракт
алгоритма**, а не рекомендация к исправлению.

## 6. Децибельная шкала и глобальная нормировка

### 6.1. Референс

```text
peak = max(S_k) по всем кадрам и всем 7 счётчикам
```

`peak` — сырой максимум амплитудных сумм, он же `global_max` в контракте.
Если `peak ≤ 0` (полная тишина) — все лучи нулевые.

### 6.2. Формула

Для `S > 0`:

```text
db = 20 · log10(S / peak)              (db ≤ 0)
pct = 100 · (db − (−60)) / (0 − (−60))
    = 100 · (db + 60) / 60
    = 100 · (1 + log10(S / peak) / 3)
```

Затем:

```text
pct = clip(pct, 0, 100)
```

Для `S = 0` проценты равны 0 **без** `log10(0)`: нулевые и отрицательные
счётчики пропускаются.

| `S / peak` | `db` | `pct` |
|---:|---:|---:|
| 1 | 0 | 100.00 |
| 1/2 | −6.0206 | 89.97 |
| 1/10 | −20 | 66.67 |
| 1/100 | −40 | 33.33 |
| 1/1000 | −60 | 0.00 |
| 0 | — | 0.00 |

Свойства:

- `normalization = "db_relative"`, `db_floor = −60.0`;
- 60 дБ по амплитуде — это ровно коэффициент 1000;
- шкала **глобальная на весь трек**, не покадровая;
- один громкий участок задаёт 0 дБ и «опускает» остальные кадры;
- значения выше референса теоретически невозможны, но зажимаются к 100 %;
- лучи округляются до 3 знаков, `global_max` — сырое число.

### 6.3. Что это значит для «дыхания» звезды

Так как нормировка глобальная, звезда «дышит» не от кадра к кадру, а
относительно самого громкого счётчика всего трека. Тихая запись с одним
громким всплеском даст почти нулевую звезду на всём остальном протяжении:
это следствие `db_relative`, а не ошибка интерполяции.

## 7. Динамический диапазон в UI

Бэкенд всегда пишет лучи с порогом `−60` дБ. UI может **перенести** уже
посчитанные проценты в другое окно `[−N … 0]` дБ без пересчёта анализа.

```text
fromFloorDb = db_floor контракта        (обычно −60)
toFloorDb   = −dbRangeDb
scale       = fromFloorDb / toFloorDb
pct₂        = clip(pct · scale, 0, 100)
```

| `dbRangeDb` | `toFloorDb` | `scale` | Эффект |
|---:|---:|---:|---|
| 96 | −96 | `60/96 = 0.625` | сжатие |
| 60 | −60 | `60/60 = 1` | без изменений |
| 40 | −40 | `60/40 = 1.5` | растяжение, зажим сверху |

Правила `framesDbRange`:

- `dbFloor` не число или `dbFloor ≥ 0` → кадры без изменений;
- `dbRangeDb ≤ 0` или `dbRangeDb === |dbFloor|` → кадры без изменений;
- иначе каждый луч: нечисловое значение → 0, затем `clip(value · scale, 0, 100)`.

Важно:

- окно `−96…0` **не восстанавливает** данные ниже `−60` дБ: в кадрах там уже
  0, поэтому «широкий» диапазон лишь сжимает видимые значения;
- окно `−40…0` растягивает и обрезает сверху: несколько лучей могут стать
  100 %, что меняет относительные длины и направление доминанты;
- перенос делается **до** вращения и темп-коррекции.

## 8. Нормативный порядок шагов в UI

Это порядок, который нельзя переставлять: он зафиксирован спецификацией
владельца и совпадает с кодом `RadialChart.tsx` / `emogram.ts`.

1. Взять `rays` кадра — уже dB-проценты с бэкенда.
2. При необходимости перенести шкалу: `framesDbRange`.
3. Получить угол вращения кадра: `frameRotations`; в анимации —
   `interpolatedRotation`.
4. Получить темп кадра: `frameTempos`; в анимации — `interpolatedTempo`.
5. Применить темп-коррекцию радиусов **к углам после вращения**:
   `tempoCorrectedRays`.
6. Если `max > 100` — условная нормализация (деление на max).
7. Построить вершины: `starPolygon`.
8. Посчитать доминанту кадра: `dominantPoint`.
9. Построить облако: `dominantCloud`.
10. Посчитать суммарную доминанту: `totalDominant` (центроид).

Формально:

```text
rays_db
  → (опционально) rays_dbRange
  → rotation(key)
  → tempoCorrection(rays, angles_after_rotation, bpm)
  → (опционально) normalize(max)
  → vertices
  → dominant
  → cloud / total
```

дБ повторно **не** применяется: лучи уже в дБ-шкале, доминанта наследует
масштаб.

## 9. Аккорды и вращение звезды

### 9.1. Источник карты аккордов

VAMP Chordino (NNLS Chroma, M. Mauch), вывод `simplechord`
«Chord Estimate». Источник в контракте:
`vamp:nnls-chroma:chordino:simplechord`.

| Поток | Transform | `sample_rate` | `step` | `block` |
|---|---|---:|---:|---:|
| «Нейромузыка», мастер 48 кГц | `chordino-simplechord.n3` | 48 000 | 4800 (0.1 с) | 24576 (0.512 с) |
| «ЕмоЛаб», моно 32 кГц | `chordino-simplechord-32k.n3` | 32 000 | 3200 (0.1 с) | 16384 (0.512 с) |

Параметры плагина — дефолты MIREX (`useNNLS=1`, `useHMM=1`, `boostn=0.1`).
Шаг 0.1 с выбран специально: при 0.2 с HMM-сглаживание «съедает» смены
аккордов (C+Am сливаются в один сегмент).

### 9.2. Разбор CSV

Строки Chordino:

```text
[имя_файла,] время, "аккорд"
```

- колонка имени файла есть во всех строках, но заполнена только в первой;
- поддерживаются строки длины 3 (`файл, время, аккорд`) и 2 (`время, аккорд`);
- некорректное время или нераспознанная метка — пропуск;
- подряд идущие одинаковые метки схлопываются;
- `label` — точное имя аккорда как есть («C», «Am», «G7», «Dm6», «Ebm6»,
  «Gaug»);
- `N` («нет аккорда») не порождает сегмент;
- `t_sec` округляется до 6 знаков.

### 9.3. Код тональности

Для вращения нужны только **корневая нота и лад**; интервалы игнорируются.

```text
semitone(C)=0, C#/Db=1, D=2, D#/Eb=3, E=4, F=5,
F#/Gb=6, G=7, G#/Ab=8, A=9, A#/Bb=10, B=11

minor = ("dim" in quality) or
        (quality.startswith("m") and not quality.startswith("maj"))

key_code = (13 if minor else 1) + semitone
```

Примеры:

| Метка | `quality` | Лад | `key_code` |
|---|---|---|---:|
| `C` | — | мажор | 1 |
| `C7` | `7` | мажор | 1 |
| `Dm6` | `m6` | минор | 15 |
| `Cdim` | `dim` | минор | 13 |
| `Gaug` | `aug` | мажор | 8 |
| `Ebm6` | `m6` | минор | 16 |
| `N` | — | не сегмент | — |

Коды: `1…12` — мажор (C…B), `13…24` — минор (Cm…Bm).

**Краевой случай:** формула не нормализует `semitone` по модулю 12. Для
`Cb` мажор даёт код 0 (вне контракта), а минор — 12 (совпадает с B);
для `B#` мажор даёт 13 (совпадает с Cm), а минор — 25 (вне контракта).
В проверенных живых выхлопах такие метки не зафиксированы; это
потенциальный, а не подтверждённый дефект.

### 9.4. Угол вращения

```text
δ = 2π / 84 = π / 42 ≈ 0.0747998 рад ≈ 4.285714°
```

- мажор, код `1…12`: `angle = +(code − 1) · δ`;
- минор, код `13…24`:

```text
tonic = code − 13
stepsDownFromA = ((9 − tonic) mod 12 + 12) mod 12
angle = −stepsDownFromA · δ
```

`Am = 0` — именно `+0`, не `−0`. Код вне `1…24` или нечисловое
значение → `0` (нет вращения). Максимум `±11δ ≈ ±47.14°`, поэтому
интерполяция угла линейная, без выбора кратчайшей дуги.

| Тоника | Мажор: код / угол | Минор: код / угол |
|---|---|---|
| C | 1 / `0` | 13 / `−9δ` |
| C#/Db | 2 / `+1δ` | 14 / `−8δ` |
| D | 3 / `+2δ` | 15 / `−7δ` |
| D#/Eb | 4 / `+3δ` | 16 / `−6δ` |
| E | 5 / `+4δ` | 17 / `−5δ` |
| F | 6 / `+5δ` | 18 / `−4δ` |
| F#/Gb | 7 / `+6δ` | 19 / `−3δ` |
| G | 8 / `+7δ` | 20 / `−2δ` |
| G#/Ab | 9 / `+8δ` | 21 / `−1δ` |
| A | 10 / `+9δ` | 22 / `0` |
| A#/Bb | 11 / `+10δ` | 23 / `−11δ` |
| B | 12 / `+11δ` | 24 / `−10δ` |

### 9.5. Кадровое вращение и интерполяция

`frameRotations`:

- для кадра берётся **последний** сегмент с `t_sec ≤ t_sec` кадра;
- сегмент длится до следующего;
- до первого сегмента — `0`;
- `null`/пустой трек — нули на все кадры;
- ожидается сортировка `key_track` по возрастанию времени (так отдаёт VAMP).

`interpolatedRotation`:

```text
position = (t − frames[0].t_sec) / hopSec
index = clamp(floor(position), 0, N − 1)
frac = clamp(position − index, 0, 1)
angle = from + (to − from) · frac
```

- хвосты держатся (до первого — первый, после последнего — последний);
- нечисловое время — первый кадр;
- нет ряда/сетки — `null`.

Вращение **жёсткое вокруг центра**: двигается только полигон; сетка, круги
25/50/75 % и границы секторов неподвижны; длины лучей не меняются.

## 10. Темп и темп-коррекция

### 10.1. Источник и параметры

VAMP Tempo and Beat Tracker, вывод `tempo` («locked tempo estimates»).
Источник в контракте: `vamp:qm-vamp-plugins:qm-tempotracker:tempo`.

Transform `backend/vamp/transforms/qm-tempotracker-tempo.n3`:

| Параметр | Значение |
|---|---:|
| `sample_rate` | 44 100 |
| `step_size` | 512 |
| `block_size` | 1024 |
| `method` | 1 (New) |
| `dftype` | 3 (Complex Domain) |
| `whiten` | 0 |
| `alpha` | 0.9 |
| `inputtempo` | 120 |
| `constraintempo` | 0 |

Вход 48 кГц (мастер) или 32 кГц («ЕмоЛаб») пересэмплируется Sonic
Annotator в 44 100 Гц. Шаг 512 при 48 000 Гц плагин отвергает
(«Unsupported step size»), поэтому частота в трансформе зафиксирована.

Разбор CSV:

- строки `[файл,] время, bpm, [метка]`;
- неположительный/нечисловой bpm — пропуск;
- некорректное время — пропуск;
- `t_sec` округляется до 6 знаков, `bpm` — до 3.

### 10.2. Темп кадра

```text
для кадра [t, t + hop):
    выбрать все оценки с t_est ∈ [t, t + hop)
    если оценки есть: tempo = среднее bpm
    если оценок нет: tempo = предыдущее значение (hold)
    до первой оценки: tempo = null
```

Детали реализации `frameTempos`:

- `tempo_track` сортируется по времени (копия, исходный порядок не важен);
- курсор движется только вперёд, поэтому проход линейный;
- оценки с `t_est < t` уже израсходованы предыдущими кадрами и в текущем
  не учитываются;
- интервал полуоткрытый: `t_est = t` входит, `t_est = t + hop` — уже
  следующий кадр;
- при `hopSec ≤ 0` или пустом/`null` треке — все `null`;
- длина ряда равна длине `frames`.

Пример (кадр 1 с):

```text
track = [(0, 120), (0.3, 100), (1.5, 90)], hop = 1
кадр 0 [0, 1): (120 + 100) / 2 = 110
кадр 1 [1, 2): 90
```

Hold:

```text
track = [(2.2, 140)], hop = 1
кадры 0, 1 → null
кадры 2, 3, 4 → 140
```

### 10.3. Ось темпа

```text
y = clamp(log2(bpm / 120), −1, +1)
```

- `bpm = 60` → `y = −1`;
- `bpm = 120` → `y = 0`;
- `bpm = 240` → `y = +1`;
- вне 60…240 — зажим к границам;
- `null`, нечисловой или `bpm ≤ 0` → `y = 0` (коррекции нет).

### 10.4. Коэффициент и выбор половины

```text
s  = sin(π/2 · y)
Kr = s² ∈ [0…1]
```

| `bpm` | `y` | `s` | `Kr` |
|---:|---:|---:|---:|
| 60 | −1 | −1 | 1.0000 |
| 90 | −0.4150 | −0.6067 | 0.3681 |
| 120 | 0 | 0 | 0.0000 |
| 150 | +0.3219 | +0.4844 | 0.2346 |
| 180 | +0.5850 | +0.7949 | 0.6319 |
| 240 | +1 | +1 | 1.0000 |

Правило:

```text
вход: r_i ← clip(r_i, 0…100); нечисловое → 0

если s < 0 и θ ∈ [π, 2π)  → r ← r · (1 + Kr)
если s > 0 и θ ∈ [0, π)   → r ← r · (1 + Kr)
иначе                     → r не меняется
```

Длины `values` и `angles` должны совпадать.

То есть темп ниже 120 удлиняет нижнюю половину (3–4 квадранты), выше 120 —
верхнюю (1–2 квадранты), ровно 120 — не меняет ничего. При `Kr = 0`
функция возвращает копию без коррекции.

Без поворота углы вершин равны `SEGMENT_START + i·2π/7`, поэтому:

- верхняя половина — лучи `0, 1, 5, 6`;
- нижняя — лучи `2, 3, 4`.

После вращения принадлежность половине определяется углом **после**
поворота.

### 10.5. Условная нормализация

```text
max = max(r)
если max > 100:
    r ← 100 · r / max
иначе:
    r не меняется
```

Это не «нормализация всегда к 100», а только защита от выхода за радиус.
Примеры при `Kr = 1` и отсутствии поворота:

| Вход | Половина | После `×2` (низ / верх) | Нормализация | Итог (низ / верх) |
|---|---|---|---|---|
| все `70` | нижняя (60 bpm) | `140 / 70` | `max = 140 > 100` | `100 / 50` |
| все `20` | нижняя (60 bpm) | `40 / 20` | `max = 40 ≤ 100` | `40 / 20` |
| все `70` | верхняя (240 bpm) | `70 / 140` | `max = 140 > 100` | `50 / 100` |

### 10.6. Метка темпа

На радаре:

```text
y_mark = CENTER − tempoY(bpm) · R
```

- 60 bpm — низ окружности;
- 120 — центр;
- 240 — верх;
- `null` — метка скрыта.

Над волной плеера («ЕмоЛаб»):

```text
y_step = (height / 2) · (1 − tempoY(bpm))
```

- 60 — низ графика;
- 120 — середина;
- 240 — верх;
- шкала та же, что у засечки радара, поэтому при одном bpm высоты
  совпадают.

Текст: `formatTempoBpm` — один десятичный знак, запятая, `bpm`; не
определён — `—`.

## 11. Вершины, доминанта, облако

### 11.1. Геометрия

```text
SEGMENT_START = π/2 + π/7
SEGMENT_STEP  = 2π/7
angle_i = SEGMENT_START + i · SEGMENT_STEP + rotation
```

```text
x = cx + r · cos(angle)
y = cy − r · sin(angle)        (SVG: y вниз)
```

`starPolygon`:

```text
r_i = R · clip(ray_i, 0, 100) / 100
```

Нечисловое/отсутствующее значение луча → 0 (вершина в центре). Порядок
вершин — `BAND_ORDER`, против часовой стрелки.

### 11.2. Доминанта кадра

```text
X = Σ (x_i − cx)
Y = Σ (y_i − cy)
length = hypot(X, Y)
если length > R:
    (X, Y) ← (X, Y) · R / length
dominant = (cx + X, cy + Y)
```

Деления на 7 нет: это сумма компонент. При равных лучах сумма ≈ 0
(семь равномерных направлений), при разных — указывает на «тяжёлую»
сторону. Длина может достигать ~1.6 R, поэтому вектор зажимается к кругу.

### 11.3. Облако и суммарная доминанта

`dominantCloud`:

```text
для каждого кадра:
    vertices = tempoStarPolygon(rays, R, center, rotation, tempo)
    point = dominantPoint(vertices, center, R)
```

То есть каждая точка — доминанта **после** вращения и темп-коррекции.

`totalDominant`:

```text
X = Σ (x_i − cx) / N
Y = Σ (y_i − cy) / N
зажим к R, если длина > R
```

Центроид, а не сырая сумма: сырая сумма на длинном треке всегда упиралась
в обод и лежала почти в одном месте. Центроид по построению внутри облака.
Пустое облако → центр.

### 11.4. «Эмограмма»

«Эмограмма» использует те же точки, что облако звезды, но в полярных
координатах единичного круга:

```text
dominantSeries(frames) →
    dominantCloud(frames, radius=1, center=(0,0))
    radiusFrac = clip(hypot(x, y), 0, 1)
    angleRad   = atan2(−y, x), нормализация в [0, 2π)
```

Столбики «Экспрессии Эмо» и ступени «Динамики Эмо»:

- кадры с `radiusFrac = 0` не рисуются;
- высота столбика — `radiusFrac`;
- высота ступени — `emoAngleFraction(angleRad)`:

```text
normalize(angle − SEGMENT_START) / (2π)
```

  где `normalize` приводит угол в `[0, 2π)`; `0` — низ (страх), шов — у
  верхней кромки;
- цвет — `sectorIndexOf(angleRad)`:

```text
relative = ((angle − SEGMENT_START) mod 2π + 2π) mod 2π
sector = min(6, floor(relative / (2π/7)))
```

- шкала Y — 14 эмоций (`EMO_LABELS`, снизу вверх: страх → агрессия);
  каждый цвет сектора радара покрывает ровно 2 эмоции.

## 12. Интерполяция анимации

```text
hopSec = hop_samples / fs_audio

position = (t − frames[0].t_sec) / hopSec
index = clamp(floor(position), 0, frames.length − 1)
frac = clamp(position − index, 0, 1)

ray_i = from.ray_i + (to.ray_i − from.ray_i) · frac
```

Правила:

- до первого кадра — первый;
- после последнего — последний (`to = from`);
- нечисловое время — первый кадр;
- `to` на последнем кадре равен `from`;
- позиция считается относительно `frames[0].t_sec`, а не от нуля;
- `hopSeconds` при `hop_samples ≤ 0` или `fs_audio ≤ 0` возвращает 0.

Тот же линейный интерполятор применяется к:

- лучам (`interpolatedRays`);
- углу вращения (`interpolatedRotation`);
- темпу (`interpolatedTempo`).

`interpolatedTempo` дополнительно:

- `from = null` → `null` (коррекции нет);
- `to = null` → `from` (держит предыдущее значение).

`frameIndexAt(t, hopSec, frameCount)` — отдельная функция для статического
выбора слайда:

```text
index = clamp(floor(t / hopSec), 0, frameCount − 1)
```

При `frameCount ≤ 0`, `hopSec ≤ 0` или нечисловом `t` — `0`. У
`interpolatedRays`/`interpolatedRotation` без кадров или сетки — `null`.

## 13. Контракт `emo.json` v6

`AudioEmoOut` (`backend/app/schemas/audio.py`):

```text
schema_version     6
fs_audio           48000 | 32000
fft_size           32768
hop_samples        32000
overlap_samples    768
normalization      "db_relative"
db_floor           −60.0
global_max         сырой пик счётчиков
duration_s         N / fs_audio
frame_count        len(frames)
frames[]           { t_sec, rays[7] }
key_track          [{ t_sec, key_code, label }] | null
key_source         "vamp:nnls-chroma:chordino:simplechord" | null
tempo_track        [{ t_sec, bpm }] | null
tempo_source       "vamp:qm-vamp-plugins:qm-tempotracker:tempo" | null
segment_track      [{ t_sec, name, segment_type }] | null
segment_source     "vamp:qm-vamp-plugins:qm-segmenter:segmentation" | null
```

`rays` — ровно 7 значений, `0…100` % радиуса, порядок `BAND_ORDER`.

Семантика `null`/пустого списка:

- `null` — инструмент недоступен/упал/таймаут;
- `[]` — инструмент отработал, но ничего не нашёл;
- `*_source` выставляется только при непустом треке;
- для UI `null` и `[]` эквивалентны: вращение/коррекция нулевые.

`parse_emo` принимает только `schema_version == 6`; старые кадры
отвергаются, вызывающая сторона пересчитывает их из `master.wav`
(рендер) или из исходного файла («ЕмоЛаб»).

`emo_bytes` — детерминированный компактный JSON:
`sort_keys=True`, `separators=(",", ":")`, UTF-8.

### 13.1. Где лежит результат

**«Нейромузыка»**

- `emo.json` — артефакт рендера рядом с `master.wav`, входит в `files`
  манифеста;
- `GET /audio/render/{id}/emo` читает `emo.json`;
- если файла нет — `emo_payload_of` читает `master.wav`, считает кадры и
  дописывает `emo.json` + манифест;
- 404 — рендер не найден; 409 — рендер идёт/упал или мастер недоступен.

**«ЕмоЛаб»**

- `emolab/{track_id}/emo.json`;
- `track_id` — sha256 содержимого, хвост 32;
- статус в памяти, TTL 15 мин, восстанавливается из манифеста;
- параллельность — семафор `MAX_PARALLEL = 2`;
- устаревший `emo.json` (не парсится в v6) — промах кэша, пересчёт.

## 15. Ловушки и инварианты

1. **Полный FFT, а не `rfft`.** Блок 14 содержит Найквист и зеркало почти
   всего спектра; счётчик 6 структурно завышен. Тест
   `test_sine_peaks_in_counter_of_its_bin_and_mirror` это закрепляет.
2. **Имена лучей — UI-полосы, не `freq_bands`.** Луч `δ` — это блоки 1+8,
   а не строго 0.5–2 Гц.
3. **Прямоугольное окно.** Утечка спектра есть; синус не на бине
   «размазывается». Нормировки на `N` нет.
4. **`global_max` глобальный.** Один громкий участок опускает остальные
   кадры; это не покадровая нормировка.
5. **`db_floor = −60` фиксирован на бэкенде.** UI-диапазон `−96…0` не
   восстанавливает данные ниже порога.
6. **Ключ и темп — только UI.** Бэкенд отдаёт неизменённые dB-лучи;
   `key_track`/`tempo_track` — отдельные карты.
7. **Квадрант — после вращения.** Темп-коррекция зависит от угла после
   поворота, поэтому ключ и темп связаны.
8. **Условная нормализация.** Делит на max только при `max > 100`; иначе
   звезда «дышит».
9. **Разные кадры на 32 и 48 кГц.** `hop_samples` один, но `hop/fs` даёт
   1 с в «ЕмоЛабе» и 2/3 с в «Нейромузыке».
10. **VAMP best-effort.** Нет инструмента, таймаут 300 с или `rc != 0` →
    `null`; расчёт не падает.
11. **`segment_track` не влияет на расчёты.** Только таблица, линии и
    метки.
12. **`Cb`/`B#` — потенциальный выход кода за 1…24.** Формула не
    нормализует `semitone` по модулю 12.
13. **`frameTempos`: hold и полуоткрытый интервал.** Оценка на `t + hop`
    уходит в следующий кадр; оценки до первого кадра не учитываются.
14. **Динамический диапазон может менять доминанту.** Зажим на 100 %
    меняет относительные длины лучей.
15. **Округление лучей до 3 знаков.** Даёт незначимые дрожания, не
    ошибку.
