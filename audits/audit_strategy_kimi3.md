## 1. Работа с EDF-файлами — 🟢 хорошо

**За:** авто-детект масштаба «вольты→мкВ» по физиологическому std (частая болезнь EDF без physical
dimension); нормализация имён каналов (префиксы «EEG/POL», алиасы T3→T7); дедуп загрузок по sha256
в одном проходе по чанкам; сайдкар `recording.json` переживает рестарт; чтение вьюером блоками
(`preload=False`) с корзинной огибающей min/max — пики артефактов не срезаются прореживанием.

**Сомнения (🟠):**
- `load_edf` делает `preload=True` целиком в RAM — для часовых записей 18 каналов × 500 Гц это
  десятки МБ на набор параметров, а кэш `prepared_signal` держит 2 набора; на 20-мин записи уже
  ~86 МБ × 2. Граница применимости не задокументирована.
- Молчаливый `resample(500)`: изменение sfreq — научно значимое решение, пользователь о нём не
  узнаёт из контракта (нет поля «исходная/фактическая частота» в паспорте).
- Только EDF: EDF+ (аннотации!), BDF не поддержаны — при этом формат событий стимулов в проекте
  отсутствует как класс.

## 2. Поиск артефактов — 🟡 есть лучшие альтернативы

**За:** состав разумный (z-score, peak-to-peak окном, flat-line, ICA-EOG опционально); зоны несут
список каналов (MNE-аннотации этого не умеют — правильное расширение); сбой ICA не роняет остальные
детекторы; результат идёт в UI-слои.

**Против / альтернативы:**
- Открытая находка F20 подтверждает: flat-line по абсолютной амплитуде даёт 222/290 ложных —
  критерий должен быть оконным «почти константа» (peak-to-peak в скользящем окне) или по дисперсии.
- 🔵 Готовые, более зрелые детекторы: `mne.preprocessing.annotate_muscle_zscore`,
  `annotate_movement`, **autoreject** (поэпохная отбраковка с кросс-валидацией порога — сильнее
  фиксированного порога), **mne-icalabel** (машинная разметка ICA-компонент: EOG/EMG/ECG без
  ручного `find_bads_eog`).
- z-score по всей записи чувствителен к нестационарности; robust-вариант (медиана/MAD) дешёвый и
  заметно устойчивее.

## 3. Фильтры — 🟣 замечательно (дисциплина), 🟠 одно сомнение

**За:** FIR применяется к continuous raw **до** нарезки (правильно против граничных эффектов на
250-мс эпохах); диапазоны δ…γ — единый источник в `config.py` (DRY); пресеты/своя полоса/одиночная
частота/notch покрывают требования README; контракт формы честный (в задачу уходит полоса, а не
имя пресета).

**Сомнение (🟠):** одиночная частота `7.83 ± 0.25 Гц` FIR'ом `firwin` — очень длинное ядро,
переходная полоса съедает половину bandpass на короткой записи; для узких полос уместнее IIR
(`iir_params`, Butterworth 4-го порядка) или Морле-вейвлеты. Это не ошибка, но точность «7.83 Гц»
в UI обещает больше, чем FIR реально выделяет.

## 4. Спектр и частотно-амплитудный анализ — 🟢 хорошо

**За:** Welch по эпохам с reject-порогом (артефакты не «съедают» спектр); один PSD на все диапазоны
(экономия ×N); спектрограмма — STFT с Ханном, дБ с 99.9-процентилем (выброс не «прижимает»
палитру); разделение «сервер считает сетку, UI красит» (DPS2) — образцовое: правка окна дБ не
запускает пересчёт; `n_fft` адаптируется под короткие эпохи.

**Альтернативы (🟡):**
- Welch при окне 256 и эпохах 250 мс даёт 1–2 окна на эпоху — дисперсия оценки высока;
  **multitaper** (`compute_psd(method='multitaper')`) дал бы сглаженную оценку той же ценой.
- 🔵 Для ЧА-анализа ритмов современный стандарт — **specparam/FOOOF** (разделение апериодической
  1/f-компоненты и пиков): «альфа-пик 10.2 Гц на фоне наклона» информативнее «мощность 8–13 Гц».
- ➕ Индивидуальная альфа-частота (IAF) как параметр нарезки диапазонов — дёшево, научно ценно.

## 5. Расчёт диполей — 🟢 хорошо (продуктово), 🟠 сомневаюсь (научно)

**За:** честная двухпрофильная схема: быстрый `fast_grid` (векторизованный МНК по сетке, 2.2 с на
261 эпоху) помечен `method='fast_grid'` и **не выдаётся** за точный фитинг; точный `mne.fit_dipole`
на BEM с честной ценой в `/meta` (5.4 с/точка) и дробным прогрессом; кэширование BEM/атласа;
`min_dist` и average reference согласованы между профилями.

**Сомнения (🟠):**
- Одна точка в пике GFP на эпоху без меры неопределённости: GOF одиночного диполя на сфере при
  18 каналах легко даёт «красивые» точки вне мозга/на границе сетки; нет отсева по GOF на входе
  в таблицу (порог — только отображение).
- Сферическая модель с центром (0,0,40) мм — допущение, которое стоит печатать в результате
  (provenance), а не только в докстринге.
- 🔵 Альтернативы, дающие больше за те же секунды: **сканеры распределённых источников** MNE —
  `mne.beamformer.make_lcmv` / **eLORETA/sLORETA** (`mne.minimum_norm`) на сфере быстры и устойчивее
  одиночного ECD при мультивозбуждении; для одиночных ECD — **RAP-MUSIC** / старт градиентного
  фитинга из узла быстрой сетки (сетка как инициализация `fit_dipole` сократила бы и время, и
  провалы в локальные минимумы).

## 6. Элементы UI — 🟣 замечательно

**За:** дисциплина «правка параметра не запускает расчёт» с признаком «результат устарел» — редкая
и правильная; единые контролы и общие сторы-срезы; бинарные контейнеры DPS1/DPS2 вместо JSON-массивов;
ETag/304 строго через один помощник (`assets.py`); измеренная производительность (`perf.ts`, замеры
в журнале, тесты на геометрию и бюджеты); демо-фикстуры явно помечены и изолированы; тексты ошибок
расчёта — на русском и по существу.

**Сомнение (🟠, мелкое):** SVG-слои проекций в одном компоненте на 723 строки — известный долг,
закрывается по плану; жёсткий `min-width: 1366px` — осознанное решение, но стоит зафиксировать
в продуктовом описании («десктоп-инструмент»).

## 7. Логирование — 🟢 хорошо

**За:** журнал шагов JSONL со строкой на шаг (не на запрос), `job_id` через ContextVar (сервисы не
знают про задачи), измерение не может сломать расчёт, ротация в 2 поколения, чтение «хвоста»,
прочерк→null в API. Плюс текстовый `logging` для необязательных веток (ICA).

**Сомнения (🟠):**
- Ротация «2 × 5 МБ» стирает историю: для аналитики «медиана шага за месяц» данных не хватит —
  собственно, запланированный `analytics.db` это и признаёт (верное решение, поддерживаю).
- 🔵 Для текстовых логов — **structlog** (JSON-строки, контекст job_id автоматом) вместо
  форматированных строк: унифицировало бы журнал и лог. Не критично.

## 8. Визуализация — 🟢 хорошо

**За:** uPlot для треков (правильный выбор против Chart.js/D3 по скорости); SVG-проекции с единым
масштабом мм/пиксель и тестами на изотропию; том МРТ — серверный PNG с ETag, контуры атласа —
вектором; слои результата — DOM поверх canvas (зоны кликабельны); осознанные компромиссы
топокарт (серый PNG без matplotlib) задокументированы.

**Альтернативы (🟡):**
- Топокарта: ортогональная проекция + IDW — служебно; серверный `mne.viz.plot_topomap` в PNG
  (backend Agg, без GUI) дал бы публикационное качество той же ценой — вопрос только зависимости
  matplotlib.
- 3D-меш (GLB + Three.js) уже в roadmap — верное направление; при переходе не терять серверную
  генерацию и кэш.

## 9. Данные: структура, хранение, повторное использование — 🟢 хорошо

**За:** `docs/data_map.md` как обязательная практика (новый кэш = строка в карте) — редкая зрелость;
единый `cache_store` (атомарная запись); отпечатки ассетов одной функцией (`asset_versions`);
обход сирот при старте; файлы задач на диске с восстановлением истории; дедуп и TTL записей;
FK «диполь→эпоха» — настоящий (F21 закрыт и проверен живым прогоном).

**Сомнения (🟠):**
- Реестр записей — RAM + ленивый подъём с диска; TTL-вытеснение только «при обращении» — на
  долгоживущем сервере без запросов диск пухнет (мелочь, но просится фоновая чистка).
- UI-результаты (быстрый расчёт, спектрограммы) в БД не попадают — известный остаток; без
  read-API «список исследований» не собрать, и это главный пробел повторного использования.
- SQLite-файл в рабочем каталоге backend — мина при смене `DATA_DIR`; alembic-миграций нет
  (в планах — правильно).

## 10. Дополнительный полезный функционал — ➕

Для приложения этого класса (сессионный анализ ЭЭГ с локализацией) органично ложатся:

1. **ROI-анализ**: агрегация мощностей ритмов и плотности диполей по полям Бродмана / структурам
   `aparc+aseg` (данные уже локализованы — осталась сводка и теплокарта по ROI).
2. **Авто-отчёт по сессии**: одна кнопка → PDF/HTML (паспорт записи, параметры, спектр, топокарты,
   зоны артефактов, таблица диполей, журнал шагов) — provenance уже собирается, отчёт = его рендер.
3. **Качество записи (QC)**: SNR по каналам, доля отброшенных эпох, уровень 50 Гц — «светофор
   качества» до анализа.
4. **Микросостояния (microstates)** и **connectivity** (coh/PLV/PLI между ROI) — стандартные
   «вторые этажи» ЧА-анализа; MNE покрывает оба.
5. **События/стимулы**: импорт EDF-аннотаций/маркеров и нарезка по событиям (сейчас только
   фиксированная длина) — открывает ERP-режим.
6. **Сравнение сессий**: раздел «Групповой» заявлен; база — дельты мощностей/IAF и кластеризация
   диполей по ROI между записями.
7. **Экспорт**: EEGLAB `.set` / BIDS-EEG / CSV таблицы локализации — интероп с научным стеком.
8. **Версионирование параметров в результате**: полный снимок `settings` в файле задачи —
   provenance для воспроизводимости.

## Итог

Проект в зрелом состоянии для MVP+: сильнейшие стороны — **дисциплина данных и кэшей**, **честные
компромиссы расчётов** (быстрый профиль не маскируется под точный) и **измеренная, а не обещанная
производительность**. Главные научные резервы: детекторы артефактов (F20 + autoreject/icalabel),
specparam для ЧА-анализа, сканеры распределённых источников как средний профиль между `fast_grid`
и BEM-фитингом. Главный продуктовый резерв — write/read-API результатов UI в БД и авто-отчёт сессии.
