## 1. Подготовка данных

Два сценария входа — математика кадров одна и та же, различается частота
дискретизации (а значит длительность кадра и частоты бинов).

### 1.1 «Нейромузыка»: микс ЭЭГ-партитуры (рендер)

* Источник — стерео-мастер рендера **до 3D-эффектов** (48 кГц; те же байты
  уходят в `master.wav` и в источник плеера): кадры синхронны с
  воспроизведением без поправок. При рендере кадры считаются прямо из массива
  мастера в памяти (`frames_from_master`), временных файлов нет.
* Моно-слияние: `mono[n] = (L[n] + R[n]) / 2`, `fs = 48000` Гц.
* Старые кэши (рендеры до среза «Эмо») добиваются на лету: `master.wav` →
  `soundfile` в память → та же схема (`frames_from_wav`); 404 — рендер не
  найден, 409 — идёт/упал либо мастер недоступен.

### 1.2 «ЕмоЛаб»: внешний трек (wav/mp3)

`emolab/track_input.py`, контракт анализа — **моно, 32000 Гц, float64**:

1. Зонд заголовка (`sf.info`): `fs`, число каналов, длительность. Не-аудио,
   пустой файл, `fs ≤ 0` → ошибка 400; длительность > `MAX_DURATION_SEC`
   (30 мин) → отказ **до** чтения отсчётов (защита памяти: длинный mp3
   разворачивается в гигабайты float64).
2. Декод блоками по 2^20 кадров (без загрузки файла целиком), `float64`.
3. Каналы: берутся первые два, моно `(L+R)/2` (моно-исходник — та же дорожка).
4. Контроль конечности: NaN/inf → «файл повреждён» (400).
5. Ресемпл до 32000 Гц: `resample_poly(mono, 32000/g, fs/g)`,
   `g = gcd(fs, 32000)` (kaiser-окно); исходная `fs` сохраняется в паспорте
   трека (`fs_source` — нужна при сравнении с ЭЭГ-сессией).
6. Для VAMP кодируется WAV в памяти: PCM_16, 32000 Гц, моно.

### 1.3 VAMP-карты (Sonic Annotator, отдельный GPL-процесс)

Инструмент опционален: недоступен → соответствующий трек `null`, коррекция в
UI нулевая (звезда работает только на FFT-кадрах).

| Трек | Плагин (вывод) | Данные | Использование |
|---|---|---|---|
| `key_track` | Chordino, «Chord Estimate» | `{t_sec, key_code, label}` | вращение звезды (§10) |
| `tempo_track` | QM Tempo and Beat Tracker, `tempo` | `{t_sec, bpm}` | темп-коррекция (§11) |
| `segment_track` | QM Segmenter | `{t_sec, segment_type, name}` | только контроль в UI, **в расчётах не участвует** |

`key_code` — упрощение имени аккорда Chordino до **корневой ноты + лада**:
1…12 — мажор C…B, 13…24 — минор Cm…Bm; уточнения «7», «6», «dim», «aug»
игнорируются («C7» → мажор C, «Dm6» → минор D); «N» (нет аккорда) сегментом
не становится. `label` хранит точное имя аккорда для таблицы в UI.

### 1.4 Порядок конвейера «ЕмоЛаб» (`track_analysis.py`)

приём файла → декод (§1.2) → карта аккордов (Chordino) → карта темпа →
сегментация → ФФТ-кадры «Эмо» (§2–6) → сохранение кэша `emolab/{track_id}/`
(`emo.json` + исходник + манифест). Повторный анализ того же файла (sha256)
не пересчитывается; параллельных анализов ≤ 2 (семафор; рендер «Нейромузыки»,
в отличие от трека, — один за раз); тяжёлые шаги — в фоновом потоке, event
loop не блокируется. Результат переживает рестарт сервера (манифест на диске,
статус в памяти — TTL 15 мин).

## 2. Сетка кадров (окна FFT)

`emo_radar.frame_starts`, окно `W = 32768`, сдвиг `H = 32000`:

* число отсчётов `N ≤ 0` → кадров нет (пустой сигнал);
* `N ≤ W` → **один** кадр с началом 0 (окно добивается нулями до 32768);
* иначе начала окон: `start_k = k·H`, `k = 0…K−1`, `K = ⌈(N − W)/H⌉ + 1`.

Последнее окно всегда накрывает хвост сигнала (добивка нулями), «лишних» окон
из одних нулей не возникает. Перекрытие соседних окон `W − H = 768` сэмплов.
Время кадра: `t_k = start_k / fs`, шаг сетки `hop = H/fs`:

* «Нейромузыка»: `32000/48000 = 2/3` с;
* «ЕмоЛаб»: `32000/32000 = 1` с (кадр звезды = ровно 1 с — уточнение
  владельца 20.10.2026, поэтому у «ЕмоЛаб» своя частота анализа).

Комментарий: сетка кадров — единая сетка синхронизации анимации плеера (и в
перспективе — дипольных эпох), поэтому сдвиг «некруглый» 32000, а не степень
двойки: сетка времени важнее красоты окна.

## 3. FFT-кадр: амплитуды бинов

Для каждого кадра `k`: окно `x = mono[start_k : start_k + 32768]` (хвост
короче — добивается нулями), комплексный FFT:

`X = FFT(x)`, длина 32768; амплитуда бина `m`: `A_m = |X_m|`.

* Окно **прямоугольное** — без аподизации (буквально по спецификации
  владельца; следствие — спектральная утечка, для сумм по широким октавным
  блокам она не критична).
* Частота бина: `f_m = m·fs/W`, ширина бина `Δf = fs/32768`:
  32000 Гц → **0.9766 Гц**, 48000 Гц → **1.4648 Гц**; Найквист `fs/2`
  (все частоты §4 для 48 кГц — умножить на 1.5).
* Бин 0 (DC, постоянная составляющая) и последний бин 32767 в счётчики не
  попадают (см. §4).

## 4. Октавные блоки бинов («логарифмическая» шкала частот)

`emo_radar.octave_blocks`: частотная ось логарифмируется не непрерывно, а
14-ю блоками двойной ширины. Блок `b = 1…14`:

* первый бин `start_b = 2^b − 1`, ширина `2^b` — занимает бины
  `[2^b − 1 … 2^(b+1) − 2]`;
* частоты блока (fs = 32000): от `(2^b − 1)·0.9766` Гц до
  `(2^(b+1) − 2)·0.9766` Гц.

| Блок | Бины | Ширина | Частоты @32 кГц, Гц |
|---|---|---|---|
| 1 | 1–2 | 2 | 0.98–1.95 |
| 2 | 3–6 | 4 | 2.93–5.86 |
| 3 | 7–14 | 8 | 6.84–13.67 |
| 4 | 15–30 | 16 | 14.65–29.30 |
| 5 | 31–62 | 32 | 30.27–60.55 |
| 6 | 63–126 | 64 | 61.52–123.05 |
| 7 | 127–254 | 128 | 124.02–248.05 |
| 8 | 255–510 | 256 | 249.02–498.05 |
| 9 | 511–1022 | 512 | 499.02–998.05 |
| 10 | 1023–2046 | 1024 | 999.02–1998.05 |
| 11 | 2047–4094 | 2048 | 1999.02–3997.85 |
| 12 | 4095–8190 | 4096 | 3999.02–7995.12 |
| 13 | 8191–16382 | 8192 | 7999.02–15996.09 |
| 14 | 16383–32766 | 16384 | 15999.02–31998.05 |

Инвариант (страж `tests/test_audio_emo.py::test_octave_blocks_cover_bins_once`):
блоки покрывают бины **1…32766 ровно по одному разу** (сумма ширин
`2^15 − 2 = 32766`); DC и бин 32767 исключены — «все 32768 результатов» окна
без постоянной составляющей и зеркального края.

## 5. Семь счётчиков — будущие лучи

`emo_radar.counter_sums`: счётчик `k = 0…6` суммирует **амплитуды** бинов двух
блоков — «своего» (низкая октава) и сдвинутого на 7 (высокая октава):

`S_k = Σ_{m ∈ B_(k+1)} A_m + Σ_{m ∈ B_(k+8)} A_m`

(в коде: `sums[index % 7] += сумма блока index`, index = 0…13 — блоки
`k+1` и `k+8`). Число амплитуд на счётчик: `2^(k+1) + 2^(k+8)`.

| Луч k | Метка полосы | Блоки | Бины | Амплитуд |
|---|---|---|---|---|
| 0 | δ | 1 + 8 | 1–2 ∪ 255–510 | 258 |
| 1 | δ/θ | 2 + 9 | 3–6 ∪ 511–1022 | 516 |
| 2 | θ | 3 + 10 | 7–14 ∪ 1023–2046 | 1032 |
| 3 | α | 4 + 11 | 15–30 ∪ 2047–4094 | 2064 |
| 4 | β | 5 + 12 | 31–62 ∪ 4095–8190 | 4128 |
| 5 | γ | 6 + 13 | 63–126 ∪ 8191–16382 | 8256 |
| 6 | γ-high | 7 + 14 | 127–254 ∪ 16383–32766 | 16512 |

Комментарий (независимое наблюдение): порядок лучей — `BAND_ORDER` полос ЭЭГ
(δ → γ-high, `bandLabels.ts`), но **частотные диапазоны блоков не совпадают с
границами полос ЭЭГ** (например, луч «δ» собирает и бины 255–510 ≈ 249–498 Гц
при 32 кГц): имена полос — номинальная семантика «луч k ↔ k-я полоса
партитуры», а не физическая полоса фильтрации. Каждый счётчик охватывает и
низкую, и высокую октаву — «7 счётчиков увеличиваются на 7 новых значений»
следующих октав (схема владельца).

## 6. Децибельная шкала: лог-зависимость и проценты радиуса

`emo_radar.db_rays` — перевод счётчиков в длины лучей, три решения:

1. **Референс глобальный**: `peak = max S_k(t)` по всем счётчикам **всех**
   кадров микса (одно число на весь трек). Лучи читаются в единицах громкости
   относительно самого громкого места микса — звезда «дышит» с общей
   интенсивностью, а не в пределах одного кадра.
2. **Лог-зависимость — амплитудная**: `db = 20·log10(S_k / peak) ≤ 0` дБ.
   Множитель 20, а не 10: счётчики — суммы **амплитуд** `|X_m|`, а не
   мощностей (для мощности было бы 10·log10).
3. **Порог шкалы** `EMO_DB_FLOOR = −60` дБ, карта дБ → проценты радиуса
   линейная с зажимом по краям:

`pct_k = clip(100·(db − F)/(0 − F), 0, 100) = clip(100·(db + 60)/60, 0, 100) %`

`0 дБ = peak → 100 % R`; `−60 дБ и глубже → 0 % R` («глубже в тишину не
показываем»). Вырожденные случаи: `peak ≤ 0` (полная тишина микса) либо
`S_k = 0` → луч 0 % (log10(0) не вычисляется). Обратная формула (нужна §8):
`db = F·(1 − pct/100) = 0.6·pct − 60`. Доминанты и геометрия (§12–13)
считаются в UI уже из дБ-процентов — их масштаб наследует шкалу автоматически.

## 7. Контракт `emo.json` (schema_version 6)

Бэкенд сериализует результат (детерминированный компактный JSON, `emo_bytes`)
и кладёт в кэш рендера/трека; отдают его `GET /api/v1/audio/render/{id}/emo`
(«Нейромузыка») и `GET /api/v1/emolab/tracks/{track_id}/emo` («ЕмоЛаб») —
контракт `AudioEmoOut` (`schemas/audio.py`):

* метаданные шкалы: `fs_audio`, `fft_size` 32768, `hop_samples` 32000,
  `overlap_samples` 768, `normalization` = `db_relative`, `db_floor` −60,
  `global_max` (референс 0 дБ), `duration_s`, `frame_count`;
* `frames`: `{t_sec, rays[7]}` по возрастанию `t_sec` — лучи в **процентах
  радиуса** (§6), порядок — `BAND_ORDER` (δ…γ-high); `t_sec` — 6 знаков,
  `rays` — 3 знака после запятой;
* `key_track` / `tempo_track` / `segment_track` (§1.3) + `*_source` —
  идентификаторы плагинов VAMP.

Страж свежести: `parse_emo` отвергает чужую/старую `schema_version` → рендер
добивает кадры из `master.wav`, «ЕмоЛаб» честно пересчитывает. Из OpenAPI
контракта генерируются TS-типы UI (`npm run gen:api`).

## 8. UI: перенос динамического диапазона (`emoRadar.raysDbRange`)

Параметр «Динамический диапазон» (−96…0 / −60…0 / −40…0 дБ) переносит
проценты лучей в другое окно шкалы **без пересчёта анализа**. Кадры записаны с
порогом `F_от = db_floor = −60`; новое окно `F_к`:

`pct₂ = clip(pct · F_от/F_к, 0, 100) %`

* `−60 → −96`: множитель `60/96 = 0.625` — `[0, 50, 100] → [0, 31.25, 62.5]`;
* `−60 → −40`: множитель `60/40 = 1.5` — `[10, 50, 70, 100] →
  [15, 75, 100, 100]` (зажим к 100);
* то же окно либо негодный порог (0, NaN, ≥ 0) — копия с зажимом 0…100;
  нечисловое значение луча → 0.

Свойства переноса (независимое наблюдение): формула линейна по процентам и
математически эквивалентна **сдвигу дБ-значений** на `F_к − F_от` (−36 дБ при
окне −96, +20 дБ при −40): старый порог −60 дБ остаётся на 0 % — данных
глубже порога в кадрах нет (они уже обрезаны бэкендом, §6), а пик микса 0 дБ
в широком окне встаёт на `100·|F_от|/|F_к|` % (62.5 % при −96). Это не
«пере-отображение окна» (при нём пик остался бы на 100 %, а −60 дБ поднялся
бы до 37.5 %): выбранная линейность гарантирует, что обрезанная тишина не
«выпрыгивает» из центра звезды.

## 9. UI: интерполяция между кадрами (`emoRadar.interpolatedRays`)

Анимация идёт по времени плеера `t`; кадры стоят на сетке `hop`. Общая
семантика для лучей, вращения (§10) и темпа (§11):

* позиция: `pos = (t − t_0)/hop`, где `t_0 = t_sec` первого кадра
  (`t_sec[0]` может быть ≠ 0);
* индексы: `i = clip(⌊pos⌋, 0, N−1)`, сосед `i+1` (за краем ряда — сам `i`);
* доля: `frac = clip(pos − i, 0, 1)`;
* значение: `v(t) = v_i + (v_{i+1} − v_i)·frac` — линейная интерполяция
  покомпонентно (для лучей — каждый из 7 независимо).

Хвосты: до первого кадра и после последнего — крайние кадры (hold);
некорректное время — первый кадр. Решение владельца: между слайдами плавный
переход, звезда «дышит» по глобальной шкале. `frameIndexAt` (индекс слайда) —
тот же `⌊t/hop⌋` с зажимом в 0…N−1.

## 10. Коррекция по аккордам: вращение звезды (`keyRotation.ts`)

**Шаг вращения**: `δ = 2π/84 = π/42 ≈ 0.0748 рад ≈ 4.2857°` — 1/12 ширины
сектора (сектор = `2π/7`). Максимум хода `±11δ ≈ ±47.14°` — диапазон не
пересекает разрыв окружности, поэтому интерполяция угла — простая линейная,
без выбора кратчайшего пути.

**Угол из кода тональности** (`key_code` из Chordino, §1.3):

* мажор (код 1…12, C…B): `φ = +(код − 1)·δ` — C = 0, C# = +δ … B = +11δ,
  вращение **против часовой** стрелки;
* минор (код 13…24, Cm…Bm): тоника `T = код − 13` (0 = C … 11 = B), число
  полутонов вниз от A: `n = ((9 − T) mod 12 + 12) mod 12`, угол
  `φ = −n·δ` — Am = 0, Abm = −δ, Gm = −2δ … Bbm = −11δ, вращение **по
  часовой** (нисходящий хроматический ряд от A);
* код вне 1…24 / не число → `φ = 0` (нет вращения).

**Сегмент тональности кадра**: активный — последний сегмент `key_track` с
`t_sec ≤ t_k` (сегмент длится до следующего); до первого сегмента — 0.
Пофреймовый ряд `frameRotations` (один линейный проход по кадрам) → во
времени `interpolatedRotation` — линейная интерполяция как у лучей (§9),
доворот плавный.

**Применение**: поворот — жёсткое вращение полигона вокруг центра (вершина на
угле «граница сектора + φ», §12); **сетка и границы секторов не вращаются**;
квадранты для темп-коррекции (§11) и доминанты (§13) считаются **после**
поворота. Источник счётчика «Аккорд» у графика — активный сегмент
(`activeKeySegment`).

## 11. Коррекция по темпу: удлинение лучей (`tempoCorrection.ts`)

**Темп кадра** (`frameTempos`): среднее арифметическое оценок `tempo_track`
(VAMP), попавших во временной диапазон кадра `[t_k, t_k + hop)`; несколько
оценок усредняются; кадр без оценок держит предыдущее значение (**hold**);
до первой оценки — `null` (коррекция не применяется). Оценки идут по
возрастанию времени — один линейный проход с курсором. В анимации — линейная
интерполяция между слайдами (`interpolatedTempo`, §9; `null` на текущем
слайде — «—», коррекция нулевая).

**Лог-ось темпа** (метка на оси Y радара; та же ось — у линии темпа над
волной плеера, `radarTempoStepY`):

`y = clip(log₂(clip(bpm, 60, 240)/120), −1, +1)`

60 bpm → −1, 120 → 0, 240 → +1 (логарифм от 2: октава темпа = единица
шкалы). Нечисловой/неположительный bpm → 0 (нет коррекции).

**Коэффициент удлинения** — «синус метки» в квадрате (правка 10.10.2026):

`s = sin(π/2 · y) ∈ [−1…1]`, `Kr = s² ∈ [0…1]`

60 → 1, 90 → ≈0.37, 120 → 0, 180 → ≈0.63, 240 → 1: чем дальше темп от
120 bpm (в обе стороны), тем сильнее коррекция; ровно 120 — коррекции нет.

**Выбор половины круга — знак синуса** (правка 10.10.2026): медленный темп
(`s < 0`, bpm < 120) удлиняет вершины **3 и 4 квадрантов** (угол
`θ ∈ [π, 2π)` — нижняя половина круга), быстрый (`s > 0`, bpm > 120) —
**1 и 2 квадрантов** (`θ ∈ [0, π)`, верхняя половина).

**Применение** (`tempoCorrectedRays`; порядок владельца: лучи → вращение
§10 → **темп-коррекция** → вершины → доминанты):

1. вход зажимается к 0…100 %, нечисловое → 0;
2. `Kr ≤ 0` (bpm = 120 или null) → без изменений;
3. для каждой вершины: `θ = norm(угол_j + φ)` в `[0, 2π)`; если `θ` попал в
   «свою» половину — `r_j → r_j·(1 + Kr)`, «чужие» вершины не меняются;
4. **условная нормализация**: если `max r > 100 %` — все делятся на max (он
   становится ровно 100 %); если `max ≤ 100 %` — не трогаем («дыхание»
   звезды по громкости сохраняется).

## 12. Геометрия: сектора и вершины полигона (`radialChart.ts`)

* Круг делится на 7 равных секторов: граница сектора 1 —
  `SEGMENT_START = π/2 + π/7 ≈ 115.71°`, далее **против часовой** шагом
  `SEGMENT_STEP = 2π/7 ≈ 51.43°`: `θ_j = π/2 + π/7 + j·2π/7`, `j = 0…6`.
* Сетка: круги 25 / 50 / 75 % радиуса.
* Точка на окружности (SVG, ось Y вниз):
  `x = c_x + ρ·cos(θ)`, `y = c_y − ρ·sin(θ)`.
* Вершины полигона-звезды (`starPolygon`): луч `j` → вершина на угле
  `θ_j + φ` (φ — вращение §10) с радиусом `ρ_j = R·pct_j/100`; значения
  зажимаются к 0…100 %, нечисловое → 0 (вершина в центре). Порядок вершин —
  порядок лучей `BAND_ORDER` (δ…γ-high).
* С темп-коррекцией (`tempoStarPolygon`): сначала `tempoCorrectedRays`
  (§11) с углами `θ_j + φ`, затем `starPolygon` — ровно порядок шагов §11.
* Цвета: сектор/луч `j` красится гаммой своей полосы ЭЭГ (`BAND_HZ` →
  `bandColors`): δ красный, δ/θ оранжевый, θ жёлтый, α зелёный, β циан,
  γ голубой, γ-high розово-фиолетовый; дуги секторов по границе круга и
  круги ⌀10 px в центрах вершин — теми же цветами.
* Индекс сектора угла (`sectorIndexOf`, нужен «Эмограмме» §14):
  `idx = ⌊norm(θ − SEGMENT_START)/(2π/7)⌋`, `idx ∈ 0…6`.

## 13. Доминанты

**Доминанта кадра** (`dominantPoint`) — точка на конце белой линии из центра:
сумма компонент вершин полигона **без деления** на их число:

`X = Σ_j (x_j − c_x)`, `Y = Σ_j (y_j − c_y)`

При равных лучах сумма = 0 (семь равномерных направлений компенсируют друг
друга) — доминанта в центре; при разных — указывает на «тяжёлую» сторону
полигона. Формальная длина может достигать ~1.6 R, поэтому вектор **зажимается**
к радиусу: доминанта не выходит за круг-границу. Считается из вершин
**после** вращения (§10) и темп-коррекции (§11) — единая формула для
рандом- и спектрального путей.

**Облако доминант** (`dominantCloud`): доминанта каждого кадра анимации
(мелкие круги на радаре; `rotation` и `tempo` кадра учитываются внутри).

**Суммарная доминанта** (`totalDominant`) — **центроид** облака:
`D = (1/N)·Σ D_i` с тем же зажимом к `R` (правка 08.10.2026: сырая сумма на
реальных миксах из тысяч кадров всегда упиралась в зажим и лежала на ободе
почти в одном месте у разных записей; центроид лежит внутри выпуклой оболочки
облака, зажим — лишь страховка). Пустое облако — точка центра.

## 14. Производный график «Эмограмма» (`emolab/emogram.ts`)

Строится из **тех же** доминант кадров (после диапазона §8, вращения §10 и
темп-коррекции §11; единичный круг, центр в нуле — `dominantSeries`):

* полярные координаты доминанты: `radiusFrac = clip(|D|, 0, 1)` (доли R),
  `angle = norm(atan2(−Y, X))` в `[0, 2π)` (минус — ось Y SVG направлена
  вниз, угол математический — от +X против часовой);
* **шкала Y «Эмо»**: 14 эмоций снизу вверх (`EMO_LABELS`: страх → трагедия →
  скорбь → отвращение → депрессия → смирение → безразличие → интерес →
  уверенность → радость → энтузиазм → вдохновение → эйфория → агрессия),
  линии разметки с шагом **π/7** по углу (`14·π/7 = 2π`): линия `i` — на
  угле `SEGMENT_START + i·π/7`; «страх» — внизу (совпадает с началом 1
  сектора), шов круга (между «агрессией» и «страхом») — у верхней кромки.
  Каждый сектор радара (`2π/7`) покрывает ровно **2 эмоции**;
* высота из угла: `emoAngleFraction = norm(angle − SEGMENT_START)/2π`
  (0 — низ, 1 — тот же угол через круг);
* **«Экспрессия Эмо»**: столбик кадра от низа до `radiusFrac` (шкала 0…1),
  цвет — сектор угла доминанты (`sectorIndexOf`);
* **«Динамика Эмо»**: горизонтальная ступень длиной 1 кадр (у «ЕмоЛаб» —
  ровно 1 с) на высоте `emoAngleFraction`, цвет — тот же сектор.

Кадры с `radiusFrac = 0` (тишина — доминанта в центре, угол не определён) не
рисуются. Сегменты трека (`segment_track`) — вертикали с метками A, B, C…;
в расчётах не участвуют.

## 15. Крайние случаи и защиты

| Случай | Поведение |
|---|---|
| полная тишина микса (`peak ≤ 0`) | все лучи 0 % во всех кадрах |
| счётчик = 0 в каком-то кадре | луч кадра 0 % (log10(0) не вычисляется) |
| VAMP недоступен | `key_track`/`tempo_track` = null → вращение и темп-коррекция нулевые; звезда живёт на одних FFT-кадрах |
| аккорд «N» / `key_code` вне 1…24 / не число | `φ = 0` (нет вращения) |
| кадр до первой оценки темпа | bpm = null → коррекции нет (счётчик «Темп» — «—») |
| время до первого / после последнего кадра | крайние кадры (hold) |
| нечисловое значение луча | 0 (вершина в центре) |
| трек «ЕмоЛаб» длиннее 30 мин / битый / не аудио / NaN в отсчётах | отказ 400 до расчёта |
| `schema_version` `emo.json` не совпадает | добивка из `master.wav` (рендер) / пересчёт («ЕмоЛаб») |
| `max r > 100 %` после темп-коррекции | деление всех лучей на max (§11, п. 4) |

## 16. Итоговый порядок применения (сводка)

```text
сигнал (стерео-мастер 48 кГц | внешний wav/mp3)
  → моно (L+R)/2; «ЕмоЛаб»: ресемпл → 32000 Гц (кадр 1 с),
    «Нейромузыка»: 48000 Гц (кадр 2/3 с)
  → окна FFT 32768, сдвиг 32000, перекрытие 768, хвост zero-pad
  → |X_m| (прямоугольное окно, DC и бин 32767 не участвуют)
  → 14 октавных блоков бинов (бины 1…32766)
  → 7 счётчиков S_k (блоки k+1 + k+8)                        [бэкенд, emo.json]
  → дБ: 20·log10(S/peak), окно [−60…0] дБ → [0…100] % R
  → [UI, каждый кадр анимации]
      перенос окна диапазона: pct·F_от/F_к (−96/−60/−40 дБ)
      → интерполяция лучей по сетке hop (линейная, hold на хвостах)
      → вращение φ по аккорду активного сегмента (±n·π/42, мажор +, минор −)
      → темп-коррекция: y = log₂(bpm/120), Kr = sin²(π/2·y),
        r·(1+Kr) вершинам половины круга по знаку sin(π/2·y),
        условная нормализация по max
      → вершины полигона: углы π/2+π/7+j·2π/7+φ, ρ = R·pct/100
      → доминанта кадра: Σ компонент вершин, зажим к R
        → облако доминант → суммарная (центроид)
        → «Эмограмма»: radiusFrac + угол → 14 эмоций (шаг π/7)
```

Каждый шаг чистой математики покрыт тестами: бэкенд —
`backend/tests/test_audio_emo.py` (страж покрытия бинов блоками, суммы
счётчиков, сетка кадров, глобальная дБ-шкала, моно-слияние, добивка старых
кэшей, контракт API), фронтенд — `emoRadar.test.ts` (сетка, интерполяция,
перенос диапазона), `keyRotation.test.ts` (углы по кодам тональностей),
`tempoCorrection.test.ts` (ось темпа, Kr, квадранты, нормализация),
`radialChart.test.ts` (вершины, доминанты) и `emogram.test.ts`
(столбики/ступени «Эмограммы»).
