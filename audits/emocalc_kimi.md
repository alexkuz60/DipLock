# Эмо-звезда: пошаговый алгоритм расчёта радарного графика

> Независимое описание по исходному коду (22.10.2026). Источники — backend:
> `app/services/emolab/track_input.py`, `track_analysis.py`,
> `app/services/audio_render/emo_radar.py`, `vamp_analysis.py`; frontend:
> `neuromusic/emoRadar.ts`, `keyRotation.ts`, `tempoCorrection.ts`,
> `radialChart.ts`, `bandLabels.ts`.
>
> Расчёт **двухэтапный**: backend готовит кадры (`{t_sec, rays[7]}` + карты
> темпа/аккордов/сегментов), frontend превращает кадр в геометрию
> семилучевой звезды. Никакой «эмоциональной» модели в этой цепочке нет:
> звезда — это **спектральный профиль громкости** трека, повёрнутый по
> аккорду и растянутый по темпу.

## 0. Общая схема и жёсткий порядок шагов

```
wav/mp3 ──A1──▶ моно (L+R)/2, 32000 Гц ──A2──▶ VAMP: аккорды | темп | сегменты
                                   │
                                   ├──A3──▶ окна 32768 / шаг 32000 → |FFT|
                                   ├──A4──▶ 14 октавных блоков бинов
                                   ├──A5──▶ 7 счётчиков (лучи)
                                   ├──A6──▶ дБ-шкала −60…0 дБ → 0…100 % R
                                   └──A7──▶ emo.json v6 (кадры 1 с)
                                                   │
   плеер (t) ──B1──▶ интерполяция кадров ──B2──▶ динамический диапазон
        ──B3──▶ углы 7 лучей ──B4──▶ вращение по аккорду
        ──B5──▶ темп-коррекция радиусов ──B6──▶ вершины и доминанта
```

**Порядок применения на кадре строго фиксирован** (нарушение меняет
результат): лучи → дБ-окно (опция) → вращение (углы) → темп-коррекция
(по углам **после** поворота) → вершины полигона → доминанта (и её облако).

## Этап A. Подготовка данных (backend)

### Шаг A1. Приём и нормализация аудио

Вход — внешний wav/mp3 (`track_input.decode_track`):

1. **Зонд заголовка** (`sf.info`): отказ (400 в API), если файл пуст, не
   аудио, нет отсчётов или длительность > **1800 с** (защита памяти).
2. **Блочное чтение** по 2²⁰ кадров (без загрузки файла целиком); каналов
   больше двух (5.1 и пр.) — берутся **первые два**.
3. **Моно-слияние**: `x[n] = (L[n] + R[n]) / 2` (у моно-исходника — та же
   дорожка).
4. **Контроль NaN/inf** — битый декод даёт честный 400, а не 500.
5. **Ресемпл в частоту анализа** `fs = 32000 Гц`:
   `x' = resample_poly(x, 32000/g, fs_src/g)`, `g = gcd(fs_src, 32000)`
   (полифазный, kaiser). Частота источника сохраняется в паспорте трека
   (`fs_source`) — она нужна при сопоставлении с ЭЭГ-сессией.

*Комментарий.* `fs = 32000` выбрана не «по качеству», а арифметически: шаг
окна 32000 сэмплов даёт кадр звезды **ровно 1 с**. В рендере «Нейромузыки»
тот же код работает на мастере 48000 Гц (кадр 2/3 с) — вся математика
параметризована `fs_audio`.

### Шаг A2. Временный моно-WAV и VAMP-карты

Моно-сигнал кодируется в WAV PCM_16 @32000 моно (Sonic Annotator читает
только файлы) и прогоняется через плагины (отдельный процесс, `VAMP_PATH`
передаётся явно, есть таймаут; недоступность инструмента → `None`,
расчёт от этого не падает):

1. **Аккорды** — Chordino «Chord Estimate», transform
   `chordino-simplechord-32k.n3` (шаг 0,1 с; при шаге 0,2 с HMM-сглаживание
   плагина «съедает» смены аккордов). Результат —
   `key_track = [{t_sec, key_code, label}]`:
   * метка `N` (нет аккорда) строку **отбрасывает** — звезда держит прошлое
     вращение; подряд идущие одинаковые метки схлопываются;
   * `key_code` — **только корневая нота + лад** (уточнения интервалов
     игнорируются): `semitone` = полутон корня (C=0 … B=11) +1 за `#`,
     −1 за `b`; минор, если в суффиксе `dim`/`hdim` или `m…` (но не `maj`);
     `aug`/sus → мажор;
   * **key_code = 1 + semitone** (мажор: C=1 … B=12) либо
     **key_code = 13 + semitone** (минор: Cm=13 … Bm=24).
2. **Темп** — QM Tempo and Beat Tracker, вывод `tempo` («locked tempo
   estimates»): `tempo_track = [{t_sec, bpm}]`; строки с битым временем или
   `bpm ≤ 0` пропускаются.
3. **Сегменты** — QM Segmenter: `segment_track = [{t_sec, segment_type, name}]`.
   **В расчёте звезды не участвует** — только визуально-слуховой контроль
   (таблица в «Опциях», вертикали с метками A/B/C…).

Порядок конвейера (`track_analysis._run_analysis`): декод → карта аккордов →
карта темпа → сегментер → ФФТ-кадры → запись кэша `emolab/{track_id}/`
(манифест = коммит; повторный анализ того же sha256 не пересчитывается).

### Шаг A3. Оконный FFT

Параметры (`emo_radar.py`): окно **N = 32768 = 2¹⁵**, шаг **H = 32000**,
перекрытие `N − H = 768`, окно **прямоугольное** (без аподизации — буквально
по спецификации владельца).

* Начала окон: `start_k = k·H`, `k = 0 … K−1`;
  число кадров **K = ⌈(N_samples − N) / H⌉ + 1** (при `N_samples ≤ N` — один
  кадр). Последнее окно покрывает хвост и **добивается нулями** (zero-pad);
  окон «только из нулей» не появляется.
* Время кадра: **t_k = start_k / fs** — при 32 кГц это ровно k секунд.
* Спектр кадра: **X = |FFT(w_k)|** — амплитуды всех 32768 бинов
  (полный FFT, не `rfft`).
* Ширина бина: **Δf = fs / N**; при 32 кГц `Δf = 32000/32768 = 0,9765625 Гц`.

### Шаг A4. Октавные блоки (бины → 14 блоков)

Блок `b` (b = 1…14) задаётся парой **`(старт, ширина) = (2^b − 1, 2^b)`**,
то есть покрывает бины `[2^b − 1 … 2^(b+1) − 2]` (ширина ровно `2^b`).
Блоки 1…14 покрывают бины **1…32766 ровно по одному разу**: бин 0 (DC) и
бин 32767 (последний) в расчёте не участвуют.

Диапазоны при `fs = 32000 Гц` (`Δf = 0,9766 Гц`):

| Блок b | Бины | Частоты, Гц | Ширина (бинов) |
|---|---|---|---|
| 1 | 1–2 | 0,98–1,95 | 2 |
| 2 | 3–6 | 2,93–5,86 | 4 |
| 3 | 7–14 | 6,84–13,67 | 8 |
| 4 | 15–30 | 14,6–29,3 | 16 |
| 5 | 31–62 | 30,3–60,5 | 32 |
| 6 | 63–126 | 61,5–123,0 | 64 |
| 7 | 127–254 | 124,0–248,0 | 128 |
| 8 | 255–510 | 249,0–498,0 | 256 |
| 9 | 511–1022 | 499,0–998,0 | 512 |
| 10 | 1023–2046 | 999,0–1998,0 | 1024 |
| 11 | 2047–4094 | 1999,0–3998,0 | 2048 |
| 12 | 4095–8190 | 3999,0–7998,0 | 4096 |
| 13 | 8191–16382 | 7999,0–15998,0 | 8192 |
| 14 | 16383–32766 | 15999,0–31999,0 | 16384 |

*Комментарий.* Найквист при 32 кГц — бин 16384, поэтому блок 14 состоит
в основном из **зеркала** спектра реального сигнала (`|X_k| = |X_{N−k}|`).
Это осознанная особенность спецификации: блок 14 работает как «широкий
верхний» член счётчика 7, а не как самостоятельная полоса.

### Шаг A5. Семь счётчиков (14 блоков → 7 лучей)

Счётчик `k` (k = 0…6) суммирует амплитуды блоков `k+1` и `k+8`:

**C_k = Σ_{j ∈ блок(k+1)} |X_j| + Σ_{j ∈ блок(k+8)} |X_j|**

— всего **2^(k+1) + 2^(k+8)** амплитуд на счётчик: 2+256, 4+512, 8+1024,
16+2048, 32+4096, 64+8192, 128+16384. Луч `k` несёт имя полосы `BAND_ORDER[k]`:
0 = δ, 1 = δ/θ, 2 = θ, 3 = α, 4 = β, 5 = γ, 6 = γ-high (порядок — от низких
частот к высоким).

*Комментарий.* Каждый счётчик — это **два октавных блока, разнесённых на
7 октав**: низкий (бины `2^(k+1)−1 … 2^(k+2)−2`) и высокий
(`2^(k+8)−1 … 2^(k+9)−2`). Так один луч получает и низкочастотную, и
высокочастотную составляющую, а грубое октавное разрешение сохраняется:
счётчик — не узкая полоса ЭЭГ-каталога, а широкий спектральный профиль.
Имена полос нужны только для подписей и цвета секторов; длина луча
вычисляется исключительно из этих сумм.

### Шаг A6. Децибельная шкала (глобальная на весь микс)

1. Референс 0 дБ: **`peak = max C_k` по всем лучам всех кадров** — шкала
   одна на трек, поэтому звезда «дышит» вместе с громкостью.
2. Децибелы по амплитуде (поэтому 20, а не 10):
   **`db = 20·log10(C_k / peak)`**, всегда `≤ 0`.
3. Линейная карта окна **`[−60 … 0]` дБ → `[0 … 100]` % радиуса**:
   **`pct = 100 · (db − (−60)) / (0 − (−60)) = 100 · (db + 60) / 60`**,
   затем `clip(0, 100)`.
4. `peak ≤ 0` (полная тишина) и нулевые счётчики → **0 %** (`log10(0)` не
   вычисляется).

*Комментарий.* Логарифмическая зависимость делает радиус читаемым в
единицах громкости: −6 дБ ≈ 90 % R, −20 дБ ≈ 67 % R, −40 дБ ≈ 33 % R,
−60 дБ и ниже — 0 % (тишина). Доминанта и геометрия считаются уже из
dB-процентов, поэтому второй раз в дБ ничего не переводится.

### Шаг A7. Контракт `emo.json` (v6)

```
{schema_version: 6, fs_audio, fft_size: 32768, hop_samples: 32000,
 overlap_samples: 768, normalization: "db_relative", db_floor: −60,
 global_max, duration_s, frame_count,
 frames: [{t_sec, rays: [7×%]}],
 key_track, key_source, tempo_track, tempo_source,
 segment_track, segment_source}
```

Кадры — доминирующий по объёму компактный JSON. Версии контракта
**ломающие**: кадры старой версии не «доклеиваются», а пересчитываются
(«ЕмоЛаб» — честный пересчёт, рендер — добивка из `master.wav`).

## Этап B. Геометрия кадра (frontend)

### Шаг B1. Выбор кадра и интерполяция (`emoRadar.ts`)

* Секунд на кадр: **`hopSec = hop_samples / fs_audio`** — в «ЕмоЛаб» это
  ровно 1 с (32000/32000), в рендере «Нейромузыки» — 2/3 с (32000/48000).
* Индекс слайда: **`i = clamp(⌊(t − t₀) / hopSec⌋, 0, K−1)`**, `t₀` — время
  первого кадра (может быть ≠ 0).
* Лучи в момент t — **линейная интерполяция** между кадрами `i` и `i+1`:
  **`rays(t) = rays_i + (rays_{i+1} − rays_i) · frac`**,
  `frac = clamp((t − t₀)/hopSec − i, 0, 1)`. До первого кадра — первый,
  после последнего — последний (хвосты держатся, назад не «отматывается»).

*Комментарий.* Между слайдами звезда «дышит» плавно; шаг 1 с — это не
точность картинки, а компромисс между временным разрешением и объёмом
кадров.

### Шаг B2. Динамический диапазон (опция, без пересчёта анализа)

Кадры записаны в окне контракта `[db_floor … 0]` дБ (`db_floor = −60`).
Параметр панели «ЕмоЛаб» переносит проценты в окно `[−D … 0]` дБ,
`D ∈ {96, 60, 40}`:

**`pct₂ = pct · db_floor / (−D)`**, затем `clip(0, 100)`.

* −60…0 (по умолчанию): масштаб 1 — как есть;
* −40…0: масштаб 1,5 (лучи растягиваются, зажим на 100 %);
* −96…0: масштаб 0,625 (лучи сжимаются), но всё, что глубже −60 дБ,
  остаётся нулём — **в кадрах нет данных ниже порога**, окно только меняет
  чтение уже сохранённых чисел.

### Шаг B3. Разметка круга (`radialChart.ts`)

Круг делится на 7 равных секторов; луч `k` (k = 0…6) стоит на границе
сектора:

**`θ_k = π/2 + π/7 + k · (2π/7)`** — отсчёт против часовой стрелки,
стартовое смещение на полсектора от вертикали (`π/7`) задаёт «шахматное»
положение звезды.

Вершина на луче: **`P_k = center + (R · pct_k / 100) · (cos θ_k, −sin θ_k)`**
(минус у синуса — потому что ось y в SVG направлена вниз). Порядок вершин —
`BAND_ORDER` (δ → γ-high).

### Шаг B4. Вращение по аккордам (`keyRotation.ts`)

* Единица смещения: **`δ = (1/12) · (2π/7) = 2π/84 = π/42 ≈ 4,2857°`**
  (полутон = 1/12 сектора).
* **Мажор** (key_code 1…12): **`φ = +(code − 1) · δ`** — C = 0, C# = +δ …
  B = +11δ (против часовой).
* **Минор** (key_code 13…24): **`φ = −((9 − (code − 13)) mod 12) · δ`** —
  Am = 0, Abm = −δ, Gm = −2δ … Bbm = −11δ (по часовой, хроматический спуск
  от A).
* Код вне 1…24 или нечисло → **0** (нет вращения).

Максимум `±11δ ≈ ±47,1°` — меньше сектора (51,4°), поэтому разрыв
окружности при интерполяции не пересекается и достаточно **линейной
интерполяции без shortest-path**.

Угол кадра: активный сегмент `key_track` — последний с `t_sec ≤ t` (сегмент
длится до следующего; до первого сегмента — 0). Между кадрами — линейная
интерполяция углов (`interpolatedRotation`), как у лучей.

### Шаг B5. Темп-коррекция лучей (`tempoCorrection.ts`)

1. **Темп кадра**: среднее всех оценок `tempo_track`, попавших в
   `[t_k, t_k + hopSec)`; кадр без оценок держит предыдущее значение
   (hold), до первой оценки — `null` (коррекция нулевая). В анимации — та же
   линейная интерполяция по слайдам.
2. **Проекция на ось Y** (логарифм по основанию 2, окно 60…240 bpm):
   **`y = clamp(log2(bpm / 120), −1, +1)`**
   (60 → −1, 120 → 0, 240 → +1; вне окна — зажим; `bpm ≤ 0`/нечисло → y = 0).
3. **«Синус метки»**: **`s = sin(π/2 · y)`** — метка темпа трактуется как
   угол ±π/2.
4. **Коэффициент удлинения**: **`Kr = s² ≥ 0`**
   (60 → 1, 90 → y ≈ −0,415 → Kr ≈ 0,37, 120 → 0, 240 → 1).
5. **Половина круга — по знаку `s`**: `s < 0` (медленный темп) → вершины
   **квадрантов 3–4** (`θ ∈ [π, 2π)`); `s > 0` (быстрый) → **квадрантов 1–2**
   (`θ ∈ [0, π)`). Квадрант определяется углом вершины **после** вращения B4.
6. **Удлинение**: **`r'_k = r_k · (1 + Kr)`** — только вершинам выбранной
   половины; «чужая» половина не меняется. Входные значения зажимаются
   к 0…100.
7. **Условная нормализация**: если `max(r') > 100`, все лучи делятся на
   `max/100` (максимум становится 100 %); если `max ≤ 100` — не трогаем,
   чтобы сохранить «дыхание» звезды по громкости.

*Комментарий.* Смысл конвенции: медленный трек удлиняет вершины **нижней
половины** (квадранты 3–4, ось y в SVG направлена вниз → это «под» центром),
быстрый — **верхней** (квадранты 1–2). Сила удлинения симметрична
относительно 120 bpm и максимальна на краях окна (60 и 240 → Kr = 1).
Та же ось `tempoY` задаёт высоту ступеней темпа над волной плеера:
**`y_px = (h/2) · (1 − y)`**, т.е. середина графика = 120 bpm, низ = 60,
верх = 240.

### Шаг B6. Вершины и доминанта (`radialChart.ts`)

* **Вершины**: `starPolygon` по лучам `r'` и углам `θ_k + φ`; опция темпа
  реализована как `tempoStarPolygon` = (темп-коррекция значений с углами
  **после** вращения) → полигон.
* **Доминанта кадра** (белая линия из центра) — сумма компонент вершин:
  **`X = Σ_k (x_k − c_x)`, `Y = Σ_k (y_k − c_y)`** (без деления на 7).
  При равных лучах сумма = 0 (семь равномерных направлений гасят друг
  друга); при неравных — указывает на «тяжёлую» сторону. Формальная длина
  достигает ~1,6 R, поэтому вектор **зажимается к R**.
* **Облако доминант** — точка доминанты каждого кадра (после вращения и
  темп-коррекции). **Суммарная доминанта** — центроид облака:
  **`(ΣX/n, ΣY/n)`** с зажимом к R: направление то же, что у суммы, но
  длина не растёт с числом кадров (сырая сумма на реальном миксе всегда
  упиралась в обод).
* «Эмограмма» (соседний таб) строится из **тех же** доминант кадров —
  повторного анализа нет, меняется только раскладка по оси времени.

## Числовой пример (проверка руками)

**Тон 1 кГц, fs = 32000, кадр 1 с.** Бин тона:
`k = 1000 / 0,9765625 = 1024` → блок 10 (`1023…2046`) → счётчик
`(10 − 1) mod 7 = 2` (луч «θ»). Если это максимум всего микса, то
`C₂ = peak`, `db = 0` → `pct = 100 % R`, остальные лучи — по своим `db`.

*Важно:* окно прямоугольное, поэтому реальный тон «протекает» по всему
спектру (leakage) — ненулевые будут все счётчики, просто с разными дБ.
Именно поэтому шкала логарифмическая, а не линейная.

**Отображение дБ → радиус:** `−6 дБ → 90 %`, `−20 дБ → 66,7 %`,
`−40 дБ → 33,3 %`, `−60 дБ и ниже → 0 %`.

**Темп:** 100 bpm → `y = log2(100/120) ≈ −0,263`, `s ≈ −0,401`,
`Kr ≈ 0,161`, т.е. вершины квадрантов 3–4 удлиняются на 16,1 %.

**Аккорд:** `Dm6` → корень D (2), минор → `key_code = 13 + 2 = 15`;
`Am` → `13 + 9 = 22` → `φ = −((9 − 9) mod 12)·δ = 0` (нулевой поворот).

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Тишина (`peak ≤ 0`) | все лучи 0 %, звезда в центре |
| Полоса без энергии (`C_k = 0`) | луч 0 % (`log10(0)` не вычисляется) |
| VAMP недоступен/упал/таймаут | карта = `null`: вращение и темп-коррекция нулевые, звезда работает |
| Кадр до первой оценки темпа/аккорда | коррекция/вращение = 0, далее hold |
| Смена аккорда на «N» | строки нет — держится прошлое вращение |
| Каналов > 2 | первые два, `(L+R)/2` |
| Трек > 30 мин, NaN/inf, не аудио | отказ 400 до расчёта |
| Трек короче окна (< 32768 сэмплов) | один кадр с zero-pad |
| `dynamic range = −96…0` | глубже −60 дБ данных нет → 0 % |
| Темп вне 60…240 bpm | `y` зажимается к ±1 (Kr = 1) |

## Сводка констант

| Константа | Значение | Где |
|---|---|---|
| Окно FFT / шаг / перекрытие | 32768 / 32000 / 768 сэмплов | `EMO_FFT_SIZE`, `EMO_HOP_SAMPLES` |
| Частота анализа «ЕмоЛаб» / кадр | 32000 Гц / ровно 1 с | `track_input.ANALYSIS_FS` |
| Ширина бина | `fs/32768` = 0,9766 Гц при 32 кГц | производное |
| Блоки / счётчики | 14 блоков `(2^b − 1, 2^b)` / 7 счётчиков (`k` + `k+7`) | `octave_blocks`, `counter_sums` |
| Нормировка | `db_relative`, 0 дБ = глобальный максимум | `EMO_NORMALIZATION` |
| Порог шкалы | −60 дБ → 0 % R | `EMO_DB_FLOOR` |
| Сектор | `2π/7`, старт `π/2 + π/7` | `SEGMENT_STEP`, `SEGMENT_START` |
| Шаг вращения δ | `2π/84 = π/42 ≈ 4,286°` | `KEY_DELTA_RAD` |
| Ось темпа | `y = clamp(log2(bpm/120), ±1)` | `TEMPO_MIN/CENTER/MAX_BPM` |
| Коэффициент темпа | `Kr = sin²(π/2 · y)` | `tempoSine` |
| Алгоритм ресемпла | полифазный `resample_poly` (kaiser) | `track_input.decode_track` |

## Ограничения описания

* Частотные диапазоны блока 14 лежат выше Найквиста 16 кГц и являются
  зеркалом спектра — это не «полоса 16…32 кГц», а особенность полного FFT.
* Проценты радиуса — относительная громкость, а не калиброванная
  амплитуда: у двух треков 100 % R означают разные абсолютные уровни.
* Сегменты VAMP и точные имена аккордов в расчёте не участвуют — только
  в подписях/таблицах; для геометрии важны лишь `key_code` и `bpm`.
