## 0. Обзор конвейера

«Эмо-звезда» — звезда-полигон из **7 лучей**: длина луча = сила одной из
семи счётных групп бинов спектра, угол вершины = её позиция на круге из
7 секторов. Данные кадров считает бэкенд (`emo_radar.emo_frames`), геометрию,
вращение и коррекции — UI (`RadialChart.tsx` и чистые модули математики).

```
вход аудио ──► моно (L+R)/2 ──► ФФТ-кадры (§2–§6): 14 октавных блоков
         │                            → 7 счётчиков → дБ → % радиуса
         └──► VAMP (Sonic Annotator)          │
              Chordino → key_track (§9)       ▼
              Tempo Tracker → tempo_track  emo.json (schema v6)
                                               │
                  UI-отрисовка кадра в момент t ▼
            дБ-диапазон (§7) → интерполяция (§8) → вращение по аккордам (§9)
            → темп-коррекция радиусов (§10) → нормализация → вершины (§11)
            → доминанты (§12)
```

Два входа с общей математикой (всё параметризовано `fs_audio` контракта):

* **«ЕмоЛаб»** — внешний трек wav/mp3: моно **32000 Гц**, кадр **1 с**;
* **«Нейромузыка»** — мастер рендера ЭЭГ: стерео **48000 Гц**, кадр **2/3 с**.

## 1. Шаг 1. Подготовка данных

### 1.1 Вход «ЕмоЛаб» (`emolab/track_input.py`)

1. Зонд заголовка (`sf.info`): частота `fs`, каналы, длительность. Не-аудио,
   пустой файл, `fs ≤ 0` → ошибка 400; потолок длительности —
   `MAX_DURATION_SEC = 1800` с (30 мин).
2. Декод блоками (`sf.read`, float64); берутся первые два канала, слияние в моно:

```
mono[n] = (L[n] + R[n]) / 2        # у моно-исходника — та же дорожка
```

3. Проверка конечности отсчётов (NaN/inf → 400, «файл повреждён»).
4. Ресемпл в `ANALYSIS_FS = 32000` Гц (`scipy.signal.resample_poly`, окно
   kaiser); частота источника сохраняется в паспорте трека (`fs_source`).

Комментарий: контракт 32 кГц выбран так, чтобы сетка кадров звезды была
**ровно 1 с** (см. §2). Каналов > 2 — берутся первые два: V-бабочку трекер
рисует из `File` на клиенте, серверу остальные каналы не нужны.

### 1.2 Вход «Нейромузыка» (`emo_radar.frames_from_master`)

Мастер рендера (после пик-контроля 0.891) — стерео 48 кГц; то же слияние
`mono = (L+R)/2`. Это и есть «чистый аудио-микс до эффектов»: байты совпадают
с `master.wav` и источником плеера, поэтому кадры синхронны с воспроизведением
без поправок. Для старых кэшей — `frames_from_wav` по `master.wav` в память.

### 1.3 VAMP-карты (`audio_render/vamp_analysis.py`)

По моно-WAV прогоняются внешние плагины (Sonic Annotator; **best-effort**:
инструмент недоступен/упал/таймаут → `None`, расчёт никогда не падает):

| Карта | Плагин (вывод) | Результат | Назначение |
|---|---|---|---|
| Аккорды | Chordino NNLS Chroma («Chord Estimate») | `key_track [{t_sec, key_code, label}]` | вращение звезды (§9) |
| Темп | QM Tempo and Beat Tracker (`tempo`) | `tempo_track [{t_sec, bpm}]` | темп-коррекция (§10) |
| Сегменты | QM Segmenter (`segmentation`) | `segment_track` | только визуальный контроль |

Transform-файлы зафиксированы в `backend/vamp/transforms/`. Ловушки:
`VAMP_PATH` передаётся **всегда явно**; Chordino при 32 кГц — step 0.1 с
(при step 0.2 с HMM-сглаживание плагина «съедает» смены аккордов);
Tempo Tracker — step 512/block 1024 при rate 44100 (вход ресемплирует сам
sonic-annotator); Segmenter при 32 кГц — step 6400/block 19200.

## 2. Шаг 2. Сетка кадров

Параметры (спецификация владельца, `emo_radar.py`):

```
EMO_FFT_SIZE        = N = 32768   (2^15) — окно FFT
EMO_HOP_SAMPLES     = H = 32000   — сдвиг окна между кадрами
EMO_OVERLAP_SAMPLES = N − H = 768 — перекрытие последних сэмплов окна
```

Начало кадра k (в сэмплах от начала трека) и число кадров:

```
s_k = k · H,  k = 0 … K−1
K = ⌈(Nсэмпл − N) / H⌉ + 1          # Nсэмпл — длина моно-сигнала
```

Окно кадра k — отсчёты `[s_k, s_k + N)`; хвост короче N **добивается нулями**
(нулевая подложка). Время кадра в контракте `emo.json`:

```
t_sec(k) = s_k / fs   →   кадр k отвечает отрезку [k·H/fs, (k+1)·H/fs)
```

| Вход | fs | Длина кадра H/fs | Сетка t_sec |
|---|---|---|---|
| «ЕмоЛаб» | 32000 | 32000/32000 = **1 с** | 0, 1, 2, … |
| «Нейромузыка» | 48000 | 32000/48000 = **2/3 с** | 0, 0.667, 1.333, … |

Комментарий: перекрытие всего 768 сэмплов (2.4 % окна) — сетка выбрана
«круглой» по времени (1 с / 2/3 с) для синхронизации анимации плеера и
(в перспективе) дипольных эпох. Кадр k стартует до окончания кадра k−1 лишь
на 768 сэмплов, то есть кадры почти не пересекаются; при `Nсэмпл < 32768`
получается один кадр с полной нулевой подложкой.

## 3. Шаг 3. ФФТ и амплитуды бинов

Каждое окно трансформируется **без аподизации** (прямоугольное окно — буквально
спецификация):

```
X_m = Σ_{n=0}^{N−1} x_n · e^(−2πi·m·n/N),   m = 0 … N−1 = 0 … 32767
амплитуда бина:  A_m = |X_m|
```

Участвуют бины **m = 1 … 32766**: DC-бин (m = 0) и бин Найквиста (m = 32767)
исключены. Частотная шкала линейна по бинам:

```
f_m = m · Δf,   Δf = fs / 32768
       Δf ≈ 1.4648 Гц  (48 кГц)     Δf ≈ 0.9766 Гц  (32 кГц)
```

Комментарий: берётся модуль комплексного спектра (амплитуда), а не мощность —
именно это определяет множитель **20** в дБ (§6). Без оконной функции
возможна утечка энергии между блоками §4 — осознанный выбор спецификации
(см. §15).

## 4. Шаг 4. Октавные блоки (формула подсчёта бинов)

Частотная шкала — **логарифмическая**: 32766 бинов режутся на 14 «октавных»
блоков, ширина каждого — степень двойки. Блок b (b = 1 … 14):

```
стартовый бин:  a_b = 2^b − 1
ширина:         w_b = 2^b
бины блока:     [ 2^b − 1  …  2^(b+1) − 2 ]
сумма блока:    S_b = Σ_{m = 2^b−1}^{2^(b+1)−2}  A_m
```

Покрытие точное, без пропусков и наложений:

```
Σ_{b=1..14} w_b = 2^15 − 2 = 32766 = числу участвующих бинов
```

(блок 1 берёт бины 1–2, блок 2 — 3–6, …, блок 14 — 16383–32766; каждый бин
входит ровно один раз: блок b кончается на бине `2^(b+1)−2`, а блок b+1
начинается с `2^(b+1)−1`).

Комментарий: границы блоков — степени двойки, поэтому каждый следующий блок
вдвое шире и примерно на октаву выше (верх блока ≈ 2 × верха предыдущего).
Это и есть «октавная лестница»: блоки 1–7 покрывают нижние 7 октав спектра
(1.46 … 281 Гц при 48 кГц), блоки 8–14 — верхние 7 октав (374 Гц … 48 кГц).

## 5. Шаг 5. Семь счётчиков (лучи звезды)

14 блоков распределяются по **7 счётчикам**: счётчик k (k = 0 … 6) суммирует
блоки k+1 и k+8 — нижнюю ступень лестницы и её «двойник» через 7 октав:

```
C_k = S_{k+1} + S_{k+8}
    = Σ_{m = 2^{k+1}−1}^{2^{k+2}−2} A_m   +   Σ_{m = 2^{k+8}−1}^{2^{k+9}−2} A_m
```

Число слагаемых амплитуд в счётчике k: `2^{k+1} + 2^{k+8}` — от 2+256 = 258
у луча 0 до 128+16384 = 16512 у луча 6.

Таблица лучей (Δf = fs/32768; Гц округлены до 0.1):

|---|---|---|---|---|---|
| 0 | δ — дельта | 1–2 | 255–510 | 1.5–2.9 / 373.5–747.1 | 1.0–2.0 / 249.0–498.0 |
| 1 | δ/θ — дельта-тета | 3–6 | 511–1022 | 4.4–8.8 / 748.5–1497.1 | 2.9–5.9 / 499.0–998.0 |
| 2 | θ — тета | 7–12 | 1023–2046 | 10.3–17.6 / 1498.5–2997.1 | 6.8–11.7 / 999.0–1998.0 |
| 3 | α — альфа | 13–24 | 2047–4094 | 19.0–35.2 / 2998.5–5997.1 | 12.7–23.4 / 1999.0–3998.0 |
| 4 | β — бета | 25–48 | 4095–8190 | 36.6–70.3 / 5998.5–11997.1 | 24.4–46.9 / 3999.0–7998.0 |

Комментарий (важно для честного чтения графика): подписи лучей (δ … γ-high) и
их цвета — **наследие партитуры** «Нейромузыки», адрес полосы **по индексу**
(луч k ↔ `BAND_ORDER[k]` ↔ `BAND_HZ[k]` = 0.5–2 … 64–128 Гц). Фактические же
частоты счётчиков — октавная лестница **аудио**-спектра: нижние октавы лучей
(1.5–281 Гц при 48 кГц; 1–188 Гц при 32 кГц) грубо следуют октавной лестнице
полос ЭЭГ, но смещены и не совпадают с её границами, а верхние октавы (от сотен
Гц до Найквиста) к полосам ЭЭГ отношения не имеют. Длина луча — художественная
метафора «силы эмоции», а не физиологическая полоса мощности.

## 6. Шаг 6. ДБ-шкала (логарифмическая нормировка)

Сначала глобальный референс — максимум всех счётчиков **всех кадров**
(«глобальная шкала»; хранится в контракте как `global_max`):

```
P = max_{кадр k, луч c}  C_c(k)
```

Затем для каждого значения счётчика (`EMO_DB_FLOOR = −60`):

```
db(C)  = 20 · log10(C / P)                       # всегда ≤ 0 дБ
pct(C) = 100 · (db − EMO_DB_FLOOR) / (0 − EMO_DB_FLOOR)
       = 100 · (db + 60) / 60,   затем clip к [0 … 100]
```

Частные случаи: `C = 0` (тишина) → 0 % без вызова log; `db ≤ −60` → 0 %;
`db = 0` (глобальный максимум) → 100 %. Значения лучей округляются до
0.001 % (`round(value, 3)`), `t_sec` — до 6 знаков.

Итог: `db = 20·log10(raw / global_max)` — шкала **глобальная и децибельная**
(решение владельца 08.10.2026): 0 дБ = самый сильный счётчик всего трека =
100 % радиуса; −60 дБ = 0 % радиуса, глубже — тишина не показывается.

Комментарии:

* множитель **20**, а не 10: счётчики — суммы **амплитуд** `|X_m|`, а не
  мощностей (для мощности было бы `10·log10`);
* референс **глобальный**, а не по-кадровый: радиусы читаются в единицах
  громкости и «дышат» с интенсивностью микса — тихий кадр сжимает звезду,
  громкий расправляет; с нормировкой на каждый кадр звезда имела бы постоянный
  размер и потеряла бы «дыхание»;
* шкала логарифмическая — ближе к восприятию громкости; линейная шкала
  (контракт v1) отвергнута, старые кадры `parse_emo` отвергает.

## 7. Шаг 7. Динамический диапазон в UI (`emoRadar.raysDbRange`)

Панель позволяет перенести шкалу лучей из окна `[−60 … 0]` дБ контракта в окно
`[−D … 0]` дБ (D = 40 / 60 / 96, параметр «Динамический диапазон») **без
пересчёта анализа** — обратная карта `db_rays`:

```
scale = fromFloor / toFloor        # оба порога отрицательные: −60 / −40 = 1.5
pct₂ = clip(pct · scale, 0, 100)
```

Примеры: −40…0 → растяжение **×1.5**; −96…0 → сжатие **×0.625**; −60…0 →
копия. Негодные пороги (0, NaN, положительные) — масштаб 1.

Комментарий: кадры пишутся с порогом −60 дБ, поэтому в более широком окне
(−96…0) всё, что было ниже −60 дБ, остаётся на нуле — **глубже порога данные
в контракте не сохраняются** и расширением шкалы не восстанавливаются.

## 8. Шаг 8. Выбор и интерполяция кадров (`emoRadar.ts`)

Секунд на кадр: `hopSec = H / fs` (1 с или 2/3 с). Индекс слайда и значение
лучей в момент t (`interpolatedRays`) — линейная интерполяция по сетке:

```
position = (t − t_sec[0]) / hopSec
index    = clamp(floor(position), 0, K−1)
frac     = clamp(position − index, 0, 1)
rays(t)  = rays[index] + (rays[index+1] − rays[index]) · frac
```

До первого кадра — первый, после последнего — последний (хвосты «держатся»);
некорректное время — первый слайд; `null` — нет кадров или сетки. Та же схема
интерполяции применяется к углам вращения (§9) и темпу (§10) — звезда плавно
«дышит» между слайдами (решение владельца: между слайдами плавный переход).

## 9. Шаг 9. Коррекция по аккордам (гармоническое вращение)

### 9.1 Имя аккорда → код тональности (`vamp_analysis.chord_key_code`)

Chordino пишет на смене аккорда его точное имя («C», «Am», «G7», «Ebm6»…).
Имя сводится к коду **1…24** (только корневая нота + лад; уточнения интервалов
игнорируются — постановка владельца 21.10.2026):

```
корень:    regex ^([A-G])([#b]?)
полутоны:  C=0, D=2, E=4, F=5, G=7, A=9, B=11   (+1 для «#», −1 для «b»)
лад:       minor = («dim» есть в хвосте имени)
                 или (хвост начинается с «m», но не с «maj»)
key_code = (13, если minor, иначе 1) + полутоны        → 1 … 24
```

Примеры (закреплены тестами `test_audio_vamp.py`): C=1, Bb=11, B=12, Cm=13,
Dm6=15, Ebm6=16, Am=22, Bm=24; Cdim=13 (малая терция → минор), Gaug=8,
G7=8, Cmaj7=1, Csus4=1 (мажорная основа). «N» (нет аккорда), пустая и
нераспознанная метки сегмент **не создают** — звезда держит прошлое вращение.
Подряд идущие одинаковые метки схлопываются (одна и та же смена).

### 9.2 Угол вращения (`keyRotation.keyRotationRad`)

Единица смещения δ — 1/12 сектора (сектор = 2π/7):

```
δ = (2π/7) / 12 = 2π/84 = π/42 ≈ 0.0748 рад ≈ 4.2857°
```

* **мажор** (код 1…12) — вращение **против часовой**: `φ = +(key_code − 1)·δ`
  (C = 0, C# = +δ … B = +11δ ≈ +47.14°);
* **минор** (код 13…24) — **по часовой**: `φ = −((9 − tonic) mod 12)·δ`,
  где `tonic = key_code − 13` (0 = Cm … 11 = Bm) — нисходящий хроматический
  ряд от A (Am = 0, Abm = −δ, Gm = −2δ … Bbm = −11δ);
* код вне 1…24 либо не число — 0 (нет вращения).

Диапазон ±11δ ≈ ±47.14° меньше половины круга — интерполяция угла простая
линейная, без shortest-path через разрыв окружности.

### 9.3 Угол кадра (`keyRotation.frameRotations`)

Для кадра берётся активный сегмент `key_track` = последний с `t_sec ≤ t_кадра`
(сегмент длится до следующего); до первого сегмента — 0 (тональность не
определена). Между кадрами угол **линейно интерполируется**
(`interpolatedRotation`) — плавный доворот, как у лучей.

Комментарий: «аккорд» в UI — термин для сегмента тональности (счётчик
«Аккорд» показывает `label` активного сегмента). Источник в контракте —
`key_source = "vamp:nnls-chroma:chordino:simplechord"`; без VAMP
`key_track = null` → вращение нулевое. Доминанты считаются **после** вращения
(§10–§12): поворот задаёт, в какой сектор попадёт каждая вершина.

## 10. Шаг 10. Темп-коррекция (`tempoCorrection.ts`)

### 10.1 Темп кадра (`frameTempos`)

Оценки темпа `tempo_track [{t_sec, bpm}]` привязываются к сетке кадров:

```
bpm(k) = среднее всех оценок с t_sec ∈ [t_k, t_k + hopSec)
```

кадр без оценок **держит предыдущее значение** (hold), до первой оценки —
`null` (коррекция нулевая). В анимации темп линейно интерполируется между
слайдами (`interpolatedTempo`) — плавно, как лучи и вращение.

### 10.2 Проекция темпа и коэффициент Kr

Ось темпа логарифмическая (от 2): 60 bpm → −1, 120 → 0, 240 → +1
(`TEMPO_MIN/CENTER/MAX_BPM` = 60/120/240):

```
y  = clamp(log2(bpm / 120), −1, +1)      # bpm сначала зажимается к [60, 240]
s  = sin(π/2 · y) ∈ [−1 … +1]           # «метка темпа» как угол ±π/2
Kr = s² ∈ [0 … 1]                        # квадрат синуса — всегда ≥ 0
```

Опорные значения (проверены тестами): 60 → y = −1, s = −1, Kr = 1;
90 → y ≈ −0.415, Kr ≈ 0.37; 120 → y = 0, Kr = 0 (коррекции нет);
240 → y = +1, Kr = 1. Нечисловой/неположительный темп → y = 0.

### 10.3 Какие вершины удлиняются (`tempoCorrectedRays`)

Половину круга выбирает **знак синуса**, квадрант вершины — её угол **после**
гармонического вращения (§9):

```
θ̂ = (θ_после_поворота) mod 2π            # нормализация в [0, 2π)
isLower = (θ̂ ≥ π)                         # квадранты 3 и 4
если (s < 0 ? isLower : !isLower):        # s < 0 — нижняя половина
    r ← r · (1 + Kr)                      # s > 0 — верхняя (θ̂ ∈ [0, π))
```

То есть при темпе **< 120** bpm (s < 0) удлиняются вершины с θ ∈ [π, 2π),
при темпе **> 120** — с θ ∈ [0, π); другая половина круга не меняется.
Множитель радиуса — от 1 (120 bpm) до 2 (60 или 240 bpm): новый радиус
`r·(1+Kr)`, Kr ∈ [0, 1].

### 10.4 Условная нормализация

```
max = max(r);   если max > 100:  r ← r / max · 100
```

Если `max ≤ 100` — не трогаем: «дыхание» звезды по громкости сохраняется
(решение владельца). `bpm = null`/нечисловой — копия без изменений; значения
зажимаются к 0…100 на входе (как у `starPolygon`).

Комментарий: порядок применения — **после** вращения и **до** доминант:
квадрант определяется углом вершины после поворота (поэтому коррекция стоит
после §9), а все доминанты (§12) считаются из **скорректированных** вершин.
Источник темпа — `tempo_source = "vamp:qm-vamp-plugins:qm-tempotracker:tempo"`;
без VAMP (`tempo_track = null`) коррекция нулевая. Метка темпа на оси Y
рисуется на высоте `tempoY(bpm)` (та же логарифмическая ось: 60 внизу,
120 в центре, 240 вверху), при `null` — скрыта.

## 11. Шаг 11. Геометрия звезды (`radialChart.starPolygon`)

Круг — 7 секторов по 2π/7; вершина луча i лежит в **центре** своего сектора
(отсчёт — против часовой от +X, сектор 1 начинается с `π/2 + π/7`):

```
угол вершины:  θ_i = π/2 + π/7 + (i+1)·2π/7 = 3π/7 + i·2π/7,   i = 0 … 6
радиус:        r_i = R · pct_i / 100        # pct_i — лучи после §6/§7/§10
точка SVG:     x = x_c + r_i · cos θ_i
               y = y_c − r_i · sin θ_i      # SVG y вниз, угол «вверх» → −y
```

Углы-разделители секторов: `π/2 + π/7 + k·2π/7`; индекс сектора угла θ
(`sectorIndexOf`, для цвета столбиков/ступеней):

```
sectorIndex(θ) = floor( ((θ − (π/2 + π/7)) mod 2π) / (2π/7) )     # 0 … 6
```

Сетка графика — круги 25/50/75 % R. Круги вершин — ⌀10 px, цвет = цвет
сектора луча (`SECTOR_COLORS` из гаммы полос). Метка темпа на оси Y —
горизонтальная засечка на высоте `tempoY(bpm)·R` над центром (60 внизу,
120 в центре, 240 вверху), верхний слой поверх полигона.

## 12. Шаг 12. Доминанты (`radialChart.ts`)

**Доминанта кадра** (`dominantPoint`) — вектор-сумма семи вершин (без деления
на число вершин), зажатый к радиусу:

```
D = Σ_i (v_i − c)                     # сумма компонент X и Y
если |D| > R:  D ← D · R / |D|       # доминанта не выходит за круг-границу
dom = c + D
```

При равных лучах сумма = 0 (семь равномерных направлений) — доминанта в
центре; при разных указывает на «тяжёлую» сторону полигона. Формула единая
для рандом- и спектрального путей. Длина «сырой» суммы формально достигает
~1.6 R (две смежные длинные вершины) — отсюда зажим.

**Облако доминант** (`dominantCloud`) — доминанта каждого кадра анимации
после вращения и темп-коррекции (`tempoStarPolygon` = §10 → §11 →
`dominantPoint`); порядок — порядок кадров.

**Суммарная доминанта** (`totalDominant`) — **центроид** облака (правка
владельца 08.10.2026: «сырая» сумма на любом реальном миксе упиралась в
зажим к ободу):

```
T = (Σ_j (p_j − c)) / n;   если |T| > R — зажим к R;   n = 0 → центр
```

Центроид по построению лежит внутри выпуклой оболочки облака; зажим остаётся
страховкой.

Производные потребители тех же доминант: «Эмограмма» (`emolab/emogram.ts` —
столбики «Экспрессии Эмо» высотой |D|/R и ступени «Динамики Эмо» по углу D
на шкале 14 эмоций «страх» … «агрессия» с шагом π/7; каждый цвет сектора
радара покрывает ровно 2 эмоции) и пиули «Аккорд»/«Темп» (`EmoCounters.tsx`).

## 15. Наблюдения и ограничения (независимый взгляд)

1. **Окно прямоугольное** — без аподизации возможна утечка энергии между
   октавными блоками (§4); для «художественной» шкалы звезды это допустимо,
   для метрологии — нет.
2. **Глобальный референс P** привязывает всю шкалу к самому громкому кадру:
   один всплеск делает остальной трек визуально тише. Возможная альтернатива
   (не реализована) — перцентильный референс.
3. **Счётчик смешивает две далёкие октавы** (луч 0 при 48 кГц — 1.5–2.9 Гц и
   373–747 Гц в одном числе): длина луча — метафора, а не физиологическая
   полоса; подписи δ…γ-high — адрес полосы по индексу (§5).
4. **Порог −60 дБ необратим**: глубже порога данные в контракте нет, широкий
   динамический диапазон UI (−96) их не вернёт (§7).
5. **Суммы не нормированы на ширину блока**: у луча 6 в 64 раза больше
   слагаемых, чем у луча 0 (16512 против 258), поэтому при «белом» спектре
   верхние лучи заведомо крупнее нижних (разница до 20·log10(64) ≈ 36 дБ).
   Замер на синусе 100 Гц (2 с, 48 кГц, кадр 0): лучи `[55.9, 55.8, 56.9,
   59.7, 70.8, 91.3, 100]` — даже чистый тон даёт максимум на луче 6:
   утечка прямоугольного окна (§3) накапливается в широких верхних блоках.
6. **Hold-семантика карт** (темп и аккорды): пропуски оценок не интерполируются
   на этапе данных, а держат прошлое значение — смены «плывут» в пределах
   пропуска (§9.3, §10.1).
7. **VAMP — best-effort**: без бинаря звезда работает, но без вращения и
   темп-коррекции (`key_track`/`tempo_track = null`) — честный деградант,
   а не ошибка (§1.3).
8. **Математика параметризована `fs_audio`**: разница «ЕмоЛаб»/«Нейромузыка» —
   только частота входа и, как следствие, длина кадра (1 с / 2/3 с) и частотная
   привязка бинов; формулы §2–§8 идентичны.
