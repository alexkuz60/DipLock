## 1. Архитектура

| Решение | Оценка | Аргументация |
|---|---|---|
| **Сервисная архитектура: один модуль = один шаг пайплайна** | **замечательно** | Выдержала рост с ~15 до 55 модулей без деградации: новые возможности (cardio, spectrogram, roi, eloreta, compare, group_reports) добавляются отдельными файлами, не ломая соседей. Конвенция зафиксирована в AGENTS.md и реально соблюдается. Это главный архитектурный актив проекта. |
| **Слоистость api → services → utils («роут = форма и контракт»)** | **хорошо, с оговоркой** | Правило сформулировано и в основном соблюдается (`params.py`, `assets.py`, `recording_jobs.py` вынесены). Но `routes.py` снова вырос: **2755 строк / 79 роутов** против 1260 строк, при которых OM6 уже фиксировал порог читаемости и откладывал декомпозицию «к Фазе 4/5». Фаза пришла — файл не разрезан. Консилиум удачно пошёл отдельным роутером (`consilium.py`, 50 операций) — это готовый образец для разрезки `routes.py`. |
| **Контракт API: Pydantic-схемы → OpenAPI → TS-типы** | **замечательно** | Полный цикл типизации от бэкенда до клиента со стражами свежести в pytest и CI — уровень дисциплины, редкий даже для коммерческих проектов. 11 схем-модулей, «сырые» dict в ответах запрещены конвенцией. Оборотная сторона: внутренние контракты сервисов остаются `dict[str, Any]` (OM1) — типы охраняют границу, но не сердцевину. |
| **Кэширующий слой** (cache_store, ETag/304, DPS-контейнеры, prepared_signal/persist, asset_versions, surface_cache) | **замечательно** | Самая сильная часть системы (согласно OM-аудиту — «образцовое»). Единые инварианты в `docs/rules/data-and-caches.md`, атомарная запись, LRU-квота, обход сирот, отпечатки версий. Повторный расчёт EDF «один раз на набор параметров» — правильный фундамент под пакетные сценарии. |
| **Job-очередь in-process** (job_manager + семафор + отмена + журнал + job_store) | **хорошо** | Для однопользовательского локального приложения — адекватный выбор: этапы, прогресс эпох, отмена из UI, переживание перезапуска. Осознанное ограничение: семафор на всё (одна тяжёлая задача душит остальные) и in-memory состояние не масштабируются на многопользовательский сценарий — но его в миссии нет. Celery/Redis (redis в docker-compose мёртвый) были бы оверинжинирингом. |
| **БД: alembic-only, SQLite dev / PostgreSQL prod** | **хорошо** | Правило «схема только через alembic» + страж паритета моделей и миграций — зрело; 13 миграций без ручных правок. Оговорки: PostgreSQL фактически не используется (dev = SQLite, docker отложен владельцем), требование №7 README («PostgreSQL для группового анализа») выполнено декларативно — групповой анализ работает на SQLite. |
| **Документация как код** (AGENTS.md-контракт, docs/rules/*, history.md, session-start.md) | **замечательно** | 23 файла правил, журнал истории 4.6k строк, памятка старта сессии с номерами тестов — проект пригоден для сессионной работы ИИ-агентов без потери контекста. Это и есть наблюдаемая причина, почему 5 недель интенсивной разработки не привели к хаосу. Цена — дисциплина: каждый срез обязан обновлять 4–5 документов; пока соблюдается. |

## 2. Принятые решения реализации

| Решение | Оценка | Аргументация |
|---|---|---|
| **MNE-Python как научное ядро** | **замечательно** | Единственный разумный выбор для этого класса задач; дрейф API между версиями осознан и закрыт тестами-стражами (`docs/rules/safety.md`). Дополнено собственными быстрыми путями там, где MNE медленен (dipole_scanner) или молчит (кардио без ECG-канала). |
| **Быстрый `fast_grid` вместо `fit_dipole` по умолчанию + честная маркировка метода** | **замечательно** | 261 эпоха за 2.2 с против ~40 с на точку у точного фитинга. Принципиально важно, что быстрый режим не выдаётся за точный (`method='fast_grid'`) — это та самая «честная немощь вместо выдумки» из стратегии, проведённая в код. |
| **Niivue для 3D вместо самописного GLB** | **хорошо** | Реконсилированное решение коллективного аудита (3.5): читает NIfTI/GIFTI/FreeSurfer как есть, убирает собственный конвейер ассетов. Свой PNG-энкодер для срезов при этом оправдан — задача (срез с ETag) уже, чем 3D-вьюер. |
| **Спайк перед внедрением: autoreject отклонён, mne-icalabel внедрён как advisory** | **замечательно** | Решение принято по измерениям (autoreject «в 5–7 раз дороже при нуле выигрыша поверх выживших»), а не по моде. ICLabel — вторая разметка рядом с корреляционным путём, не замена: правильная граница доверия к ML-меткам в исследовательском инструменте. |
| **Модельный роутер LLM через внешние API (openai/anthropic-совместимые), отказ от llama.cpp** | **хорошо** | Для исследовательского инструмента на одной машине внешние API снимают проблему весов/VRAM; ключи маскируются, провайдер подменяется в тестах. Оговорки: (1) 1170-строчный `llm_router.py` — крупнейший модуль после report/compare; (2) зависимость от стороннего шлюза «Джев-лив» — официальный `api.typesafe.ai` отдаёт 451 по региону, т.е. часть функционала Jev живёт на неофициальном канале (задокументировано, риск осознан). |
| **«Числа клиенту, палитра на клиенте»** (DPS1/DPS2-контейнеры, спектрограмма сеткой дБ) | **замечательно** | Правильное разделение: сервер отдаёт измеренное, клиент рендерит. Пирамида сигналов ×1…×16 — то, что делают зрелые продукты просмотра сигналов. |
| **Дисциплина состояния UI: «правка параметра не запускает расчёт», zustand-срезы, URL-зеркало** | **замечательно** | Правило сформулировано после реального инцидента (24.09.2026), закреплено в `docs/rules/frontend-state.md` и соблюдается. Устраняет целый класс «фантомных» пересчётов и рассинхрона чисел. |
| **Тест-стратегия: синтетический ЭЭГ + TestClient, маркер `integration` для живых данных** | **хорошо** | 1055 pytest / 1229 Vitest при быстром прогоне без сети — крепко. Пробел: integration-ветки скипаются и в CI их нет (открытый остаток F12) — «зелёный» CI не проверяет научные ветки на реальном fsaverage/test.edf. |
| **rc-зависимость `specparam>=2.0.0rc7` в runtime** | **сомнительно — но риск зафиксирован** | Release-candidate в production-зависимостях — против правил; смягчено тем, что API зафиксирован тестами и альтернативы (стабильного 2.0) пока нет. Держать в поле зрения при выходе релиза. |
| **Docker/PostgreSQL-контур** | **сомнительно — есть лучший вариант** | Отложен владельцем 12.09, с тех пор мёртвый груз: `redis` не используется нигде, пароль БД захардкожен, пути fsaverage не монтируются. Лучший вариант — честно удалить docker-compose/init_db.sql из репозитория (или перенести в `contrib/` с пометкой «не поддерживается») до появления реальной потребности в развёртывании. |

## 3. Степень готовности основных разделов

Оценка по совокупности: реализация + тесты + прошёл ли **живой прогон владельцем**
(последнее — системная слабость: многие срезы закрыты проверками, но не приёмкой на живых
данных — прямо отмечено в `docs/session-start.md`).

| Раздел | Готовность | Оценка | Комментарий |
|---|---|---|---|
| **EDF — просмотр записи** | ~95 % | **замечательно** | Вьюер треков с пирамидой ×1…×16, стадии предподготовки, зоны артефактов, ручные пометки эпох, кардио-трек ЧСС, слои «сырой/очищенный/разница», экспорт окна. Открыто лишь мелочь (вертикальный зум в режиме «Трек» — осознанно отклонён для мультитрека). |
| **ЭЭГ (спектрограмма канала, миксы)** | ~90 % | **хорошо** | STFT → сетка дБ (DPS2) с ETag, виртуальные каналы-миксы 10-20. Раздел моложе вьюера, но архитектурно повторяет его проверенные паттерны. |
| **Диполи** | ~90 % | **хорошо** | Проекции с МРТ-срезом и контурами атласа/BA, быстрый расчёт, пакетный сценарий по поддиапазонам, RIV/CI-фильтры доверия, воспроизведение траектории, eLORETA пик/ROI, GPU-тумблер. Осознанно не закрыто: распределённые источники для δ/длинных окон (sLORETA-Lite — отложено до пакетных данных). |
| **Таблица локализации** | ~95 % | **замечательно** | Сортировка/состав колонок без запросов к серверу, фильтры GOF/RIV — эталон «честной» таблицы результатов. |
| **Сравнение пары (B9)** | ~80 % | **хорошо** | Дельты B−A, FDR/бутстрап, кластерный тест MNE, карты разности, ERDS-панель. Не было живого прогона владельцем. |
| **Групповой анализ (4.7)** | ~75 % | **хорошо** | Агрегаты «BA × сессии», два знаменателя share, тепловая карта, кластеры, отчёты Тип 1/2, персист прогонов. Read-API закрыт 02.10.2026; живой прогон G1–G4 — впереди. |
| **Итоги (автоотчёт)** | ~80 % | **хорошо** | MNE.Report + пакет диполей по полосам + тема оформления, групповые отчёты. Развитие отчёта — открытый пункт todo. |
| **Консилиум** | ~60 % | **требует доработки** (по плану, не по качеству) | Самый активный фронт последних двух недель: дело/досье, материалы и снимки, раунды советников Т3 со стримингом, триаж и разметка Jev (живой прогон 14.10 — успешен), мозговой штурм, библиотека предложений Т5, боковая консультация и дерево навигации. Впереди крупные блоки: **Т2** (аудио/стенограмма — ASR-пробы ещё не сделаны), **Т4** (микрофон/роли), **Т6** (исполнение и память). Качество сделанного высокое (append-only, advisory-пороги, запрет вердиктов §0.3), готовность — половина роадмапа. |
| **Нейромузыка** | ~70 % (как эксперимент) | **хорошо** | Ядро ×128, ряды 10-20, 3D-bake, радар «Эмо», WAV+sidecar, IR-реверберация (pyroomacoustics). Открыты: вторая нижняя область визуализации, doppler (осознанно отложен за питч-контуром). Экспериментальный статус заявлен честно. |
| **ЕмоЛаб / Нейроаудио** | ~5 % | **требует доработки** | Заглушки в меню (хоткеи 8/9). Это заявленные направления concept.md (С9 «Эмоциональный анализ»), фактически не начаты — держать в плане, но не считать долгом: постановка ждёт эксперта. |
| **Wiki / Настройки / Состояние сервера** | ~95 % | **замечательно** | Wiki со статьями руководства и глоссарием, перезапуск бэкенда из UI, GPU-ресурс, индикатор устаревшего кода — редкая для исследовательского ПО забота об эксплуатации. |

**Общий вывод по готовности:** ядро научного пайплайна (EDF → артефакты → эпохи → фильтры →
диполи → локализация → таблица/отчёт) — **готово и зрело**; дифференциальный и групповой
анализ — **готовы, ждут живой приёмки**; Консилиум — **середина пути по плану**; эмоциональные
направления — **не начаты** (и это согласуется с concept.md: правила эмоционального анализа —
открытый вопрос эксперта).
