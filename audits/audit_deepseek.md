## 0. Методика и ограничения

Объект: `backend/app` — ~50 сервисных модулей (21 267 строк только в `services/`), `api/routes.py`
2755 строк, 28 моделей SQLAlchemy; `frontend/src` — 339 файлов / 88 284 строки.

**Проверено запуском:** `pytest --collect-only` — **1055** тестов. Число Vitest и размер бандла
взяты из документации (`docs/rules/tests.md`, `docs/session-start.md`): ~1229 Vitest; бандл
~2.4 МБ JS (gzip ~768 КБ) — эти цифры не перепроверялись прогонами.

**Модель эксплуатации:** локальное рабочее место одного исследователя, один uvicorn-процесс,
записи в `data/`; многопользовательский сервер — «потолок на вырост».

**Не подтверждается:** живой e2e-прогон на реальном `test.edf`/`~/mne_data`, профилирование
CPU/RSS — все оценки скорости ниже являются гипотезами по чтению кода и прежним замерам.

## 2. Архитектура

### 2.1 Слоёность «роут = форма и контракт, работа — в сервисе» — замечательно
`api/routes.py` держит только формы/статусы; разбор форм — `api/params.py`, приём файла —
`api/uploads.py`, задачи записи — `api/recording_jobs.py`, отдача ассетов — `api/assets.py`;
расчёты — `services/*` («один шаг пайплайна = один модуль»). Тяжёлые MNE/CPU-вызовы из
async-роутов уходят через `asyncio.to_thread`/job-очередь. Это главная причина, по которой
проект пережил рост до 70+ роутов без деградации. Оговорка: `routes.py` снова разросся (см. 2.6).

### 2.2 Контракт API → TypeScript со стражами — замечательно
Pydantic-схемы в `app/schemas/` → OpenAPI → `npm run gen:api`; свежесть обоих файлов ловят
pytest-страж и `git diff --exit-code` в CI. Разъехаться контракту «тихо» невозможно.

### 2.3 Схема БД через alembic + отдельный write-слой — хорошо
28 моделей SQLAlchemy; alembic — единственный источник схемы, паритет моделей и миграций — страж
`test_migrations.py`; результаты пишутся только `results_store.py`/`recording_store.py`
(«история не UPSERT», TTL строк, PHI-псевдоним) — инварианты в `docs/rules/results-db.md`.
Слабость: часть `recording_id` без FK намеренно (SQLite не проверяет), каскады — кодом; перенос
на PostgreSQL потребует проверки этих каскадов.

### 2.4 Кэши, ETag и версии ассетов — замечательно
Единый `cache_store` (атомарная запись, «сбой кэша = промах, а не падение»), `api/assets.py` —
единственная точка ETag/304/Cache-Control, `asset_versions.py` — единый отпечаток версий ассетов
со стражем. Ключи кэшей содержат параметры расчёта и версии библиотек — «залипание» старых чисел
исключено построением. Самая сильная часть системы.

### 2.5 Модель фоновых задач — хорошо
`job_manager`: 202 + `job_id`, прогресс по этапам, `asyncio.Semaphore`, отмена, история на диске
(`job_store`), `run_manifest`. Оговорка: семафор общий на всё (аудио-рендер вне его), а
долгоиграющие LLM-вызовы Консилиума добавляют свой класс ожидания (очередь, стриминг) — система
работает, но «потолок» одновременных задач и приоритизация не настроены.

### 2.6 Слабые места (требует доработки)
- `api/routes.py` — 2755 строк: после выделения A1 (17.09.2026, 1438→875) файл снова вырос за счёт
  новых групп роутов. Группировка по файлам отложена к write-API Фазы 4/5.
- Гиганты в `services/`: `report.py` (1490), `compare.py` (1181), `llm_router.py` (1170),
  `atlas_contours.py` (944), `group_reports.py` (927). Это не «слишком большие», а смешение
  ответственностей в одном модуле.
- `init_db()` вызывается на операциях БД (см. `audit_dsh.md` 1.6) — перекладывается в `lifespan`
  с guard `current == head`. **P0**.
- Docker/Compose: `python` без версии, `init_db.sql` в compose, `--reload` в проде, пути в дефолтах
  без `/home/...`. Отложено владельцем — **P0 при переходе на контейнер**.

## 3. Принятые решения реализации

### 3.1 Научный аппарат — хорошо
- **FSAverage как условная модель мозга** (требование README №4): честный выбор для группового
  шаблона; BEM/transform считаются чистым MNE из `.surf` (ico-4, ~62 с) с дисковым кэшем —
  воспроизводимо и проверено бит-в-бит с готовыми.
- **Два режима диполей — замечательно**: быстрый расчёт (сферическая модель + перебор сетки
  `grid_scan`, метод `fast_grid`) для превью и точный `mne.fit_dipole` (экспериментальный, лимит
  эпох, оценка стоимости в `/meta`). Быстрый режим явно не выдаётся за точный — честность, которой
  не хватает многим инструментам.
- **Кросс-полосной фильтр доверия по RIV/CI**, а не по GOF (узкая полоса завышает R²) — корректно.
- **Морле (TFR) для узкой «одиночной частоты»**, IIR вместо узкого FIR, гармоники notch, буферы
  края `BAD_edge`, АЧХ-отклик в UI — методически аккуратно (`docs/rules/filters.md`).
- **Robust-оценка (медиана/MAD) вместо z-score**, `multitaper` для коротких эпох, specparam/FOOOF
  (1/f + пики) — современный, обоснованный набор.

### 3.2 Визуализация — хорошо
- Три SVG-проекции с единым масштабом мм/px + реальный срез МРТ + векторные контуры aparc/BA
  (клик по полигону) — серверные числа, клиентская отрисовка.
- **Niivue для 3D** вместо самописного GLB — реконсилированное решение: читает NIfTI/GIFTI/
  FreeSurfer как есть, контур головы из `seghead.mgz`.

### 3.3 Данные и БД — хорошо
- SQLite для локали / PostgreSQL в prod, **alembic** — единственный источник схемы.
- Write-API результатов отделён от кэшей; «история не UPSERT», TTL строк = TTL записи,
  PHI-псевдоним заголовка EDF (4.4) — правильные инварианты для исследовательских данных.

### 3.4 UX-принципы — замечательно
- **«Правка параметра не запускает расчёт — считает кнопка»** — ключевая защита от скрытых
  пересчётов и «разъехавшихся» чисел; закреплено тестами.
- Воспроизводимая ссылка (`?rec/band/slice` в URL), job-очередь с отменой и прогрессом,
  оценка стоимости до запуска — зрелая модель работы с долгими расчётами.
- «Число первично, картинка — следствие» (числа клиенту, палитра на клиенте), «измерено /
  модель / интерпретация» различаются в подписях, «честная немощь вместо выдумки»
  («не определено» вместо мусора) — методическая зрелость, редко встречающаяся.

### 3.5 ИИ-интеграция — хорошо (с оговоркой о зрелости)
- **Модельный роутер ИИ через внешние API** (openai/anthropic, chat/transcribe/decide) вместо
  локального llama.cpp — отклонён после спайка (10.10.2026), аргументированно; ключи маскируются,
  `data/llm_router.json` не коммитится.
- **Консилиум** как отдельный раздел (досье, снимки, раунды советников, мозговой штурм,
  библиотека предложений, триаж Jev) — согласован с уточнённой миссией («помочь исследователю
  в осмыслении, а не выдать вердикт»). Это самый быстрорастущий участок: из 28 моделей БД
  16 — Consilium-таблицы. Оговорка: раздел живёт на стыке ручного Т1 и ИИ-советников, автоматика
  исполнения (Т6) ещё не подключена — границы доверия к выводу ИИ нужно держать явными.

### 3.6 Отклонённые решения — хорошо (аргументированные «нет»)
- **autoreject отклонён** (мягче детекторов, теряет адресность зон/QC, в 5–7 раз дороже);
  **mne-icalabel внедрён** как вторая разметка ICA — решения по числу, задокументированы.
- **C1 (перебор диполей на клиенте) отклонён** после замеров ×7.7 на сервере; **C2 (EDF/фильтрация
  на клиенте) отклонён** (второй источник истины в научных числах); C3 (том МРТ на клиент) —
  открытый кандидат без срочности.
- **Полные карты sLORETA/LCMV не тащатся в пакет** — осознанное ограничение; eLORETA пик/ROI
  реализован.

## 5. Возможности оптимизации

### 5.1 Уже оптимизировано (не трогать)
Вынос leadfield из цикла диполей (×20–24, рабочие сетки 7/4 мм — доли секунды), `n_jobs` в PSD,
кэш подготовленного сигнала (EDF читается один раз), дисковый персист по полосе, ETag/304,
сборка под gzip. Слой кэшей/ETag, job-очередь и сервисная декомпозиция — сильная сторона,
подтверждённая тестами.

### 5.2 Где есть выигрыш (по приоритету)
1. **Код-сплиттинг бандла** (lazy + manualChunks) — ~2.4 МБ JS одним куском; P1.
2. **Память аудио и потоки вне семафора** (аудио-рендер вне общего semaphore) — P1.
3. **ORM группового анализа целиком в память** (`group_analysis`) — при росте числа записей; P2.
4. **Буфер спектрограммы ~82 МБ** и **журнал I/O на строку** — P2, по замерам.
5. **`prepared_signal` float64 + копии** → float32/лимит по байтам — P1, с проверкой точности.
6. **`init_db()` на операциях БД** и **Docker/Compose** — P0 (см. 2.6).

### 5.3 Где оптимизировать не нужно (негативный результат)
- `mne.fit_dipole` медленен по определению (цена метода) — ограничен лимитами и вынесен в задачу.
- Мелкие Python-циклы (`cluster_dipoles`, детекторы) быстры — «сначала число, потом правка».
- Перенос вычислений на клиент (C1/C2) — отклонён по замерам/второму источнику истины.

## 6. Итоговое резюме

| Направление | Оценка | Аргументация |
|---|---|---|
| **Архитектура** | **замечательно** (с точечным долгом) | слоёность, контракт API↔TS со стражами, кэши/ETag/версии ассетов — образцовые. Долг: `routes.py` 2755 строк, гиганты-сервисы, `init_db` и Docker — «требует доработки», но не меняет общей оценки |
| **Принятые решения реализации** | **хорошо** | развилки принимаются по числу и честно (fast_grid ≠ fit_dipole, отклонение autoreject/llama.cpp/C1, Niivue, FSAverage). Единичные места «сомнительно»: общий семафор задач, отсутствие приоритизации LLM-очереди, зрелость ИИ-вывода |
| **Степень готовности разделов** | **требует доработки** (на флангах) | ядро готово; незрелы ЕмоЛаб/Нейроаудио (заглушки), Нейромузыка (эксперимент), Групповой (read-API 4.7), Консилиум (Т6) |
| **Оптимизация** | **хорошо** | горячие точки в основном закрыты; остались код-сплиттинг, память аудио, ORM группового, инфраструктура P0/P1 |

**Сомнительно — есть лучший вариант:** (1) вызов `init_db()` на каждой операции БД вместо
`alembic upgrade head` в `lifespan`; (2) общий `asyncio.Semaphore` на все задачи без классов
приоритета (LLM-очередь и CPU-расчёты в одной корзине); (3) монолитные `routes.py`/`report.py`/
`compare.py` — лучше группы роутов и декомпозиция сервисов по ответственностям.

## 7. Рекомендации для планирования

1. **Сначала честность и контракт деплоя (P0):** `alembic upgrade head` в `lifespan` + guard,
   почистить Docker/Compose (версия python, `init_db.sql`, `--reload`, пути).
2. **Довести групповой анализ до read-API (4.7)** — закрывает единственный «незавершённый» участок
   основного научного контура.
3. **Определиться с приоритетом флангов** — ЕмоЛаб / Нейроаудио / Нейромузыка / Т2–Т6 Консилиума:
   не открывать новые разделы, пока не решено, какие из заглушек реально нужны (миссия уточнена
   10.10.2026 — психоэмоциональный фон в приоритете, что смещает акцент к ЕмоЛаб).
4. **P1-оптимизации по замерам** (код-сплиттинг → память аудио → ORM/буферы), каждый шаг с
   `journal`/`perf` до-после.
5. **Не трогать:** слой кэшей/ETag, job-очередь, сервисную декомпозицию по шагам, инварианты
