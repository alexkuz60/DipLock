## 3. Работа с EDF (источник данных) — **хорошо**

**Есть.** `load_edf` (`services/edf_loader.py`): чтение EDF, нормализация имён каналов
(префиксы `EEG`/`POL`/`CH`, `T3→T7`), монтаж 10-20 с совместимостью имён MNE (`colin27_1020` →
`standard_1020`), референс (average / свои каналы / `none`), полосовой и сетевой фильтр **на
continuous raw**, ресемпл до 500 Гц; эвристика «EDF без physical dimension» (медианный std > 1 мВ →
×1e-6) с предупреждением в паспорте; дедуп по sha256 с сайдкаром `recording.json`, переживающим
рестарт; паспорт записи (частота, длительность, каналы, нераспознанные каналы, флаг авто-масштаба);
потоковое чтение EDF для пирамиды сигналов; лимит загрузки 200 МБ, санитизация имени, запись
чанками с удалением каталога при любой ошибке. Это выше среднего по индустрии.

| # | Ур. | Находка | Что делать |
|---|---|---|---|
| N1 | P1 | `raw.pick([...])` по жёсткому списку `settings.standard_channels` (20 каналов 10-20): остальное **молча** отбрасывается; позиции берутся из стандартного монтажа, а не из файла. Плотные монтажи (10-10, 64/128 кан.) не поддерживаются | Список каналов — из паспорта/`/meta`; поддержать 10-10 и `read_custom_montage` (координаты из файла), `set_montage(..., on_bad_channels="warn")`; в ответе явно сообщать, какие каналы **не** вошли |
| N2 | P1 | `read_raw_edf(..., stim_channel=False)`, а `segment_epochs` делает `raw.set_annotations(artifact_annotations)` — **маркеры и аннотации исходного EDF+ не доходят ни до вьюера, ни до нарезки**. Событийного режима (стимул → эпоха) нет вовсе | `stim_channel="auto"` + `raw.get_events()`; маркеры — слоем вьюера; событийная нарезка отдельным режимом; аннотации файла не перетирать, а объединять |
| N3 | P2 | `preload=True` при лимите 200 МБ: одна запись ≈ до 1.6 ГБ float64, а `MAX_CONCURRENT_JOBS=2`; пирамида сигналов читает потоково, а подготовленный сигнал — целиком | Читать `preload=False` с окнами либо ограничивать по памяти, а не по размеру файла |
| N4 | P2 | Ресемпл до 500 Гц зашит в код (не в `config`), порог не настраивается и не попадает в паспорт; при полосе 1–40 Гц достаточно 250 Гц | `max_sfreq` в `Settings`, факт ресемпла — в паспорт записи |
| N5 | P2 | «Плохие» каналы только помечаются как flat-line зоны: интерполяции нет (`find_bad_channels_lof`/`interpolate_bads` не используются), при этом плохой канал попадает и в average reference, и в свинцовое поле | Кнопка «найти/интерполировать плохие каналы» стадией предподготовки; список bad-каналов — в параметры расчёта (тогда он входит в сигнатуру кэша) |

**Альтернативы / более новые решения.** MNE покрывает больше источников, чем использует проект:
`read_raw_brain_vision`, `read_raw_eeglab`, `read_raw_nihon`, `read_raw_neuralynx`, `read_raw_kit`.
Для BIDS-совместимости — `mne-bids`; для записи размеченной сессии обратно в EDF+ — `pyEDFlib`
(экспорта сейчас нет вовсе). Предварительный поиск плохих каналов —
`mne.preprocessing.find_bad_channels_lof` + `equalize_bads` + `interpolate_bads`.

**+ функционал.** Пакетная загрузка (несколько файлов/ZIP), анонимизация заголовка EDF при приёме
(сейчас PHI уходят на диск как есть, см. N36), авто-определение типа записи (rest/task), паспорт
с демографией и условиями съёмки, экспорт аннотаций и эпох в EDF+/CSV.


## 4. Поиск артефактов — **сомневаюсь (аргументированно)**

**Есть.** `services/artifact_detector.py`: z-score по каналу (порог 5), peak-to-peak в скользящем
окне 2 с (порог 100 мкВ), flat-line (`|x| < 5 мкВ` ≥ 200 мс), опциональная ICA-EOG-ветка; зоны
(onset/duration/каналы) уходят в слои вьюера, типы и счётчики — в контракт результата стадии.

**Аргументы «сомневаюсь» — три независимых дефекта и одна мёртвая ветка.**

| # | Ур. | Находка | Что делать |
|---|---|---|---|
| N6 | **P0** | Аннотации называются `zscore_outlier`/`peak_to_peak`/`flat_line`, а `mne.Epochs` отбраковывает только описания с префиксом `BAD`. **Замер:** те же 2 зоны → осталось **19/20** эпох с текущими именами против **15/20** с `BAD_`. То есть найденные артефакты **не влияют на состав эпох** (решает только амплитудный `reject`), хотя UI показывает обратное | Переименовать описания в `BAD_*` (или передавать `reject_by_annotation` с явным `ignore`), тогда зоны станут частью решения о годности эпохи; в контракт — сколько эпох отброшено именно по зонам |
| N7 | P1 | **F20 подтверждён замером:** на 30 с чистого белого шума детектор объявляет **4 «плоские» зоны** (при нулевых z-score и peak-to-peak) — критерий абсолютной амплитуды ловит треть отсчётов полосового сигнала; с одним добавленным артефактом зон становится 5 | Оконный критерий «почти константа» (peak-to-peak в окне) вместо порога по модулю амплитуды; готовые альтернативы — `annotate_amplitude`/`annotate_break` |
| N8 | P1 | ICA-ветка **недостижима**: `load_edf` делает `raw.pick(available)` по 20 каналам 10-20, среди них нет имён с `eog`, поэтому `eog_like` всегда пуст. Плюс ICA не фильтруется (нужен high-pass ~1 Гц) и `ica.apply()` не вызывается — артефакт только «помечается» | Либо убрать ICA из «ЭЭГ-записи» и оставить EOG-регрессию/SSP (`compute_proj_eog`, `find_eog_events`), либо импортировать каналы EOG/ECG и применять `ica.apply` с отчётом об удалённых компонентах |
| N9 | P1 | z-score считается по **глобальному** std канала: артефакт сам завышает σ, длинные записи с дрейфом уровня смещают порог. Окна peak-to-peak идут с шагом 1 с при окне 2 с → одна зона считается дважды и раздувает `total` | Робастная оценка (MAD, modified z) в скользящем окне; зоны — интервалами, а не перекрывающимися окнами |
| N10 | P2 | Нет детекторов мышечных артефактов, разрывов и NaN; нет метрики «доля годных данных». Два самых частых класса артефактов реальных записей (ЭМГ, потеря контакта) не детектируются, а сводка `total` — число срабатываний, а не интервалов | `annotate_muscle_zscore`, `annotate_nan`, `annotate_break`; отдавать `good_data_percent` и разбивку «доля записи» по типам |

**Альтернативы / более новые решения.** В MNE уже есть протестированные замены ручному коду:
`annotate_amplitude` (в т.ч. peak-режим и `reject_by_annotation` «из коробки»),
`annotate_muscle_zscore`, `annotate_movement`, `annotate_nan`, `annotate_break`; для глаз и сердца —
`find_eog_events`/`create_eog_epochs`/`compute_proj_eog` и `find_ecg_events`/`create_ecg_epochs`/
`compute_proj_ecg` (детерминированные SSP-проекции вместо ICA); для сопоставления компонент между
сессиями — `corrmap`. Внешние варианты: `neurokit2` (метрики качества ЭЭГ и артефакт-детекторы),
ASR (Artifact Subspace Reconstruction, порт EEGLAB), wavelet-подходы. Автоклассификация ICA-компонент
(классы ICLabel: brain/eye/muscle/heart/line) — то, чего сейчас нет вообще.

**+ функционал.** Правка зон руками (ручные пометки в UI уже есть — их надо допустить в расчёт),
режим «не отбрасывать эпоху, а интерполировать каналы», канал-ориентированная теплокарта артефактов,
экспорт аннотаций в EDF+/CSV, авто-пороги из распределения канала (а не одна константа на файл).


## 5. Фильтры — **хорошо** (есть лучшие альтернативы)

**Есть.** `services/bandpass_filter.py` + вызов фильтрации внутри `load_edf`: полосовой FIR
(`firwin`) и сетевой notch применяются к **continuous raw до нарезки** (методологически верно:
эпоха 250 мс короче FIR-фильтра и даёт искажения), пресеты δ…γ из `core/config.py` (DRY), «свой
диапазон», «одиночная частота» как узкая полоса, «без фильтра»; отдельные endpoint-стадии
предподготовки; полоса и notch входят в сигнатуру кэша (`prepared_signal`, `spectrum_signature`,
`spectrogram_signature`) — смена фильтра не «залипает» в кэше браузера.

| # | Ур. | Находка | Что делать |
|---|---|---|---|
| N11 | P2 | `fir_design="firwin"` — устаревший аргумент (в MNE ≥ 1.7 это и так default): шум в коде и место для дрейфа API | Убрать аргумент, оставив явными `l_trans_bandwidth`/`h_trans_bandwidth` |
| N12 | P2 | Краевые эффекты не компенсируются: фильтруется вся запись, а нарезка начинается с 0 с, поэтому первые/последние ~пол-фильтра эпохи содержат переходный процесс FIR; в паспорте и UI об этом ничего нет | Буферная зона (отбрасывать ±X мс краёв) или явное предупреждение; показывать длину фильтра |
| N13 | P2 | Notch — одиночная частота: гармоники сети (100/150 Гц) остаются, а FIR-notch на 50 Гц дорог и «вырезает» широкую полосу | Список частот `[50, 100, 150]`; MNE-альтернатива — `fit_iir_model_raw` (адаптивная оценка линии питания сохраняет форму сигнала лучше статичного notch) |
| N14 | P2 | Фильтр стадии `filter` **не влияет** на пирамиду сигналов вьюера: пользователь видит нефильтрованный сигнал, а расчёт идёт по фильтрованному (`docs/data_map.md` §2 это фиксирует как «хотим») | Отдавать пирамиду по «применённому» фильтру либо явно подписывать вьюер «сигнал не фильтрован» |

**Альтернативы / более новые решения.** `mne.filter.create_filter` даёт АЧХ и порядок фильтра —
это дешёвый способ показать пользователю, что именно делает пресет (сейчас фильтр невидим).
`raw.filter(..., method="iir", phase="zero-double")` — вариант с меньшим ringing при узких полосах.
Для референса: кроме average/свои каналы — REST (spherical spline reference) и
`compute_current_source_density` (CSD/Laplacian, есть в MNE) — стандарт для анализа локальной
синхронности; полезно и методологически (average reference применяется до детекции артефактов, что
размывает общую компоненту — это стоит либо переключать, либо документировать в отчёте).

**+ функционал.** Пресеты-конфигурации («клиника 1–35, notch 50»), график АЧХ в панели, отчёт
«параметры фильтрации» в экспортируемом отчёте, единый набор параметров фильтра на всю сессию
(сейчас полоса/notch задаются отдельно в EDF, «Диполях» и «ЭЭГ» — риск несогласованных снимков).

## 6. Спектр и частотно-амплитудный анализ — **сомневаюсь** по метрикам, **есть более новые решения** для ЧАА

**Есть.** `services/spectral.py`: Welch PSD по эпохам (`n_fft ≤ 256`), мощности δ…γ, топокарты
(128 px, PNG, IDW, серый + альфа, ETag/304, дисковый кэш по сигнатуре), ссылки на картинки и числа
PSD в JSON, FFT-гистограмма на клиенте. `services/spectrogram.py`: собственный STFT одного канала
или микса (окно Ханна, 75 % перекрытие, шаг `window×(1−overlap)`, уровень амплитуды в дБ,
потолок по 99.9-му процентилю, floor −60 дБ), сетка `DPS2` float32 (частота-мажорно) с ETag, а
палитра/окно дБ/сглаживание — параметры просмотра на клиенте (правильно: правка не запускает расчёт).
Миксы каналов по группам 10-20 — сильная, редкая фича.

| # | Ур. | Находка | Что делать |
|---|---|---|---|
| N15 | P1 | «Мощность диапазона» = `mean(PSD)` по бинам, а не интеграл по полосе: у α (8–13) и β (13–30) сравниваются средние по разной ширине, а физически сравнимой величиной является интеграл (µV²) | Считать интеграл (`np.trapezoid`) + относительную мощность (% от охвата) и явно назвать единицы в контракте и UI |
| N16 | P1 | Нет индивидуальной пиковой α-частоты (IAF), нет θ/β-индексов, нет медианы/разброса по эпохам — то есть нет главных метрик, по которым ЭЭГ-спектр реально интерпретируют | Добавить IAF, relative power, индексы θ/β и (θ+α)/β, медиану и квартили по эпохам; эпохи уже есть в контракте |
| N17 | P2 | Welch с `n_fft = min(256, n_times)` на эпохах 250–500 мс даёт разрешение 4 Гц при полосе α в 5 Гц — полоса покрывается 1–2 бинами; перекрытия окон нет | `method="multitaper"` (DPSS) для коротких окон или Welch по continuous с 50 % перекрытием — обе возможности уже в MNE |
| N18 | P2 | Спектрограмма: только амплитуда, линейная шкала частот, нет нормировки по baseline (ERD/ERS), нет лог-шкалы и изоконтуров | Дополнить log-нормировкой (уже есть параметром просмотра на клиенте) и режимом ERD/ERS; MNE-варианты TFR — `tfr_array_morlet` (лучше по времени-частоте на низких частотах), `tfr_array_multitaper`, `tfr_array_stockwell` |

## 7. Расчёт диполей — **сомневаюсь** + **есть лучшие альтернативы**

журналу — ровно то, что `todo.md` §4 называет `analytics.db`, но без самодельного ETL. Для
подготовленного сигнала — `raw.save(..., .fif)` с `preload=False` (memmap) вместо RAM-LRU на два
набора: 86 МБ на 20-минутную запись при 18 каналах перестают быть пределом, а кэш переживает
рестарт.

**+ функционал — то, чего у приложений этого класса обычно ещё нет.**
1. **ROI-анализ**: агрегация мощностей и диполей по `aparc+aseg`/BA и по миксам групп 10-20 —
   «сколько диполей с GOF > 0.8 в ROI X», асимметрия полушарий, теплокарта ROI × полоса. Данные уже
   есть (`structure_at`, производный BA-объём, `channel_mix`); нужны таблица (N39) и агрегирующий запрос.
2. **Автоматический отчёт по сессии** (PDF/HTML/Markdown): паспорт записи, снимок параметров, доля
   годных данных и профиль артефактов, таблица спектра с IAF и относительными мощностями, топ-N
   структур и полей с диполями, мини-топокарты, проекции, предупреждения, версии ПО и ассетов
   (воспроизводимость). Для научного инструмента это самый большой недостающий блок; реализуется без
   новых зависимостей (Jinja2 + печать, WeasyPrint или целиком на клиенте).
3. **Пакетный/когортный режим**: очередь записей → один пресет → сводная таблица и групповые
   агрегаты (Фаза 5) с прогрессом и частичным результатом.
4. **Событийный режим и ERP/ERD-ERS** (открывается N2): стимул → эпоха → усреднение → карта.
5. **Микросостояния ЭЭГ** (кластеризация карт GFP) и **коннективность** (PLV/wPLV/когерентность,
   `mne_connectivity`) — естественные соседи уже посчитанных «диполь на эпоху» и «спектр по эпохам».
6. **Воспроизводимость и валидация**: run manifest (версии + параметры + отпечатки данных),
   сравнение профилей fast/accurate, «пересчитать всё как было» одной кнопкой.

import time, numpy as np
from app.services.dipole_scanner import candidate_grid, _leadfield
rng = np.random.default_rng(0)
pos = 0.055*rng.standard_normal((18, 3))          # 18 электродов на сфере ~55 мм
for step in (7.0, 4.0):
    grid = candidate_grid(step)
    sig = rng.standard_normal((18, 20))*1e-6      # 20 «эпох» одного отсчёта
    t0 = time.perf_counter()
    for j in range(sig.shape[1]):                 # как в scan_point: геометрия каждый раз
        g, _ = _leadfield(pos, grid)
        g = g - g.mean(axis=0, keepdims=True)
        gram = np.einsum('iqj,iqk->qjk', g, g)
        gram += (1e-9*np.maximum(np.trace(gram, axis1=1, axis2=2)/3, 1e-30))[:, None, None]*np.eye(3)
        np.linalg.solve(gram, np.einsum('iqj,i->qj', g, sig[:, j])[:, :, None])
    a = (time.perf_counter()-t0)/sig.shape[1]*1000
    t0 = time.perf_counter()
    g, _ = _leadfield(pos, grid)                  # геометрия один раз на все эпохи
    g = g - g.mean(axis=0, keepdims=True)
    gram = np.einsum('iqj,iqk->qjk', g, g)

    b = (time.perf_counter()-t0)/sig.shape[1]*1000
    print(f'step={step}mm nodes={grid.shape[0]}: в цикле {a:.1f} мс/эпоха, один раз {b:.2f} мс/эпоха')
