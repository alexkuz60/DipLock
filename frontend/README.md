# DipLock frontend (Vite + React + TS)

Дев-сервер и сборка UI для бэкенда FastAPI.

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 (проксирует /api на :8000)
npm run test       # Vitest (jsdom)
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint
npm run build      # сборка в ../backend/app/static/ui (раздаётся FastAPI по /ui/)
```

Бэкенд должен быть запущен:

```bash
cd ../backend && venv/bin/uvicorn app.main:app --reload --port 8000
```

Адрес бэкенда для dev-прокси переопределяется переменной `VITE_BACKEND_URL`.

## Слои результата во вьюере

Слои — это результат предподготовки (зоны артефактов, границы эпох, штриховка отброшенных),
нарисованные **DOM поверх canvas-треков uPlot** (`app/sections/viewer/TrackLayers.tsx`). Так зона
остаётся кнопкой: клик даёт детали, а зум только пересчитывает позиции через `timeToX`, не трогая
canvas. Геометрия и фикстура — в `shared/lib/viewerLayers.ts` (чистые функции, покрыты тестами).

Пока стадии `artifacts`/`epochs` не подключены к серверу (срез 2.7), слои берутся из
детерминированной фикстуры `demoLayers` (`source: 'demo'`) — она одинакова между запусками, поэтому
тесты и сравнение «до/после» не шумят. Границы эпох считаются из параметра «длина эпохи», а не из
результата, — сетка живая уже сейчас. Цвета зон — токены темы (`--color-artifact-*`), заливка через
`color-mix`, hex в JS не дублируется.

## Правило обработки данных

UI **не запускает расчёт сам**. Правка параметра только складывает выбор в стор раздела
(`shared/state/edfParams.ts`), а расчёт идёт отдельной задачей строго по кнопке
(`markApplied()` фиксирует снимок параметров, для которого получен результат). Пока результат
не получен или параметры изменились, панель показывает это статусом в блоке «Запуск».

Кнопки стадий в тулс-хедере (`EdfRecalcButtons`) ставят задачу `POST /recordings/{id}/preprocess`
(`stage=filter|artifacts|epochs`), опрашивают прогресс через `GET /jobs/{id}` и кладут результат в
слои вьюера (`layers.source === 'result'`). Снимок параметров берётся в момент запуска
(`stageSignature` → `markStageApplied(stage, signature)`), поэтому правка параметра во время задачи
честно показывает «параметры изменены».

Планируемый функционал разделов — в `docs/ui.md` (корень репозитория).

## Интерактив вьюера (срез 2.9) и разметка эпох (срез 2.10)

- **Навигация по окну.** Кнопки `<<` `<` `>` `>>` в шапке листают окно на его ширину или прыгают в
  начало/конец записи. Команда идёт не напрямую, а через состояние: `requestNav(command)` кладёт в
  `edfRecording` пару `{command, seq}` с монотонным `seq`, а `TrackStack` применяет только новую
  команду (`handledNavSeqRef` инициализируется текущим `seq`, поэтому повторное монтирование вьюера
  не проигрывает старую команду). Сервер окно не пересчитывает — это чистая перерисовка кадра.
- **Курсор** ставится кликом и живёт до следующего клика (мышь его не таскает). Клик после
  панорамирования и клики по кнопкам (подписи каналов, зоны артефактов) игнорируются, поэтому
  перетаскивание окна не сбивает курсор.
- **Разворот трека.** Клик по названию канала разворачивает его на высоту видимой области,
  повторный — сворачивает; остальные треки уезжают в скролл. Высота берётся из `ResizeObserver`
  (в jsdom — фолбэк `TRACK_HEIGHT`). Разворот и центр окна живут в локальном состоянии вьюера:
  это параметры отрисовки, они не обесценивают стадии и не переживают выход из раздела.
- **Оверлеи внутри прокручиваемого контента** (срез 2.11). Абсолютный потомок скролл-контейнера
  скроллится вместе с содержимым, но его `inset-y-0` считается по высоте *видимой области*: линия
  курсора, будучи ребёнком контейнера, при прокрутке вниз обрывалась на середине стека. Поэтому
  линия курсора живёт в `data-testid="viewer-content"` и тянется на весь стек, а подпись времени и
  карточка выделенной зоны «липнут» к верху области (`position: sticky` внутри `absolute inset-0`
  высотой во весь контент). Проверяйте прокруткой в браузере: jsdom раскладку не считает.
- **mute/solo убраны** — видимость каналов задаётся чекбоксами панели «Каналы».
- **Скроллбар неотключаемый**: утилита `.scroll-y-always` (`overflow-y: scroll` +
  `scrollbar-gutter: stable`) в треках и панели опций, чтобы полоса не
  «дёргалась» при смене раздела и показывала долю окна в записи. Ширина полосы (20 px, срез 2.11)
  задана только через `::-webkit-scrollbar`: стандартные `scrollbar-width`/`scrollbar-color` в
  Chrome отключают legacy-псевдоэлементы, поэтому для Firefox они вынесены в
  `@supports (-moz-appearance: none)`. Скролл существует только потому,
  что каркас (`AppShell`) ограничен высотой окна: grid со строкой `grid-rows-[minmax(0,1fr)]` —
  проверяйте такие правки в браузере, jsdom раскладку не считает.
- **Разметка эпох привязана к нарезке, которой считался результат** (`gridEpochLength`): у слоя
  `source: 'result'` сетка берётся из `epochLengthMs` (= `epoch_length_ms` стадии «эпохи»),
  у фикстуры — из параметра панели. Так смена длины эпохи в панели не переносит штриховку
  отброшенных эпох на другой участок записи; расхождение видно пилюлей «разметка эпох: N мс».
- **Ручные пометки эпох** (`Ctrl`+двойной клик по треку): `toggleEpochMark` инвертирует итоговый
  вердикт эпохи (снять штриховку алгоритма или поставить свою) и хранит пометку **интервалом на
  таймлайне** в сторе записи (`edfRecording.epochMarks`, не localStorage). Пометки видно даже при
  выключенной штриховке, счётчик — в полосе вьюера, снять все — кнопкой «Снять» в панели «Эпохи».
  Счётчик считает **пометки** (`epochMarks.length`, срез 2.11), а не ячейки сетки: после смены длины
  эпохи одна пометка накрывает несколько эпох новой нарезки, но остаётся одной пометкой — так же
  считает и панель «Эпохи».
  В расчёт на сервере правки пока не уходят (`docs/ui.md` §12).

## Экспорт окна (срез 2.8)

Экспорт **клиентский**: данные уже в браузере (кадр пирамиды сигналов, слои, окно просмотра),
поэтому сервер не участвует — ни запросов, ни пересчёта того, что видно на экране. Кнопки PNG/CSV
живут в полосе окна вьюера (`app/sections/viewer/ExportActions.tsx`), рядом со шкалой времени: им
нужны окно, видимые каналы и canvas'ы треков (регистрируются в `TrackStack` через
`canvasesRef`/`registerCanvas` — ref, а не состояние, чтобы регистрация холста не перерисовывала
вьюер).

- **CSV** — длинный формат `time_sec,channel,min_uv,max_uv`: строка на пару «временная корзина ×
  канал», то есть ровно то, что показывает окно. Кадр уровня ×k уже прорежен сервером, и выдавать
  его за полноразрешённый сигнал нельзя — «одного числа на точку» в файле нет.
- **PNG** — снапшот окна, а не только линии сигнала: canvas'ы uPlot склеиваются с подписями каналов,
  шкалой времени, зонами артефактов, сеткой эпох и легендой. Canvas не читает CSS-токены, поэтому
  цвета разрешаются через `getComputedStyle` с hex-fallback.
- Имя файла `<запись>-win<from>-<to>s-<level>.csv|png` (уровень 0 → `full`), имя записи
  санитизируется: экспорт не должен уметь записать файл за пределами каталога загрузок.
- Если браузер не умеет `toBlob` (или холст не закодировался), кнопка показывает ошибку текстом:
  пустой файл хуже отказа.

Форматы и геометрия — в чистом `shared/lib/exportWindow.ts` (без React и zustand, DOM трогает только
`drawSnapshot`), доставка файла — в `shared/lib/download.ts`. Оба покрыты тестами
(`exportWindow.test.ts`, `download.test.ts`, `viewer/ExportActions.test.tsx`).
