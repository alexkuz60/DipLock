# UI §3.4–3.5 — таблица локализации и групповой анализ

### 3.4 Таблица локализации
**Срез 4 (готово):** раздел `/table` показывает **все точки расчёта диполей** текущей записи:
семантическая `<table>` со «липкой» шапкой, колонки — эпоха (нумерация с 1, как в подсказках
проекций), пик GFP внутри эпохи (с), MNI x/y/z, амплитуда момента (нАм), GOF (%), полушарие,
**структура атласа** (`aparc+aseg` по
MNI-координате точки, приходит с сервера полем `anatomical_structure`; «—» — координат нет или узел
не размечен), поле Бродмана. Структура и поле — **разные колонки**:
первая читается из объёма, вторая — производная разметка коры. Ячейки атрибуции подписаны формой
шага 1.4: «X» при точном попадании (≤ 1 мм), «около X ~N мм» дальше, «вне мозга (~N мм до X)»
в колонке «Структура» (у такой строки «Поле Бродмана» — «—»: метка ближайшего узла вне мозга
вымышленная). Строки — все точки результата,
включая те, что без MNI (там «—»): «все результаты»
это все, а не «те, что удалось навести», а причина приходит предупреждением задачи. Сортировка —
по номеру эпохи (направление — сегментный переключатель панели), состав колонок — чекбоксами;
настройки живут в `shared/state/tableParams.ts` и правятся **без единого запроса** (раздел не
запускает расчёт: из запросов у него нет ни одного). Если параметры расчёта в разделе «Диполи»
изменили после расчёта, таблица предупреждает «параметры изменены — результат не пересчитан»
(отпечаток `calcSignature`/`resultSignature`), а не выдаёт старые числа за посчитанные на новых
настройках. Пороги отображения («GOF ≥ X %» / «Момент диполя ≥ X нАм») на таблицу не влияют — они
параметры отображения проекций, и это
сказано подписью.
**Вкладки просмотра (16.11.2026):** рабочая область делится на три вкладки
(`SegmentedControl` «Вид», активная живёт в `tableParams.viewTab` и переживает
перезагрузку): **«Точки локализации»** — таблица точек выше; **«Сопоставление
полос»** (С1) — таблица пакета поддиапазонов (только нормированные величины,
колонки GOF нет — принцип 3, кросс-полосной фильтр доверия — RIV); **«Кластеры
диполей (С2)»** — паспорт нормировки (воксель, минимум точек, фильтр КД) и
сравнительная таблица профилей признаков кластеров (Т2). Обе таблицы перенесены
из панели «Пакет поддиапазонов» раздела «Диполи» — в сайдбаре их приходилось
прокручивать. Вкладки — чистое представление, ни одна ничего не запрашивает;
без пакетного прогона они объясняют, где взять данные («Рассчитать пакет» в
шапке раздела «Диполи»). Предупреждение «параметры изменены — результат не
пересчитан» видно на любой вкладке. Форма «Черновик правила из профиля» (Т5)
осталась в панели «Пакет поддиапазонов» — она делает запросы и в раздел
просмотра не входит.

Дальше (следующий срез): фильтры (GOF, амплитуда, BA/ROI), поиск, виртуализация (TanStack
Table + Virtual), клик по строке → фокус на диполе в разделе «Диполи», экспорт выборки в CSV/JSON,
сохранение выборки в БД. Колонки ROI пока нет: в результате быстрого расчёта есть только поле
Бродмана — пустая колонка «ROI» читалась бы как «не определено», хотя ROI просто не считали.

### 3.5 Групповой анализ
Список сессий из БД с параметрами анализа каждой записи; групповые фильтры (диапазон, длина эпохи,
GOF, BA/ROI, файл, дата); агрегаты (число диполей, средняя/стд амплитуда, средний GOF по BA);
тепловая карта «BA × сессии»; экспорт сводки. **Реализовано срезами G1–G4 (октябрь 2026,
остаток 4.7)**: read-API сессий + роуты №52–55, таблицы `group_analyses`/`group_analysis_members`,
блоки «Кластеры диполей (B8)» (с колонкой «Признаки (профиль)» — характерное ищем сами,
29.10.2026) и экспорт CSV; правило — `docs/rules/group-analysis.md`.
