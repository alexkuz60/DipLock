> Срез 01.10.2026. Разделы стоят в Главном меню (рейл) под номерами хоткеев
> **7 (Итоги), 8 (ЕмоЛаб), 9 (Нейроаудио)**; общие принципы — `docs/ui.md` §1,
> каркас — `docs/ui/shell.md`. Правило «правка не запускает расчёт» действует
> полностью.

## 3.9.1 Назначение

**«Итоги»** — автоматический отчёт о результатах **полного пайплайна записи**
одним документом. Отчёт собирается фоновой задачей `kind=report`
(`POST /api/v1/recordings/{id}/report`) в три ступени:

1. **Часть 1 — качество и препроцессинг.** Те же три стадии, что раздел EDF
   (`run_preprocess` filter → artifacts → epochs), с **теми же параметрами
   формы EDF** (фильтр, notch, референс, пороги детекторов, очистка, длина
   эпохи): светофор QC и причины, числа QC, доли видов артефактов, QC по
   каналам, паспорт фильтра/очистки, нарезка и отбраковка эпох, предупреждения
   стадий. Новых измерений нет — MNE.Report пересказывает уже получаемые
   данные (таково задание среза).
2. **Часть 2 — пакет диполей по полосам.** Для каждой выбранной именованной
   полосы (`freq_bands` + `functional_bands` из `/meta`) — быстрый расчёт
   `compute_dipole_scan` (одна точка на эпоху, пик GFP) и агрегаты:
   топы активных структур и полей Бродмана, **динамика активности** (5 равных
   бинов по индексам эпох), медианные GOF/RIV. Подпись обязательна и стоит
   перед таблицами: **GOF между полосами не сравним** (принцип 3
   `docs/rules/dipoles.md`), кросс-полосной фильтр — RIV/CI.
3. **Сборка** — самодостаточный HTML `mne.Report` (MNE 1.13: CSS/JS
   встраиваются, один файл) → дисковый кэш
   `data/cache/reports/{recording_id}/{sig}.html` → ассет с ETag/304
   (`GET …/report/{job_id}/html`).

HTML показывается в рабочей области **iframe** по `html_url` с `?v={report_version}`
(версия ассета — хеш содержимого): тот же документ открывается ссылкой
«Открыть отчёт» в новой вкладке и печатается без пересборки на клиенте.

**Тема отчёта** — светлая (дефолт, для печати) и тёмная (для просмотра) —
живёт в самом HTML (`THEME_CSS`/`THEME_JS` в `services/report.py`, инъекция
через `mne.Report.add_custom_css`/`add_custom_js`): стартовая тема читается
из `?theme=dark`, кнопка в углу документа переключает и синхронизирует URL
(скопированная ссылка открывается с той же темой). Тема — параметр
**отображения**: она не входит в отпечаток кэша и не меняет ETag — один файл
на обе темы, iframe и «Открыть отчёт» тему правок не требуют. Печать
(`Ctrl+P`) **всегда светлая**: блок `@media print` возвращает светлые значения
CSS-переменных `--dl-*` при любой выбранной теме. Ограничение: тепловая карта
— PNG matplotlib со светлым фоном, в тёмной теме показывается светлой
карточкой (осознанно, прозрачный фон — задача на развитие).

## 3.9.2 Состояние и элементы

Стор — `shared/state/summaryReport.ts` (персист только параметров пакета):

| Элемент | Где | Поведение |
|---|---|---|
| «Собрать отчёт» / «Пересобрать» | тулс-хедер | единственный триггер расчёта; выключен без записи и при пустом наборе полос |
| Прогресс + отмена | тулс-хедер | полоса 0…100 % + сообщение этапа (в сообщении полосы пакета виден номер: «θ: Диполи: 12 из 30»); отмена — `DELETE /jobs/{id}` (3.2) |
| «Открыть отчёт» | тулс-хедер | ссылка `html_url?v=…` (новая вкладка), только при результате |
| Сводка-пилюли | рабочая область | QC-вердикт, эпохи «использовано из нарезано», полос пакета, отклонено, чистые данные %, число предупреждений (тултип с текстами) |
| iframe | рабочая область | документ MNE.Report |
| Панель «Полосы пакета» | справа | чекбоксы всех полос `/meta` (октавные + функциональные); `null` в сторе = «все» (дефолт), первый клик раскрывает в явный список; «Все полосы» возвращает `null`; пустой список → кнопка расчёта выключена |
| Панель «Расчёт» | справа | шаг сетки 2…20 мм; строки-сверка «Длина эпохи/Фильтр/Notch/Референс — из формы EDF»; при событийном режиме EDF — предупреждение |
| Панель «Результат» | справа | справка: файл, QC, эпохи, время расчёта, последняя ошибка |

Состояния рабочей области: **нет записи** (плейсхолдер «загрузите EDF») →
**собирается** (этап + полоса прогресса) → **ошибка** (текст сервера,
`apiErrorText`) → **не собран** (план из двух частей — чем отчёт полезен) →
**результат** (пилюли + iframe).

Результат принадлежит записи: при закрытии/смене записи `SummarySection`
сравнивает `result.recording_id` с текущей и зовёт `reset()` (он же сдвигает
токен поллинга — ответ старой записи не мигнёт в UI).

## 3.9.3 Параметры: почему форма EDF, а не своя

Часть 1 обязана совпасть с EDF **числами**, поэтому форма задачи — это форма
стадий EDF (`buildPreprocessForm`) + `bands` + `grid_mm`; параметры части 1 на
панели не дублируются, а показываются строками-сверкой. Ограничение среза:
**событийная нарезка (ERP) в отчёт не входит** — поле `epoch_mode` не читается,
нарезка всегда `fixed`; при включённом событийном режиме EDF панель показывает
предупреждение (иначе молчаливое расхождение со штриховкой вьюера).
Очистка и пороги входят в отпечаток кэша HTML (`report_signature` считается от
`repr(PreprocessParams)` целиком) — отменённая зона или иной порог = другой файл.

## 3.9.4 Что заметили при сборке: кандидаты проверок сквозного пайплайна

Сборка отчёта — первый взгляд на пайплайн «одним глазом»: ниже очередь
кросс-проверок, которые просились сами (комментарий среза 01.10.2026; статус —
кандидаты, не обещания; пункты переносятся в `todo.md` при взятии в работу):

1. **Сверка отчёта с последней стадией EDF.** Одинаковые параметры → одинаковый
   `good_data_percent`/счётчики: сейчас это верно «по построению» (общий
   `run_preprocess`), но ничем не проверяется — расхождение невидимо.
2. **Доля выживших эпох как вердикт.** Если пакет/стадии отбрасывают >30 % эпох
   (BAD_ по видам), отчёт обязан сказать это первой строкой, а не числом в
   таблице: 90 % отброшенных эпох делает таблицы структур шумом.
3. **Согласованность нарезки частей.** Часть 1 и пакет нарезают эпохи
   раздельно (свой `segment_epochs`): сверить `n_epochs_used` между ними —
   расхождение означает, что «структуры по полосам» считались не по тем эпохам,
   что описаны в части 1.
4. **Доля точек без атрибуции.** `n_no_attribution` растёт, если fsaverage
   недоступен или точка вне маски мозга: порог (например, >20 %) → явное
   предупреждение в шапке отчёта вместо честных, но пустых таблиц.
5. **Кросс-полосной аутlier структуры.** Структура «активна» в 100 % эпох
   одной полосы — подозрительно (атласная привязка к одному узлу сетки):
   кандидат на проверку «доля эпох ≤ порога» в топах.
6. **Notch до/после в одном отчёте.** L1 (`line_noise_levels_db`) уже считается
   в отчёте очистки — включить её в часть 1 числом «было/стало», чтобы
   эффективность notch была видна без раздела «EDF».
7. **Паспорт сырого файла шире QC:** единицы/физический диапазон EDF, каналы
   вне монтажа 10-20, частота дискретизации против верхней границы пакета
   (γ-high 64–128 Гц требует ≥256 Гц — сейчас пилюля SNR этого не говорит).
8. **Повторяемость прогона:** в заголовок отчёта — полный отпечаток
   параметров (сейчас только дата/полосы/сетка), чтобы два HTML можно было
   сверить парами «что именно отличается».
