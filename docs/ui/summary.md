> Срез 01.10.2026. Разделы стоят в Главном меню (рейл) под номерами хоткеев
> **7 (Итоги), 8 (ЕмоЛаб), 9 (Нейроаудио)**; общие принципы — `docs/ui.md` §1,
> каркас — `docs/ui/shell.md`. Правило «правка не запускает расчёт» действует
> полностью.

## 3.9.1 Назначение

**«Итоги»** — автоматический отчёт о результатах **полного пайплайна записи**
одним документом. Отчёт собирается фоновой задачей `kind=report`
(`POST /api/v1/recordings/{id}/report`) в три ступени:

1. **Часть 1 — качество и препроцессинг.** Те же три стадии, что раздел EDF
   (`run_preprocess` filter → artifacts → epochs), с **теми же параметрами
   формы EDF** (фильтр, notch, референс, пороги детекторов, очистка, длина
   эпохи): светофор QC и причины, числа QC, доли видов артефактов, QC по
   каналам, паспорт фильтра/очистки, нарезка и отбраковка эпох, предупреждения
   стадий. Новых измерений нет — MNE.Report пересказывает уже получаемые
   данные (таково задание среза).
2. **Часть 2 — пакет диполей по полосам.** Для каждой выбранной именованной
   полосы (`freq_bands` + `functional_bands` из `/meta`) — быстрый расчёт
   `compute_dipole_scan` (одна точка на эпоху, пик GFP) и агрегаты:
   топы активных структур и полей Бродмана, **динамика активности** (5 равных
   бинов по индексам эпох), медианные GOF/RIV, **ROI-агрегат** (4.5:
   `services/roi.py` — «структура/поле × полоса», надёжные точки GOF ≥ порога
   внутри полосы, асимметрия полушарий; в HTML — секция после тепловой карты,
   в результат — поле `roi` под вкладку UI). Подпись обязательна и стоит
   перед таблицами: **GOF между полосами не сравним** (принцип 3
   `docs/rules/dipoles.md`), кросс-полосной фильтр — RIV/CI.
3. **Сборка** — самодостаточный HTML `mne.Report` (MNE 1.13: CSS/JS
   встраиваются, один файл) → дисковый кэш
   `data/cache/reports/{recording_id}/{sig}.html` → ассет с ETag/304
   (`GET …/report/{job_id}/html`).

HTML показывается в рабочей области **iframe** по `html_url` с `?v={report_version}`
(версия ассета — хеш содержимого): тот же документ открывается ссылкой
«Открыть отчёт» в новой вкладке и печатается без пересборки на клиенте.

**Пользовательское описание** раздела (подготовка к сборке, методика двух частей,
кросс-проверки, чтение результата) — статья Wiki «Итоги: сквозной автоотчёт записи»
(`/wiki#summary-report`).

**Тема отчёта** — светлая (дефолт, для печати) и тёмная (для просмотра) —
живёт в самом HTML (`THEME_CSS`/`THEME_JS` в `services/report.py`, инъекция
через `mne.Report.add_custom_css`/`add_custom_js`): стартовая тема читается
из `?theme=dark`, кнопка в углу документа переключает и синхронизирует URL
(скопированная ссылка открывается с той же темой). Тема — параметр
**отображения**: она не входит в отпечаток кэша и не меняет ETag — один файл
на обе темы, iframe и «Открыть отчёт» тему правок не требуют. Печать
(`Ctrl+P`) **всегда светлая**: блок `@media print` возвращает светлые значения
CSS-переменных `--dl-*` при любой выбранной теме. Ограничение: тепловая карта
— PNG matplotlib со светлым фоном, в тёмной теме показывается светлой
карточкой (осознанно, прозрачный фон — задача на развитие).

## 3.9.2 Состояние и элементы

Стор — `shared/state/summaryReport.ts` (персист только параметров пакета):

| Элемент | Где | Поведение |
|---|---|---|
| «Собрать отчёт» / «Пересобрать» | тулс-хедер | единственный триггер расчёта; выключен без записи и при пустом наборе полос |
| Прогресс + отмена | тулс-хедер | полоса 0…100 % + сообщение этапа (в сообщении полосы пакета виден номер: «θ: Диполи: 12 из 30»); отмена — `DELETE /jobs/{id}` (3.2) |
| «Открыть отчёт» | тулс-хедер | ссылка `html_url?v=…` (новая вкладка), только при результате |
| Сводка-пилюли | рабочая область | QC-вердикт, эпохи «использовано из нарезано», полос пакета, отклонено, чистые данные %, число предупреждений (тултип с текстами) |
| Вкладки вида | рабочая область | **«Документ»** (дефолт), **«Динамика структур»** и **«ROI»** (4.5) — три вида одного результата; переключение только рисует, запросов не делает (часть 3, §3.9.6) |
| iframe | рабочая область | документ MNE.Report (вид «Документ») |
| «Динамика структур» | рабочая область | выбор полосы (`SelectField inline`), пилюли чисел полосы (эпохи/точки/без атрибуции/GOF/RIV), таймлайн топ-структур (5 бинов с поперечными барами), таблицы топов структур/BA, кнопка «Скачать CSV» (клиентский экспорт, `shared/lib/summaryExport.ts`), предупреждения полосы |
| «ROI» | рабочая область | агрегат `result.roi` (серверный `services/roi.py`, те же точки пакета, что в `dipole_points`): выбор полосы, таблицы «структуры/поля БА × полоса» (точек, доля %, **GOF ≥ порога — внутри полосы**, медианный GOF, медианная КД), пилюли «точек/полушария/без структуры», обязательная подпись принципа 3 (GOF между полосами не сравним), «Скачать CSV» (`roiCsv`); `roi: null` (старый результат) — заглушка «пересоберите отчёт» |
| Панель «Полосы пакета» | справа | чекбоксы всех полос `/meta` (октавные + функциональные); `null` в сторе = «все» (дефолт), первый клик раскрывает в явный список; «Все полосы» возвращает `null`; пустой список → кнопка расчёта выключена |
| Панель «Расчёт» | справа | шаг сетки 2…20 мм; строки-сверка «Длина эпохи/Фильтр/Notch/Референс — из формы EDF»; при событийном режиме EDF — предупреждение |
| Панель «Результат» | справа | справка: файл, QC, эпохи, время расчёта, последняя ошибка |

Состояния рабочей области: **нет записи** (плейсхолдер «загрузите EDF») →
**собирается** (этап + полоса прогресса) → **ошибка** (текст сервера,
`apiErrorText`) → **не собран** (план из двух частей — чем отчёт полезен) →
**результат** (пилюли + iframe).

Результат принадлежит записи: при закрытии/смене записи `SummarySection`
сравнивает `result.recording_id` с текущей и зовёт `reset()` (он же сдвигает
токен поллинга — ответ старой записи не мигнёт в UI).

## 3.9.3 Параметры: почему форма EDF, а не своя

Часть 1 обязана совпасть с EDF **числами**, поэтому форма задачи — это форма
стадий EDF (`buildPreprocessForm`) + `bands` + `grid_mm`; параметры части 1 на
панели не дублируются, а показываются строками-сверкой. **Режим нарезки —
как в EDF** (3c остатка B9, 04.10.2026): поле `epoch_mode`/`event_id`/окна
форма носит целиком, часть 1 пересказывает событийную нарезку какой бы она ни
была, а панель подписывает разницу с пакетом (штриховка вьюера и отчёт больше
не разъезжаются молча). **Пакет диполей (часть 2) остаётся на `fixed`** —
событийные диполи отдельная задача (`docs/rules/events.md` п.8), и это
подписано в контроле №3 и в секции «Как читать часть 2» самого HTML.
Очистка и пороги входят в отпечаток кэша HTML (`report_signature` считается от
`repr(PreprocessParams)` целиком) — отменённая зона, иной порог **или иной
режим нарезки** = другой файл.

## 3.9.4 Что заметили при сборке: кросс-проверки сквозного пайплайна

Сборка отчёта — первый взгляд на пайплайн «одним глазом»: очередь кросс-проверок,
которые просились сами (комментарий среза 01.10.2026). **Реализовано 02.10.2026**
(`services/report.py::_cross_checks` + `_edf_stage_match` + `_part1_html` +
`_fingerprint_html`; пороги — `core/config.py`: `report_epoch_drop_warn_share`
0.3, `report_no_attribution_warn_share` 0.2, `report_top_share_max` 0.95,
`report_epochs_mismatch_warn_share` 0.05):

1. **Сверка отчёта с последней стадией EDF** ✅ — файлы задач хранят
   `meta.params_sig` (`submit_recording_job`); отчёт ищет последнюю стадию
   «Артефакты» с тем же отпечатком и сверяет `good_data_percent` + счётчики
   видов. Расхождение → предупреждение; стадии нет → строка «не выполнялась»
   без warn (нечего сверять — не ошибка).
2. **Доля выживших эпох как вердикт** ✅ — >30 % отброшенных → **первая строка
   документа** («ВЕРДИКТ: отброшено N% …») + предупреждение результата.
3. **Согласованность нарезки частей** ✅ — числа «часть 1 ↔ каждая полоса» в
   шапке всегда; >5 % расхождения → предупреждение. Живой замер 02.10.2026
   вскрыл реальное расхождение (часть 1 — 66 эпох, пакет — 128: у пакета своя
   нарезка) — проверка сделала то, для чего задумана.
4. **Доля точек без атрибуции** ✅ — >20 % в любой полосе → предупреждение.
5. **Кросс-полосной аутlier структуры** ✅ — топ-структура с долей >95 % эпох
   своей полосы → предупреждение («привязка к одному узлу сетки»).
6. **Notch до/после в одном отчёте** ✅ — L1 (`clean.loss.line_noise`) в части 1
   числом «было → стало» по линиям (строки появляются, когда очистка включена —
   иначе отчёта очистки нет, честного «—» недостаточно).
7. **Паспорт сырого файла шире QC** ✅ — единицы EDF (включая авто-масштаб),
   каналы вне монтажа 10-20, «верхняя граница пакета / Nyquist» в паспорте +
   предупреждение, если полоса пакета выше Nyquist записи (γ-high требует
   sfreq ≥ 256 Гц).
8. **Повторяемость прогона** ✅ — `<details>` «Полный отпечаток параметров» в
   шапке: `report_signature`, версия формата HTML, полосы, сетка, все поля
   `preprocess`, Python/MNE — два HTML сверяются парами.

Формат HTML закреплён `REPORT_HTML_VERSION` (входит в `report_signature`):
смена разметки отправляет старые файлы кэша в невалидность (урок A7).

## 3.9.8 Отчёты группового анализа (Тип 1 и Тип 2)

> Срез «2 отчёта групповых анализов» (октябрь 2026): сервис
> `backend/app/services/group_reports.py`, контракт `ReportHtmlOut`
> (`schemas/analysis.py`), роуты №56–59 (`docs/rules/api-jobs.md`), вкладки
> `SummarySection`/`SummaryPanel`/`SummaryToolActions`. Пользовательское
> описание (подготовка, секции документа, чтение) — статьи Wiki
> «Итоги: отчёт по сравнению (Тип 1)» (`/wiki#summary-compare-report`) и
> «Итоги: отчёт по группе (Тип 2)» (`/wiki#summary-group-report`).

**«Итоги» — зритель всех трёх отчётов.** Переключатель **«Отчёт»** в шапке
рабочей области: **Запись** (автоотчёт, задача `kind=report`), **Сравнение
(Тип 1)** и **Группа (Тип 2)**. Групповые виды **не требуют открытой записи**:
их источник — готовый результат (задача `kind=compare` / сохранённый прогон
`group_analyses`), а сборка — один ленивый запрос без задачи и поллинга
(прецедент «промах кэша карты разности»).

Что именно в документах (оба — самодостаточный `mne.Report` в той же теме,
что автоотчёт: `THEME_CSS`/`THEME_JS`, `?theme=dark`, печать всегда светлая):

1. **Тип 1 «Сравнение»** — результат задачи `kind=compare` целиком: паспорт
   пары и совпадение параметров (B9), таблица дельт по полосам (Δ мкВ²/дБ,
   95% bootstrap-ИИ, p, q FDR, число FDR-каналов), ряды PSD/дельты с заливкой
   значимых кластеров (matplotlib), карты разности B−A (PNG в base64 из кэша;
   промах — `<img>` по URL с ленивым пересчётом пары), кластерный тест,
   индексы (IAF/θ/β) и 1/f, обязательные `notes`/`warnings` без правок.
2. **Тип 2 «Группа»** — прогон `group_analyses` + **свежий пересчёт**
   агрегата: паспорт прогона и фильтры, участники (взятый прогон, точки),
   подписи «как читать» (оба знаменателя share, GOF внутри полосы), таблицы
   структур/полей с ячейками «доля (число)» по записям, тепловые карты
   «строка × запись» (matplotlib), кластеры B8 с паспортом сетки
   (`cluster_params`, устойчивость `session_share`), предупреждения.

**Сборка и кэш.** `GET …/report` (метаданные) и `GET …/report/html` (ассет с
ETag/304) вызывают один и тот же `ensure_*_report`: отпечаток
`sig = sha256(версия формата + стабильный payload)` — имя файла в
`data/cache/reports/{compare|group}/{source_id}/{sig}.html`; метрики
`duration_sec_calc` из отпечатка исключены (иначе каждый пересчёт менял бы
ETag, а 304 не совпадал бы сам с собой). На источник — **один** отпечаток:
старый файл убирается при сборке. Изменились числа источника (у группы —
свежий пересчёт по живой БД) → новый отпечаток → документ собирается заново.
Замер сборки/чтения уходит в журнал шагов (`kind=report`, step
`compare_report`/`group_report`, `cache_hit`).

**Жизненный цикл кэша** (`services/orphans.py`): `reports/compare|group` —
не `recording_id`, обход сирот записей их щадит (`RESERVED_REPORT_SUBDIRS`);
отчёт сравнения сиротеет вместе с выходом задачи из истории
(`_sweep_compare_reports`, после `prune_records`), отчёту прогона сирота не
грозит — строки `group_analyses` не удаляются (§8.4.2).

**UI.** Панель — «Источник отчёта» (завершённые задачи `kind=compare` из
`GET /jobs` / прогоны из `GET /group/analyses`) + справка «Результат»;
**правка источника ничего не считает и убирает прежний документ** (результат
принадлежит выбранному источнику), сборка — только кнопка «Собрать отчёт» в
тулс-хедере (состояние «Собираем…» вместо полосы прогресса — запрос один),
результат — пилюля с заголовком документа + iframe `html_url?v=report_version`
+ ссылка «Открыть отчёт».
