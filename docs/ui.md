## 1. Принципы и ограничения

| Принцип | Реализация |
|---|---|
| Только десктоп, без мобильного адаптива | `min-width: 1366px` на `body`, `height: 100vh`, скролл только внутри рабочих областей |
| Тёмная тема | Токены Tailwind v4 в `frontend/src/styles/index.css` (`--color-bg-*`, `--color-fg-*`, `--color-accent`) |
| Крупный шрифт, системный для ОС | `system-ui, -apple-system, "Segoe UI", Roboto, Ubuntu…`; базовый кегль 16/18/20 px (переключатель в «Настройках»), цифры — `tabular-nums` |
| Крупные иконочные кнопки с тултипами | `IconButton` + Radix `Tooltip` (задержка 300 мс, доступ по фокусу с клавиатуры, есть `aria-label`) |
| Три зоны | Левый рейл 72 px (навигация) · центр: тулс-хедер + рабочая область + статусбар · правый сайдбар 384 px (схлопывается в 48 px) |
| Хоткеи | `1…5` — разделы, `[` — панель опций; обработчик игнорирует ввод в полях |
| **Обработка — только по кнопке** | Правка параметра никогда не запускает расчёт: параметры складываются в состояние раздела, кнопка действия становится доступной, UI показывает «параметры изменены — результат не пересчитан». Расчёт стартует исключительно по нажатию кнопки: сначала параметры и визуализация, обработка подключается к уже готовому UI |
| Долгие операции | Только через job-API (`POST /api/v1/jobs`), прогресс по этапам, индикатор активных задач в рейле; перед запуском дорогой операции показывается оценка стоимости |

## 3. Разделы подробно (целевой функционал)

### 3.1 Главная
- Заставка: 🧠 + `DipLock` + подзаголовок «Анализ ЭЭГ и расчёт токовых диполей в 3D».
- Строка готовности: «все компоненты готовы» / «часть компонентов не готова» / «сервер недоступен».
- Быстрые действия: «Открыть EDF», «Состояние сервера».
- Футер: версия приложения, версия MNE, драйвер БД (из `/api/v1/meta`).

### 3.2 EDF — просмотр записи и подготовка

**Тулс-хедер раздела (срез 2.4, готов).** Шапка рабочей области — основной пульт
раздела; все действия только по нажатию (ни одно не делает запросов «заранее»):

| Элемент | Что делает | Состояние |
|---|---|---|
| Кнопка-иконка «Загрузить EDF» | Открывает диалог выбора файла (тот же input, что у зоны загрузки); активна подсветка, если запись уже есть | включена; выключена во время загрузки |
| Кнопки-иконки перерасчёта: «Фильтр и референс» / «Поиск артефактов» / «Нарезка эпох» | Раздельные действия по стадиям: пересчёт фильтра не обесценивает найденные артефакты. Точка-индикатор на кнопке: серая — стадия не считалась, жёлтая — параметры изменились, красная — ошибка задачи. Результат стадии заменяет её слой в треках (зоны/штриховка) | активны при загруженной записи (срез 2.7): кнопка ставит задачу `POST …/preprocess` и показывает прогресс; тултип объясняет стадию и причину |
| Прогресс-бар готовности перерасчётов | Три сегмента по стадиям (готово / устарело / не считалось) + подпись «Готовность: k из 3» | появляется, когда есть запись или демо-сигнал |
| Кнопка-иконка «Паспорт» | Диалог просмотра/правки метаданных сессии (название, испытуемый, дата, заметки, единицы для БД). Здесь же — **единственное место**, где видны факты о файле (имя, каналы, «каналов 10-20», `sfreq`, длина сессии, единицы) и предупреждения загрузки | выключена без загруженной записи |
| Кнопка-иконка «Закрыть запись» | Закрывает запись (уборка выбора каналов и паспорта), возвращает зону загрузки. Локальное действие — запросов нет | выключена без загруженной записи |
| Кнопки-иконки листания окна: `<<` `<` `>` `>>` | В начало записи, на окно назад, на окно вперёд, в конец записи. Команда уходит во вьюер через состояние (`requestNav`), окно не пересчитывается сервером | выключены при ×1 (в окне вся запись — листать нечего) |
| Комбо-бокс зума | Дискретные уровни ×1 … ×16 (×1 — вся сессия); дублирует колесо мыши и контрол панели, окружён кнопками листания | всегда доступен |

**Паспорт сессии.** «Паспорт» — это данные для БД (таблица `sessions`), а не для
EDF-файла: правка не перезаписывает исходник и не делает запросов, значения живут в
состоянии раздела и уйдут в БД при запуске анализа. Панель «Запись» и карточка записи в
рабочей области убраны (срез 2.9): факты о файле (имя, каналы, `sfreq`, длина сессии,
«каналов 10-20»), предупреждения и поле «Единицы в БД» показываются только в диалоге —
черновик полей записывается в состояние по кнопке «Сохранить».

**Загрузка.** Drag & drop / диалог (кнопка в шапке или в зоне загрузки), прогресс
по чанкам, лимит 200 МБ, проверка суффикса `.edf` до отправки (на бэкенде имя
санитизируется: отбрасывается путь, `../`, небезопасные символы).
Загрузка **не запускает обработку** и возвращает только паспорт записи
(`POST /api/v1/recordings`): файл сохраняется как есть, пользователь сначала видит
сырой сигнал и уже потом решает, нужна ли обработка артефактов и шума.
«Закрыть запись» (кнопка в шапке) убирает запись вместе с выбором каналов и паспортом.

**Мультитрек.** 18+ треков в порядке 10-20 на `<canvas>`: общая ось времени, курсор с временем
(ставится кликом, живёт до следующего клика — мышь его не таскает), шкала мкВ, режимы
«общий масштаб» / «авто по каналу», **клик по названию канала разворачивает трек на всю высоту
видимой области** (повторный — сворачивает; соседи не скрываются, уезжают в скролл),
неотключаемый вертикальный скроллбар (`.scroll-y-always`, срез 2.9; ширина полосы — 20 px,
срез 2.11: узкую «тонкую» полосу трудно хватать мышью) — ползунок показывает долю
окна в записи при большом числе каналов. **Оверлеи живут в прокручиваемом контенте** (срез 2.11):
линия курсора тянется на весь стек треков и прокручивается вместе с ним, а подпись времени и
карточка выделенной зоны «липнут» к верху области (`sticky`) — при скролле вниз они остаются
на месте. Каркас держит рабочую область ровно в высоте окна
(строка grid `minmax(0,1fr)` в `AppShell`, срез 2.10): иначе неявная строка растягивалась под
содержимое, треки уходили за экран и внутренние скроллы не появлялись вовсе. Срез 2.5 подключил
к вьюеру реальные сигналы записи
(`GET …/signals?level=`): уровень зума — индекс в `TIME_LEVELS`, кадры кэшируются в сторе записи,
пока нужный уровень грузится — показывается ближайший загруженный, поэтому переключение зума не
мигает пустотой. Демо-сигнал (`shared/lib/demoSignal.ts`, синтетика с «артефактными» всплесками)
остался кнопкой в зоне загрузки — отладка вьюера без сервера.

**Зум (дискретный, без дробного).** Уровни **x1 / x2 / x4 / x8 / x16** по оси времени, дефолт —
вся сессия; комбо-бокс в шапке, колесо мыши переключает уровни, drag — панорамирование.
Индикатор «Зум треков ×N» в статусбаре раздела. Хоткея «вся сессия» (`F`) пока нет — он в плане
§9 вместе с `+/-` и `Space`. Глубже x16 — окно полного разрешения по запросу.

**Навигация по окну (срез 2.9).** Кнопки `<<` `<` `>` `>>` вокруг комбо-бокса листают окно:
`<`/`>` — на ширину текущего окна, `<<`/`>>` — в начало и в конец записи. Центр окна — локальное
состояние вьюера, поэтому команда идёт не напрямую, а через стор записи (`navRequest` с монотонным
`seq` — тот же приём, что у запроса диалога файла). Обрабатывается только новая команда: при
повторном монтировании вьюера старая не применяется. Навигация — чистая перерисовка, запросов нет;
при ×1 кнопки выключены.

**Артефакты и эпохи.** Цветные зоны (4 типа: `zscore_outlier`, `peak_to_peak`, `flat_line`, `ica_eog`),
легенда с чекбоксами в правой панели, клик по зоне → панель деталей (тип, onset, длительность, каналы);
вертикальные маркеры границ эпох с номерами; отброшенные reject-фильтром эпохи — штриховка.
Срез 2.6 реализовал слои **на детерминированной фикстуре** (`shared/lib/viewerLayers.ts`):
пока стадии `artifacts`/`epochs` не подключены к серверу, зоны и вердикты эпох берутся из
генератора по сиду (одинаковы между перерисовками) и помечены в шапке вьюера статусом
«слои: демо-фикстура». Слои — чистый DOM поверх canvas-треков (`viewer/TrackLayers.tsx`):
позиции пересчитываются из окна (`timeToX`/`xToTime`), поэтому зум и панорамирование не
перерисовывают canvas, а зона остаётся кнопкой с `aria-pressed` и тултипом. Сетка эпох
(`buildEpochCells`) считается из длины эпохи: **у результата расчёта — из его собственной нарезки**
(`epoch_length_ms` стадии «эпохи», срез 2.10), до расчёта и у демо-фикстуры — из параметра панели.
Индексы отброшенных эпох имеют смысл только внутри своей сетки: пока разметка считается по
результату, смена длины эпохи в панели не «переезжает» штриховкой на другой участок записи, а
показывает в полосе вьюера пилюлю «разметка эпох: N мс» (стадия помечена устаревшей — пересчёт
по кнопке «Нарезка эпох» разложит эпохи заново).

**Ручные пометки эпох (срез 2.10).** Ctrl+двойной клик по треку переключает блокировку эпохи,
в таймлайн которой попала точка клика: так снимается штриховка алгоритма (`manual: 'allowed'`) и
ставится своя (`manual: 'blocked'`). Пометка хранится **интервалом на таймлайне**, а не индексом
эпохи, поэтому переживает смену длины эпохи и видна даже при выключенной штриховке: своя
блокировка — акцентной штриховкой с красной границей, снятая — пунктирным контуром. Правки живут
при записи (стор `edfRecording.epochMarks`, не в localStorage), считаются в полосе вьюера
(«ручных пометок: N») и снимаются кнопкой «Снять» в панели «Эпохи». Счётчик считает **пометки**
(правки пользователя, срез 2.11), а не ячейки сетки — так же, как панель «Эпохи»: после смены длины
эпохи одна пометка накрывает несколько эпох новой нарезки, но остаётся одной видимой пометкой, и
«ручных пометок: 3» не превращается в «6».

Легенда над треками и чекбоксы панели делят одно состояние (`artifactVisibility`),
цвет метки — токен темы `--color-artifact-*` (продублирован и в панели через `swatch`).

**Предподготовка (правая панель).** Панель = инвентарь параметров записи (срез 2.1, готов):
все контролы складывают выбор в состояние раздела и **не запускают расчёт**. Значения по умолчанию
приходят из `/api/v1/meta`, то есть из `backend/.env`; кнопка «К значениям сервера» возвращает их.
Запуск перерасчёта живёт в тулс-хедере (три раздельные кнопки), панель показывает состояние стадий
и сводку готовности. Блока «Запись» в панели больше нет (срез 2.9): факты о файле,
предупреждения и «Единицы в БД» показываются **только** в диалоге паспорта в шапке.

| Блок | Контролы | Источник дефолта | Кто применяет |
|---|---|---|---|
| Фильтры и референс | пресет полосы (1–40 / 0.5–70 / без / свой), границы «свой диапазон», notch 0/50/60 Гц, режим референса (средний / по каналам) | `freq_bands` | стадия «Фильтр и референс» (срез 2.7, готово) |
| Пороги артефактов | z-score, peak-to-peak (мкВ), flat-line (мкВ), длительность плоского участка (мс) | `artifact_thresholds` | стадия «Поиск артефактов» (срез 2.7, готово) |
| Эпохи | длина эпохи (список `epoch_lengths_ms`), тумблеры «Маркеры границ эпох» и «Штриховка отброшенных эпох», счётчик ручных пометок и «Снять» (срез 2.10) | `epoch_lengths_ms` | стадия «Нарезка эпох» (срез 2.7, готово) + отрисовка во вьюере |
| Каналы | чекбоксы каналов записи, «Все» / «Ничего» | монтаж 10-20 | вьюер треков + стадия фильтра (при референсе «по каналам») |
| Отображение | шкала амплитуды (общая / авто по каналу) + мкВ/дел, масштаб времени ×1…×16 | локальные дефолты | вьюер треков (срез 2.3); зум дублируется комбо-боксом в шапке |
| Единицы EDF | селект «авто / мВ / мкВ» — переопределение авто-детекта масштаба | авто-детект единиц файла | стадия «Фильтр и референс» (иначе пайплайн читает «вольты») |
| Легенда артефактов | видимость 4 типов зон: чекбоксы панели и чипы легенды над треками (общее состояние) | локальные дефолты | вьюер треков (срез 2.6, готов) |
| Запуск | статус («не рассчитан» / «результат неполный: k из 3» / «параметры изменены» / «актуален»), сводка по стадиям, ошибки упавших стадий, «К значениям сервера» | — | кнопки стадий — в тулс-хедере (срез 2.7, готово) |

**Стадии перерасчёта.** Одна стадия = один набор параметров и один снимок результата;
правка параметра помечает устаревшей только свою стадию. Параметры отрисовки
(зум, шкала мкВ, видимость зон) расчёт не устаревают вовсе.

| Стадия | Параметры | Слот результата в UI |
|---|---|---|
| `filter` | пресет полосы, свой диапазон, notch, референс, единицы EDF, выбранные каналы | параметры фильтра зафиксированы (срез 2.7): `band_hz`/`notch_hz`/`reference` в результате стадии; треки пока показывают «сырой» сигнал — переход на filtered-пирамиду отдельным срезом |
| `artifacts` | z-score, peak-to-peak, flat-line, длительность плоского участка | зоны артефактов и легенда (срез 2.6 + реальный результат 2.7) |
| `epochs` | длина эпохи | маркеры границ, штриховка отброшенных (срез 2.6 + индексы отброшенных из результата 2.7); сетка строится по длине нарезки результата, ручные правки эпох (Ctrl+двойной клик) — срез 2.10 |

**Экспорт.** PNG-снапшот окна (треки + подписи каналов, шкала времени, зоны артефактов,
сетка эпох, легенда) и CSV окна записи: строка на пару «временная корзина × канал» с
`min_uv`/`max_uv` — ровно то, что видно в окне (срез 2.8). Экспорт **клиентский**: данные уже в
браузере, сервер не пересчитывает экран. Кнопки — в полосе окна вьюера, рядом со шкалой времени.

### 3.3 Диполи — расчёт и 3 проекции
- Форма фильтров: δ/θ/α/β/γ, custom-диапазон, одиночная частота (например 7.83 Гц, bw 0.5 Гц).
- Запуск задачи с прогрессом по этапам (чтение → артефакты → фильтр → эпохи → PSD → диполи → локализация).
- Три проекции: axial (top), sagittal (side L/R), coronal (front) + 3D-меш fsaverage (GLB, кэш).
- Timeline-playback: play/pause, скорость, покадрово, синхронизация трёх проекций — **срез 3.7**.
- График GOF по времени, выбор эпохи, фильтр «GOF ≥ X», подсветка поля Бродмана/ROI, сравнение эпох.

**Срез 3.1 (готово):** три проекции — SVG-фигуры (`app/sections/dipoles/MriProjection.tsx`) с четырьмя
включаемыми слоями: силуэт головы на срезе, схема среза MNI с координатной сеткой и следами соседних
срезов, поля Бродмана и (пока пустой) слой точек диполей с векторами моментов. Срез наводится кликом
по фигуре (с прилипанием к `x = 0` / `y = 0` / `z = 0`) и линейкой панели; клик наводит **все три**
среза на выбранную точку. Геометрия — `shared/lib/mriProjections.ts`, состояние —
`shared/state/dipoleParams.ts`, фикстуры слоёв детерминированы (без ГПСЧ). Расчёт, форма фильтров и
playback — следующие срезы; слой диполей пуст по замыслу (панель пишет «расчёт не подключён»).

**Срез 3.2 (готово):** в проекции добавлен **реальный срез томографии**. Бэкенд читает
`fsaverage/mri/T1.mgz` + `brainmask.mgz`, приводит их к MNI-сетке 1 мм (`fsaverage` совмещён с
MNI305: `talairach.xfm` — единичная матрица), кэширует том на диске и отдаёт срез PNG (серый +
альфа: вне мозга прозрачно) с ETag/304 — `app/services/mri_slices.py`, `GET /surface/mri` (границы,
шаг, плоскости, окно яркости) и `GET /surface/mri/slice/{plane}/{mm}.png`. UI рисует его как SVG
`<image>` в слое `mri` (включён по умолчанию), ссылку с версией ассета собирает
`shared/lib/mriSlices.ts`; пока срез включён, условная схема среза не рисуется — настоящая анатомия
вместо фикстуры. Срез квантуется сеткой тома (1 мм), поэтому подпись среза может отличаться от
картинки на полшага; фактические значения хранит заголовок `X-Mri-Slice-Mm`. Границы тома =
bounding box маски мозга (с мозжечком и стволом) — они же и границы проекций (`MNI_BRAIN_BOUNDS`).
Том fsaverage лежит в коронарной укладке (`L, I, A`): узлы сетки берутся уравнением **своей оси
вокселей**, иначе оси y и z меняются местами и срез показывает чужую анатомию (пиксельная сверка с
`nibabel.resample_from_to` — в тестах). Полушария подписаны по RAS (x > 0 — правое), а горизонталь
аксиальной и коронарной проекций развёрнута знаками: слева на экране правое полушарие (R) —
радиологическая раскладка, как в просмотрщиках срезов.

**Срез 3.4 (готово):** раздел считает результат и спектр. Тулс-хедер: кнопка «Рассчитать диполи»
(`POST /recordings/{id}/dipoles`), прогресс по этапам и **эпохам** (`epochs_done`/`epochs_total`),
поле порога «КД ≥ X нАм» и две кнопки выдвижной панели. Расчёт — **быстрый режим** (`method:
fast_grid`, `app/services/dipole_scanner.py`): одна точка на эпоху в пике GFP и перебор узлов
объёмной сетки (~7 мм, шаг настраивается) на сферической модели головы — без BEM и
`mne.fit_dipole`; ошибка позиции порядка шага сетки, и это видно в UI («Быстрый режим, сетка N мм»).
Замер на живой записи (`data/edf/test.edf`: 130.7 с, 500 Гц, 18 каналов, нарезка 500 мс → 261 эпоха,
все точки с MNI): шаг **7 мм — 2.2 с, 4 мм — 11.8 с, 2 мм — 99.8 с** (диапазон 2–20 мм, по умолчанию
7). Число узлов сетки растёт как шаг⁻³, поэтому шаг — главный рычаг скорости.
Спектр — отдельная задача (`app/services/spectral.py`): Welch PSD по эпохам и топокарты ритмов
δ…γ, которые сервер отдаёт готовыми PNG (`GET …/spectrum/topomap/{band}.png`, ETag/304, вне круга
скальпа прозрачно). Выдвижная панель (`drawer` у `AppShell`) показывает топокарты или
FFT-гистограмму (полосы по диапазонам + логарифмическая PSD) и запускает спектр своей кнопкой.
Порог «КД» — параметр **отображения**: он скрывает слабые диполи на проекциях (со счётчиком
скрытых), не меняя результат задачи. Точки без MNI (fsaverage недоступен) в слой не попадают —
раздел сообщает об этом предупреждением. Состояние расчёта — `shared/state/dipoleCalc.ts`,
чистая арифметика — `shared/lib/spectrum.ts` и `shared/lib/dipolePoints.ts`. Playback траектории и
точный профиль (`mne.fit_dipole` на BEM) — следующие срезы.

**Срез 3.5 (готово):** доработки по итогам просмотра результата. Позиции диполей и векторы их
моментов — **раздельные слои** панели («где» и «куда» отвечают на разные вопросы, а при плотном
облаке точек лучи мешают читать позиции; выключение позиций не выключает лучи). Позиция диполя —
**белое кольцо фиксированного экранного размера** (Ø 10 px, штрих 2 px при любом размере окна: фигура
SVG растягивается по ширине колонки, поэтому пиксели кольца делятся на масштаб
`renderedWidth / viewBox.width`; поправка ручной проверки), выделенный диполь залит оранжево-жёлтым.
Сила момента видна по **лучу** (`dipoleRayVisual`: плотность 0.35→1 со шкалой, насыщающейся на
100 нАм, иначе одиночный выброс «придавил» бы остальные; толщина у всех лучей одна —
`DIPOLE_RAY_STROKE_PX` = 2 px), наконечник стрелки считается от длины луча полигоном: один
`<marker>` на проекцию накрывал бы короткий луч целиком. Клик по точке **выделяет диполь** во всех
трёх проекциях **и наводит срезы на его позицию** (поправка ручной проверки: срезы меняются при любом
клике по фигуре; всплытие гасится лишь от двойной обработки — хит-зона шире кольца); повторный клик
или кнопка «Снять выделение» снимают выбор, а подпись выбора показывает эпоху, MNI, поле, момент и
GOF. Бегающего за мышью маркера на фигуре нет: координаты под курсором показываются текстом в строке
под фигурой.
Геометрия эллипсов полей Бродмана вынесена в одну функцию (`ellipsePx`) и зафиксирована тестом на
согласие с хит-тестом: подсветка поля не может «разъехаться» с тем, что нарисовано. FFT-гистограмма
получила **интерактивное окно частот**: кнопки ритмов, поля «от/до» и «Весь диапазон» сужают график
без единого запроса (числа PSD уже в браузере), полосы вне окна приглушаются, но остаются на месте,
а логарифмический масштаб берётся по всему спектру — иначе при сужении окна пики «подтягивались» бы
к максимуму внутри окна и сравнение с полным спектром стало бы ложным.

**Срез 3.6 (готово):** у расчёта появилась **форма фильтров**. Список «Фильтр расчёта» в панели
собирается из метаданных сервера: пресеты δ…γ берут границы из `/meta` (`freq_bands`), рядом «1–40 Гц
(широкий)», «Одиночная частота», «Свой диапазон» и «Без фильтра», плюс селект сетевого фильтра
(выключен / 50 / 60 Гц). Одиночная частота — это узкая полоса `f ± bw/2` (по умолчанию 7.83 Гц и
0.5 Гц, как в предподготовке записи): отдельного поля у задач расчёта нет, поэтому форма отправляет
честную пару `band_min`/`band_max`, а не выдаёт узкую полосу за «частоту». Поля «своего диапазона»
не прячутся, когда набранные числа совпали с пресетом (иначе ввести полосу 1–40 Гц было бы нельзя):
пресет — это выбор пользователя, а полоса — то, что уходит в задачу, и они хранятся синхронно
(`shared/lib/calcFilter.ts`). Итоговая подпись печатает **полосу из состояния** («В расчёт уйдёт:
α — альфа 8–13 Гц · сетевой фильтр 50 Гц»), поэтому после смены конфига сервера она покажет
фактические границы, а не название ритма со старыми числами. Правка формы, как и раньше, **ничего не
запускает**: результат помечается устаревшим («параметры расчёта изменены — результат не пересчитан»),
а пересчёт — кнопкой; сохранённые параметры прежней версии UI поднимаются с выводом пресета из полосы.
Контракт задач с полосой зафиксирован на бэкенде (`tests/test_filter_band_jobs.py`): сервер считает по
присланным `band_min`/`band_max`/`notch_hz`, возвращает их эхом результата (по этому эху UI и строит URL
топокарт, и сверяет актуальность), а мощности диапазонов вне полосы остаются «остатками фильтра», а не
подменяются нулём или `null`.

**Срез 3.7 (готово):** появилось **воспроизведение траектории**. Тулс-хедер получил кластер кадра:
play/pause, покадрово `‹`/`›`, скорость ×1/×2/×4, снятие кадра и подпись «Кадр: эпоха N из M · t с · ×N»
(плюс хоткей `Space` в разделе). Кадр идёт по **сетке эпох результата**: время сессии непрерывно,
эпоха — `floor(t / epoch_length_ms)`, длительность — `n_epochs_total × epoch_length_ms`, поэтому ×1 — это
реальное время записи (на `test.edf` 261 эпоха по 500 мс ≈ 130 с, ×4 — около 33 с). Внутри эпохи кадр
**интерполируется** между её точкой и точкой следующей эпохи: позиция — по прямой, направление момента —
по дуге (slerp), амплитуда — линейно, чтобы длина и плотность луча менялись плавно. Это **отображение, а
не измерение**: промежуточных положений в результате задачи нет, поэтому интерполяция идёт только между
соседними эпохами с точками (у отброшенной эпохи кадр пуст — «протягивать» диполь через дыру в данных
нельзя), а на паузе и при покадровом шаге кадр равен измеренной точке своей эпохи. Кадр отмечается
**гало** (второе кольцо акцентным цветом) при неизменном размере кольца позиции, облако точек
приглушается, а выделенный кликом диполь — нет: это осознанный выбор пользователя. За кадром тянется
**затухающий шлейф** — отрезки между измеренными точками соседних эпох за последние 10 секунд сессии
(окно во времени, а не в числе эпох), гаснущие от кадра к хвосту; через разрыв (эпоху без диполя) шлейф
не тянется, число отрезков ограничено, а рисуется он в слое позиций и под маркером. Порог «КД ≥ X нАм»
действует и на кадр, и на шлейф (отрезок не рисуется, если слабее порога любой из его концов), но
воспроизведение не останавливает. Конец записи —
стоп на последней эпохе, play с последней эпохи начинает запись сначала; уход из раздела останавливает
часы, но кадр остаётся. Внутри: состояние команд живёт в `shared/state/dipoleCalc.ts` (`playback`:
играет/пауза, скорость, эпоха, `seekSeq` — как `navRequest.seq` в EDF), непрерывное время — в часах
раздела (`app/sections/dipoles/playbackClock.ts`), а маркер получает кадр контекстом: 60 кадров в
секунду обновляют только его, а срез, поля и облако из сотен точек не перерисовываются
(`dipoles/PlaybackFrame.test.tsx` это фиксирует).

### 3.4 Таблица локализации
**Срез 4 (готово):** раздел `/table` показывает **все точки расчёта диполей** текущей записи:
семантическая `<table>` со «липкой» шапкой, колонки — эпоха (нумерация с 1, как в подсказках
проекций), пик GFP внутри эпохи (с), MNI x/y/z, полушарие, амплитуда момента (нАм), GOF (%),
поле Бродмана. Строки — все точки результата, включая те, что без MNI (там «—»): «все результаты»
это все, а не «те, что удалось навести», а причина приходит предупреждением задачи. Сортировка —
по номеру эпохи (направление — сегментный переключатель панели), состав колонок — чекбоксами;
настройки живут в `shared/state/tableParams.ts` и правятся **без единого запроса** (раздел не
запускает расчёт: из запросов у него нет ни одного). Если параметры расчёта в разделе «Диполи»
изменили после расчёта, таблица предупреждает «параметры изменены — результат не пересчитан»
(отпечаток `calcSignature`/`resultSignature`), а не выдаёт старые числа за посчитанные на новых
настройках. Порог «КД ≥ X нАм» на таблицу не влияет — он параметр отображения проекций, и это
сказано подписью.
Дальше (следующий срез): фильтры (GOF, амплитуда, BA/ROI), поиск, виртуализация (TanStack
Table + Virtual), клик по строке → фокус на диполе в разделе «Диполи», экспорт выборки в CSV/JSON,
сохранение выборки в БД. Колонки ROI пока нет: в результате быстрого расчёта есть только поле
Бродмана — пустая колонка «ROI» читалась бы как «не определено», хотя ROI просто не считали.

### 3.5 Групповой анализ
Список сессий из БД с параметрами анализа каждой записи; групповые фильтры (диапазон, длина эпохи,
GOF, BA/ROI, файл, дата); агрегаты (число диполей, средняя/стд амплитуда, средний GOF по BA);
тепловая карта «BA × сессии»; экспорт сводки. Требует read-API и наполнения БД (Фаза 5).

### 3.6 Настройки
Масштаб текста (16/18/20 px), плотность списков, сброс раскладки разделов; таблица параметров
расчёта и путей — **только чтение**: источник истины `backend/.env`, дублирование настроек в UI
привело бы к конфликту конфигураций.

### 3.7 Состояние сервера
Проверки `/init-status`: MNE, конфигурация, БД, fsaverage, transform, BEM; версии
(Python/MNE/numpy/scipy/SQLAlchemy/trimesh), пути (`subjects_dir`, `trans`, `upload_dir`,
`results_dir`, `cache_dir`), параметры расчёта и API, признак сборки UI. Кнопка «Проверить сейчас»
+ поллинг 5 с — **только при открытой вкладке** (react-query не опрашивает сервер в фоне).


## 4. Технологический стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite 6 + TypeScript (strict) | HMR, code-splitting по разделам, `base: '/ui/'` — один базис для dev и prod |
| UI | React 19 | 7 разделов с общим состоянием, таблицы, 3D, playback: на Vanilla это не масштабируется |
| Стили | Tailwind CSS v4 + токены темы | тёмная тема через `@theme`, отдельная CSS-система не нужна. Утилита `.scroll-y-always` (срез 2.9) даёт **неотключаемый** вертикальный скроллбар с нативным пропорциональным ползунком: в вьюере ползунок показывает долю окна в записи, в панели опций полоса не «дёргается» между разделами |
| Примитивы | Radix UI (`@radix-ui/react-tooltip`) | тултипы с корректным a11y и клавиатурным доступом |
| Иконки | lucide-react | единый стиль, tree-shaking |
| Состояние | zustand (+`persist`) | UI-настройки, раскрытие панелей, счётчик задач (localStorage) |
| Серверные данные | TanStack Query | кэш, ретраи, поллинг задач, отсутствие фонового опроса скрытой вкладки |
| ЭЭГ-треки (Фаза 2) | uPlot | canvas, ~40 КБ, десятки тысяч точек на трек, draw-хуки для зон артефактов |
| 3D (Фаза 3) | react-three-fiber + drei | 3 проекции, playback, подсветка BA |
| Таблицы (Фаза 4) | TanStack Table + Virtual | тысячи строк без просадок |
| Тесты | Vitest + Testing Library | симметрия с pytest; 462 теста UI в 41 файле (Фаза 1 + срезы 2.0–2.11, 3.1–3.7, 4), 152 pytest |

Отклонено: Vanilla + Three.js без сборки (нет типов/состояния/таблиц), Streamlit/NiceGUI (не тянет
интерактивный 3D и playback), общие chart-библиотеки (Recharts/Chart.js) для ЭЭГ — SVG/DOM не держат
десятки тысяч точек на трек при 60 fps.

## 7. Контракт API ↔ UI

Источник истины — Pydantic-схемы `backend/app/schemas/analysis.py`, они попадают в OpenAPI
(`/openapi.json` содержит `AnalyzeResponse`, `DipoleFit`, `JobStatus`, `MetaResponse`, `SurfaceOut`…).
TS-типы в `frontend/src/shared/api/types.ts` пока описаны вручную; следующий шаг — генерация
через `openapi-typescript` (пункт дорожной карты). Каждый ответ типизирован: `response_model`
в FastAPI валидирует данные, поэтому расхождение контракта и реализации падает тестом, а не UI.

| Метод | Назначение | Кто использует |
|---|---|---|
| `POST /api/v1/jobs` | Запуск анализа: 202 + `job_id` | Диполи (Фаза 3), предподготовка EDF (Фаза 2) |
| `GET /api/v1/jobs/{id}` | Этап, прогресс 0..1, ошибка | прогресс-бар, индикатор задач в рейле |
| `GET /api/v1/jobs/{id}/result` | Результат по схеме `AnalyzeResponse` | 3 проекции, таблица локализации |
| `GET /api/v1/jobs` | История задач | «Состояние сервера» |
| `POST /api/v1/analyze` | Синхронный анализ (скрипты/curl) | не UI |
| `GET /api/v1/surface` | Меш fsaverage: ETag, `Cache-Control`, gzip | 3 проекции |
| `GET /api/v1/surface/brodmann` | Индексы вершин всех BA (≈1.8 МБ, кэш на неделю) | интерактивная карта BA |
| `GET /api/v1/surface/brodmann/{ba}` | Одна область (лёгкий ответ) | подсветка ROI |
| `GET /api/v1/brodmann-labels` | Имена меток из кэша | список BA в панели опций |

**Измеренный эффект Фазы 0.** Payload `/analyze` уменьшился на ≈2 МБ (меш больше не вкладывается,
вместо него ссылка `surface: {version, url, brodmann_url}`); `/api/v1/surface` = 0.73 МБ против 2.86 МБ
общего JSON, BA-индексы (1.78 МБ, 82 области) вынесены в отдельный эндпоинт; меш строится один раз и
кэшируется на диске (`data/cache/surface/`), повторная отдача — `0.001 с` вместо ≈1.6 с пересчёта;
повторный запрос с `If-None-Match` получает 304. Также `n_epochs_total` теперь показывает все
нарезанные эпохи, а `n_epochs_dropped` — сколько отбросил reject-фильтр (раньше оба числа совпадали).

## 8. Пирамида зума ЭЭГ (Фаза 2)

Дискретные уровни **x1 / x2 / x4 / x8 / x16** вместо дробного зума: детерминированно, кэшируемо,
предсказуемо по времени. Две поправки, без которых контроль артефактов фиктивен:

1. **Декация — min/max по бакету (огибающая), а не «каждый N-й сэмпл».** На уровне x1 для записи
   130 с бакет ≈163 сэмпла: точечное прореживание срежет именно пики и артефакты — то, ради чего
   раздел существует. min/max сохраняет амплитуду выбросов при том же числе точек.
2. **Бюджет считается от пикселей, а не от длительности:** `pts/channel = 2 × ширина_вьюпорта`
   (для 1920 px ≈ 4000 точек). Тогда объём пирамиды **не зависит от длины записи**:
   `sum(x1…x16) = 31 × pts/ch × n_channels × 4 байта`.

Измерено на `data/edf/test.edf` (18 каналов, 500 Гц, 130.7 с) при бюджете 4000 точек/канал.
Размер уровня = `2 × pts/ch × n_channels × 4 байта` (min и max), заголовок — единицы процентов:

| Уровень | Точек на канал | Ответ API, 18 каналов | Сборка / повтор |
|---|---|---|---|
| x1 (вся сессия) | 4 000 | 0.58 МБ | 0.033 с / 0.003 с |
| x2 | 8 000 | 1.15 МБ | — / — |
| x4 | 16 000 | 2.30 МБ | 0.046 с / 0.002 с |
| x8 | 32 000 | 4.60 МБ | — / — |
| x16 | 64 000 | 9.22 МБ | 0.045 с / 0.005 с |

Сборка уровня для 130-секундной записи — десятки миллисекунд (потоковое чтение блоками, без
`preload`), поэтому «лениво при первом запросе» выбрано ради **памяти и места на диске**, а не
скорости: полная пирамида ×1…×16 — это 16 МБ на запись, а до уровня ×16 пользователь дозумивает
редко. `SIGNAL_BASE_POINTS` в `.env` меняет бюджет без правки кода (например, 2000 → ×16 = 4.6 МБ):
UI берёт бюджет из `/meta`.

Механика (реализована в срезе 2.5, `app/services/recording_signals.py` + `GET …/signals?level=`):
уровень строится **лениво при первом запросе** (а не фоном при загрузке — до первого просмотра
он может не понадобиться), кладётся на диск в `data/cache/signals/{recording_id}/level{k}.bin`
и отдаётся с `ETag` и `Cache-Control: private, max-age=3600`: повторный запрос с тем же
`If-None-Match` получает 304, повторный уровень — чтение файла без пересчёта. Уровень ×1
запрашивается сразу после загрузки записи — мгновенный вид «вся сессия».
Чтение EDF потоковое (`preload=False`, блоками по 8192 корзины), поэтому 200-МБ файл не
поднимается в память целиком.

Ответ — не JSON, а компактный бинарный контейнер (иначе 64k точек × 18 каналов не влезают в
разумный payload; схема `RecordingSignalsHeader` в OpenAPI описывает заголовок):

```
'DPS1' | uint32 LE len(header) | header (JSON UTF-8) | payload float32 LE, channel-major
```

В payload на каждый канал идут `min` (только при `decimated=true`) и `max` — по одной паре на
корзину; времена корзин восстанавливаются на клиенте из `duration_sec / n_points`
(корзины равномерны, погрешность ≤ половины корзины). Единицы — мкВ: без авто-пересчёта единиц
значения домножаются на 1e6, при `units_autoscaled` численные значения файла уже микровольты
(см. §12 про единицы EDF). Уровень вне `signal_levels` → 400, неизвестная запись → 404.

Глубже x16 — окно полного разрешения по требованию
(`GET …/signals?t0&t1&level=raw`: 5 с × 18 каналов @500 Гц ≈ 180 КБ) — ещё не реализовано.

## 9. Состояния, хоткеи, доступность

Каждый раздел обязан уметь: **empty** (что сделать, чтобы появились данные), **loading** (скелет),
**error** (текст от FastAPI через `apiErrorText`, кнопка «Повторить»), **stale** («данные устарели,
пересчитать»). Примитивы: `Placeholder`, `LoadingBlock`, `ErrorBlock`, `InfoRow`.

Хоткеи: `1…5` — разделы, `[` — панель опций, `Space` — воспроизведение кадра траектории (раздел
«Диполи», срез 3.7); в следующих фазах добавятся `F` (вся сессия) и `+/-` (зум). Обработчик игнорирует
ввод в `INPUT/TEXTAREA/SELECT` и `contenteditable`, а хоткеи разделов не перехватываются в чужих разделах.

Доступность: у иконочных кнопок есть `aria-label` и тултип; активный раздел помечен `NavLink`;
панель опций имеет `aria-label`; статусы проверок сервера подписаны текстом, а не только цветом;
фокус всегда виден (`:focus-visible` — акцентная обводка).

## 11. Принятые решения и открытые вопросы

**Решения.**
- `backend/.env` — единственный источник конфигурации; UI показывает параметры, но не редактирует их.
- Тяжёлые статические ассеты (меш, BA-индексы) отдаются только отдельными кэшируемыми эндпоинтами,
  никогда внутри `/analyze`.
- Долгие операции — только асинхронные задачи с прогрессом; синхронный `/analyze` оставлен для скриптов.
- Предподготовка (артефакты/эпохи) — отдельный тип задачи: правка порога не должна запускать фитинг.
- **UI пишется до обработки**: сначала контролы и визуализация (на фикстурах), затем подключение
  расчёта кнопкой. Правка параметров ничего не запускает — состояние хранится отдельно от результата
  (`params` против снимка `applied`), рассинхронизация показывается как «параметры изменены».
- Параметры раздела живут в zustand-срезе раздела (`shared/state/edfParams.ts`) и сохраняются в
  localStorage; снимок результата не сохраняется — после перезагрузки страницы это честное
  «результат не рассчитан», а не «результат актуален».
- Пока задача предподготовки не подключена, кнопки перерасчёта неактивны и объясняют почему: UI не
  имитирует обработку и не запускает тяжёлый пайплайн «для проверки».
- Перерасчёт разложен на **стадии** (`filter` / `artifacts` / `epochs`), а не на одну кнопку «всё»:
  у каждой стадии свой набор параметров и свой снимок результата, поэтому правка порога артефактов
  не обесценивает уже посчитанный фильтр. Параметры отрисовки (зум, шкала мкВ, видимость зон) в
  снимок не входят — они не влияют на расчёт. Кнопки стадий живут в тулс-хедере раздела, состояние —
  в `shared/state/edfParams.ts` (`stageApplied`), срез 2.4.
- Паспорт сессии — метаданные для БД, а не для EDF-файла: правка в диалоге не перезаписывает исходник
  и не делает запросов, значения лежат в состоянии раздела и уйдут в `sessions` при запуске анализа.
- Сигналы вьюера отдаются **бинарным float32-контейнером**, а не JSON (срез 2.5): 64k точек × 18 каналов
  в JSON — это десятки мегабайт; контейнер `DPS1` (заголовок-схема в OpenAPI + канало-мажорный payload)
  отдаётся с `ETag`. Уровни пирамиды строятся **лениво при первом запросе** и кэшируются на диске:
  фоновая предсборка всех уровней при загрузке могла бы не понадобиться ни разу.
- Единицы в сигналах вьюера — всегда мкВ: контейнер не повторяет эвристику масштаба, а опирается на
  флаг `units_autoscaled` из паспорта записи (`looks_unscaled` из `edf_loader.py`).
- Кадр сигнала на клиенте (`shared/lib/signalFrame.ts`) — единый тип и для записи, и для демо-фикстуры:
  вьюер не знает, откуда данные, и не хранит сырые отсчёты ЭЭГ.
- Слои результата (зоны артефактов, границы эпох, штриховка отброшенных, срез 2.6) — **DOM поверх
  canvas**, а не часть uPlot: зона остаётся кнопкой (клик → детали, `aria-pressed`), легенда — набором
  доступных тумблеров, а зум лишь пересчитывает `left/width` через `timeToX`, не перерисовывая canvas.
  Контракт типов и цветов вынесен в `shared/lib/artifacts.ts` (реэкспорт из `edfParams`), цвета — токены
  темы (`--color-artifact-*`) с заливкой через `color-mix`, чтобы hex не дублировался в JS. Видимость
  типов — **один** параметр `artifactVisibility` для чекбоксов панели и чипов легенды: они не расходятся.
  Границы эпох считаются из параметра «длина эпохи» (геометрия), а не из результата, — сетка живая уже
  сейчас; отброшенные эпохи приходят индексом и раскладываются по текущей сетке. До нажатия кнопки
  стадии слои — детерминированная фикстура `demoLayers` с явным `source: 'demo'` (статусбар
  подписывает «демо-фикстура»), а не имитация результата; после выполнения стадии фикстуру заменяет
  результат задачи (`source: 'result'`, срез 2.7) — слоты стадий не перетирают друг друга.
- Предподготовка записи (срез 2.7) — **отдельный тип задачи** на запись, а не на загрузку: `POST
  /recordings/{id}/preprocess` (202 + `job_id`, `kind=preprocess`) возвращается сразу, прогресс идёт
  через общий `/jobs/{id}`, а результат лежит рядом с записью (`/recordings/{id}/preprocess/{job}`),
  потому что его контракт (`PreprocessResult`) отличается от `AnalyzeResponse`. Файл записи при этом
  не удаляется: он принадлежит реестру просмотра и живёт по своему TTL.
- Каждая стадия считает свой результат на **свежем** предподготовленном сигнале: параметры фильтра
  уходят в запрос любой стадии, поэтому артефакты не ищутся на сигнале со старым фильтром. Плата —
  повторное чтение/фильтрация на каждую кнопку; выигрыш — предсказуемость и независимые снимки стадий.
- Снимок параметров стадии фиксируется **в момент запуска** задачи, а не по её завершении: правка
  порога, пока задача выполняется, оставляет стадию «параметры изменены» — UI не выдаёт чужой
  результат за актуальный. Детектор артефактов теперь возвращает `zones` с каналами (аннотации MNE
  их не хранят), иначе тултип слоя не смог бы показать, какие каналы затронуты.
- Стадия `filter` пока не меняет треки: пирамида сигналов (2.5) отдаёт «сырой» EDF, а перевод её на
  отфильтрованный сигнал потребовал бы отдельного кэша/ETag по параметрам фильтра. Стадия реально
  считается (читает файл, ставит референс, применяет notch и полосу) и фиксирует параметры; переход на
  filtered-пирамиду — отдельный срез, а не тихая подмена данных.
- Экспорт окна (срез 2.8) — **клиентский и без запросов**: данные уже в браузере (кадр пирамиды, слои,
  окно), сервер не пересчитывает то, что видно на экране. Геометрия и форматы живут в чистом
  `shared/lib/exportWindow.ts`, доставка файла — в `shared/lib/download.ts`; кнопки `viewer/ExportActions`
  берут окно/каналы/canvas'ы у вьюера, поэтому стоят в его полосе, а не в тулс-хедере раздела.
- CSV отдаёт **то, что видно**: строку на пару «корзина × канал» с явными `min_uv`/`max_uv`, а не
  «сырые отсчёты». Кадр уровня ×k уже прорежен сервером, и выдавать его за полноразрешённый сигнал
  нельзя — поэтому в файле нет колонки «одно число на точку», а имя файла содержит окно и уровень
  (`probe-win0.00-10.00s-level1.csv`; уровень 0 → `full`).
- PNG собирается **из canvas'ов uPlot** (по одному на трек) плюс собственные подписи каналов, шкала
  времени, зоны и сетка эпох: снапшот обязан повторять экран, а не одни линии сигнала. Canvas не читает
  CSS-токены (`color-mix` тем более), поэтому цвета разрешаются через `getComputedStyle` с hex-fallback.
  Если браузер не умеет `toBlob` (или холст не закодировался), кнопка честно показывает ошибку текстом:
  пустой файл хуже отказа.
- Vite proxy в dev вместо правки CORS (порт 5173 всё равно разрешён для прямого доступа).
- Команды из шапки в вьюер идут **через состояние с монотонным `seq`**, а не через ref/события: у
  вьюера не может быть «императивной ручки» снаружи, а `seq` отличает новую команду от повторного
  рендера и от старой команды при повторном монтировании (срез 2.9).
- Вьюер сам решает, что в нём «параметры отрисовки»: курсор, разворот трека и центр окна — локальное
  состояние `TrackStack`, в zustand живут только те настройки, что переживают перезаход в раздел
  (уровень зума, каналы, шкала). Поэтому разворот трека не сбрасывает стадии и не помечает результат
  устаревшим (срез 2.9).

- **Маркер диполя — кольцо фиксированного размера, сила — в луче; порог «КД» ничего не подменяет**
  (срез 3.5, ✅, поправка ручной проверки): позиции — белые кольца Ø 10 px со штрихом 2 px при любом
  размере окна (пиксели делятся на масштаб SVG `renderedWidth / viewBox.width`), выделенный диполь
  залит оранжево-жёлтым; толщина лучей у всех одна (2 px), а прозрачность считается от амплитуды
  момента (`dipoleRayVisual`, насыщение на 100 нАм), поэтому облако точек читается без таблицы. Порог
  «КД ≥ X нАм» остаётся **отдельным** параметром отображения: он скрывает слабые диполи и не меняет
  вид оставшихся — иначе «скрыто порогом» и «слабее прочих» выглядели бы одинаково, и по картинке
  нельзя было бы понять, что именно скрыто.
- **Выделение диполя — просмотр, и срезы наводятся тоже** (срез 3.5, ✅, поправка ручной проверки):
  клик по точке подсвечивает её во всех трёх проекциях **и** наводит срезы на её позицию — срезы
  меняются при любом клике по фигуре, а `stopPropagation` лишь не даёт клику обработаться дважды
  (фигура навела бы срезы на «сырую» точку клика у края хит-зоны). Ничего не запрашивается у сервера.
  Выделение живёт в `dipoleCalc` рядом с результатом и сбрасывается вместе с ним (это точка
  результата, а не записи).
- **Окно частот FFT — только просмотр посчитанного** (срез 3.5, ✅): кнопки ритмов и поля «от/до»
  срезают уже полученные числа PSD, масштаб логарифма берётся по всему спектру, а окно зажимается в
  частоты текущего расчёта (оно персистится и переживает смену записи). Пересчёт спектра по-прежнему
  возможен **только кнопкой** — «фильтрация по частоте» здесь не заказ нового расчёта, а просмотр.

- **Быстрый расчёт диполей ≠ точный фитинг** (срез 3.4, ✅): раздел считает диполи «сразу», но
  другой ценой за скорость — одна точка на эпоху (пик GFP) вместо траектории по всем отсчётам,
  сферическая модель головы (σ = 0.3 См/м) вместо BEM fsaverage и перебор узлов объёмной сетки
  (≈7 мм, шаг настраивается в панели) вместо градиентной оптимизации. Ошибка позиции — порядка
  шага сетки, поэтому позиция точки кратна шагу, а не «миллиметр в миллиметр». Результат помечен
  `method='fast_grid'`, и UI показывает эту метку в шапке и в панели: выдавать быстрый режим за
  точный нельзя. Точный профиль (`mne.fit_dipole`) и playback траектории — срез 3.5+.
- **Топокарты — служебная картинка, а не публикационная** (срез 3.4, ✅): каналы монтажа
  раскладываются ортогональной проекцией на плоскость, мощность интерполируется обратными
  расстояниями, а цвет — серая шкала (PNG-энкодер проекта умеет серый + альфу). Сферическая
  сплайн-интерполяция MNE (`mne.viz.plot_topomap`) не подключена осознанно: она тянет matplotlib в
  бэкенд, а картинка нужна для формы распределения, не для публикации. Вне круга скальпа пиксель
  прозрачен: за границей электродов мощности нет, и «дорисовывать» её нельзя. Диапазон, у которого **ни
  одна измеренная частота PSD не попадает в границы**, отдаётся как `null` («не измерено») и
  подписывается «—»: `NaN` в JSON невалиден, а нулём эту ситуацию показывать нельзя. Узкая полоса
  фильтра такого не даёт: частоты PSD остаются на месте (ось — от 0 до Найквиста), и вне полосы виден
  лишь небольшой остаток фильтра — он показывается как есть, а не подменяется нулём или `null`
  (`tests/test_filter_band_jobs.py`).
- **Воспроизведение траектории показывает кадр, а не новые данные** (срез 3.7, ✅): интерполяция между
  эпохами (позиция, направление момента, амплитуда) — приём **отображения**: в результате задачи лежит
  одна измеренная точка на эпоху, и промежуточных положений никто не считал. Поэтому интерполяция идёт
  только между соседними эпохами с точками, кадр отброшенной эпохи пуст, а на паузе и при шаге кадр
  равен измеренной точке своей эпохи. В UI это подписано (подсказка кнопки и текст раздела), а `AGENTS.md`
  держит то же правило для будущих срезов. За кадром тянется **затухающий шлейф** — отрезки между
  измеренными точками соседних эпох за последние 10 секунд сессии, гаснущие с возрастом: он показывает
  путь, а не «дорисовывает» его, поэтому через разрыв (эпоху без диполя) не тянется и подчиняется порогу
  «КД» вместе с кадром. Технически часы живут **вне стора** (непрерывное время —
  локальное состояние провайдера, в zustand уходит только смена эпохи), маркер кадра обновляется
  контекстом, а статичные слои проекций не перерисовываются — иначе облако из сотен точек во всех трёх
  проекциях перерисовывалось бы 60 раз в секунду, что на 261 эпохе `test.edf` съело бы CPU.
- **Полоса расчёта и пресет — две связанные величины** (срез 3.6, ✅): в задачу уходит **полоса**
  (`band_min`/`band_max`), а δ…γ, «одиночная частота», «свой диапазон» и «без фильтра» — выбор
  пользователя, который её задаёт (`shared/lib/calcFilter.ts`). Диапазоны ритмов не дублируются в UI:
  их отдаёт `/meta` вместе с длинами эпох. Итоговая подпись печатает полосу, а не название пресета —
  иначе после смены `freq_bands` на сервере она обещала бы одни границы, а в расчёт уходили другие.
  Пресет **не выводится** из чисел для полей («свой диапазон» с границами 1–40 Гц немедленно
  «отскакивал» бы к «широкому», пряча свои поля): он хранится как выбор, а вывод из полосы
  (`filterPresetOf`) используется только как страховка при подъёме старых параметров и когда
  сохранённый ритм пропал из метаданных. Одиночная частота — узкая полоса `f ± bw/2` (как `single_freq`
  в предподготовке записи), сетевой фильтр — только 50/60 Гц, и оба правила нормализуются при любом
  вводе. Полоса живёт в сторе расчёта (`dipoleCalc`), а не берётся из параметров предподготовки записи:
  иначе правка фильтра в разделе EDF незаметно меняла бы локализацию. URL топокарты собирается из
  **результата** (`spectrumQueryOf`), а не из текущих настроек панели: картинка обязана соответствовать
  тому расчёту, чьи числа показаны рядом, иначе пользователь сравнивал бы числа одного фильтра с
  картинкой другого.
- **Спектр, диполи и порог «КД» — раздельные действия** (срез 3.4, ✅): расчёт диполей запускается
  кнопкой в шапке, спектр — своей кнопкой в выдвижной панели, а порог «КД ≥ X нАм» вообще ничего не
  запускает: это параметр отображения, он скрывает слабые диполи на проекциях (со счётчиком
  «скрыто порогом: N из M») и не меняет результат задачи. Устаревших стадий здесь нет: результат
  живёт до «Сбросить расчёт», загрузки новой записи или «Закрыть запись».

**Открытые вопросы.** Формат 3D-обмена (GLB против `.npz`) — решается в Фазе 3; профиль расчёта
по умолчанию (`fast`/`accurate`) — после появления профилей в бэкенде (F11); объём истории в UI —
зависит от read-API (Фаза 5).

## 12. Локальные компромиссы (документированные ограничения)

- **Одиночная частота задаётся полосой, а не полем `single_freq`** (срез 3.6): у задач
  `/recordings/{id}/dipoles` и `/recordings/{id}/spectrum` есть только `band_min`/`band_max`/`notch_hz`,
  поэтому форма отправляет узкую полосу `f ± bw/2` — ровно ту же, что бэкенд строит из `single_freq` в
  предподготовке записи (`bandpass_filter.py`). Числа совпадают, и в подписи видно и частоту, и
  фактические границы полосы; отдельного поля `single_freq` у этих задач пока нет (`edf_loader`
  применяет фильтр к continuous raw до нарезки, поэтому смысл фильтрации одинаковый).
- **Сетевой фильтр — только 50 и 60 Гц** (срез 3.6): список не даёт ввести произвольное значение, а
  сохранённое приводится к ближайшему из двух (`normalizeNotchHz`), чтобы состояние и список не
  разъезжались. Произвольная частота notch — отдельная задача (сервер принимает любое число).
- **Частотная сетка PSD задана сервером** (срез 3.5): окно частот FFT-графика сужает только то, что
  уже посчитано (`freqs` из результата), и не интерполирует и не досчитывает спектр на клиенте.
  Поэтому окно уже ~шага сетки может не содержать ни одной измеренной частоты — UI честно сообщает
  «в выбранном окне нет измеренных частот», а не рисует выдуманную линию. Точный произвольный
  диапазон (пересчёт PSD по своим частотам) — задача сервера и отдельный срез.
- **Поля Бродмана в проекциях — фикстура** (срез 3.1, уточнено в 3.5): эллипсы заданы таблицей
  `DEMO_BA_LAYOUT` в долях полуразмаха оси, и хит-тест проверяет попадание по **той же** геометрии,
  что нарисована (`ellipsePx` + `brodmannAreaAt`). Это согласованность клиента, а не реальные поля:
  настоящие области появятся из `PALS_B12_Brodmann` (`surface_cache.py`) — тогда форму сменит
  источник данных, а не отрисовка.
- **Только локальный сервер**: UI и API предполагаются на одной машине; авторизации в UI нет,
  сетевой доступ не предусмотрен.
- **Единицы EDF**: файлы без physical dimension MNE читает как «вольты» (в 1e6 раз больше) —
  работает авто-детект масштаба, override задаётся через `EDF_UNITS` в `backend/.env`.
- **ICA без EOG-каналов**: ICA-ветка выполняется только при наличии EOG-подобных каналов, факт
  применения фиксируется в `pipeline.ica_applied`. Для записей без EOG нужна отдельная логика (F8, P1).
- **`decim` без антиалиасинга**: перед децимацией нет low-pass фильтра (в логах MNE есть warning) —
  на GOF влияет, поэтому значение фиксируется в `pipeline.dipole_fit_decim` каждого результата.
- **Ассеты fsaverage**: при отсутствии `~/mne_data` эндпоинты `/surface*` отвечают 503 с понятным
  текстом, `/init-status` показывает `loading`/`error` — приложение не падает.
- **Ручные пометки эпох живут в браузере** (срез 2.10): Ctrl+двойной клик правит вердикт
  reject-фильтра только в UI (`edfRecording.epochMarks`, интервалы на таймлайне). В расчёт
  (нарезка эпох на сервере, фитинг диполей) эти правки пока не уходят — передача списка
  заблокированных/разрешённых интервалов в задачу будет отдельным срезом, а не тихим
  изменением уже посчитанного результата. Счётчики («ручных пометок: N» в полосе вьюера и
  «Ручных пометок: N» в панели «Эпохи») считают **пометки**, а не ячейки сетки (срез 2.11):
  после смены длины эпохи одна пометка накрывает несколько эпох новой нарезки, и счёт по ячейкам
  показывал бы больше видимых полос, чем пользователь нарисовал.
- **Изотропный масштаб проекций** (срез 3.3, ✅): раньше каждая ось растягивалась на свой размах, и
  квадрат 284×284 px показывал анатомию с искажением до 22% (в аксиальной проекции 160 мм по x и
  196 мм по y ложились в одну ширину). Теперь масштаб **один на все проекции**
  (`PROJECTION_SCALE = 1.5` px/мм — целые пиксели на размахах 160/172/196 мм), поэтому фигуры
  прямоугольные: axial 240×294, sagittal 294×258, coronal 240×258 px (`projectionBox`). Колонки
  раздела заданы **пропорционально ширине фигур** (`flex: <ширина> 1 0%`), иначе SVG растянулся бы
  по-разному и общая шкала пропала бы; свойство фиксирует тест
  `mriProjections.test.ts::держит единый масштаб` и `DipolesSection.test.tsx` (пропорции колонок).
  Сетка MNI теперь даёт **квадратные клетки** — по ним и видно, что проекция не растянута.
  Полушария подписаны по RAS (x > 0 — правое), а горизонталь аксиальной и коронарной развёрнута:
  слева на экране R, справа L (радиологическая раскладка).
- Там же остаётся условная схема среза (`demoSliceStructures`) — она показывается только при
  выключенном слое МРТ, а реальные поля Бродмана из атласа и контур головы из тома (`seghead`) —
  следующие срезы. Границы тома — bounding box маски `brainmask`, то есть мозг занимает почти всю
  фигуру: поле подписей даёт минимальный зазор.
- **Таблица локализации живёт результатом задачи, а не БД** (срез 4): она показывает точки
  текущего результата `dipoleCalc` и после загрузки другой записи (или «Закрыть запись») вместе с
  ним пустеет — сохранение выборки в БД и групповые срезы это отдельные срезы. Точки без MNI
  (fsaverage недоступен) в таблице **есть** (координаты «—»): результат задачи должен быть показан
  целиком, даже если на проекции такие точки не наводятся. Колонки ROI нет, пока ROI не считается:
  в `DipoleScanPointOut` есть поле Бродмана, а пустая колонка «ROI» читалась бы как «не
  определено». Сортировка пока одна — по номеру эпохи (требование среза): ключи MNI/амплитуда/GOF
  добавятся вместе с фильтрами, чтобы сортировка и фильтрация опирались на одни и те же поля.
  Порог «КД ≥ X нАм» из раздела «Диполи» — параметр отображения проекций, поэтому в таблице все
  точки: расхождение чисел между разделами объяснено подписью, а не «тихой» фильтрацией.
- **Legacy-страница**: `backend/app/static/index.html` сохранена и доступна по `/legacy` для сравнения
  с новым UI (в ней остался бесконечный поллинг `/init-status` каждые 2 с).
