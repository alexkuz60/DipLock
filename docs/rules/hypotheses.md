# Правила-гипотезы «N из M»: признаки пробы и проверка на выборке

> Срез 4 слоя «признаки + правила» (29.10.2026), вслед за срезами 1–3:
> пороги КД (`docs/rules/dipoles.md`), доля вращения момента, магистраль и
> упорядоченность потока. Миссия — `concept.md` §1 («измеримая,
> воспроизводимая и **накапливаемая** методика»); формат науки — «научный
> критерий = данные + правило» (`concept.md` §2).

## Что это

**Гипотеза — проверяемое суждение над признаками пробы.** Проба — запись-
участник выборки (добровольец-испытуемый, условие эксперимента). Правило =
полоса + условия «признак оператор значение» + (опционально) порог
подтверждения. Проверка отвечает на вопрос «**признак выполнен в N записях
из M**» и приносит контрпримеры; интерпретацию признаков даёт исследователь.

Пример правила (гипотетический, как в обсуждении 29.10.2026):

```json
{
  "label": "у целителей CCW ≥ 80 % в γ при активности",
  "band_key": "gamma",
  "conditions": [
    {"feature": "rotation_ccw_share", "op": ">=", "value": 0.8},
    {"feature": "flow_orderliness", "op": ">=", "value": 0.5}
  ],
  "min_share": 0.8,
  "recording_ids": ["id1", "id2", "..."]
}
```

## Признаки пробы (`services/probe_context.py`, `PROBE_FEATURES`)

| Признак | Что это | Источник |
|---|---|---|
| `n_points` | точек расчёта в полосе (одна на эпоху) | `report_band_summaries` |
| `kd_passed_share` | доля точек, прошедших КД («не оценено» → `None`) | `analysis_bands` (тот же прогон) |
| `rotation_ccw_share` / `rotation_cw_share` | доля тройек траектории с поворотом CW/CCW (срез 2) | `report_band_summaries` |
| `flow_orderliness` | упорядоченность потока R (срез 3) | `report_band_summaries` |
| `median_gof` / `median_riv` | медианы полосы (GOF — только внутри полосы) | `report_band_summaries` |

Источник — **последний прогон автоотчёта** записи (§8.4.2: история, не UPSERT;
`report_runs` → `report_band_summaries` + `analysis_bands` через `analyses_id`).
Правило всегда **одной полосы** — принцип 3 «GOF между полосами не сравним»
(`docs/rules/dipoles.md`) распространяется и на гипотезы.

## Семантика N из M (честность важнее красивого ответа)

1. **Трёхзначная И-логика условий**: невыполненное условие → `passed=False`
   даже при неизмеренных соседях (провал определён); без провалов, но с
   неизмеренными признаками → `passed=None` («не оценено»).
2. **N** — записей с `passed=True`; **M** — оценённых (`passed is not None`):
   «не оценено» **не входит в знаменатель** и перечисляется в предупреждениях.
   `share = N / M`; M = 0 → статус `insufficient`, доля `None` (не 0).
3. **Статус**: `min_share` задан → `confirmed` (`N/M ≥ min_share`) /
   `rejected`; не задан → `descriptive` (описать N из M без вердикта).
4. **Контрпримеры** — записи с `passed=False` (их подписи невыполненных
   условий и признаки — в каждой строке ответа).
5. Шлюзы (400, как у группового агрегата): пустая выборка, неизвестная
   полоса, пустое правило, неизвестный признак/оператор.

## API (`app/api/hypotheses.py`, `PrivateRoute`)

* `POST /hypotheses/probe-context` — признаки выборки в одной полосе
  (`ProbeContextOut`): что именно измерено, до проверки правила;
* `POST /hypotheses/check` — проверка правила (`HypothesisCheckOut`):
  N/M/`share`/`status` + построчные итоги `records` + `warnings`.

Операторы условий: `>=`, `<=`, `>`, `<`, `==`, `!=` (`==`/`!=` — с допуском
1e-9). Работа — `services/hypothesis_check.py` (правило, N/M, контрпримеры) и
`services/probe_context.py` (признаки).

## Сверх-принцип «не навреди» (срез слоя)

* **Гипотеза — суждение, а не диагноз и не «оценка одарённости»**: ответ
  проверки — только «выполнилось в N записях из M» и контрпримеры; никакой
  интерпретации признаков и никаких выводов о способностях/здоровье
  (добровольцы — не пациенты: `docs/strategy/05-consilium.md`).
* **Семантику даёт исследователь**: «доля CCW ≥ 80 %» — измеримый факт;
  «приём информации извне» — гипотеза-объяснение, её программа не выдаёт и не
  подтверждает (`concept.md` §2 «интерпретация — проверяемая гипотеза, а не
  диагноз»).
* **Эмо-анализ, нейромузыка и ИИ-консультанты слоем признаков не
  обслуживаются** (отдельные треки; их критерии — своим решением владельца).
  Для нейромузыки «не навреди» — инвариант `docs/rules/neuromusic.md`
  (фотостимуляция/частоты, провоцирующие эпилепсию, запрещены).
