# Раздел «Нейромузыка» — ЭЭГ в звук (эксперимент, фаза 1)

> Экспериментальный модуль: рендер записей ЭЭГ в стерео-аудио. Математика
> зафиксирована техзаданием и здесь не переобсуждается; правила ведения
> документации — `docs/rules/docs.md`.

## Концепция

ЭЭГ = **партитура оркестра**: 7 полос мозговых волн (`freq_bands` из
`core/config.py`) = 7 инструментов-треков, каждый поднимается через
аналитический сигнал на **5/6/7 октав** (×32/×64/×128 — выбор
`octave_shift`, дефолт 7) и звучит отдельным треком. Пространство
сцены — шины **L/C/R** по карте монтажа: левые электроды (нечётный номер) —
слева, правые — справа, срединные (`Fz`/`Cz`/`Pz`/`Oz`…) — по центру в оба
канала с весом 0.5. Цель — слушать музыкальные свойства записи: тональность,
гармонию/диссонанс, «расстроенность» ансамбля.

Задел будущего (`extensions` в sidecar): 3D-панорамирование с учётом фазы,
свёрточная реверберация свода черепа, движение источников по дипольным
траекториям, эффект Доплера. Обратный путь (корректирующие треки для
психоэмоционального фона) — сценарий раздела «Нейроаудио», не здесь.
Выбор библиотек для этой пространственной обработки — `docs/rules/spatial-audio.md`
(исследование 06.10.2026: гибрид Tone.js в браузере + IR от pyroomacoustics;
Resonance Audio архивирован, librosa запрещён ТЗ).

## Конвейер (`services/audio_render/`)

| Модуль | Что делает |
|---|---|
| `core.py` | Ядро `band_stem`: `hilbert` → `resample_poly` ×96 по Re/Im (kaiser(10)) → `pitch_steps` комплексных квадратов (×2**`pitch_steps`; выбор 5/6/7, дефолт 7 → ×128) → стем `(N*96, 2)`. **Порядок операций не менять** (питч до ресемплера невозможен: частоты ×128 уходят за Найквист 500 Гц) |
| `input.py` | Одно чтение EDF (`prepared_raw_report`, RAM-кэш A4) с дефолтной очисткой `AUDIO_DEFAULT_CLEAN` (гармоники notch → интерполяция мёртвых → ICA) и **авто-notch 50 Гц** + **обязательный режект первых гармоник 100/150 Гц** (`apply_line_harmonics`, в каждом прогоне — даже при деградации очистки; приёмка 05.10.2026); референс `none` (как у миксов `channel_mix`); sfreq → 500; 7 полосовых пакетов float64; валидация NaN/inf; пиковый контроль остатка 50 Гц (предупреждение) |
| `mix.py` | `bus_weights` (равные веса по группе: `mono = mean(L) + 0.5·mean(C)`), нормализация трека к −18 dBFS **+ `boost_db` (0…12, дефолт +6) + `loudness_db` (смещение ISO 226)**, индивидуальный потолок трека 0.891 (защита PCM_24 при boost), мастер = сумма, пик-контроль вниз к 0.891 |
| `loudness.py` | Кривые равной громкости **ISO 226:2003**: `equal_loudness_spl_db` (таблицы α/L_U/L_T + формула стандарта) и `band_loudness_offsets`/`pit_bands` — смещения и набор «ямы» считаются на аудио-частотах полосы ×2**`pitch_steps` (выбор октав параметр, см. §«Психоакустика») |
| `export.py` | WAV PCM_24 @48000 через `soundfile` (детерминизм: одинаковые входы → одинаковые байты), sha256 входа, sidecar «партитура» |
| `render.py` | Оркестрация + **in-memory статус** рендера |

Прогресс: подготовка 0..30 %, семь треков 30..90 %, сведение/экспорт
90..100 % — UI рисует единый прогресс-бар по `GET …/status`.

## API (синхронный, без job-системы)

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/api/v1/audio/render` | 202 `{render_id}`; тело `{recording_id, gains_db?, boost_db?, octave_shift?, loudness_phon?}`; 400 — гейны/полосы/boost вне 0…12/loudness_phon вне 60…90/`octave_shift` не 5/6/7, 404 — запись, 409 — уже идёт рендер (один за раз) |
| GET | `/api/v1/audio/render/{id}/status` | `{status, stage, pct, message, error, tracks}` — поллинг ~400 мс |
| GET | `/api/v1/audio/render/{id}/master.wav` | WAV мастера (audio/wav) |
| GET | `/api/v1/audio/render/{id}/track/{band}.wav` | WAV одного трека (соль) |
| GET | `/api/v1/audio/render/{id}/sidecar.json` | Партитура (ТЗ §6) |
| GET | `/api/v1/audio/ir` | Каталог IR-пресетов реверберации (`AudioIrCatalogOut`) |
| GET | `/api/v1/audio/ir/{preset}.wav` | Стерео-IR 48 кГц (ETag/304, ленивая генерация, 404 — неизвестный пресет) |

Состояния рендера живут **в памяти процесса** (TTL 15 мин): история, файлы,
БД и журнал не участвуют (решение по ТЗ фазы 1). Перезапуск сервера теряет
активный рендер — клиент честно получает 404. `job_manager`/`job_store` не
используются принципиально: это не задача, а разовый эксперимент.

WAV-эндпоинты отдаются **без** `Content-Disposition`: файл проигрывается в
плеере (Tone fetch+decode и `<audio src=…>` — оба пути работают), скачивание
UI инициирует атрибутом `download` (same-origin).


## UI (вкладка «Нейромузыка», хоткей 0)

В рейле (Главное меню) «Нейромузыка» идёт **раньше** «Нейроаудио» — сначала
генерация звука, потом анализ результата воздействия (правка 06.10.2026,
`sections/registry.ts`). Хоткеи принадлежат разделам, а не позиции, поэтому
не меняются: Нейроаудио — `9`, Нейромузыка — `0`.

Кнопка «Создать аудио» — **иконка в тулс-хедере** раздела
(`neuromusic/NeuromusicToolActions.tsx`, без записи выключена с объяснением) →
прогресс-бар с шагами → **трекер-плеер** (`neuromusic/WaveTracker.tsx`, см.
§«Плеер-трекер» ниже). Транспорт **Play/Pause и Stop — кнопки хедера раздела**,
ссылки «Скачать мастер / партитуру / 7 × .wav» — секция **«Файлы»** правого
сайдбара: основная область отдана графической визуализации (срез 06.10.2026,
вторая половина).
Параметры — секция **«Параметры рендера»** правого сайдбара «Опции раздела»
(`neuromusic/NeuromusicPanel.tsx`, открыт по умолчанию — как у рабочих
страниц): сегмент-контрол **«Транспонирование»** (**5 октав ×32 / 6 октав
×64 / 7 октав ×128**, дефолт 7 — эксперимент 06.10.2026; при 5 октавах
слышимая «яма» уезжает в β/γ/γ-high, при 6 — в α/β/γ), **«Усиление полос»**
(0…12 дБ, дефолт +6), чекбокс **«Перцептуальный баланс (ISO 226)»** (вкл.),
поле **«Уровень прослушивания»** (60…90 фон, дефолт 75, видно при включённом
балансе) и переключатель **«Режим базы»** (**Баланс ≈ −17** — автобаза «ямы»
(дефолт) ↔ **Максимум (boost)** — база −18+boost). Правка значений не
запускает расчёт (правило UI), в запрос уходит при нажатии кнопки.
Пользовательских гейнов по полосам в UI нет (API поддерживает `gains_db`,
дефолт 0), персиста параметров нет. Множитель выбранной октавы виден в
заголовке рабочей области («полос ×{2**n} (n октав)»).

Состояние (параметры + запуск + поллинг) — zustand-стор
`shared/state/neuromusic.ts`: хедер, панель и рабочая область делят его, как
«Итоги» (`summaryReport`); поллинг свой (running/succeeded/failed, без
`job_id`) и переживает уход из раздела, а результат принадлежит записи — при
закрытии/смене записи стор сбрасывает `NeuromusicSection`.

## Плеер-трекер (срез 06.10.2026, вторая половина)

Основная область раздела — **трекер отрисовки волны**, `<audio>` заменён
(`neuromusic/WaveTracker.tsx`; математика и отрисовка — `shared/lib/waveformView.ts`,
движок — `shared/lib/neuromusicPlayer.ts`, транспорт/вид — стор
`shared/state/neuromusicPlayer.ts`):

- **Волна-бабочка** (canvas, высота **≤ 200 px** — потолок по ТЗ; под трекером
  будущими шагами появятся ещё две горизонтальные области визуализации):
  положительная полуволна левого канала вверх от линии нуля, отрицательная
  полуволна правого — вниз; **цвета полуволн разные** (`--color-nm-wave-up`
  синий / `--color-nm-wave-down` фиолетовый — токены в `styles/index.css`),
  **линия нуля — последним штрихом поверх волны** (правки после живого прогона
  06.10.2026). Пики (`filePeaks`) считаются по всему файлу один раз на комбинацию
  «источник × зум × ширина», глобальные max нормируют амплитуду — при прокрутке
  окна волна не «дышит»; колонок не больше числа отсчётов. Смена источника
  перерисовывает волну по **dirty-флагу** (`waveDirtyRef`) — без смены окна;
  ресайз тоже сбрасывает окно (`viewRef = null`), иначе линейка осталась бы
  растянутой картинкой прошлой ширины.
- **Линейка времени** над волной («красивые» шаги 1/2/5×10ⁿ, на узких окнах —
  доли секунды) и **позиционер поверх сигнала** (линия через линейку и волну +
  ручка) на отдельном canvas-оверлее: в rAF-кадре перерисовывается только он —
  волна и линейка перерисовываются лишь при смене окна (правило
  `frontend-perf.md`). Клик/перетаскивание по волне — перемотка (драг — с
  троттлингом 50 мс, финальная точка — точная).
- **Зум ×1/×10/×100** — окно `duration/zoom` с якорем на позиционере
  (`viewWindow`): окно держится, пока позиционер внутри 15…85 % окна, и
  перескакивает у края — позиционер «гуляет» по волне, а не залипает в центре.
  Настройка чисто визуальная, движок не трогает.
- **Слайдер горизонтальной прокрутки** под волной (после живого прогона
  06.10.2026): 0…(длительность − окно), шаг = 1/100 окна, **выключен на ×1**
  (окно = файлу, рядом подпись видимого отрезка). Ручное значение держит окно,
  пока позиционер внутри; при игре позиционер вышел за окно — автослежение
  возвращается; смена зума сбрасывает прокрутку (окно снова «вокруг
  позиционера»). Слайдер — **не перемотка**: `seek` не зовётся; большой палец
  синхронизируется из `paint` без ре-рендеров (пока слайдер в фокусе — значение
  не перетирается).
- **Скорость ×0.5 / ×1.0** — только замедление (`player.playbackRate`): ×0.5 —
  слуховой контроль быстрых перемещений по записи, **в итоговый файл не попадает**
  и в рендер не влияет; высота тона при замедлении падает, искажения допустимы
  (уточнение владельца 06.10.2026) — PitchShift-компенсации нет. Смена при игре —
  перестарт с той же позиции.
- **Источник** («проигрывания и визуального контроля»): **«Микс (до эффектов)»**
  (мастер-файл — сухая микс-сумма до любой пост-обработки) либо любая из 7
  полосных WAV-дорожек; волна всегда рисует **сухой выбранный сигнал**. В
  3D-режиме «Микс» — вся сцена из семи стемов на дуге, полоса — соло через ту же
  цепочку (остальные в `mute`, остаются синхронными). Ошибка загрузки буфера —
  текст для пользователя и откат к прежнему источнику.
- **Транспорт Play/Pause и Stop** — кнопки хедера раздела; позиция живёт не в
  сторе, а в rAF-цикле трекера (ref'ы и canvas, без ре-рендеров хедера).
  Конец трека → `finish()`, позиционер в начало. Стоп — пауза + в начало.
- **Буферы** (мастер/полосы/IR) грузятся лениво: начальная сборка — только
  выбранный источник (+ стемы и IR в 3D), остальное — при переключении источника;
  кэш `ToneAudioBuffer` отдаётся трекеру для пиков (`bufferFor`). Разборка графа —
  при размонтировании трекера (смена/закрытие записи, уход из раздела); хранение
  позиции/вида — стор не персистит (рендер живёт в памяти сервера, TTL 15 мин).

Скачивание готового рендера — секция **«Файлы»** сайдбара (мастер, партитура,
семь соль-треков): рабочая область ссылок не содержит.

## Пространственная обработка (реализация `spatial-audio.md`, п.1–2, 06.10.2026)

**3D-режим плеера** — цепочка на Tone.js внутри **единого движка**
(`shared/lib/neuromusicPlayer.ts`, см. §«Плеер-трекер»): на каждый из 7 стемов
`Player → StereoWidener → Panner3D`
(HRTF; стерео-вход паннер сохраняет — проверено по коду Chromium), шина →
dry/wet (`Convolver` с IR) → master. Стемы стартуют с **одного момента**
аудио-контекста (семпл-точная синхронизация); транспорт, позиция и длительность —
в руках трекера (rAF-цикл, §«Плеер-трекер»), `play/pause/seek` инкапсулированы
в классе движка.

**Раскладка** (`shared/lib/spatialLayout.ts`, чистая математика без Web Audio):
7 источников на дуге ±60° перед слушателем (слева δ, справа γ-high, Z отрицательный
— конвенция Web Audio), дистанция 1.5 м (=`refDistance`, равномерная громкость);
`spread` 0…100 % схлопывает дугу к центру. Параметры UI → узлы: ширина 0…150 %
(100 % = width 0.5 StereoWidener = без изменения), влажность 0…100 % = линейный
dry/wet.

**Параметры** — в панели «Пространство» (`NeuromusicPanel`), стор `neuromusic.ts`
(`spatial*`-поля): правка применяется к живому графу мгновенно (`setWidth`/
`setSpread`/`setWet`, смена IR — `convolver.load`) и **не создаёт ни POST, ни
пересчёта** — это и есть критерий real-time среза. Каталог пресетов — один GET
`/audio/ir` (TanStack Query, `enabled` только при включённом режиме).

**IR-ассеты** (`services/audio_ir.py`): три пресета (комната малая, зал,
прокси свода черепа), генерация `pyroomacoustics` image source model
(детерминирована: одинаковые входы → одинаковые байты; замер 06.10.2026 —
4–11 мс/пресет), стерео с базой микрофонов 17 см, WAV 48 кГц/PCM_24 через
`wav_bytes` рендера, нормировка пика к 0.891. Кэш — `cache_dir/ir/{id}.wav`
(прогрев: `venv/bin/python -m scripts.build_audio_ir`), ETag — отпечаток байтов;
генерация ленивая при первом запросе (`asyncio.to_thread`).

**Ловушки среза:** плеер грузит 7 стемов целиком (память — «Память фазы 1»
усугубляется: часовые записи в 3D-режим не годятся); автополитика браузера —
`Tone.start()` только из пользовательского жеста (кнопка play); HRTF слушается
в наушниках; в 3D-режиме источник «Микс» звучит разом, полоса — соло через ту же
цепочку (§«Плеер-трекер»), ссылки «Скачать .wav» живут в панели «Файлы».

## Психоакустика (`loudness_phon`, ISO 226:2003)

Одинаковый RMS семи треков даёт равенство **электрическое**, а не субъективное
(приёмка 05.10.2026, PDF «Психоакустика — АЧХ слуха»): слух неравномерен —
«яма» 2–4 кГц, глухие басы. После ×128 середина спектра (alpha 1–2 кГц,
beta 2–4 кГц) попадает в зону максимальной чувствительности и доминирует,
bass-полосы (64–256 Гц) — звучат тихо. **При выборе 5/6 октав** аудио-диапазоны
сдвигаются вниз и «яма» ловит другие полосы (×64 → α/β/γ, ×32 → β/γ/γ-high) —
`band_loudness_offsets`/`pit_bands`/автобаза считают это автоматически.
Реализация:

- `loudness.py`: таблицы и формула **ISO 226:2003** (α/L_U/L_T на 29 частотах
  + `A_f`/`L_p`; сверено с эталонными реализациями — точка 100 Гц/60 фон =
  78.6546 дБ). `band_loudness_offsets` считает по **аудио**-диапазону полосы
  (полоса × 2**`pitch_steps`): `offset = среднее SPL(полоса) − SPL(1 кГц)` по
  лог-сетке.
- Цель трека: `−18 + boost + offset(band) + gain` (`mix.normalize_track`).
  При 75 фон: delta ≈ +11.7, delta_theta +2.8, theta +0.1, alpha +2.1,
  **beta −2.2** («яма» опускается), gamma +4.9, high_gamma +10.3 дБ.
- `loudness_phon`: 60…90 фон (дефолт **75** — домашнее прослушивание);
  **`null` выключает** компенсацию (A/B). Смещения — в sidecar
  (`loudness: {method, phon, offsets_db, autobase, base_db}`) и в строке
  каждой банды (`loudness_offset_db`).
- **Автобаза «ямы» (`loudness_autobase`, стратегия A, дефолт true)**: пока
  цель `база + offset` выше потолка `bound = −1 − crest`, RMS определяется
  только crest'ом и **ни boost, ни компенсация не работают** (приёмка
  05.10.2026: при boost все 7 треков упёрлись в 0.891 → «дельта 0.00 дБ»).
  Поэтому перед нормализацией считаются crest-факторы стемов «ямы»
  θ/α/β (`pit_bands`, аудио 0.5…4 кГц) и база ограничивается
  `base = min(−18 + boost, min(bound − offset))` ≈ **−17 дБ** — середина
  выходит из потолка и выравнивается по перцептиву `P = RMS − offset`:
  у θ/α/β получается одинаково (инвариант: цель ≤ bound по построению).
  В этом режиме boost реально поднимает базу максимум до запаса потолка
  (~+1 дБ) — физика без компрессии. Режим **«Максимум громкости»**
  (`loudness_autobase=false`): база честные −18+boost, все треки
  crest-limited (громче, но компенсация почти не действует).
- **Статика, не динамика**: гейны постоянны, детерминированы и не зависят от
  уровня сигнала — динамическая тонкомпенсация и компрессоры запрещены ТЗ §3.
- **Зависимость от уровня воспроизведения**: кривые ISO 226 круче на тихой
  громкости — при прослушивании тише 75 фон середина снова будет доминировать
  (лечится громкостью прослушивания или `gains_db`); на 90 фон поправки меньше
  (кривые выполаживаются — тест `test_offsets_shrink_at_loud_reference_level`).
- **Оговорки**: кривые — для чистых тонов на нейтральном тракте; узкополосные
  «инструменты» и наушники (Harman-кривая) дают свои отклонения. Выше 12.5 кГц
  (край high_gamma до 16.4 кГц) стандарт данных не даёт — таблицу продолжаем
  повтором пороговой строки 20 Гц. Потолок 0.891 приоритетнее компенсации:
  у delta (crest 21 дБ) подъём упирается в запас — фикс срабатывает
  преимущественно опусканием середины (там и была перекомпенсация).

## Усиление полос (`boost_db`, приёмка 05.10.2026)

Внешние анализаторы показали запас: RMS файлов −22…−18 дБ — «при создании
полосовых стерео-ЭЭГ увеличивать сигнал на +6…+12 дБ». Реализация:

- `boost_db` (0…12, дефолт **+6**) в `POST /audio/render` → целевой RMS трека
  `−18 + boost` (`mix.normalize_track`); значение пишется в sidecar.
- **Индивидуальный потолок трека 0.891**: при boost пик громкого трека может
  перевалить 1.0 — PCM_24 клипнул бы. Потолок — масштабирование вниз
  (ТЗ «без компрессоров»), величина возвращается в `applied_gain_db`.
- **SQNR-тезис проверен численно** (`test_pcm24_sqnr_improves_with_boost`):
  квантование 24 бит — главный шум выхода, +6 дБ сигнала дают ~+6 дБ SQNR
  записи (ресемпл ядра идёт в float64 и SNR не портит).
- **Ограничение мастера**: RMS мастера поднимается boost'ом лишь насколько
  позволяет потолок пика — у суммы семи полос высокий crest-фактор, и мастер
  почти всегда упирается в −1 dBFS (тогда его RMS ≈ 0.891/crest и не зависит
  от boost). Громкость треков (соль-прослушивание) boost поднимает всегда.
- Обязательный режект **100/150 Гц**: `apply_line_harmonics` после приведения
  к 500 Гц в каждом прогоне (частоты — `filter_design.harmonic_frequencies`,
  с учётом Nyquist), независимо от успеха дефолтной очистки (она режет те же
  гармоники через `CleanSpec.notch_harmonics=3`, но при деградации в
  `load_edf` остаётся только 50 Гц). Факт и число гармоник — в sidecar
  (`notch_hz`, `notch_harmonics`).

## Отклонения от буквы ТЗ (обоснованные)

1. **Потолок «суммарного гейна +24 дБ» → порог тишины.** Буквальный потолок
   измерялся бы от исходного уровня в вольтах: нормализация микровольтового
   трека до −18 dBFS требует ~76 дБ, все полосы упёрлись бы в потолок и
   баланс инструментов пропал (приёмка «все 7 слышимы» не проходила).
   Вместо этого `mix.AUDIO_SILENCE_FLOOR_V` (1 нВ): трек без сигнала
   (математическая тишина/мёртвые каналы) не нормализуется вовсе.
2. **Проверка 50 Гц «−60 дБ от медианы» → пиковый критерий +10 дБ.**
   Буквальный порог невыполним по построению: бины шума лежат на уровне
   медианы (0 дБ ≫ −60), чистая запись всегда давала бы «провал».
   Неподавленный тон всегда пики на десятки дБ над фоном — ловим его.
   Контроль — **предупреждение** (авто-notch уже применён), не ошибка.
3. **`GET /audio/schema` убран**: контракт — OpenAPI (Pydantic → `gen:api`) +
   `schema_version` в sidecar + `/api/v1/meta`; четвёртая точка версии —
   лишний дрейф.
4. **Пик-контроль мастера — только вниз** (к ТЗ): тихий мастер не раздувается
   к 0.891, нулевой вход не ломает деление.

## Ловушки

- **Память фазы 1**: в рендере живут мастер float64 + текущий стем +
  накопленные WAV-байты (7 файлов). Запись ~2 мин — сотни МБ; часовые
  записи требуют блочного рендера (вне фазы 1).
- **float32 запрещён**: пакеты приводятся к float64 сразу после чтения;
  фаза после 7 квадратов чувствительна к точности.
- **Короткие записи (<20 с)**: FIR-фильтры длиннее сигнала дают краевые
  выбросы (`RuntimeWarning: filter_length is longer than the signal`) —
  у тестовой 4-секундной записи треки могут упираться в клиппинг PCM_24.
  На реальных записях (минуты) артефакт не слышен.
- **ICA может не сойтись** (`ConvergenceWarning`): чистка деградирует
  best-effort с предупреждением в sidecar (`clean`/`warnings`), рендер
  не падает.
- **`sfreq < 500`** (записи 250 Гц): рендер ресемплирует вход к 500, но
  полоса γ-high физически зажата Найквистом исходной записи (`clamped_band`).
- Полифазовый ресемплер несёт **групповую задержку** (~10 исходных
  отсчётов): тест огибающих выравнивает её кросс-корреляцией — это свойство
  фильтра, а не дефект рендера.

## Чек-лист приёмки (M6, наушники, реальная запись)

1. Слышны все 7 полос как различимые слои (критерий нормализации −18 dBFS).
2. Артикуляция (всплески/затухания) треков совпадает с огибающими полос.
3. Нет свиста майнса: 50 Гц × pitch_factor (6.4 кГц при ×128, 1.6 кГц при ×32 —
   в самой чувствительной зоне уха) — авто-notch на входе + предупреждение в sidecar.
4. Нет щелчков на стыках (каждый трек — сплошной, без нарезки).
5. Партитура `.json` открывается и содержит веса/гейны/checksum входа.
