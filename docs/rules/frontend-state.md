# Состояние фронтенда: разделы, сторы, правила

> Правила срезов вьюера — `docs/rules/edf-viewer.md`, диполей — `docs/rules/dipoles.md`,
> ЭЭГ — `docs/rules/eeg.md`. Спецификация экранов — `docs/ui.md` + `docs/ui/*.md`.

## Каркас

- `frontend/src/app/sections/registry.ts` — **единственное место**, где описан состав навигации:
  `home`, `edf`, `eeg`, `dipoles`, `table`, `group` (рабочие) + `settings`, `server` (утилитные).
  Новый раздел = запись в реестре + компонент в `routes.tsx`/`sections/`; `AppShell` сам построит
  рейл, тулс-хедер, правую панель и хоткей.
- Хоткеи разделов идут по порядку рейла: `1` Главная, `2` EDF, `3` ЭЭГ, `4` Диполи, `5` Таблица,
  `6` Групповой; `Space` перехватывается **только** в «Диполях» (воспроизведение кадра).
- Ссылка раздела в рейле — `className` **строкой**: `NavLink`-функция внутри `Tooltip asChild`
  ломается Radix `Slot` (классы склеиваются в текст функции). Активность считает локальная
  `isSectionActive` от `useLocation`, ссылка помечается `aria-current`. Ловит `AppShell.test.tsx`.
- Контролы берём из `shared/ui/` (`FieldRow`, `SegmentedControl`, `SelectField`, `NumberField`,
  `CheckboxRow`, `StatusPill`, `ZoomNavControls`) — свой самодельный контрол плодит расхождения.

## Сторы (zustand, `frontend/src/shared/state/`)

| Файл | Хук | localStorage | Что хранит |
|---|---|---|---|
| `uiStore.ts` | `useUiStore` | `diplock.ui` | активный раздел, открытая панель, свёрнутые секции панели опций (`collapsedPanels`), служебный UI |
| `edfParams.ts` | `useEdfParams` | `diplock.edf` | параметры раздела EDF: каналы, пресеты фильтра, пороги, слои, режим навигатора `navMode` + тип его навигации `navKind` |
| `edfRecording.ts` | `useEdfRecording` | **нет** | сессия записи: паспорт, окно, `navRequest`, `artifactNav` (шаг режима «Навигация»), `epochMarks` — живёт только в текущей сессии браузера |
| `eegParams.ts` | `useEegParams` | `diplock.eeg` | канал, окно, зум, `navMode`, `navKind`, `artifactNav`, палитра/дБ, `eegNav`, отпечаток расчёта |
| `dipoleParams.ts` | `useDipoleParams` | `diplock.dipoles` | слои проекций, срезы, референс-точка, выделенное поле |
| `dipoleCalc.ts` | `useDipoleCalc` | `diplock.dipoleCalc` | задача расчёта, результат, порог «КД», окно FFT, окно уточнения (`refineHalfwinMs`), playback, `seekSeq` |
| `tableParams.ts` | `useTableParams` | `diplock.table` | сортировка и состав колонок таблицы (только отображение) |

Правила:

1. **UI не запускает обработку сам.** Правка параметра только помечает результат устаревшим;
   расчёт стартует исключительно кнопкой (`POST /recordings/{id}/{kind}`) — сначала контролы и
   визуализация, затем подключение расчёта. Фикстуры (`demo*`) подписаны как демо и не выдаются
   за результат. Перенос **отрисовки** на другое ядро или GPU обработкой не является: правило про
   старт расчёта, а не про ускорение картинки (`docs/rules/frontend-perf.md` §4).
2. **Команды идут через состояние, а не через «ручки» компонентов.** Листание/переходы —
   `{command, seq}` с монотонно растущим `seq` (`navRequest` в `edfRecording`, `eegNav`,
   `seekSeq` в `dipoleCalc`); `handledNavSeqRef` инициализируется текущим `seq`, поэтому
   перемонтирование раздела не проигрывает старую команду. **То же правило — для счётчиков-запросов**
   (`fileDialogRequest`: иконка «Загрузить EDF» в шапке → скрытый input рабочей области): потребитель
   реагирует на **изменение** счётчика, а не на «счётчик > 0». Проверка «> 0» выглядит рабочей, но
   счётчик живёт в сторе и не сбрасывается, поэтому каждое повторное монтирование раздела проигрывает
   накопленный запрос — при возврате «ЭЭГ» → «EDF» поверх уже открытой записи выскакивал диалог выбора
   файла (ручная проверка, 18.09.2026; ловит `EdfSection.test.tsx`).
3. **Персистим только то, что переживает перезаход.** Параметры отрисовки, которые не должны
   обесценивать расчёт (зум, шкала, канал, палитра), не входят в отпечатки `eegSignature` /
   `calcSignature`. Временное (центр окна, курсор, разворот трека, «точка под курсором») живёт
   в локальном состоянии компонента. Обратный пример: **свёрнутость секций панели опций**
   персистится (`uiStore.collapsedPanels`, ключ «раздел:заголовок», `Panel`) — это настройка места
   на экране, и перезаход в раздел не должен её терять. Разовый «разворот трека» в `TrackStack`
   остаётся локальным: он живёт до перезагрузки страницы. Обёртка скрытия секции-аккордеона **не
   участвует в раскладке**: вне панели опций её нет вовсе (содержимое — прямые дети секции), раскрытая —
   `display: contents`, свёрнутая — `hidden`. Иначе она рвёт flex-цепочку панели «Треки записи», высота
   области треков начинает течь от контента, и разворот трека ведёт вкладку в бесконечный рост
   (регрессия и фикс 22.09.2026; ловушка — `docs/rules/frontend-perf.md` п. 3.7, форму DOM
   закрепляет `shared/ui/Panel.test.tsx`).
4. **Результат принадлежит записи.** Загрузка новой записи и «Закрыть запись» сбрасывают
   `dipoleCalc` (таблица становится пустой с объяснением, а не показывает прежний результат).
   «Закрыть запись» — **клиентское** действие: серверу ничего не отправляется, файл записи
   удалит TTL-обход реестра.
5. **Ошибки и «устарело» — разными текстами.** Ошибка расчёта и ошибка спектра хранятся
   раздельно; расхождение отпечатков подписывается «параметры расчёта изменены — результат
   не пересчитан» без подмены чисел.
6. Чистая логика — в `shared/lib/*` (без React): геометрия, строки таблицы, парсеры контейнеров,
   интерполяция кадра, опции чарта (`trackOptions.ts`). Компонент рисует, но не считает.
   **Практика разрезки (17.09.2026):** крупный модуль делят по ответственности, а не «по строкам»:
   * чистая арифметика и данные-заглушки — в `shared/lib` (`mriProjections` ↔ `mriDemoShapes`:
     фикстуры собраны в один файл, чтобы удалить их одной операцией, когда появятся реальные данные);
   * части одного экрана — в файлы рядом (`viewer/TrackRow.tsx`, `dipoles/MriProjectionParts.tsx`),
     чтобы хозяин остался сборкой: `TrackStack` — окно, жесты и слои; `TrackRow` — чарт канала;
   * домен стора — в `shared/lib` (`state/dipoleCalc.ts` → `lib/dipoleCalcModel.ts`: типы и дефолты
     параметров, рамки контролов, `FormData`-формы, отпечатки параметров/результата, `CalcJob` и
     чтение задачи, нормализация сохранённых параметров). В сторе остаются значения, действия,
     поллинг и персист — те, кому нужны только правила расчёта, больше не тянут хранилище;
   * после каждой разрезки — `npm run lint && npm run typecheck && npm run test`: тесты обязаны
     остаться зелёными **без правок**, иначе это не перенос кода, а изменение поведения.
7. **Ожидание задачи — одно на весь UI** (`shared/lib/jobPolling.ts`): `waitForJob` (опрос
   `GET /jobs/{id}` до `succeeded` с отдачей прогресса) + токен запуска `createRunToken` +
   `isCancelled`. Своих копий поллинга и своих токенов в сторах быть не должно: новая задача =
   пара методов клиента (`recordingJob(kind)` в `shared/api/client.ts`) + вызов `waitForJob`.
   Отмена — состояние **своей** попытки: `token.next()` (новый расчёт/стадия), `token.cancel()`
   (сброс раздела, «Закрыть запись»), проверка `isCurrent()` после каждого `await`.

- Конструкторы состояния задачи у разделов свои и различаются осознанно: у «Диполей»
  `succeededJob` ставит `epochsDone = epochsTotal` и сохраняет этап, у «ЭЭГ» — текст
  «Спектрограмма готова» и этап `done`, а `failedJob` там сохраняет прогресс. При выносе в общий
  модуль эти отличия нельзя терять: их видит подпись задачи в тулс-хедере.
