# «Знания»: библиотека источников, База знаний и вложения чата

Раздел Консилиума `?view=knowledge` (вкладка «Знания», подвкладки «Источники» и
«База знаний»). API — `/api/v1/knowledge` (`app/api/knowledge.py`), работа —
`app/services/knowledge/`, контракт — `app/schemas/knowledge.py`, миграция
`0021_knowledge_library`. Знания нужны и ролевым экспертам (профессиональные
скиллы), и пользователю как справочник: один и тот же документ служит обоим.

## 1. Носители и лимиты

| Объект | Носитель | Ключ |
|---|---|---|
| Папки («Источники» и вложенные) | БД `knowledge_folders` | `folder_id`, `parent_id` |
| Документы | БД `knowledge_documents` + файл на диске | `document_id`, sha256 |
| Фрагменты (оглавление) | БД `knowledge_chunks` | `chunk_id`, `ordinal` |
| Теги и связи документа | `knowledge_tags`, `knowledge_doc_tags` | имя тега уникально |
| Аннотации разделов | `knowledge_annotations` | `annotation_id` |
| Граф знаний | `knowledge_links` | `link_id`, `confirmed` |
| Вложения нити чата | `agent_thread_attachments` | `attachment_id` |

* Корень файлов — `settings.knowledge_dir` (по умолчанию `data/knowledge`),
  каталог документа — `data/knowledge/documents/<document_id>/`. Пути только из
  `settings`: локальный сервер и ВМ Abacus работают одним кодом, `/home/...` не
  хардкодим.
* Лимиты: `knowledge_max_file_mb` (50 МБ на файл) и `knowledge_max_total_mb`
  (2 ГБ на библиотеку). Превышение — 413, без молчаливого усечения.
* Дедуп по sha256: повторная загрузка того же файла возвращает существующий
  документ (201 с его телом), файл второй раз не пишется.
* Каталог `data/knowledge/` в `.gitignore`: книги и статьи не коммитятся.
  `deploy/backup.sh` библиотеку пока не архивирует (она может занимать до 2 ГБ) —
  это известное ограничение, а не «бэкап всего».
* Удаление документа удаляет строки БД и каталог файлов; удаление папки —
  каскадом её документы.

## 2. Разбор источников

`services/knowledge/extract.py`, тяжёлая работа — в `asyncio.to_thread`.

* PDF — только с текстовым слоем (`pypdf`); сканы сохраняются со статусом
  `empty` и честным пояснением, OCR не подключён.
* DOCX — `python-docx`, XLSX — `openpyxl` (листы как разделы).
* Изображения — статус `empty` (в v1 не распознаются).
* Веб-страница — `httpx` + stdlib `HTMLParser`, только `http(s)`; сохраняется
  текст и заголовок, картинки не тянутся.
* Статусы документа: `ok` (текст извлечён), `empty` (текста нет), `failed`
  (разбор упал, текст ошибки в `error`). Отсутствие текста — не «норма» и не
  повод выдумывать содержание.

## 3. Фрагменты, поиск, граф

* Нарезка — `chunking.chunk_sections` по разделам/заголовкам с перекрытием
  (`knowledge_chunk_chars`, `knowledge_chunk_overlap`); заголовок и страницы
  хранятся во фрагменте, поэтому оглавление читалки — это реальные разделы.
* Поиск всегда считает TF-IDF по фрагментам; если модельный роутер даёт
  провайдера эмбеддингов, добавляется семантика. Режим возвращается честно:
  `hybrid` — работали эмбеддинги, `tfidf` — провайдер недоступен, поиск только
  лексический. Молчаливой подмены режима нет.
* Эмбеддинги — `POST {base_url}/embeddings` выбранного провайдера
  (`knowledge_embedding_model`, батч `knowledge_embedding_batch`); ошибка
  провайдера не ломает загрузку — документ индексируется лексически.
* Граф (`GET /knowledge/graph`) содержит **только подтверждённые** рёбра
  (`confirmed=true`); предложенные ИИ связи в граф не попадают и показываются
  отдельно. Узлы — документы, теги, понятия.

## 4. Вложения чата

`agent_thread_attachments` привязывает к нити `document`/`web`/`report`/
`analysis`. Вложения попадают в промпт только при отправке сообщения
(`services/agent_chat/runner.py` → `store.attachment_context`), и UI заранее
предупреждает, что материалы уходят провайдеру. Отчёт/анализ ЭЭГ передаётся
ссылкой и сводкой, а не всем файлом результата.

## 5. Роль «Ассистент» и Wiki

Встроенная роль `assistant` («Ассистент») отвечает по тексту вики-документации
проекта. Кнопка «Спросить Ассистента» на странице Wiki выгружает текст статьи
в библиотеку (`POST /knowledge/documents`), открывает чат
(`/consilium?view=chat&attach=<document_id>&ask=<вопрос>`), прикрепляет документ
к нити и подставляет вопрос. Если нити ещё нет, она создаётся автоматически.
