## Что считается и почему

Единица выборки — **запись** (`recording_ids`, те же кандидаты `GET /sessions`,
что у пары). Источник точек — **пакет диполей автоотчёта**: последний
прогон `analyses` каждой записи, прошедший фильтры (история прогонов не
UPSERT, §8.4.2). Запись без пакетного прогона — честное предупреждение, не
ошибка.

Расчёт **синхронный** (`POST /group/aggregate`): SQL-выборки и арифметика по
`dipole_points`, ни MNE, ни job-очереди. Кнопка «Считать» — единственный
запуск (правка фильтра в панели не шлёт запросов, правило
`docs/rules/frontend-state.md`).

Фильтры §3.5 (`docs/ui/table.md`): диапазон (`band_key` — обязателен,
валидация по `report_band_catalog`), длина эпохи прогона, отбор точек по GOF,
даты прогона, фильтр строк `names`, `top_n`. **Всё внутри одной полосы**:
GOF и амплитуда момента между полосами не сравнимы (принцип 3
`docs/rules/dipoles.md`) — это подписано в `notes`, которые UI показывает
без правок.

## Два знаменателя share — главная подпись чисел

* **строка** — доля от всех точек выборки в полосе (сравнимо между строками);
* **ячейка** — доля от точек **своей** записи (сравнимо между колонками:
  у записей разное число эпох, только она честна).

Фильтр `names` сужает вывод строк, но не знаменатель; фильтр `gof_min`
сужает выборку точек (и отключает перекрёстную сверку счётчиков — она
считалась без отбора: `report_name_counts` сверяется с точками только при
`gof_min is None`, расхождение → `warnings`).

## Перекрёстная сверка счётчиков

`report_name_counts` того же прогона (`report_runs.analyses_id` = взятому)
сверяются с точками по имени и kind: расхождение — в `warnings` с числами
«в отчёте X, в точках Y» (одна истина на прогон, §8 вариант (а)). Поток
обрезается десятью строками.

## Персист прогонов — определение, не числа

`POST /group/analyses` (201) сохраняет **снимок определения**: фильтры
(`filters` JSON) + отпечаток `params_sig` (sha256 фильтров+состава) +
состав (`group_analysis_members`, порядок выбора = порядок колонок карты).
`GET /group/analyses/{id}` **пересчитывает** агрегат по живой БД тем же
сервисом — история хранит «что считалось», а не устаревающие цифры
(решение-точка плана: честность по текущим данным). Каскад: запись
удалена → членство исчезает (явный DELETE в `recording_store`), прогон —
история и остаётся; чтение при неполной группе — предупреждение
«участников в БД N из M сохранённых». История — **не UPSERT**: повтор =
новая строка.

## Тепловая карта и экспорт

`GroupHeatmap` — чистый SVG над серверными долями, **масштаб 1:1**
(`ResizeObserver`, ширина в `viewBox`, высота = шапка + строки × 22 —
правило `docs/rules/frontend-perf.md` п. 3.7, страж-тест: viewBox
`0 0 1024 148` при двух строках). Шкала линейная 0..max по всей матрице,
цвет — токен `--color-accent` насыщенностью. Экспорт сводки — клиентский
CSV (`shared/lib/groupExport.ts`, RFC 4180, оба словаря + ячейки, полоса
в шапке файла).

## Кластеры диполей (B8, `dipole_clusters.py`)

Воксельная сетка плотности + связные компоненты `scipy.ndimage.label`
(26-связность) — **без новых зависимостей** (выбор против scikit-learn:
`scipy` уже в requirements; замер качества — до смены метода, concept §10).
Метрики B8: центроид MNI, объём (ячейки × куб вокселя), плотность точек/см³,
протяжённость ббокса, доля выборки; **устойчивость** — `session_share`
(доля участников группы, чьи точки вошли в кластер): общая закономерность
обязана воспроизводиться на нескольких записях. Доминирующие ROI — топ-3
структур и полей Бродмана точек кластера.

Параметры `group_cluster_voxel_mm` / `group_cluster_min_points`
(`core/config.py`) входят в паспорт `cluster_params` ответа — числа без
базиса не подписываем (concept §11.3: смена сетки меняет кластеры);
кластер меньше минимума отбрасывается, пустой результат — `warnings`
«Кластеров нет…», а не тихое пустое поле.
