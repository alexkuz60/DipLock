# Данные, кэши и артефакты

> Полная карта «пайплайн → артефакт → носитель → ключ → жизненный цикл» — `docs/data_map.md`.
> Здесь — правила, которые нельзя нарушать при работе с данными.

## Инварианты

1. **`recording_id` — адрес содержимого.** `POST /recordings` считает sha256 в том же проходе,
   что и запись файла; при совпадении отпечатка реестр возвращает **существующую** запись
   (`deduplicated=true`, 200) и удаляет только что записанный каталог. Значит, кэши, ключ
   которых — `recording_id`, не могут отдать данные чужого файла, и добавлять sha256 файла
   в сигнатуры кэшей не нужно. Отпечаток и паспорт лежат в сайдкаре `recording.json`
   (дедуп переживает рестарт), легаси-каталоги без сайдкара чистятся
   `backend/scripts/dedupe_recordings.py`.
2. **Шесть дисковых кэшей, один отпечаток ассетов** (`docs/data_map.md`, раздел «Носители»):
   `signals` / `spectra` / `spectrograms` — по записи, живут и умирают вместе с ней;
   `surface` / `mri` / `contours` — по версии ассета, не чистятся по TTL. Входы трёх ассетов
   (номер сборки, параметры, файлы данных) объявлены **в одном месте** — `services/asset_versions.py`
   (п.12), и версия считается одной функцией `fingerprint(kind, subjects_dir)`. Меняете сборку
   тома/атласа/меша — **поднимайте версию там**, иначе на диске подхватится старый кэш.
   Седьмой кэш — RAM-кэш подготовленного сигнала (п.10): диска он не касается, но живёт и умирает
   вместе с записью. Рядом с шестью дисковыми кэшами лежит `journal.jsonl` — это **не** кэш, а журнал
   шагов (п.11). Не путайте версию ассета с **отпечатком расчёта** (`topomap_version`, `grid_version`):
   второй собирается из параметров задачи и меняется автоматически.
3. **Чистка кэшей привязана к вытеснению записи, а сироты убирает обход.** `_drop_signal_cache`
   (signals, spectra, spectrograms + RAM-кэш сигнала) срабатывает при вытеснении записи — TTL 24 ч
   (`RECORDINGS_TTL_HOURS`) и лимит 10 (`RECORDINGS_HISTORY_LIMIT`) применяются при обращении к реестру
   (`_drop_expired`). Кэш записи, которую реестр уже не знает, никто бы не убрал — этим занимается
   `services/orphans.py` (`sweep_orphans`, п.13): обход «каталоги данных против реестра» при старте
   приложения и по требованию из скрипта.
4. **Кэш — оптимизация, а не источник истины.** Сбой записи кэша логируется и не ломает расчёт
   (`cache_write`: запись во временный файл + `os.replace`). Любой кэш обязан пересчитываться
   при промахе, а не отдавать «что-нибудь».
5. **Бинарные контейнеры вместо JSON** там, где данных много: `DPS1` (сигналы: magic +
   uint32 LE + JSON-заголовок + float32, канало-мажорно) и `DPS2` (сетка спектрограммы:
   частото-мажорно). Формат меняется **синхронно** в трёх местах: сервис-производитель,
   `backend/app/schemas/analysis.py` (заголовок) и `frontend/src/shared/lib/signalFrame.ts`
   (парсер). Единицы: сигналы — всегда мкВ, спектрограмма — дБ.
6. **Тяжёлые ассеты — не в `/analyze`.** Меш fsaverage, индексы BA, том МРТ и объёмы атласа
   живут в отдельных кэшируемых эндпоинтах (`/surface*`) с ETag/304; внутри анализа их нет.
7. **Результаты расчётов не кладём рядом с кэшем ассетов.** Результат задачи отдаётся по `result_url`
   и лежит в двух местах: в RAM (`job_manager`) и **файлом задачи**
   `results_dir/jobs/<job_id>.json` (`services/job_store.py`, п.14). На диск идут только артефакты,
   переживающие процесс: бинарные сетки, PNG топокарт, файлы задач, `data/results/*.json`
   (legacy `/analyze`) и БД `sessions`/`epochs`/`dipoles`.
   **Связь «диполь → эпоха» в БД настоящая** (F21 закрыт 17.09.2026, этап 7): `save_analysis_to_db`
   вставляет строки `epochs` (все нарезанные эпохи, включая отброшенные; мощности по диапазонам —
   NULL, если PSD не считался) **до** диполей и переводит `epoch_index` → id после `flush`; лишний
   `epoch_index` даёт `epoch_id=NULL`, а не висящую ссылку. Пишет по-прежнему только legacy-ветка
   (`/analyze`, `/jobs`) — разделы UI считают в RAM. Пробел остался продуктовый: read-API и перенос
   результатов UI в БД (Фаза 4/5).
8. **`None`, а не `NaN`** в любом JSON-ответе: неизмеренная величина = `null`, UI рисует «—».
9. **Один модуль на все дисковые кэши — `services/cache_store.py`.** Путь — `cache_path(cache_dir, ...)`,
   чтение — `cache_read`, запись — `cache_write(path, data, label=...)` (сама делает `makedirs`,
   временный файл и `os.replace`, сбой логирует и возвращает `False`), очистка — `cache_clear(cache_dir, ...)`.
   Своей копии «временный файл + `os.replace`» в новом сервисе быть не должно: до этапа 2 (17.09.2026)
   таких копий было шесть, и они разошлись. Два следствия, которые модуль держит сам: кэш не бывает
   «наполовину записан» и промах записи не бросает исключение. `cache_clear` **требует** часть пути —
   вызов без частей запрещён, чтобы опечатка не снесла весь `data/cache`. Исключение осознанное —
   сайдкар записи (`recordings.write_sidecar`): он не кэш, а носитель дедупа, и у него своя семантика
   отказа. Обратный случай — файл задачи (`job_store`, п.14): тоже не кэш, но осознанно пользуется
   `cache_write` как готовой атомарной записью, чтобы не заводить вторую копию «tmp + `os.replace`».
10. **Кэш подготовленного сигнала — RAM и копия наружу.** `services/prepared_signal.prepared_raw` —
   единственный путь «прочитать EDF и подготовить сигнал» для задач записи (`preprocess`, `spectral`,
   `spectrogram`, `dipole_scanner`); `load_edf` остаётся чистой функцией загрузчика (её зовут legacy
   `/analyze` и тесты). Три правила этого кэша: ключ — **все** параметры, влияющие на сигнал
   (единицы, каналы, референс, полоса, notch), но **не** sha256 файла и не строка `reference`
   из формы (эффективный референс — список каналов, `average` при пустом); наружу отдаётся
   `raw.copy()`, потому что `segment_epochs` мутирует аннотации на полученном сигнале; вытеснение
   записи чистит кэш (`_drop_signal_cache` → `clear_prepared_cache`). Размер — `PREPARED_SIGNAL_CACHE_SIZE`
   (`0` — выключить): один набор это float64-данные записи (9.4 МБ на 130.7 с × 500 Гц × 18 кан.,
   86.4 МБ на 20 мин).
11. **Журнал шагов — диагностический артефакт, а не кэш.** `services/journal.py` пишет
   `data/cache/journal.jsonl` (каталог тот же, что у кэшей — общий `CACHE_DIR`, семантика другая):
   у записи нет ключа, она ничего не «отдаёт» и не пересчитывается. Три следствия: журнал не
   участвует в `cache_clear`/`_drop_signal_cache` (его **не** чистят вместе с записью) и в ETag/304;
   он не влияет на результат и **не может сломать расчёт** — сбой записи логируется и гасится, как
   у кэша (п.4); свой объём он ограничивает сам ротацией по `JOURNAL_MAX_BYTES` (не больше двух
   поколений файла, `JOURNAL_ENABLED=false` выключает записи целиком). Читает его только
   `GET /journal` (хвост файла) — это диагностика разработчика, UI журнал не показывает.
12. **Версии ассетов — один модуль и один отпечаток.** `services/asset_versions.py` объявляет входы
   всех трёх ассетов (номер сборки `SURFACE_VERSION`/`MRI_GRID_VERSION`/`CONTOUR_VERSION`, параметры
   сборки, файлы данных FreeSurfer) и считает отпечаток `fingerprint(kind, subjects_dir)` =
   `sha256(kind:version + params + size/mtime файлов)[:16]`. Три правила: сервисы
   (`surface_cache.surface_version`, `mri_slices.mri_version`, `atlas_contours.contour_version`) —
   только тонкие вызовы, своей копии хеширования в них нет; меняете **данные** — отпечаток поднимется
   сам, меняете **шаги сборки** — поднимайте `version` в этом модуле; входы и снапшот
   `tests/test_asset_versions.py::test_snapshot_of_asset_inputs` правятся в одном срезе, иначе тест
   падает (это его работа — напомнить про версию). Отпечаток расчёта (`topomap_version`,
   `grid_version`) — не ассет: он собирается из параметров задачи и подъёма не требует.
13. **Сироты убирает обход, а не кнопка.** `services/orphans.py` (`sweep_orphans`) сносит три вида
   мусора: каталоги загрузок без живого владельца (через `RecordingRegistry.prune_orphans`), кэши
   `signals`/`spectra`/`spectrograms` и файлы задач записи, которой нет **ни** в реестре, **ни** в
   каталоге загрузок, а также файлы задач сверх `JOBS_HISTORY_LIMIT`. Вызовы: lifespan приложения
   (`main.py`) и `backend/scripts/dedupe_recordings.py --prune`. Правила: ассеты
   (`surface`/`mri`/`contours`) и `journal.jsonl` обход не трогает; уборка best-effort — исключение
   логируется и гасится (п.4), потому что служебная операция не имеет права мешать старту; новых
   «чистильщиков по расписанию» не заводим — один проход на старте плюс скрипт для живого процесса.
14. **Файл задачи — не кэш, но атомарная запись общая.** `services/job_store.py` пишет
   `results_dir/jobs/<job_id>.json` при завершении задачи (успех и ошибка) и `JobManager.restore`
   поднимает записи в историю при старте: без этого после рестарта процесса `GET /jobs/{id}` и
   `result_url` мертвы. Четыре правила: ключа у файла нет (имя = `job_id`), он не участвует в
   `cache_clear`/ETag и не «пересчитывается при промахе»; результат больше `JOB_RESULT_MAX_BYTES`
   не сохраняется — задача остаётся в истории с флагом `result_omitted`, а API отвечает 409
   «результат не сохранён» (текст отличается от «ещё не завершена»); запись идёт через
   `cache_store.cache_write` — единственную копию «временный файл + `os.replace`» (сбой не роняет
   задачу); формат версионируется (`RECORD_VERSION`), файл чужой версии просто не поднимается в
   историю. `JOB_STORE_ENABLED=false` возвращает прежнее поведение «результат живёт в сессии».
15. **Дорогие объекты читаются один раз на процесс (этап 7).** BEM-решение fsaverage —
   `dipole_fitter._read_bem` (`lru_cache` по **пути файла**, не по объекту настроек: `Settings`
   не хешируется), том атласа — `atlas_contours.load_volumes` (`lru_cache` + дисковый кэш
   `contours`), BA-центры и transform — тоже `lru_cache`. Правило простое: если чтение файла
   FreeSurfer попадает в цикл по эпохам/точкам, это дефект стоимости (F19), а не «медленная машина» —
   выносите чтение из цикла в кэш с ключом-строкой. Анатомия точки в обоих режимах расчёта берётся
   **одним** источником (`atlas_contours.structure_at`), чтобы кэш был один и подписи не расходились.



## Что делать при добавлении нового кэша (чек-лист)

- [ ] Ключ-сигнатура собирается из **всех** параметров расчёта (включая список каналов,
      reference, reject, параметры фильтра, окно/перекрытие) — как `spectrum_signature`.
- [ ] Сигнатура едет в URL (`?v=`/ETag) и в `result_url` — иначе клиент «залипнет» на старых данных.
- [ ] Путь — под `settings.cache_dir` (никаких `/home/...` в коде), внутри — подкаталог по сути
      данных и `recording_id`/версия ассета. Запись/чтение/очистка — только через `services/cache_store.py`.
- [ ] Добавлена функция `clear_*_cache` (обёртка над `cache_clear`) и вызов из `_drop_signal_cache`,
      если кэш относится к записи; для RAM-кэша — свой `clear_*` в том же вызове.
- [ ] Если это **ассет** (собирается из файлов FreeSurfer) — входы и номер сборки идут в
      `services/asset_versions.py`, отпечаток считается `fingerprint(kind, subjects_dir)`, снапшот в
      `tests/test_asset_versions.py` обновлён (п.12).
- [ ] Строка в `docs/data_map.md` (пайплайн → артефакт → носитель → ключ → жизненный цикл → объём).
- [ ] Тест: попадание в кэш после промаха + ETag/304 (см. `docs/rules/tests.md`).
- [ ] Новый носитель под `results_dir` (не кэш: файл результата, отчёт) — строкой в `docs/data_map.md`
      §0/§8 и попадает под обход сирот, если привязан к записи (п.13).
