# Раздел «ЕмоЛаб» — прогноз эмоциональной реакции на аудиотрек

> Постановка владельца 20.10.2026. Цель: данные, собранные из аудио,
> сравнивать с записанной ЭЭГ-сессией прослушивания этого аудио (отдельная
> задача; привязка к эпохам 2000 мс для нижней дельты 1…2 Гц — позже).
> Правила ведения документации — `docs/rules/docs.md`; связанная
> экспериментальная механика — `docs/rules/neuromusic.md` (оттуда переиспользуются
> блоки кода).

## Шаг 1 (20.10.2026): анализ внешнего аудиотрека

Пользователь открывает **внешний** аудиофайл (wav/mp3) — он не синтезируется из
ЭЭГ. Раздел собирает данные для прогноза эмоциональной реакции на прослушивание
и рисует ту же механику «Нейромузыки»:

1. **Открытие файла** — кнопка «Открыть аудио» в тулс-хедере (`<input
   accept=".wav,.mp3">`), файл живёт в памяти страницы (`File` → `blob:` URL).
2. **Пирамида превью + волна-бабочка** — трекер `emolab/EmoLabTracker.tsx`
   (адаптация `neuromusic/WaveTracker.tsx`): пики «бабочки»
   (`waveformView.filePeaks`) кэшируются **по уровням зума ×1/×10/×100**
   (пирамида превью: уровень пересчитывается при смене ширины/буфера, а не на
   каждый зум), +полуволна левого канала вверх, −правого вниз, линейка времени,
   позиционер, перемотка кликом/драгом, слайдер прокрутки.
3. **Плеер** — движок `shared/lib/neuromusicPlayer.ts` в простом режиме
   (`spatial: false`, `tracks: []`): играет **локальный файл** (blob URL),
   сервер для воспроизведения не нужен. **Скорость только ×1** — контрол
   «Скорость» не показывается (`rate` фиксирован).
4. **Анализ на сервере** — **те же** функциональные блоки «Нейромузыки»:
   * быстрый ФФТ — `services/audio_render/emo_radar.emo_frames`: окно 32768,
     сдвиг 32000, 14 октавных блоков → 7 счётчиков,
     дБ-шкала `db_relative` (−60…0 дБ → 0…100 % R); сетка кадров — по шагу 2
     (моно 32000 Гц → кадр **1 с**, см. ниже);
   * VAMP-плагины Соник Аннотатора — `services/audio_render/vamp_analysis`:
     **карта темпа** (Tempo and Beat Tracker) и **карта аккордов** (Key
     Detector; «аккорд» — термин UI для сегмента тональности, как в
     «Нейромузыке»).
5. **Звезда-полигон** — компоненты «Нейромузыки» **без правок**:
   `RadialChart` (7 лучей, облако/суммарная доминанта, метка темпа),
   `keyRotation` (вращение по аккордам, δ=π/42), `tempoCorrection`
   (темп-коррекция длин лучей), `EmoCounters` (пиули «Аккорд»/«Темп»).
   Поверх волны — те же оверлеи: вертикали смены аккордов (`drawKeyLines`) и
   ступени темпа (`drawTempoSteps`).

**Что осознанно вне шага 1:** постпроцессор пространственной обработки
(spatial-audio) и файлы отфильтрованных аудиополос не используются; опции
раздела (окно анализа и шаг динамики, набор маркеров аффективного фона,
привязка к стадиям препроцессинга) — позже, после уточнения постановки.

## Шаг 2 (20.10.2026): моно 32000 Гц, кадр звезды = 1 с, VAMP на моно-файле

Уточнение владельца: моно-файл анализа в этом разделе — **32000 Гц** (а не
48 кГц контракта рендера «Нейромузыки»). Окно FFT 32768 со сдвигом 32000
(перекрытие 768 = 32768 − 32000) даёт кадр анимации звезды длиной **ровно
1 с** (кадр = 32000 сэмплов = 1 сек): сетка `t_sec` кадров — 0, 1, 2…,
лучи/вращение/темп между кадрами интерполирует общая механика
`emoRadar`/`keyRotation`/`tempoCorrection` (без правок — параметризована
`fs_audio`/`hop_samples` контракта).

* **VAMP** — во временный **моно** WAV (32000 Гц) прогоняются обе карты:
  темпа (tempo-трансформ сам фиксирует rate 44100, вход ресемплирует
  sonic-annotator) и аккордов (Key Detector, «ЕмоЛаб»-трансформ ниже).
* **Ловушка Key Detector**: плагин диктует step/block ≈ 512 мс, приведённые к
  степени двойки, и отвергает другие («step/block sizes … differ from
  required …» → карта молча пропадает, best-effort): при 32 кГц нужны
  **16384/16384**, при 44.1/48 кГц — 32768/32768. Поэтому у «ЕмоЛаб» свой
  трансформ `qm-keydetector-key-32k.n3` (`vamp_analysis.KEY_TRANSFORM_NAME_32K`:
  rate 32000 + step/block 16384); общий `qm-keydetector-key.n3` рендера
  «Нейромузыки» (мастер 48 кГц) не тронут.
* **Синхронизация плей ↔ анимация** — механизм «Нейромузыки» без правок:
  rAF `RadialChart` читает `getActivePlayer().position` →
  `interpolatedRays`/`interpolatedRotation`/`interpolatedTempo` по сетке
  `hopSec = 1 с`; пауза/перемотка — слайд к позиции (тест
  `EmoLabSection.test.tsx`: позиция 0/3/2.5 → лучи кадра 0/3/середины).
* **Отложено (отдельная задача):** привязка к ЭЭГ-эпохам 2000 мс, чтобы
  захватить нижнюю дельту (1…2 Гц), и сравнение с записанной сессией
  прослушивания.

## Шаг 3 (21.10.2026): гамма полос радара, таблица аккордов, опции анализа

1. **Гамма цветов секторов графика-радара** — та же, что у базовых полос
   спектра в «Диполях» (`shared/lib/bandColors.ts`: красный, оранжевый,
   жёлтый, зелёный, циан, голубой, розово-фиолетовый): дуги секторов 1…7
   вдоль круга-границы (`data-part="sector-arc"`) и залитые круги **⌀10 px**
   в центрах вершин полигона-звезды (`data-part="vertex-dot"`) красятся
   цветом полосы своего луча (δ…γ-high, `BAND_ORDER` + `BAND_HZ`
   `neuromusic/bandLabels.ts`). Рисует `RadialChart` пропом `bandColors`
   (дефолт пропа — выключен; с 21.10.2026 его включает и «Нейромузыка» —
   см. п. 5).
2. **Панель «Параметры анализа»** (`EmoLabPanel.tsx`, панель больше не
   read-only):
   * под строкой «Карта аккордов VAMP Key Detector» — **таблица аккордов**:
     «Время» (`formatTime` с десятыми), «Аккорд» (метка QM без слова лада:
     «C major» → «C»), «Тип (минор/мажор)» (по коду QM: 1…12 — мажор,
     13…24 — минор); `key_track` нет — «Нет данных»;
   * параметр **«Динамический диапазон»** шкалы лучей звезды — окно
     **−96…0 / −60…0 / −40…0 дБ** (−60 — шкала контракта, `db_floor` кадров).
     Перенос процентов лучей — `emoRadar.raysDbRange` в UI (анализ не
     пересчитывается; кадры пишутся с порогом −60 дБ, поэтому в окне −96…0
     всё глубже −60 дБ остаётся 0 % — данных ниже порога в кадрах нет);
   * под строкой «Карта темпа VAMP Tempo and Beat Tracker» — **чекбокс
     «Учитывать темп при расчёте лучей звезды»**: выкл — радиусы вершин без
     темп-коррекции значений VAMP (`tempoRays` → проп `RadialChart`), метка
     темпа на оси Y при этом продолжает показывать bpm кадра;
   * состояние опций — стор `emolab.ts` (`dbRangeDb` = 60 по умолчанию,
     `tempoRays` = true), пропы `RadialChart` — `dbRangeDb`/`tempoRays`;
   * прочие инфо-строки параметров (частота моно-файла, окно FFT, сдвиг
     окна, лучи полигона, скорость плеера) **удалены**.
3. **Линия темпа над волной плеера — на шкале темпа радара** (поправка
   21.10.2026): вертикальный масштаб ступеней темпа (`drawTempoSteps` с
   функцией высоты `radarTempoStepY` из `neuromusic/tempoCorrection.ts`) —
   **0 сигнала волны (середина графика) = 120 bpm, нижняя граница графика =
   60 bpm, верхняя = 240 bpm** (та же логарифмическая ось `tempoY`, что у
   метки темпа на радаре: при одном bpm линия над волной и засечка радара
   стоят на одной высоте). Без `stepY` — авто-шкала min…max (прежний дефолт
   `drawTempoSteps`).
4. **Круги вершин полигона** — **⌀10 px** (поправка 21.10.2026 к шагу 3:
   было ⌀5 px).
5. **«Нейромузыка» — аналогично** (правка 21.10.2026): `WaveTracker` рисует
   ступени темпа над волной на той же шкале радара (`radarTempoStepY`),
   `RadialChart` раздела включает `bandColors` (дуги секторов + круги вершин
   ⌀10 px); опции `dbRangeDb`/`tempoRays` раздел не задаёт (шкала контракта,
   темп-коррекция лучей включена).

## Шаг 4 (21.10.2026): график «Эмограмма» в табе секции «Визуализация»

Лучи полигона-звезды, **развернутые по шкале времени** звучания аудиотрека
(`emolab/Emogram.tsx`, математика `emolab/emogram.ts`). Строится из **тех же
доминант кадров «Эмо»**, что облако радара (динамический диапазон `dbRangeDb`,
вращение по аккордам, темп-коррекция `tempoRays` — пропы радара); backend не
менялся.

* **Табы секции «Визуализация»** (правка владельца 21.10.2026): графики
  разделены по табам (`shared/ui/SegmentedControl`, layout `inline`):
  **«Звезда»** (звезда-полигон + пиули «Аккорд»/«Темп») и **«Эмограмма»**,
  каждый занимает всю высоту секции — звезда не мельчает под вторым
  графиком. Новые аналитические графики добавляются следующими табами
  (`VIZ_TABS` `EmoLabSection.tsx`); активный таб — стор `emolab.ts`
  (`vizTab: EmoVizTab`, сбрасывается в «Звезда» при `reset()`).

* **Шкала Y справа «Эмо»** — 14 текстовых значений снизу вверх (`EMO_LABELS`:
  страх, трагедия, скорбь, отвращение, депрессия, смирение, безразличие,
  интерес, уверенность, радость, энтузиазм, вдохновение, эйфория, агрессия) и
  **14 горизонтальных линий разметки** с шагом **π/7** по углу (14 · π/7 = 2π).
  Низ графика = угол `π/2 + π/7` (начало 1 сектора звезды,
  `radialChart.SEGMENT_START`), отсчёт — против часовой на полный круг 2π:
  доля высоты угла θ — `((θ − (π/2+π/7)) mod 2π)/2π` (`emoAngleFraction`);
  линия «страх» — внизу (совпадает с началом 1 сектора), шов круга (между
  «агрессией» и «страхом») — у верхней кромки. Каждый цвет сектора радара
  (2π/7) покрывает ровно **2 эмоции**.
* **Сетка** — 14 горизонталей разметки эмо-реакции + вертикали шкалы времени
  звучания (круглые секунды `eegView.timeTicks`, подписи м:СС `formatTime`).
* **Экспрессия Эмо** (`data-part="express-bar"`) — вертикальные столбики от
  низа до значения радиус-вектора доминанты кадра: шкала Y 0…1 в динамическом
  диапазоне радиус-векторов (`radiusFrac` = |r|/R, доминанта зажата к
  кругу-границе). Ширина столбика — кадр (1 с) с зазором `EMO_BAR_GAP_PX` 1 px;
  **цвет столбика — сектор Эмо** его угла доминанты (правка владельца
  21.10.2026: тот же цвет сектора, что у ступени кадра), заливка 35 %
  прозрачности — ступень «Динамики» читается поверх.
* **Динамика Эмо** (`data-part="emo-step"`) — горизонтальные линии-ступени
  длиной **1 с** (= 1 кадр анимации звезды) на высоте угла доминанты кадра;
  **цвет ступени = цвет сектора радара**, в котором лежит угол
  (`radialChart.SECTOR_COLORS` + `sectorIndexOf`).
* **Курсор позиции плеера** (`data-part="playhead"`) — вертикаль по
  `getActivePlayer().position`: `rAF` + императивный ref (приём `RadialChart`).
* Кадры без радиус-вектора (тишина — доминанта в центре) не рисуются ни
  столбиком, ни ступенью (угол не определён); без кадров — только сетка и
  подписи. Размер полотна — по замеру `ResizeObserver` (jsdom → дефолт
  `EMO_VIEW_W`×`EMO_VIEW_H` 640×200, тесты видят «честные» пиксели).

## Шаг 5 (21.10.2026): Segmenter — сегменты трека для визуально-слухового контроля

Ещё один VAMP-плагин в «Эмо» — **Segmenter** (QM Vamp Plugins, `qm-segmenter`):
делит трек на последовательность однородных сегментов. **Данные пока не
участвуют в расчётах** (лучи/вращение/темп не трогают) — они нужны для
визуально-слухового контроля «Емо»-анализа:

* **Параметры по умолчанию изменены** (постановка владельца) в трансформе
  `vamp/transforms/qm-segmenter-segmentation-32k.n3`: **Number of
  segment-types = 8** (`nSegmentTypes`, дефолт плагина 10), **Minimum segment
  duration = 2 с** (`neighbourhoodLimit`, дефолт 4 с); Feature Type —
  дефолтный Hybrid (Constant-Q).
* **Выход плагина** — сегменты `[{t_sec, segment_type, name}]` в контракт
  `emo.json` (`segment_track` + `segment_source`, **`schema_version` 5**):
  `segment_type` — тип сегмента (1…8), `name` — **имя сегмента** (метка
  плагина A, B, C… по типу: 1 → A, 2 → B, …; пустая метка достраивается
  буквой по типу).
* **Таблица в «Опциях»** (`EmoLabPanel`, под строкой «Сегментер»): поля
  **«Время»** и **«Имя сегмента»** — по строке на сегмент (`segment_track`
  нет — «Нет данных — сегменты не рассчитаны»).
* **Вертикальные линии с метками имён A, B, C…** поверх волны плеера
  (`waveformView.drawSegmentLines` в `EmoLabTracker`) и на «Эмограмме»
  (`data-part="segment-line"`/`"segment-label"`, метка у верха графика):
  линия — на начало каждого сегмента (включая 0.0 — это начало первого
  сегмента «A»), метки разреживаются по `SEGMENT_LABEL_MIN_PX` 14 px
  (плотные сегменты не сливают подписи). Цвет — `--color-nm-segment`.

## Шаг 6 (21.10.2026): карта аккордов — Chordino «Chord Estimate» взамен QM Key Detector

Постановка владельца: QM Key Detector **пропускал смены аккордов и часто
ошибался**; заменён на **Chordino** (NNLS Chroma, M. Mauch; вывод `simplechord`
«Chord Estimate») — он умеет сложные аккорды («C7», «Dm6», «Gaug»,
«Ebm6»), и его смены аккордов точнее.

* **Точные имена в UI**: `label` сегмента `key_track` — имя аккорда Chordino
  **как есть**; таблица аккордов в «Опциях» (колонка «Аккорд»), оверлей
  волны (`drawKeyLines`), пиуля «Аккорд» показывают «G7», «Dm6», «Ebm6» —
  без урезаний.
* **Звезда — только тональность + лад**: `key_code` (1…24) считается из
  корневой ноты и мажора/минора, уточнения интервалов игнорируются
  («C7» → C мажор, «Dm6» → D минор, «Gaug» → G мажор, «Cdim» → C минор —
  dim сводится к минору по малой терции, aug/sus — к мажору);
  `keyRotation`/математика звезды **не менялись** (маскинг кодов тот же).
* **«N» (нет аккорда) отбрасывается**: не порождает сегмент — звезда держит
  прошлое вращение, в таблицу не попадает; подряд идущие одинаковые метки
  схлопываются.
* **Трансформы**: `chordino-simplechord-32k.n3` («ЕмоЛаб», моно 32 кГц,
  step 3200 = 0.1 с, block 16384) и `chordino-simplechord.n3` (рендер,
  мастер 48 кГц, step 4800, block 24576); параметры плагина — дефолты
  MIREX (useNNLS=1, useHMM=1, boostn=0.1). QM-трансформы
  `qm-keydetector-key*.n3` удалены.
* **Контракт `emo.json` → v6** (`key_source` =
  `vamp:nnls-chroma:chordino:simplechord`): кадры v5 отвергаются `parse_emo`
  → честный пересчёт («ЕмоЛаб») / добивка из `master.wav` (рендер) — старые
  метки «B major» заменяются аккордами автоматически. Структура
  `AudioKeySegment {t_sec, key_code, label}` не менялась.

## Backend (`services/emolab/`)

| Модуль | Что делает |
|---|---|
| `track_input.py` | приём байтов wav/mp3: зонд `sf.info` (400 на «не аудио»/пусто/длиннее `MAX_DURATION_SEC` 1800 с), декод, **моно `(L+R)/2`** (>2 каналов → первые два), **ресемпл в 32000 Гц** (`ANALYSIS_FS`, шаг 2: кадр звезды = 32000 сэмплов = 1 с), `wav_bytes` — моно WAV для VAMP |
| `track_analysis.py` | оркестрация + статусы: `start_analysis` (sha256 содержимого = `track_id`, хвост 32) → фоновый поток (семафор `MAX_PARALLEL` = 2; **в отличие от рендера — параллельно**), payload = `emo_frames` + VAMP-карты (аккорды, темп, сегменты); in-memory статус (TTL 15 мин) восстанавливается из манифеста после рестарта; **устаревший кэш** (`emo.json` не парсится в текущую версию контракта) — промах: файл пересчитывается заново |
| `store.py` | дисковый кэш `cache_dir/emolab/{track_id}/`: `source.{wav|mp3}` + `emo.json` + `manifest.json`-коммит; чистка своя — `sweep_tracks` (TTL 7 дней + максимум 24 трека, LRU по mtime) |

**API** (роутер `api/emolab.py`, префикс `/api/v1/emolab`; паттерн рендера
«Нейромузыки» — 202 + поллинг, без job-системы):

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/emolab/analyze` | 202 `EmoAnalyzeOut` `{track_id, status, cached, filename, duration_s}`; multipart `file`; 400 — не wav/mp3, битый, длиннее 30 мин; 413 — > лимита загрузки; повтор того же содержимого — `cached=true`, `status=succeeded` |
| GET | `/emolab/{track_id}/status` | `EmoTrackStatus` `{status, stage, pct, message, error, duration_s}`; 404 — нет |
| GET | `/emolab/{track_id}/emo` | **`AudioEmoOut`** (контракт рендера v5: `frames`, `key_track`, `tempo_track`, `segment_track`); 404 — нет, 409 — идёт/упал |

## Ловушки

- **Воспроизведение и волна — из локального `File`** (`blob:` URL →
  `NeuromusicPlayer.load({spatial: false})`); на сервер уходит копия для
  анализа. Механика отрисовки — единая `shared/lib/waveformView.ts`, копий
  математики нет (дублируется только компонентная обвязка трекера — осознанная
  адаптация `WaveTracker` без 3D/полос).
- **Ресемпл в 32000 Гц** (шаг 2) — не «косметика»: параметры ФФТ (32768/32000)
  дают кадр звезды **ровно 1 с** только на 32 кГц — сетку синхронизации с
  анимацией и будущими эпохами ЭЭГ-сессии. `fs_source`/`fs_analysis`
  сохраняются в манифесте.
- **Chordino диктует hop карты аккордов** (ловушка 21.10.2026): step 0.2 с —
  HMM-сглаживание плагина «съедает» смены аккордов (C+Am сливаются в один
  сегмент), step **0.1 с** (3200 при 32 кГц, block 16384) — точные смены.
  Трансформ «ЕмоЛаб» — `chordino-simplechord-32k.n3`, рендера —
  `chordino-simplechord.n3`; живой прогон цепочки — integration-тест
  `test_live_vamp_chain_on_32k_mono`, живой прогон аккордов —
  `test_chord_track_live_sonic_annotator` (C/Am/G7 по 4 с).
- **Segmenter диктует step/block своей частоты** (32 кГц → step 6400 = 0.2 с,
  block 19200 = 3 × step; «supplied step size … differs from required …» →
  молча нет сегментов) — трансформ `qm-segmenter-segmentation-32k.n3`.
  CSV-вывод сегментера — **с длительностью**: `[имя_файла,] начало,
  длительность, тип, "имя"` (не как у Chordino); имена A, B, C… — метки
  **самого плагина** по типу (1 → A, 2 → B, …), а не выдумка UI.
- **mp3 читает libsndfile 1.2.2** (бэкенд) и браузер (`decodeAudioData`);
  возможна расхождение длительности на доли секунды (encoder delay mp3) —
  учитывать при будущей привязке к ЭЭГ-сессии.
- **«Аккорд» = сегмент Chordino** (терминология UI «Нейромузыки»): в таблицу
  и оверлеи идёт **точное имя аккорда** («G7», «Ebm6», «Gaug»), для вращения
  звезды из него берётся **только корневая нота + лад** («C7» → C мажор,
  «Dm6» → D минор, dim → минор, aug/sus → мажор); «N» (нет аккорда)
  сегментом не становится — звезда держит прошлое вращение.
- **VAMP best-effort**: sonic-annotator недоступен/упал → `key_track`/
  `tempo_track`/`segment_track` = `null`, вращение/коррекция в UI нулевые,
  таблица/линии сегментов без данных, кадры не падают (та же семантика, что
  у рендера).
- **Смена версии контракта «съедает» старый кэш**: `parse_emo` отвергает
  `emo.json` прошлой версии (v5 при контракте v6) — `start_analysis` ловит
  это и **честно пересчитывает** трек (`_emo_cache_valid`); без проверки
  повторное открытие файла навсегда осталось бы без сегментов/темпа.
- **Кэш не привязан к записям** — его нет в `orphans.RECORDING_CACHE_SUBDIRS`:
  чистка своя (`sweep_tracks`), сироты и квота записи его не трогают.
- **Тесты**: глобальный `afterEach` (`vitest.setup.ts`) зовёт
  `vi.restoreAllMocks()` — реализации `vi.fn()` моков перепривязываются в
  `beforeEach` (приём `NeuromusicSection.test.tsx`).
