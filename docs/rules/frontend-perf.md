# Производительность клиента: замеры и правила отрисовки

> Появился 19.09.2026 вместе со срезом **P0+P1** аудита производительности клиента
> (`audit-2026-09.md` §7): сначала измерения, затем чистые выигрыши рендера — без нового API и без
> изменения семантики. Перенос отрисовки в **воркеры / OffscreenCanvas / WebGL** и **клиентский
> пересчёт** научных чисел — отдельные срезы (§7.2 аудита), правил здесь пока нет: они появятся
> вместе с кодом (правило `docs/rules/docs.md` п.2).

## 1. Замеры: правило A5 распространяется и на клиент (P0)

Серверный журнал шагов (`services/journal.py`, формат — `docs/data_map.md` §9) делает измеримыми
**расчёты**; про клиент он не знает ничего. До 19.09.2026 любая правка отрисовки была «кажется, стало
быстрее». Инструмент — `frontend/src/shared/lib/perf.ts`:

| Функция | Что делает | Зачем |
|---|---|---|
| `perfCount(name, times?)` | считает **событие** (0 мс в сводке) | «растр пересобрался N раз», «огибающая пересчиталась N раз» |
| `perfSpan(name, body)` | меряет синхронный блок, возвращает результат; меряет и при исключении | «сколько стоит сборка растра» |
| `perfStats()` / `perfEntries()` / `perfReset()` | сводка / кольцо `PERF_RING_CAPACITY = 240` / сброс | приоритет по суммарному времени, а не по частоте |

Сводка доступна из **консоли браузера**: `__diplockPerf.stats()`. Панели в UI нет намеренно — замеры
не должны влиять ни на вёрстку, ни на бюджет кадра. Счётчики ничего не отправляют на сервер и ничего
не хранят (в `localStorage`/IndexedDB не пишутся).

Занятые имена (новое имя добавляется только вместе со своим местом):

| Имя | Где | Что означает |
|---|---|---|
| `eeg.raster.rebuild` | `SpectrogramCanvas.tsx` | растр спектрограммы собран заново (движение курсора сюда **не** входит) |
| `eeg.raster.build` / `eeg.raster.paint` | `SpectrogramCanvas.tsx` | время сборки растра / время отрисовки в холст |
| `edf.pan.frame` | `TrackStack.tsx` | кадр панорамы (рендер стека), а не событие мыши |
| `edf.envelope.recompute` | `TrackRow.tsx` | пересчёт огибающей канала |
| `edf.chart.create` | `TrackRow.tsx` | создание чарта uPlot |

**Порядок замера:** `perfReset()` → сценарий (панорама, клик по треку, правка окна дБ, ресайз) →
`perfStats()`. В dev-сборке React `StrictMode` вызывает рендер и монтирование эффектов дважды, поэтому
счётчики в `npm run dev` завышены: числа для решений снимаются на сборке (`npm run build` → UI
раздаётся FastAPI по `/ui/`).

## 3. Правила отрисовки (введены срезом P1)

1. **Растровый слой и оверлеи — раздельно.** Тяжёлая картинка пересобирается только по своим входам
   (у спектрограммы — сетка, окно времени, окно частот, окно дБ, палитра, размер области). Курсор,
   маркер частоты, линии сетки, зоны и рамка окна рисуются **поверх** и растр не пересобирают.
2. **Растр — в разрешении данных, апскейл — композитору.** `spectrogramRaster` (чистая функция,
   `eegSpectrogram.ts`) собирает RGBA размером «строки × видимые окна STFT», но не больше бюджета
   холста (`maxColumns × maxRows`); `drawRaster` (`eegCanvas.ts`) кладёт его через `drawImage` с
   `imageSmoothingEnabled = false`. `putImageData` для этого не годится: он не проходит трансформацию
   контекста и не умеет масштаб (тест `eegCanvas.test.ts`).
3. **Производные объекты мемоизируются по примитивам.** Окно вьюера — `useMemo` по
   `[durationSec, factor, centerSec]`, а не новый объект на каждый рендер: от идентичности окна
   зависит пересчёт огибающей в `TrackRow`. Свежесозданный объект в деп-массиве `useMemo` означает
   «пересчитывать всегда».
4. **Чарты не пересоздаём.** Канал и признак оси времени — единственные причины нового `uPlot`;
   размер идёт через `setSize`, шкала Y — через `setScale('y')` (иначе ресайз и переключение шкалы
   амплитуды собирали заново все 18+ чартов стека). Жесты панорамирования: слушатели ставятся **один
   раз** (значения — из `ref`), накопление — в `ref`, рендер стека — один кадр экрана
   (`requestAnimationFrame`), коммит состояния — на отпускании указателя.
5. **Чистая логика — в `shared/lib`, компонент рисует.** Растр, сглаживание и правила выбора ячеек
   живут в `eegSpectrogram.ts` без DOM и без импортов, поэтому проверяются Vitest в jsdom
   (`spectrogramRaster`, `boxSmooth`). Компонент не считает пиксели.
6. **Тяжёлая работа переезжает в воркер только по замеру.** Сначала P0-счётчики, потом обсуждение
   воркера/GPU: воркер с передачей буферов дороже, чем отсутствие пересчёта (правило 1).
7. **Замер размера области не должен замыкаться на её же контент.** Регрессия 22.09.2026: обёртка
   сворачиваемой секции `Panel` рвала flex-цепочку панели «Треки записи», высота области треков текла
   от контента, `ResizeObserver` (`TrackStack.tsx`) отдавал растущую высоту, развёрнутый трек тянулся
   на неё — петля «высота → контент → замер» с бесконечным ростом DOM и зависанием вкладки. Теперь
   страховка структурная (решение владельца, 22.09.2026): развёрнутый трек — фикс
   `EXPANDED_TRACK_HEIGHT` (×8 к превью, `shared/lib/trackOptions.ts`), наблюдатель меряет **только
   ширину**, высота обратно в рост контента не уходит. Обёртка скрытия секции тоже не участвует в
   раскладке (`Panel` вне панели опций её не рисует вовсе, раскрытая — `display: contents`); jsdom
   петли не ловит — заглушка `ResizeObserver` отдаёт константу, форму DOM закрепляют
   `shared/ui/Panel.test.tsx`, фикс высоты — `trackOptions.test.ts` и `TrackStack.test.tsx`.

Сглаживание спектрограммы (`boxSmooth`) считается **бегущей суммой**: окно скользит на один отсчёт,
из суммы уходит крайний и приходит новый — O(length) вместо O(length · width) на строку.
Эквивалентность прежней формуле (включая обрезанные края) закреплена тестом против наивной реализации.

## 4. Границы

- **UI не запускает обработку** (`docs/rules/frontend-state.md` п.1). Перенос **отрисовки** на другое
  ядро или GPU обработкой не является: правило запрещает старт расчёта без кнопки, а не ускорение
  картинки. Клиентский пересчёт научных чисел этой строкой **не** разрешён — он требует отдельного
  решения владельца (§7.2 аудита).
- **Научные числа считает сервер.** Замеры §2 показывают, что переносить нечего: STFT — 4.1 мс,
  чтение EDF из кэша — 3.7 мс. Дублирование пайплайна на клиенте даёт второй источник истины, а не
  скорость.
- **Кэш растра — view-кэш.** Живёт в `useRef` компонента, инвалидируется по входам и исчезает вместе
  с компонентом; в `localStorage`/IndexedDB ничего не пишется. Появится клиентское хранилище — строка
  в `docs/data_map.md` (правило `docs/rules/docs.md` п.3).
- **Клиентские счётчики — не данные расчёта.** Они не уходят на сервер, не участвуют в отпечатках
  (`eegSignature`/`calcSignature`) и не влияют на результат.
