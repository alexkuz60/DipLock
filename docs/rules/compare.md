## Зачем и что сравнивает

Одна пара записей одного испытуемого — например, **покой с закрытыми глазами** и
**умственная деятельность** — обрабатывается **одними и теми же параметрами**
спектра (фильтр, notch, референс, длина эпохи, метод PSD). Без этого дельты не
определены: это и есть «совпадение параметров» кирпича B9
(`docs/data-blocks.md` §4). Направление всех дельт — **B − A**: знак числа
означает «насколько выросло в B относительно A».

Что считается (`services/compare.py`, этапы задачи → подписи в `STAGE_TITLES`):

1. **PSD-кубы обеих сторон** на общей сетке: тот же путь, что у спектра
   (`_prepare_epochs` → `_compute_psd`: монтаж, референс, фильтр до нарезки,
   кэш prepared_raw A4). Каналы сужаются до **пересечения** пары (разошедшиеся —
   в `warnings` и в блоке `match` результата); sfreq обязан совпасть — шлюз 400
   до старта задачи.
2. **Дельты по полосам `freq_bands`**: мощность (мкВ²), дельта мкВ² и дБ
   (10·log10(B/A)), относительная доля, медиана по эпохам, **95% bootstrap-ИИ
   дельты дБ** (ресэмплинг эпох внутри каждой стороны: записи — независимые
   выборки, пары «эпоха к эпохе» нет; ноль внутри интервала = различие не
   подтверждено), робастный эффект (медианная разность / pooled MAD).
3. **Welch t-тест + FDR**: уровень полосы (p, затем FDR-поправка q по всем
   полосам результата) и отдельный проход по каналам внутри полосы
   (`fdr_significant_channels` — по ним UI выделяет строки, а не по q полосы).
4. **Кластерный пермутационный тест MNE** (`mne.stats.permutation_cluster_test`)
   по мощности «канал × частота» в дБ: соседство скальпа —
   `mne.channels.find_ch_adjacency` (Delaunay по позициям монтажа), частоты —
   решётка (`combine_adjacency(n_freqs, ch_adj)`). Уровни —
   `compare_n_permutations` / `compare_alpha` / `compare_n_bootstraps` в
   `core/config.py`. Меньше 2 эпох у стороны или меньше 3 каналов с позицией —
   тест **пропускается** с предупреждением (не ошибка).
5. **Карты разности B−A** по полосам: дельты дБ по каналам, дивергентная палитра
   `RdBu_r` со шкалой `(-m, m)` (`topomap_png(cmap=…, vlim=…)`), кэш на диске
   `cache/compare/{id_A}/{signature}/{band}.png`, отдача — `GET
   /compare/topomap/{band}.png` с ETag; подпись включает параметры и **обе**
   записи (смена любой стороны меняет URL). Промах кэша — ленивый пересчёт пары
   (тот же принцип, что у `cached_topomap` спектра).
6. **TFR/ERDS-карты (остаток B9, включаются полем формы `tfr_event`)**: честны
   **только при выравнивании по событию** — ветка режет обе стороны
   `segment_epochs_events` (та же подготовка `pipeline="spectrum"`, что PSD), а
   не фиксированные эпохи. Морле-вейвлеты (`tfr_array_morlet`,
   `n_cycles = 3 + f/6`) → per-epoch baseline → ERDS% = (P − P_base)/P_base × 100;
   карта — среднее по эпохам и **общим каналам** (40 лог-частот × ~100 точек
   времени через декимацию), дельта B − A в %-пунктах. Сетка частот сжимается
   полосой фильтра и Найквистом (как в `_compute_psd`); окно обязано вмещать
   самый длинный вейвлет, иначе задача падает с читаемым текстом (падение на
   честном месте лучше молчаливого zero-pad'а и «карты краёв-фикции»).
   Полосовая сводка — Welch p + FDR и **bootstrap-ИИ дельты в %-пунктах**
   (`_bootstrap_ci_delta`, зеркало
   `_bootstrap_ci_db` для линейной шкалы). Heatmap дельты — PNG data-URI прямо
   в результате (принём `covariance_qc`: картинка и числа одного пересчёта).
   TFR чанками (`_TFR_CHUNK`), набор эпох ограничен бюджетом памяти
   (`_TFR_DATA_BUDGET_BYTES` — честный отказ вместо свопов). Каветы ERDS
   (`ERDS_NOTES`) добавляются к `notes` только при включённой ветке; шлюз
   роута до старта задачи проверяет, что событие есть **в обеих** записях
   (400 с перечнем доступных), валидация окна/baseline — в
   `api/params.py::compare_params` (baseline строго до события).

## Контракт и задача

- `POST /compare` (FormData: две записи, ярлыки условий, параметры спектра) →
  202 + `job_id`; шлюз пары — 400 с текстом (одинаковые записи, разный sfreq,
  нет общих каналов), неизвестная запись — 404. Задача `kind=compare` живёт в
  общем `job_manager` (**не** в `RECORDING_JOB_KINDS`: пара — не одна запись),
  поэтому `job_status` отдаёт `result_url = /compare/{job_id}`, а не адрес у
  записи. Носитель результата (срез 1) — файл задачи + дисковый кэш карт;
  строк в БД нет — это задача остатка 4.7 вместе с ORM `group_analysis`.
- `GET /compare/{job_id}` → `CompareResult` (`response_model`): паспорт пары,
  сводка `match` (что совпало/разошлось), PSD-кривые и дельта-кривая, таблица
  `bands`, индексы (IAF, θ/β, 1/f), `stats` (кластеры) и обязательные `notes`;
  опционально `erds` (`CompareErdsOut | None` — событийная ветка, пункт 6).
- Результат читается только по своему адресу: чужой `kind` на `/compare/{id}` —
  404 (`compare_job_result`), незавершённая — 409 (правило 6
  `docs/rules/api-jobs.md`).

## Каветы — часть контракта, не оформление

`CompareResult.notes` (и `COMPARE_NOTES` в сервисе) показываются UI **без
редактирования**:

1. Кластерный тест указывает на связку «частота × канал», но не доказывает
   значимость каждой её точки (Sassenhagen & Draschkow, 2019);
2. эпохи внутри записи автокоррелированы — эффективная выборка меньше числа
   эпох, p-значения могут быть оптимистичными;
3. дельты считаются по общим каналам при одинаковой обработке; направление — B − A.

GOF между полосами не сравнить и здесь (правило `docs/rules/dipoles.md`) —
дипольные метрики в контракт сравнения не входят.

## UI: раздел «Групповой анализ»

Готовый результат пары — исходник **первого отчёта «Итогов»** (Тип 1):
раздел «Итоги» → переключатель «Отчёт» → «Сравнение (Тип 1)» собирает из
него самодостаточный HTML (`services/group_reports.py`, правило —
`docs/ui/summary.md` §3.9.8).

`frontend/src/app/sections/group/`: панель (пара из `GET /sessions` —
санкционированный вход, листинга записей в API нет — + текущая открытая запись;
ярлыки условий; метод PSD), кнопка «Сравнить» в тулс-хедере (**правка параметра
не запускает расчёт**), результат в рабочей области: паспорт пары, таблица дельт,
кластеры, PSD-кривые, карты разности (`?v=` = `topomap_version`), индексы,
`notes`/`warnings`. Стор — `shared/state/groupCompare.ts` (персистятся только
ярлыки: пара/результат — состояние сессии).

**Графика цифровых блоков** — `group/GroupCharts.tsx` (+ `chartFormat.ts`:
общие форматтеры/шкалы): чистый SVG над числами сервера (та же причина и
приём, что у `FftHistogram`), дивергентная пара «рост в B / спад» повторяет
серверную палитру RdBu_r карт разности (красный `--color-danger` / синий
`--color-accent`), «нет числа — нет линии»:

- таблица дельт — **правая колонка «Δ (график, дБ)»**: вертикальный
  столбик-строка от нуля + ус 95% bootstrap-ИИ на общей симметричной шкале
  всех полос (`bandDeltaScale`), значение напротив своей строки таблицы;
  яркость — значимость после FDR (`BandDeltaBar`);
- **PSD, дельта и кластеры совмещены в одной панели** (`SpectrumStats`):
  один график `CompareStackChart` на **общей частотной оси** — ряд PSD
  обеих сторон (лог-ось Y с разметкой и сеткой) → ряд ΔдБ → прямоугольники
  кластеров → ось X; сквозная вертикальная сетка и **курсор**: при наведении
  под графиком параметры «диапазон (полоса из `/meta`) · частота · уровень
  A/B», точки кривых подсвечены. Легенда и оба пояснительных комментария —
  под графиками; ниже — числовые карточки кластеров;
- индексы — «dumbbell»-стрелки A→B в столбце таблицы (`IndexDumbbell`);
- ERDS-панель (`ErdsPanel`, рисуется только при `result.erds`): сводная строка
  (событие, окно, число событий сторон), heatmap дельты из `delta_png`
  (data-URI), таблица полос (ERDS% A/B/Δ в %-пунктах, ИИ, p, q) и warnings
  ветки; поле «Событие (TFR/ERDS)» в панели пары (пусто — чисто спектральное
  сравнение, как прежде).

**Масштаб графиков — всегда 1:1 с контейнером.** `CompareStackChart` меряет
свою ширину `ResizeObserver` (ширина только, высота — константа; приём
`MriProjection`, правило `docs/rules/frontend-perf.md` п. 3.7) и строит
`viewBox` в экранных пикселях: шрифты/толщины линий не растягиваются при
resize окна. Вертикальная геометрия — константы: PSD 150, ΔдБ 100, строка
кластера 20, зазоры и ось 16 (≈ 366 px при двух кластерах). Рендер
начинается после первого замера (ширина 0 — пустышка, как у `HeartRateTrack`);
X-тики адаптивны (6 при ширине ≥ 480, иначе 4). Мелкие SVG держат
фиксированную CSS-ширину, равную viewBox: `BandDeltaBar` — `w-44` (=176),
`IndexDumbbell` — `w-[100px]` (=100). Страж — тест «график 1:1 с контейнером»
(viewBox = ширина заглушки 1024, высота = 366 px).

Мини-схемы монтажа с точками кластеров в v1 не рисуются (решение среза):
MNE-топокарты по полосам — PNG с сервера в блоке «Карты разности».


## Кэши и очистка

- `cache/compare/` входит в `RECORDING_CACHE_SUBDIRS` (обход сирот A6): верхний
  уровень — `id_A`, удаление записи сносит её каталог; файлы с мёртвым `id_B`
  под живой `id_A` чистит `clear_compare_cache(settings, id)` из
  `_drop_signal_cache` (второй уровень).
- Подпись карт — `compare_signature` = `spectrum_signature` + обе записи +
  версия отрисовки `COMPARE_TOPOMAP_VERSION` (смена версии отправляет старые
  PNG в невалидность, урок A7).
