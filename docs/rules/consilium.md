## 0.9. Общий чат с ролевыми агентами (миграция 0019)

Отдельная вкладка «Чат экспертов» в разделе Консилиума (`?view=chat`), API —
`/api/v1/agent-chat`, сервисы — `services/agent_chat/`. Это единственный
диалоговый режим раздела после удаления «Исследования» 23.11.2026.
Нити и сообщения исследователя/агентов хранятся в `agent_threads` и
`agent_messages`; роли с инструкциями и необязательным назначением провайдера/
модели — в `agent_roles`. Стартовые роли создаются при первом чтении, встроенные
можно выключить, но нельзя удалить; пользовательские роли можно изменять и
удалять.

* Запрос запускается только кнопкой и адресуется через `@метку`/`@id` и/или
  явный выбор адресатов; выключенная/неизвестная роль не вызывается. Одна роль —
  одна LLM-задача класса `llm`, ответ отдельной репликой. Заглушек нет.
* Агент видит историю до исходного вопроса и сам вопрос; реплики, появившиеся
  позже, и параллельные ответы этого обмена в промпт не попадают. Переданные
  прошлые ответы коллег помечены ролью. Контекст ограничивается
  `agent_chat_prompt_max_chars`; пропуск ранних сообщений сопровождается
  предупреждением. ИИ не получает автоматически результаты ЭЭГ,
  инструменты, БД, файлы или произвольный Python.
* Инструкция роли, сообщение и ответ — данные, не доверенные инструкции для
  системы. Модель/провайдер выбираются из настроенного модельного роутера;
  незарегистрированная модель не подменяется молча. Бюджет ответа задаёт
  `agent_chat_answer_max_tokens`. Инструкция роли ставится перед базовой:
  для локального однопользовательского инструмента это приемлемо, но при
  появлении общего сервера базовую инструкцию нужно дублировать после
  инструкции роли (см. долг в `todo.md`, Шаг 4).
* Ответы идут фоновыми задачами, стримятся общим SSE-механизмом, но итог
  сохраняется в БД до успеха задачи; сбой/пустой ответ честно помечается,
  повтор возможен только после `failed`/`interrupted`; след прошлой ошибки
  сохраняется в warnings реплики. При рестарте `running`
  помечается `interrupted`; нить нельзя удалить, пока есть ответ `running`, после
  завершения удаление удаляет её реплики. SSE-дельты — только
  RAM-удобство, клиент дочитывает итог из БД.
* Веб-поиск Архивариуса (миграция 0020, `agent_web_searches`): запрос уходит
  поисковику (DuckDuckGo HTML, `agent_web_search_*`) только по кнопке «Найти»;
  найденные заголовки и фрагменты сохраняются в нити, перевод на русский —
  отдельной кнопкой через провайдера роли (`agent_web_search_translate_max_tokens`),
  ошибки перевода честно показываются по каждому материалу. Свежий поиск
  подмешивается в контекст Архивариуса с пометкой «перевод машинный»; если
  перевода нет, это отдельное предупреждение. Поисковый контекст не заменяет
  оригинальные материалы и не означает обучения весов модели.
* Перед отправкой UI предупреждает, что сообщения уходят провайдерам,
  назначенным ролям (возможно, внешним), и просит не передавать персональные
  данные добровольцев/секреты. Политика обезличивания и разрешений внешней
  передачи остаётся отдельной открытой задачей (`todo.md`, Шаг 4).
* История отображается по времени; выбор нити адресуется через `?thread=`.
  Данные чата не сохраняются в `localStorage`; переключение вкладки обратно к
  «Исследованию» сохраняет доступ к Т1 и прежней панели опций.

## 0.10. «Знания»: библиотека источников и База знаний (миграция 0021)

Вкладка «Знания» (`?view=knowledge`) с подвкладками «Источники» (`?tab=sources`)
и «База знаний» (`?tab=base`). API — `/api/v1/knowledge`, сервисы —
`services/knowledge/`, правила — `docs/rules/knowledge.md`.

* «Источники»: папки (корневая «Источники», вложенность через `parent_id`),
  загрузка PDF с текстовым слоем, DOCX, XLSX, изображений и веб-страниц по
  ссылке; дедуп по sha256; лимиты 50 МБ на файл и 2 ГБ на библиотеку.
  Читалка показывает оглавление по разделам, аннотации к разделам и теги.
* «База знаний»: поиск по фрагментам (TF-IDF всегда, эмбеддинги — при
  доступном провайдере; режим `hybrid`/`tfidf` показывается честно), теги и
  граф знаний только из подтверждённых рёбер.
* Вложения нити чата (`agent_thread_attachments`): документ, веб-ссылка, отчёт
  или анализ ЭЭГ; в промпт попадают при отправке сообщения, с предупреждением о
  передаче провайдеру.
* Встроенная роль «Ассистент» отвечает по тексту вики-документации; кнопка
  «Спросить Ассистента» на странице Wiki выгружает статью в библиотеку и
  открывает чат с вложением и подставленным вопросом.
* Изображения и сканы без текстового слоя сохраняются со статусом `empty`:
  OCR не подключён, содержание не выдумывается.

## 5. Провайдер модели

Доступ к модели — за небольшим интерфейсом: проверка доступности, генерация,
отмена/тайм-аут, вызов разрешённых инструментов, сведения о модели и расходе.

**Решение 10.10.2026: локальные урезанные модели (llama.cpp) отклонены** как
советники — «советоваться» с обрезанной моделью не соответствует тематике
исследования. Советники работают с **полноценными моделями через внешние API**;
подключение — **модельный роутер** в разделе «Настройки»
(`GET/PUT /api/v1/llm-router`, `POST .../probe`, сервис
`backend/app/services/llm_router.py`). Локальный запуск весов не производится.

Роутер хранит провайдеров (протокол `openai` — совместимый `/chat/completions`,
или `anthropic` — Messages API; адрес, модель, ключ) и маршруты `chat`
(советники, Т3) и `transcribe` (распознавание, Т2; только `openai`). Ключи
лежат в JSON-файле на сервере (`settings.llm_router_config_path`), в ответах UI
заменены маской `key_hint` и не попадают в логи/тексты ошибок; ошибка формы не
эхо-передаёт ввод (`PrivateRoute`). Правка настроек ничего не отправляет
наружу: внешний запрос выполняется только явным действием («Проверить связь» —
нейтральный запрос «Ответь одним словом: готов» без материалов — или ответ
агента в чате). Выбор модели и конкуренция с MNE за ресурсы заменены
вопросами латентности/лимитов провайдера — измеряются в пробах §10 стратегии.

`httpx` добавлен в основные зависимости (ранее — только dev), закрыт тестами
(`tests/test_llm_router.py`), вызовы идут через него.

**Дополнительные параметры запроса** (`extra` провайдера): JSON-объект,
дополняющий тело вызова, — для опций вида DeepSeek
`{"thinking": {"type": "enabled"}, "reasoning_effort": "high"}` (и аналогов у
других провайдеров). Ключи `model`/`messages`/`stream` зарезервированы
роутером (400 в PUT, отсекаются и при чтении кустарного файла); размер — не
больше 30 ключей и 4 КБ JSON. Адрес базы — как у провайдера SDK, с `/v1` или
без (`https://api.deepseek.com` — роутер сам дописывает `/chat/completions`;
Anthropic-формат DeepSeek — `https://api.deepseek.com/anthropic`). Проба связи
шлёт `extra` как есть и держит бюджет `llm_probe_max_tokens` (8192 токенов по
умолчанию), чтобы thinking-режим не давал ложный отказ на «одном слове»;
тайм-аут вызова — `llm_request_timeout_s` (180 с: thinking-модели отвечают
десятки секунд).

Поле «Модель» — список id моделей через запятую (кандидаты одной учётки API):
пробы идут **перебором по каждой** модели, маршрут `chat` работает **выбранной**
моделью списка (`chat_model` в маршрутах, UI — выпадающий список «Модель
советников (chat)»; не выбрана — первая в списке); до 10 id по 200 символов,
пустые элементы отбрасываются. Модель маршрута обязана входить в список
провайдера — иначе сохранение отклоняется с текстом для UI.

**Каталог RouteLLM (22.11.2026).** Для провайдера Abacus RouteLLM
(`https://routellm.abacus.ai/v1`, модель `route-llm`) панель роутера подтягивает
список моделей: `GET /api/v1/llm-router/routellm/models?provider_id=...`
(`services/routellm_catalog.py`) читает `GET {base_url}/models` выбранного
провайдера и обогащает ответ каталогом models.dev (`routellm_catalog_url`, кэш
`routellm_catalog_ttl_s`): цена за 1M входных/выходных токенов, модальности,
лимиты контекста/ответа, reasoning/tool_call. Ключ в тексте ошибок маскируется.
Остаток кредитов RouteLLM по API не отдаётся — UI честно показывает пояснение и
ссылку на «Billing and Invoices», а не выдуманное число.

**Ключ провайдера (23.11.2026).** Ключ нормализуется (`strip`) и при сохранении
формы, и при чтении `data/llm_router.json`: вставка из буфера с хвостовым
пробелом или переводом строки больше не даёт `Illegal header value` в httpx
(раньше такой ключ сохранялся как есть и провал выглядел как «ключ не
принимается»). `GET {base_url}/models` у RouteLLM публичный — каталог
загружается и с неверным ключом, поэтому проверять ключ нужно пробой
«Проверить связь», а не каталогом. Если маршрут `chat` указывает на провайдера
без ключа и это не локальный адрес (`localhost`/`127.0.0.1`), панель показывает
предупреждение: маршрут получит отказ провайдера.

**Сохранение формы и дубли адресов (23.11.2026).** Пустые «Имя»/«Модель»/
«Адрес» отклоняет сервис русским 400 (`Укажите id модели…`), а не схема
английским 422 `String should have at least 1 character`: раньше такое
сохранение падало целиком, и ключ не записывался вовсе. Две строки на один
`protocol` + `base_url` запрещены (`_reject_duplicate_endpoints`): маршрут
уходил в строку без ключа, и проба отвечала `403 User not logged in`, хотя ключ
был вставлен в соседнюю строку. Отказ авторизации в пробе объясняется словами:
`403 Invalid API Key` → создать новый ключ на странице RouteLLM API и вставить
в строку маршрута; `403 User not logged in` → ключ у провайдера маршрута не
сохранён.

Внешняя передача материалов советнику требует отдельного согласия на конкретные
материалы и записи того, какая версия контекста ушла наружу (реализуется в Т3).
Псевдоним EDF не делает голос и рассказ обезличенными.

## 5.1. Пробы советника (§10 стратегии)

Выбор модели для маршрута `chat` — по живым пробам на провайдере. Инструмент —
блок «Пробы советника (§10)» панели модельного роутера и
`POST /api/v1/llm-router/chat-probe`. Четыре сценария (реестр
`CHAT_PROBE_SCENARIOS` в `services/llm_router.py`):

| Ключ | Что проверяем (§10) | Ожидается |
|---|---|---|
| `dialog` | русский диалог | связный русский ответ и уточняющий вопрос без подсказки |
| `role` | роль и структура ответа | «замечено / возможное объяснение / чего не знаем / следующий шаг», без выдуманных измерений |
| `insufficient` | отказ при недостаточности данных | честный отказ и перечень недостающего при пустом контексте |
| `leading` | ненаводящие вопросы | вопрос добровольцу без закладываемого ответа |

Правила пробы: промпты **синтетические и заданы сервером** — записи, имена и
ключи не отправляются; запуск — только явной кнопкой (правка
формы ничего не шлёт); ответ возвращается с моделью и задержкой `latency_ms`
(бюджет `llm_probe_max_tokens` = 8192 токенов на модель); ошибка провайдера —
в `error` без ключа, ложного успеха нет. Проба не сохраняется в историю чата и
не является материалом.

**Thinking-модели и бюджет (случай 11.10.2026).** Рассуждение модели
(`reasoning_content`) входит в тот же бюджет токенов, что и итоговый текст:
малый бюджет даёт ложный «пустой ответ» (модель молчит, потратив всё на
рассуждение), а обрезанный по бюджету ответ обрывается на полуслове. Поэтому:
бюджет щедрый (настраивается `llm_probe_max_tokens`), пустой `content`
разбирается честно — «бюджет токенов исчерпан на рассуждении, итоговый текст
пуст (рассуждение N симв.)» / «модель вернула только рассуждение», а обрезка
(`finish_reason=length`) помечается флагом `truncated` и подписью UI «⚠ Ответ
обрезан по бюджету токенов».

**Список моделей — перебором (параллельно).** Если в поле «Модель» перечислено
несколько id, проба (и нейтральная «Проверить связь», и каждый сценарий) идёт
отдельным запросом по каждой модели **параллельно** (перебор не ждёт по
очереди), итог — строка на модель (модель/задержка/ответ/ошибка); сводка
`ok` — только когда ответили **все** модели, `error` перечисляет не прошедшие.
Маршрут `chat` работает выбранной моделью списка (или первой, если выбор не сделан).

**Протокол измерений (выход §10)** — таблица владельца: провайдер / модель /
сценарий / задержка / вердикт (годится / не годится + почему). По ней выбирается
одна рабочая конфигурация маршрута `chat`; для `transcribe` — после ASR-проб.
Приватность: запрос уходит внешнему провайдеру только нажатием кнопки; офлайн —
проба честно падает ошибкой связи.

## 10. Безопасность

Базовый режим — локальный один пользователь и локальное хранение; веса моделей
локально не запускаются, ИИ работает только через явно настроенный модельный
роутер (§5). Внешняя передача выключена до явного действия пользователя: правка
настроек и «Проверить связь» (нейтральный запрос) материалов не отправляют.
Веб-поиск Архивариуса отправляет поисковый запрос поисковику (DuckDuckGo), а
найденный текст — провайдеру перевода, тоже только по явным кнопкам.
Голос, даты, имена файлов, аннотации и рассказы могут идентифицировать
добровольца даже при псевдониме EDF.

Раздельные разрешения: запись, хранение аудио, распознавание, передача текста
советнику, внешняя передача. Содержимое бесед не пишется в обычные логи и
traceback. Удаление учитывает БД, файлы, версии и экспорты на сервере; скачанный
пользователем файл приложение контролировать не может — это честно подписываем.

Нельзя сохранять чувствительные копии под предлогом неизменяемости снимка:
удаление очищает материалы, производные сводки и память, оставляет лишь отметки
без содержания. Архивирование не удаляет; удаление EDF не должно молча уничтожать
самостоятельную беседу, зависимости и последствия показываются до подтверждения.
Внешние адреса/ключи задаёт сервер, не чат; в локальном пилоте нет собственного
шифрования, сетевой доступ требует отдельного среза аутентификации/прав.

Общая память Т6 пополняется только подтверждёнными приёмами с исходами (включая
отрицательные), источниками, версиями, областью применимости и отзывом; не
характеристиками личности, автоматически извлечёнными из реплик. Поисковый контекст
не заменяет оригинальные материалы и не означает обучения весов модели.
