# Пространственная обработка треков «Нейромузыки» — выбор библиотек

> Исследование 06.10.2026 (срез **без кода**: сравнение кандидатов и вердикт; реализация —
> отдельным срезом). Все факты о версиях/статусе проверены в день написания по
> `registry.npmjs.org`, `pypi.org` и GitHub. Связанный раздел: `docs/rules/neuromusic.md`.

## Требования среза

Модули пост-обработки треков (7 стемов + мастер) для пространственного звучания:

1. **Расширение стереобазы** (mid/side-обработка).
2. **3D-позиционирование и перемещение источников** (траектории — из БД диполей).
3. **Акустика помещения — свёрточный ревербератор** (в т.ч. «свод черепа» из
   `extensions.intracranial_ir` sidecar).

**Ключевой критерий — эксперимент с параметрами в реальном времени** при прослушивании
через плеер раздела: правка → мгновенное услышанное изменение, без перерендера (кроме
итогового «запекания»). Дополнительные пожелания владельца (06.10.2026): отрисовка
волны при плее и синхронизация с таймлайном с точностью до семпла — это тоже даёт
выбранный фреймворк. **Отрисовка волны закрыта** тем же днём срезом «Плеер-трекер»
(§ в `docs/rules/neuromusic.md`); семпл-точная синхронизация таймлайна — Transport
и есть, точность до отсчёта при необходимости подключается поверх.

## Вердикт: гибрид (браузер как основа, Python — только ассеты и печать)

1. **Основная цепочка пост-обработки — браузер, Tone.js поверх нативного Web Audio API.**
   Это единственный способ выполнять ключевой критерий — real-time эксперимент с
   параметрами при прослушивании. Tone.js выбран (вердикт владельца 06.10.2026) и по
   расширениям: `StereoWidener` → база, `Panner3D` + автоматизация positionXYZ →
   движение по дипольным траекториям, `Convolver` → реверберация; дополнительно —
   отрисовка волны при плее и таймлайн с точностью до семпла (Transport) для будущих
   расширений функционала.
2. **Resonance Audio — запрещён к выбору** как архивированный (19.04.2026): красивый API
   на материалах комнат никого не спасёт, если исправления не приходят с 2017 года.
   **Howler — отклонён** (нет 3D/HRTF/реверберации). **librosa — отклонён**: spatial-функций
   нет вообще, а сама библиотека запрещена ТЗ рендера (`backend/requirements.txt`:
   «librosa/rubberband/pydub запрещены ТЗ»).
3. **Python — только две роли:**
   - **генерация импульсных характеристик (IR)** — `pyroomacoustics` (image source model +
     ray tracing, материалы стен, 3D-комнаты; для «свода черепа» — геометрия полусферы с
     отражающими свойствами кости/ткани) → готовые stereo-IR WAV как **ассет**, отдаётся
     через `app/api/assets.py` (ETag/304), НЕ внутри `/analyze`;
   - **офлайн-печать итога** — детерминированный финальный рендер в WAV
     (`scipy.signal.oaconvolve` со свободным requirements, `spaudiopy` — если понадобится
     ambisonics/бинаурал) для «запекания» выбранных параметров.

## Ловушки и ограничения

- **ТЗ рендера**: звуковые библиотеки обработки (librosa/rubberband/pydub) в бэкенд-рендер
  запрещены — Python-часть вердикта (pyroomacoustics/scipy) добавляется осознанно и только
  в генерацию IR/печать, в текущий пайплайн рендера `audio_render/` не вмешивается.
- **Детерминизм**: байты WAV гарантирует только Python-рендер; Web Audio (real-time и
  `OfflineAudioContext`) детерминизма байт не обещает — «запечённый» эталон печатает
  backend, браузер — инструмент эксперимента.
- **HRTF слушается в наушниках**: на встроенных динамиках 3D-эффект слабее — в UI учитывать.
- ~~Плеер `<audio src=…>`~~ — **заменён трекер-плеером** (срез 06.10.2026): цепочка Tone
  берёт буферы через fetch+decode (`NeuromusicPlayer`, ленивый кэш `ToneAudioBuffer`),
  WAV-эндпоинты без `Content-Disposition` пригодны для обоих путей
  (правило `docs/rules/neuromusic.md`, §«Плеер-трекер»).
- **Память**: 7 стемов float64 @48 кГц в памяти браузера — держать в уме вместе с
  «Память фазы 1» из `docs/rules/neuromusic.md` (часовые записи — блочный рендер).
