# Часть 4. ИИ-агент препроцессинга (контур)

> **Статус: контур, не написан.** Затравка — `docs/strategy/01-signal-quality.md` §11.
> Пишется **последней**: агенту нужны профиль качества (B11), единообразный рецепт (B10) и метрики
> потерь (B12) в журнале — иначе обучаться и проверяться не на чем.
>
> **Порядок (решение владельца 22.09.2026, вторая волна):** ни агент, ни пакетный режим **не планируются
> заранее**. Сначала методы выводятся в UI и тестируются руками и глазами; только после этого видно, какие
> решения вообще стоит автоматизировать. Поэтому здесь нельзя перечислять «умные» шаги до ручных прогонов.

## Что здесь будет

- контракт входа: профиль грязи (B11) + требования задачи (что ищем: локализация полосы, спектр,
  сравнение сессий) + ограничения (время счёта, допустимые потери L6);
- контракт выхода: **рецепт** — список шагов (методы M1…M20 из Части 1 §5 с параметрами) +
  ожидаемые потери (L3–L8) + причина по каждой строке («какая метрика вызвала шаг»);
- набор правил Части 1 §6.2 как проверяемая таблица (до модели — детерминированные правила);
- границы: методические числа (X % КД, порог GOF, набор полос) агент не выбирает; «непригодные»
  записи (клип) агент называет непригодными, а не «улучшает»; пакетный запуск — только с
  подтверждением человека;
- как измеряется польза агента: сравнение «рецепт агента vs рецепт эксперта» по L7 (КД/GOF) и L8
  (сдвиг локации, мм) на одних и тех же записях;
- режим работы в UI: «предложить / принять / отклонить / поправить», с записью в журнал решения
  человека (это будущие данные для обучения).

## Что должно быть готово к моменту написания

Части 1–3 приняты; в журнале шагов накопились записи с профилем (B11) и метриками потерь (B12) —
хотя бы на десятках сессий архива.
