## 26.09.2026 — шаг 2.7 (N2): событийный режим: EDF+-аннотации/маркеры, нарезка по событиям, ERP

**Из `todo.md` (закрыто 26.09.2026, дословно):**
> **2.7 (N2, P1):** событийный режим: чтение EDF+-аннотаций/маркеров, нарезка по событиям (ERP).

Объём уточнён владельцем: «ядро N2 + ERP-усреднение» (график усреднённой волны в UI);
диполи/спектр по событийным эпохам и «карта по Evoked» — отдельная задача после.

1. **События — один механизм (`services/edf_events.py`, N2).** EDF+-аннотации (TAL) MNE
   парсит в `raw.annotations` сам; стим-каналы (`status`/`trigger` у MNE + имена
   `stim`/`sti`/`markers`/`marker`/`trig`) при чтении (`stim_channel='auto'`) превращаются
   `mne.find_events` в аннотации **`STIM/<код>`** и удаляются из записи — события
   привязаны к исходному времени (до `pick`/фильтров/ресемпла) и не мешают масштабу/QC.
2. **Аннотации объединяются, а не перетираются (N2).** `epoch_segmenter.merged_annotations`
   ставит `файловые ∪ артефактные ∪ BAD_edge`: файловые `BAD_*` теперь роняют эпохи наравне
   с нашими детекторами (правило N6 распространено на файл), стимульные описания нарезку
   не трогают (`events_from_annotations` пропускает `BAD_`).
3. **События в паспорте и слой вьюера.** `RecordingMeta.events`/`event_counts` (без `BAD_`,
   cap 5000, сортировка по времени) — в сайдкаре записи; старые сайдкары дочитываются
   лениво (`ensure_record_events`). Слой «Маркеры событий» (`TrackLayers.EventLayer`):
   вертикальные линии с тултипом «описание, интервал», тумблер в панели (`eventsLayer` —
   отрисовка, в `STAGE_PARAM_KEYS` не входит).
4. **Нарезка по событиям.** Режим стадии «Нарезка эпох» (`epoch_mode='events'`): окна
   `[−pre; +post]` мс вокруг моментов события `event_id` (описание из паспорта); длительность
   окна в этом режиме **не** привязана к `epoch_lengths_ms` (ERP-окна −100…500 мс).
   Результат несёт `epoch_starts_sec` + параметры события — вьюер строит **нерегулярную**
   сетку из явных начал (`buildEpochCells(..., startsSec)`), индексы `rejectedEpochs` живут
   в порядке событий; пилюля «разметка: по событиям «X»» при расхождении параметров.
   Валидация формы — 400 с текстом (`api/params.py`).
5. **ERP (`kind='evoked'`, `services/evoked.py`).** Отдельная задача (не 4-я стадия):
   `prepared_raw` → BAD_-зоны (пороги формы — числа согласованы со штриховкой) →
   `segment_epochs_events` → baseline-коррекция (пара мс внутри окна, опционально) →
   `epochs.average()`. `EvokedResult` — волна [канал][время] в µV, ось от события,
   `n_used`/`n_total` + `rejected_epochs`. Блок «ERP» в панели EDF: baseline «−200…0 мс»,
   канал графика, кнопка «Усреднить (ERP)» (правка параметров, как и везде, ничего не
   запускает), статичный SVG-график (`shared/lib/evokedChart.ts` + `EvokedChart`).

Валидация: ruff/mypy/pytest **486** (+23: `test_edf_events` — стим-каналы/TAL/merge/паспорт/
событийная нарезка, `test_preprocess` +4, `test_evoked` +6 — усреднение, baseline, счёт

   на набор эпох, `whitened_riv` считает долю отбелённой невязки `‖W·r‖²/‖W·d‖²`, `conf_ci_mm`
   — радиус доверительной области из `dip.conf` MNE (максимум границ depth/long/trans, мм).
2. **Точный фит (`fit_dipoles_for_epochs`).** Расширена распаковка `mne.fit_dipole`: невязка

3. **`fast_grid` (`dipole_scanner.py`).** `_fit_best_node` возвращает `ScanFit`

   Уточнение (`refine_dipole_point`) отдаёт RIV узла/обоих BEM-фитов и CI свободного фита

4. **UI.** Колонки `RIV, %` и `CI, мм` в таблице локализации (12 колонок), подписи

   порог снят): скрывает строки, но не удаляет их (счётчик «строк N из M», пустая после

## 24.09.2026 (поздний вечер) — шаг 2.4 (N17, N18): multitaper, 1/f + пики, лог-шкала, ERD/ERS

**Из `todo.md` (закрыто 24.09.2026, дословно):**
> **2.4 (N17, N18, P2):** спектр: `multitaper` для коротких эпох; лог-шкала; ERD/ERS;
> specparam/FOOOF (1/f + пики) — после IAF (1.2).

Решение по развилке (владелец, план этапа): ERD/ERS — **параметр просмотра клиента**
поверх уже полученной сетки дБ (без пересчёта задачи); метод PSD — переключатель
Welch/multitaper с дефолтом **Welch** (обратная совместимость чисел прежних расчётов).

1. **Multitaper (N17, `services/spectral.py`).** `SpectrumParams.psd_method`
   (`welch` | `multitaper`): multitaper (DPSS, `compute_psd`) считает эпоху целиком
   вместо Welch-окна `n_fft ≤ 256`, которое на эпохе 250 мс даёт разрешение ≈4 Гц при
   ширине α в 5 Гц. Ширина полосы сглаживания — константа 4 Гц с клипом не ниже
   `2·sfreq/n_times` (иначе time-bandwidth DPSS падает ниже единицы). Метод входит в
   `spectrum_signature` (топокарты не «залипают» под чужим ETag) и в query топокарты
   (`psd_method` в форме и в `GET …/topomap/{band}.png`), результат несёт `psd_method`
   и `n_fft` = длина окна анализа для multitaper.
2. **1/f + пики (specparam/FOOOF, kimi3).** Зависимость `specparam>=2.0.0rc7`
   (стабильного 2.0 на PyPI ещё нет — как и MNE, API зафиксирован тестами). Фит
   апериодики (fixed, без «колена») и гауссовых пиков по **среднему спектру** —
   `SpectrumResult`: `aperiodic_exponent`/`aperiodic_offset`, `aperiodic_fit_uv2`
   (кривая фона на сетке `freqs`), `peaks` (центр/высота в дБ/ширина, по убыванию
   высоты), `fit_r_squared` (R² в log-пространстве, как в FOOOF). Отказ фита — не 500,
   а null-поля + строка в `warnings` (тест мокает `fit` на исключение).
3. **UI «Диполи».** `SegmentedControl` «Метод PSD» рядом с «Длиной эпохи» (правка без
   запросов, метод не входит в `calcSignature` — диполи от него не «устаревают»);
   FFT-гистограмма поверх ломаной PSD рисует **пунктир фона 1/f и метки пиков**
   (`psdX` — та же шкала x, что у ломаной); метрики `spectrumMetrics` пополнились
   «1/f 2.10» и «пик 10.2 Гц».
4. **Лог-шкала частот (N18, «ЭЭГ»).** `freqScale: 'lin' | 'log'` — параметр просмотра
   (не в `eegSignature`): лог-ось определена от 1 Гц (0 Гц не логарифмируется),
   деления — 1/2/5 × 10^k, `fmaxToY`/`yToFreq`/`freqTicks`/выбор строк растра
   (`spectrogramRaster`) считают обеих шкал (обратность — тест).
5. **ERD/ERS (N18, «ЭЭГ»).** `valueMode: 'db' | 'erd'` + `baselineSec` + `erdRangePct`
   — параметры просмотра поверх сетки дБ: `(P − P_ref)/P_ref × 100 %`, мощность
   восстанавливается точно (`10^(дБ/10)`), `P_ref(f)` — среднее по baseline-столбцам
   (строго попавшим в интервал, без «зажима» к ближайшему). `[0, 0]` в baseline —
   «первые 10 % записи» (`resolveBaselineSec`); baseline вне сетки — null-трансформация,
   а не проценты по пустому отсчёту. Палитра в режиме ERD растягивается окном %
   (`erdToUnit`), в панели — контролы baseline и окна %.

Замер (синтетик α 10 Гц, эпохи 250 мс): Welch-сетка ≈4 Гц даёт **три** ложных пика
specparam при R² = −0.12, multitaper — один пик **10.2 Гц** при ширине ≈2 Гц — ровно
та находка N17, ради которой этап задуман.

400 по методу, ETag топокарты от метода, форма параметров), Vitest **724** (+15:

## 22.09.2026 — фикс зависания: обёртка аккордеона против раскладки вьюера

## 18.09.2026 — Исправлено: возврат в EDF переоткрывал диалог выбора файла

  `error=…`: упавший шаг обязан быть виден, иначе «почему задача упала» выясняется по тексту ошибки
  задачи); `record()` — для уже измеренного шага (ступень или сумма по циклу). Поля можно дополнить
  внутри блока (`entry.bytes_out = len(blob)`). До этого время мерилось в шести несвязанных местах
  (`duration_sec_calc`, `Job.elapsed_sec`, `duration_sec` в `/analyze`).
- **`job_id` проставляет `job_scope` (ContextVar) вокруг `asyncio.to_thread`** в `job_manager._execute`:
  контекст доезжает до потока задачи, потому что `to_thread` копирует контекст, и сервисы пишут
  `job_id` **без параметров** (про задачи не знают). Синхронный вызов (`/analyze`, тесты) пишет
  прочерк — в файле `-`, в API он превращается в `null` (правило «неизмеренное — `null`»).
- **Носитель — `data/cache/journal.jsonl`** (под `CACHE_DIR`, не коммитится). Дописывание под локом
  (шаги идут из нескольких потоков job-очереди), перед записью сверяется `JOURNAL_MAX_BYTES`
  (5 МБ по умолчанию): полное поколение уезжает в `journal.jsonl.1`, старше — перезаписывается,
  поэтому на диске всегда не больше двух файлов. Чтение — только «хвост» (1 МБ): журнал читают ради
  последних шагов. `JOURNAL_ENABLED=false` выключает запись; **сбой записи логируется и гасится** —
  журнал не может сломать расчёт (то же правило, что у кэшей в `cache_store`).
- **Роут `GET /api/v1/journal`** (`limit` 1–2000, фильтр `pipeline`, `response_model=JournalOut`):
  `enabled`, путь файла, список строк. Отсутствие файла — пустой список, а не 404. UI журнал не

- **`params_key` — та же сигнатура, что у кэша результата** (`spectrum_signature`, ключ
